# 2026-09-11 小说下载闭环、地图归区、事件日志收口

阶段性交接记录。本轮围绕三条线：**小说下载从"能用"到"可靠"**、**世界地图区域自动化**、
**AI 调用事件统一收口**，并补齐了素材库/风格页的若干交互缺口。

## 一、小说下载（`/novel-bookshelf` → `/novel-reader`）

原先的坑都不是单点 bug，而是互相叠加：

1. **下载任务不可见**：任务中心读内存队列，而 `should_persist` 要求「白名单 + `project_id`」，
   小说下载两个都不满足（它属于书架资产、不挂创作项目）→ 只活在内存，重启即消失。
   修：新增 `PERSISTED_STANDALONE_TASK_TYPES` 放行不挂项目的任务类型。
2. **僵尸任务**：重启后残留的 `pending/running` 永远转圈（协程已随进程消失）。
   修：启动首次恢复时做对账，收尾为「服务重启，任务中断」。
3. **干等 8 分钟才失败**：站点反爬（实测起点 403）时逐章请求全失败。
   修：连续 15 章失败熔断，事件日志报出首个真实错误（HTTP 403）。
4. **书架进度不动**：`downloaded_chapter_indices` 要下载结束才写，中断后一片空白。
   修：成败都落库；新增 `POST /novels/local-sync` 按磁盘文件重算索引。
5. **重下浪费**：重下会重复抓已下章节。修：下载器断点续下，已有章节文件直接跳过。
6. **阅读走网络**：阅读器按索引判断是否已下载，而索引滞后；且记账曾按 `req.chapters`
   全量虚报。修：本地优先 + 按实际成功记账；本地没该章才回退在线。

## 二、世界地图

- 工作台独立页此前只能从创作项目深链进入（否则按钮全禁用）→ 加项目选择器（写回 URL）。
- `from-places` 按地点实体的 `region` 属性自动建区域并归类；已有据点重跑补齐归属且不重建
  （保留精修坐标）。初稿版本从 v2 修正为 v1 并落版本快照。
- 提取侧 `region` 匹配不到同名地点时补建 `entity_type="region"` 实体连 `part_of`
  （用 `region` 而非 `place`，避免被当成据点生成到地图上）。
- 前端新增「生成全部形状」，只给没有形状的区域生成，不覆盖手绘。

## 三、事件日志统一收口

事件日志此前两套并存：端点手写 + `AIService` 收口自动记，同一次调用落两条。
本轮删除端点层 12 处重复记账（llm 1 / videos 3 / images 3 / characters 5），
并补齐两个删除前提：

- `ai_call_context` 支持 `retry_payload`——端点记录里带着「重发」所需的原始请求，
  删了重发就废了，改由上下文注入。
- `AIService.generate_image / generate_video` 补异常兜底（此前只有 `chat` 有）。

`novel_sources` 的 12 处业务事件（"几个模块/多少候选"）改用 `suppress_auto_event`
抑制自动记账，保留业务语义。保留项：资产谱系、创作阶段、重发、小说下载，
以及不走 `AIService` 的旁路（model3d 直连 httpx、breaker STT、embedding）。
顺带把摘要上限从 60000 缩回 20000（60000 会让截断保护失效）。

对应 `openspec/changes/platform-event-logging` #38 已完成，仅剩 #30 手动验收。
