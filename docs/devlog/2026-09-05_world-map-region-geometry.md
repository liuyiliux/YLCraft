## 二、区域几何重构：为什么要改（这是语义错误，不是样式问题）

用户原话：*"福贵的村子是个区域，但福贵的房子不是区域的角——我们会把它设为区域的角，
实际应该是城墙角之类的。"*

**旧实现的错误**：区域渲染为「成员据点围成的凸包」——等于把"房子"当成"村子的城墙角"。
后果：据点一动形状就变形；凸包画不出凹形（村子绕过山头的边界、海湾、城墙拐角）。

**正确层级**：

```
区域（有形状的地理范围）  ← 村子、县城、势力范围
  └─ 据点（区域内的一个位置） ← 福贵的房子、村口老槐树
```

形状是区域的**独立几何**；据点通过 `region_id` **引用**区域，不决定其形状——
与既有「引用不复制」纪律一致。

## 三、已确认的关键决策（13 项）

完整记录在 `.ai-sdd/requirements/region-geometry-rework/discover-2026-09-04.md`（状态：已确认）：

1. 形状来源：双模式（一键生成 + 手绘微调）
2. 归属：**引用为准，位置仅提示**（据点画到形状外只警告，不自动改引用）
3. 生成方式：**可控生成**（不接 Azgaar 随机生成管线，形状由我们的数据确定性展开）
4. 旧数据：直接清库，不备份（已确认；执行前会再报数量）
5. AI 输出：**语义参数 + seed**，不输出几何
6. 触发：独立动作（用户点 / Agent 调工具）
7. 顶点上限：64
8. 层级视觉：父淡子艳，选中更艳
9. 清理范围：全部清空 `world_maps` + `world_map_revisions`
10. 嵌套：不限层，深度自动算视觉权重
11. 词表：三维度（自然意象 8 × 聚落形态 6 × 人工构筑 3+）
12. 据点 kind：扩到 20 种 + 每种配图标
13. 许可证：Azgaar 为 **MIT**，参考其算法无法律障碍

**D-1（重要）**：几何由**前端唯一实现**，后端与 Agent **不实现几何**。
AI/Agent 只产语义参数，顶点一律由 `frontend/src/utils/regionShape.ts` 展开——
单一实现、零双份维护、天然一致。

## 五、接手者必须知道的坑

1. **不要照旧文档/旧代码写"据点围合"**——架构文档已改为新语义（`docs/architecture/YLCRAFT_SYSTEM_ARCHITECTURE.md`
   搜索"区域几何"）。旧凸包逻辑已从 `MapCanvas` 移除。
2. **形状算法是纯函数且有测试**：改参数先跑 `npm test`（frontend 已装 vitest 1.6.0，现 27 项）。
   测试覆盖确定性、顶点上限、坐标裁剪、**据点必被包住**、面积感递增、越界判定、层级成环校验等。
3. **基础半径公式别改错**：`最远据点距离 × 1.15 + 面积感半径`——先包住据点再按面积感外扩。
   早期版本写成 `max(面积感, 离散度)`，导致据点一分散"小=中"（面积感失效），已修正并被测试覆盖。
4. **编辑工具有时会"看似成功但未落盘"**：本轮发生过两次 `replace_in_file` 返回成功但文件未变。
   改完关键文件后务必 `tsc` 或回读确认。
5. **清库是破坏性操作**，阶段 6 执行前必须再向用户确认一次。
6. **网络限制**：GitHub 直连常被重置（push / clone 都失败过），需要代理；
   npm 可用（vitest 已装上）。
7. **frontend 用了 unplugin-auto-import**：`src/auto-imports.d.ts` 全局声明了 React hooks 等，
   文件里不写 `import { useCallback } from 'react'` 也能编译——这不是丢导入，别"修复"它，
   也别因此怀疑 tsc 没跑对。项目 `tsc` 是 `strict: false`。
