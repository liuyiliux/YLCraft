# 03 前端开发规范

> **面向受众**：AI 编程助手
> **用途**：约束前端 React/TypeScript 代码的编写方式

---

## 1. 页面组件结构规范

### 1.1 目录约定
- 页面位于 `frontend/src/pages/` 下，一个页面一个文件夹
- 组件文件使用 PascalCase 命名（如 `ImageGen.tsx`）
- 页面专属的子组件放在同目录的 `components/` 下

### 1.2 组件模板
```tsx
// frontend/src/pages/image-gen/ImageGen.tsx
import React from 'react';
import { Card } from 'antd';

const ImageGen: React.FC = () => {
  return <Card title="AI图片生成">{/* 页面内容 */}</Card>;
};

export default ImageGen;
```

> **AI 注意**：新增页面时在 `App.tsx` 注册路由（见下文第 3 节）。

## 2. API 调用层规范

### 2.1 目录约定
- API 调用封装在 `frontend/src/api/` 下
- 按后端模块分文件（如 `image.ts`、`video.ts`、`bilibili.ts`）

### 2.2 调用模式
```typescript
// frontend/src/api/image.ts
import request from '@/utils/request';
import type { ImageGenerateParams, ImageGenerateResult } from '@/types/image';

export const generateImage = async (
  params: ImageGenerateParams
): Promise<ImageGenerateResult> => {
  const { data } = await request.post('/api/v1/images/generate', params);
  return data;
};
```

### 2.3 类型安全
- 每个 API 函数的请求参数和返回值必须有完整的 TypeScript 类型
- 类型定义放在 `frontend/src/types/` 下对应文件
- 禁止使用 `any` 作为 API 函数的返回类型

---

## 3. 路由注册规范

### 3.1 集中管理
- 所有路由在 `frontend/src/App.tsx` 中统一配置
- 使用 `react-router-dom` v6 的 `createBrowserRouter`

### 3.2 注册模板
```tsx
const router = createBrowserRouter([
  { path: '/', element: <Home /> },
  { path: '/model-config', element: <ModelConfig /> },
  { path: '/image-gen', element: <ImageGen /> },
  { path: '/bilibili/login', element: <BilibiliLogin /> },
]);
```

### 3.3 懒加载建议
- 非首页组件推荐使用 `React.lazy(() => import('...'))` + `<Suspense>`
- 减少首屏加载体积

## 4. UI 组件使用规范

### 4.1 组件库
- **唯一 UI 库**：Ant Design 5（`antd`），不得引入其他 UI 库
- 中文 locale 已在项目级配置，无需页面级重复设置

### 4.2 常用组件模式

| 场景 | 组件 | 用法 |
|------|------|------|
| 数据表单 | `Form` + `Form.Item` | 表单验证使用 `rules` 属性 |
| 数据表格 | `Table` | 分页使用 `pagination` 属性 |
| 卡片容器 | `Card` | 页面内容的标准容器 |
| 弹窗 | `Modal` | 确认/编辑等临时交互 |

### 4.3 消息反馈
```tsx
import { message, Modal, notification } from 'antd';

// 操作成功
message.success('操作成功');

// 确认弹窗
Modal.confirm({
  title: '确认删除？',
  onOk: async () => { await api.delete(id); },
});

// 错误提示
notification.error({
  message: '操作失败',
  description: error.message,
});
```

## 5. 状态管理约定

### 5.1 决策流程
```
需要全局共享状态？
├─ 否 → useState / useReducer
├─ 是，且是服务端缓存 → 自定义 Hook + 缓存策略
└─ 是，且是运行时状态 → React Context
```

### 5.2 Context 使用
- 按领域拆分 Context（如 `AgentContext`、`AuthContext`）
- Context 文件放在 `frontend/src/context/` 目录
- 每个 Context 配套导出 Provider 组件和 useXxx Hook

### 5.3 自定义 Hook
- Hook 文件放在 `frontend/src/hooks/` 目录
- 以 `use` 为前缀命名（如 `useWebSocket`、`useVideoTask`）
- 封装重复的数据获取/处理逻辑

---

## 6. 样式规范

### 6.1 样式方案
- 优先使用 Ant Design 的内置样式和主题变量
- 自定义样式使用 CSS Modules 或内联 style
- 避免全局 CSS 污染

### 6.2 响应式
- 使用 Ant Design `Grid` 系统（Row/Col）实现布局
- 考虑移动端适配（部分运营场景需要）

---

## 7. 安全注意事项（AI 必须遵守）

1. **XSS 防护**：用户输入内容渲染时必须使用 React 的 JSX（自动转义），禁止 `dangerouslySetInnerHTML`
2. **敏感信息**：API Key、Token 不得在前端 localStorage 明文存储
3. **文件上传**：前端校验文件类型和大小，后端再次校验
4. **错误展示**：用户端错误信息使用友好的中文提示，不得暴露堆栈信息
