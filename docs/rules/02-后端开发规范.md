# 02 后端开发规范

> **面向受众**：AI 编程助手
> **用途**：约束后端 Python 代码的编写方式和架构模式

---

## 1. API 路由注册规范

### 1.1 路由文件组织
- 所有路由文件位于 `backend/app/api/v1/` 目录
- 每个功能模块一个 router 文件，使用 `APIRouter` 创建
- 大型模块可拆分为子目录

### 1.2 路由命名与注册
- 路由前缀格式：`/api/v1/{module}`
- 在 `backend/app/main.py` 中统一通过 `app.include_router(router)` 注册

```python
# 正确示例
from fastapi import APIRouter

router = APIRouter(prefix="/api/v1/images", tags=["图片生成"])

@router.post("/generate")
async def generate_image(request: ImageGenerateRequest):
    ...
```

### 1.3 标签约定
- `tags` 参数使用中文描述（如 `["图片生成"]`、`["B站管理"]`）
- 保持与已有路由一致的标签风格

## 2. 服务层架构约定

### 2.1 服务层职责
- 业务逻辑放置于 `backend/app/services/` 下的领域目录
- 服务类使用 `Service` 后缀命名（如 `ImageService`、`VideoDownloadService`）
- 服务层负责业务编排，不直接操作 HTTP 请求/响应对象

### 2.2 依赖注入模式
```python
# 正确的服务层结构
class ImageService:
    def __init__(self, db_session: AsyncSession, config: ProvidersConfig):
        self.db = db_session
        self.config = config

    async def generate(self, request: ImageGenerateRequest) -> ImageGenerateResponse:
        # 业务逻辑编排
        ...
```

### 2.3 跨服务调用
- 通过依赖注入完成，避免全局单例（配置类除外）
- 禁止服务层内直接 import 路由层代码

## 3. 配置管理系统

### 3.1 配置层次

| 配置文件 | 用途 | 读取方式 |
|----------|------|---------|
| `backend/config/providers.yaml` | Provider 模型/端点/默认值 | `ProvidersConfig` 类 |
| `backend/app/data/settings.json` | 下载路径、存储类型 | 运行时读写 |
| 环境变量 | 密钥、URL 等敏感项 | `${ENV_VAR}` 语法 |
| 数据库 api_keys 表 | API Key | `ApiKeyStore` 类 |

### 3.2 配置读取规范
```python
from app.core.config import ApiKeyStore, ProvidersConfig

# Provider 配置
config = ProvidersConfig()
model = config.get_provider("openai").get_model("gpt-4o")

# API Key（自动解密+缓存）
key_store = ApiKeyStore()
api_key = await key_store.get_key("openai")
```

> **AI 注意**：禁止硬编码 URL、密钥或路径，必须使用上述配置系统。

## 4. 错误处理规范

### 4.1 异常层次
- 业务错误：自定义异常类，继承 `Exception`
- HTTP 错误：FastAPI 的 `HTTPException` + 标准状态码

```python
class ImageGenerationError(Exception):
    """图片生成业务异常"""
    pass

# 路由层捕获
@router.post("/generate")
async def generate(request: ImageGenerateRequest):
    try:
        result = await image_service.generate(request)
        return result
    except ImageGenerationError as e:
        logger.error(f"图片生成失败: {e}")
        raise HTTPException(status_code=500, detail=str(e))
```

### 4.2 日志规范
- 使用标准 `logging` 模块
- 错误日志包含足够的上下文信息（用户ID、任务ID、请求参数）
- 外部 API 调用失败必须记录原始错误

## 5. 异步与同步代码约定

### 5.1 API 处理函数
- 路由函数必须使用 `async def`
- 数据库操作使用 `AsyncSession`
- 文件 I/O 密集操作使用 `run_sync` 或线程池

### 5.2 任务队列
- 长时间运行的任务提交到 `TaskQueue`
- 任务状态通过 WebSocket 推送或轮询接口查询

## 6. 数据库迁移规范（Alembic）

> **PostgreSQL 必须使用 Alembic 管理 schema 变更，禁止 SQLModel 自动 create_all。**

### 6.1 迁移工作流

```bash
# 1. 修改 SQLModel 模型定义后，生成迁移脚本
cd backend
alembic revision --autogenerate -m "描述性命名（如 add_asset_embeddings_table）"

# 2. 检查生成的迁移脚本是否正确（人工 review！）
#    - 确认字段类型、索引、约束无误
#    - autogenerate 可能遗漏某些变更，需手动补充

# 3. 执行迁移
alembic upgrade head

# 4. 如需回滚
alembic downgrade -1
```

### 6.2 迁移文件命名规范

| 模式 | 示例 |
|------|------|
| 新增表 | `add_asset_nodes_table` |
| 新增字段 | `add_quality_score_to_asset_nodes` |
| 新增索引 | `add_hnsw_index_on_asset_embeddings` |
| 新增扩展 | `enable_pgvector_extension` |

### 6.3 严禁事项

- ❌ 禁止在 `main.py` 中调用 `SQLModel.metadata.create_all()`
- ❌ 禁止手动修改已执行的迁移文件
- ❌ 禁止直接连数据库执行 DDL（`ALTER TABLE` 等）
- ❌ 禁止跨多个功能合并为一个大迁移（每个功能独立迁移）
- ⚠️ autogenerate 生成的脚本必须人工 review 后再执行

### 6.4 新增字段必须向后兼容

```python
# ✅ 正确：所有新字段都 Optional + default
class AssetNode(SQLModel, table=True):
    # ... 已有字段 ...
    quality_score: Optional[int] = Field(default=None)  # 安全新增
    phash: Optional[str] = Field(default=None, max_length=64)

# ❌ 错误：NOT NULL 无默认值会导致迁移失败
class AssetNode(SQLModel, table=True):
    quality_score: int  # 已有数据没这个值，迁移报错
```

## 7. pgvector 操作规范

### 7.1 向量表定义

```python
from pgvector.sqlalchemy import Vector  # pgvector 的 SQLAlchemy 类型

class AssetEmbedding(SQLModel, table=True):
    __tablename__ = "asset_embeddings"

    id: uuid.UUID = Field(default_factory=uuid.uuid4, primary_key=True)
    asset_node_id: uuid.UUID = Field(
        foreign_key="asset_nodes.id", unique=True, index=True
    )
    embedding: list[float]  # pgvector Vector(384)，SQLModel 用 list[float]
    embedding_model: str = Field(default="paraphrase-multilingual-MiniLM-L12-v2", max_length=100)
    created_at: datetime = Field(default_factory=datetime.now, sa_column_kwargs={"server_default": "now()"})
```

### 7.2 向量搜索查询（原生 SQL）

```python
from sqlalchemy import text

# ✅ 混合搜索必须用原生 SQL（ORM 无法表达余弦距离排序）
sql = text("""
    SELECT a.*, 
           1 - cosine_distance(e.embedding, :query_vec) AS similarity
    FROM asset_nodes a
    JOIN asset_embeddings e ON a.id = e.asset_node_id
    ORDER BY e.embedding <=> :query_vec
    LIMIT :top_k
""")
result = await session.execute(sql, {
    "query_vec": embedding,
    "top_k": 20
})
```

### 7.3 向量索引

```sql
-- 在 Alembic 迁移中创建 HNSW 索引（不在模型定义中）
CREATE INDEX IF NOT EXISTS ix_asset_embeddings_hnsw
    ON asset_embeddings USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 200);
```

## 8. 接口请求/响应约定

### 8.1 类型定义
- 请求体和响应体使用 Pydantic `BaseModel` 定义
- 类型定义可放在 `app/core/contracts/` 或模块级的 `schemas.py`

### 8.2 响应格式
```python
from typing import Generic, TypeVar

class ApiResponse(BaseModel, Generic[T]):
    code: int = 0
    message: str = "success"
    data: Optional[T] = None
```

### 8.3 分页约定
- 分页参数：`page: int = 1, page_size: int = 20`
- PostgreSQL 推荐 keyset 分页（`WHERE created_at < $cursor`），比 OFFSET 更稳定
- 分页响应包含 `total`、`items`、`page`、`page_size`

---

## 9. 安全注意事项（AI 必须遵守）

1. **禁止执行用户输入的代码**：不使用 `eval()`、`exec()`、`os.system()` 执行用户或外部输入
2. **SQL 注入防护**：通用查询使用 SQLModel ORM；pgvector 向量搜索可使用参数化原生 SQL（`text()` + 绑定参数 `:query_vec`），**禁止字符串拼接**
3. **密钥不落地**：API Key 使用 `ApiKeyStore` 加密存储，不得明文写入日志或响应
4. **文件路径校验**：文件上传/下载操作必须验证路径在允许范围内
5. **速率限制**：对 B站搜索等外部 API 调用考虑请求频率控制
