## 1. 常用开发命令

| 命令 | 用途 |
|------|------|
| `docker compose up -d` | 启动本地 PostgreSQL + Redis（仅本地开发环境） |
| `docker compose down` | 停止并移除容器 |
| `start.bat` | Windows 一键启动（docker + 后端 + 前端） |
| `start.sh` | Linux/Mac 一键启动 |
| `cd backend && uvicorn app.main:app --reload --port 8000` | 单独启动后端 |
| `cd frontend && npm run dev` | 单独启动前端 |
| `cd backend && alembic upgrade head` | 执行数据库迁移 |
| `python tools/check_migration_state.py` | 只读检查远程 PostgreSQL 的 Alembic revision |
| `cd backend && alembic revision --autogenerate -m "描述"` | 生成迁移脚本 |
| `cd backend && python -m pytest tests/` | 运行后端测试 |
| `cd frontend && npm run build` | 构建前端生产版本 |
| `cd frontend && npm run lint` | 前端代码 Lint 检查 |

### 2.1.1 CNB 云原生开发模式

- **单容器模式**：`.ide/Dockerfile` 已安装 `code-server`，开发环境与 code-server 运行在同一容器，支持 WebIDE 与 VSCode 远程开发。
- 修改 `.ide/Dockerfile` 时若移除 `code-server` 安装，系统将自动降级为**双容器模式**（额外启动一个 code-server 容器），插件等能力受限，请保持单容器模式。

## 3. 环境变量

| 变量名 | 用途 | 默认值 |
|--------|------|--------|
| `DATABASE_URL` | PostgreSQL 连接串 | `postgresql+asyncpg://ylcraft:ylcraft_dev@localhost:5432/ylcraft` |
| `SYNC_DATABASE_URL` | PostgreSQL 同步连接串（Alembic 用） | `postgresql://ylcraft:ylcraft_dev@localhost:5432/ylcraft` |
| `OPENAI_API_KEY` | OpenAI API Key | 无 |
| `COMFYUI_URL` | ComfyUI 服务地址 | `http://127.0.0.1:8188` |
| `REDIS_URL` | Redis 连接（可选） | 无（降级为内存队列） |
| `DOWNLOAD_DIR` | 下载保存目录 | `./downloads` |
| `CORS_ORIGINS` | 前端跨域来源 | `http://localhost:5173` |

在 `providers.yaml` 中通过 `${VAR_NAME}` 引用环境变量。

### 3.1 远程 PostgreSQL 迁移操作顺序

> 适用于当前 YLCraft 的远程 PostgreSQL。应用启动、HTTP 请求和 AI Agent 都不得自动执行迁移。

1. **只读诊断**：从仓库根目录运行 `python tools/check_migration_state.py`，记录 `current_revisions` 和 `local_heads`。
2. **备份**：由远程数据库提供方创建可恢复快照，或由有权限的运维人员导出数据库；确认备份可见后才继续。
3. **审阅**：在一次性 PostgreSQL 副本上先运行 `cd backend && alembic upgrade head`，核对核心表和应用启动日志。
4. **显式升级**：仅由已审批的部署人员在目标库执行 `cd backend && alembic upgrade head`。
5. **验证**：再次运行 `python tools/check_migration_state.py`，应显示 `state: current`；再执行对应模块的 focused tests 和应用健康检查。
6. **回退**：停止应用写入，优先从第 2 步的数据库快照恢复。除非某个 revision 已提供并审阅过 `downgrade()`，不要在远程库临时执行 Alembic downgrade。

禁止事项：不要对未知远程库执行 `alembic stamp head`、`metadata.create_all()`、删除表或 reset；这些操作会掩盖真实 schema 差异，无法替代迁移演练。

## 5. 调试技巧

按以下优先级排查问题：

1. **后端日志**：控制台输出，检查异常堆栈和错误信息
2. **配置验证**：确认 `providers.yaml` 格式正确，YAML 语法无误
3. **数据库状态（默认远程 PostgreSQL）**：
   - 首先运行 `python tools/check_migration_state.py`；它只读 `alembic_version`，不会建表或升级。
   - 数据库连接由 `DATABASE_URL`（通常在 `backend/.env`）提供；输出会隐藏密码。
   - 需要人工核对时使用 DBeaver 或 pgAdmin，连接实际的远程地址；不要把生产连接串贴进日志、文档或聊天。
   - 本地 Docker 仅用于隔离开发/演练，不能假定线上库在 `localhost:5432`。
4. **网络连通性**：
   - 前端 → 后端：检查 Vite 代理配置（`vite.config.ts`）
   - 后端 → ComfyUI：确认 `COMFYUI_URL` 正确且服务运行中
   - 后端 → B站 API：检查 Cookie 是否有效
   - 后端 → PostgreSQL：检查 `DATABASE_URL` 和 Docker 容器状态
5. **B站 Cookie**：通过 `GET /api/v1/bilibili/auth/status` 验证登录态
6. **前端代理**：开发环境 Vite 代理指向 `http://localhost:8000`

## 6. 常见问题

| 问题 | 快速排查 |
|------|---------|
| PostgreSQL 连接失败 | 运行 `python tools/check_migration_state.py`；检查远程网络、凭证和 SSL，不要自行重置库 |
| 迁移报错 | 先备份，再运行只读诊断并记录 current/head；仅在审批后执行 `cd backend && alembic upgrade head`。禁止用 `stamp head` 跳过未知结构差异 |
| 图片生成失败 | 检查 ComfyUI 是否运行、模型是否下载、API Key 是否配置 |
| B站搜索无结果 | 检查 Cookie 有效性、网络连通性、搜索关键词格式 |
| 视频下载卡住 | 检查 yt-dlp 版本、磁盘空间、下载路径权限 |
| 向量搜索不工作 | 确认 `CREATE EXTENSION vector` 已执行；检查 HNSW 索引是否创建 |
| 数据库操作报错 | 先确认模型与 revision 状态；远程库必须在备份和审批后由部署人员显式迁移，应用请求不能触发 DDL |
