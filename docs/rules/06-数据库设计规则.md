> **数据库**：PostgreSQL 16 + pgvector

## 1. 模型定义规范

### 1.1 基础模板（PostgreSQL）
```python
from sqlmodel import SQLModel, Field
from datetime import datetime, timezone
from typing import Optional
from enum import Enum
import uuid

class TaskStatus(str, Enum):
    PENDING = "pending"
    RUNNING = "running"
    COMPLETED = "completed"
    FAILED = "failed"

class VideoTask(SQLModel, table=True):
    """视频下载任务"""
    __tablename__ = "video_tasks"           # 显式表名，snake_case 复数

    id: uuid.UUID = Field(                  # 🆕 UUID 主键
        default_factory=uuid.uuid4,
        primary_key=True,
        sa_type=UUID(as_uuid=True)
    )
    url: str = Field(index=True)
    title: str = Field(max_length=500)
    status: TaskStatus = Field(default=TaskStatus.PENDING)
    progress: float = Field(default=0.0)
    file_path: Optional[str] = None
    created_at: datetime = Field(
        default_factory=lambda: datetime.now(timezone.utc),
        sa_column_kwargs={"server_default": "now()"}
    )
    updated_at: datetime = Field(
        default_factory=lambda: datetime.now(timezone.utc),
        sa_column_kwargs={"server_default": "now()", "onupdate": "now()"}
    )
    error_message: Optional[str] = Field(max_length=1000, default=None)
```

### 1.2 必须遵守的规则
- ✅ 继承 `SQLModel`，`table=True`，显式指定 `__tablename__`
- ✅ 主键：**`uuid.UUID`**（不再使用自增 int），`from sqlalchemy.dialects.postgresql import UUID`
- ✅ 时间字段：`datetime` + `timezone.utc`，用 `server_default="now()"` 让 PG 生成
- ✅ 枚举字段：自定义 `str, Enum` 子类
- ✅ 可选字段：`Optional[T]` + `default=None`
- ✅ JSON 字段：用 `sa_column=Column(JSONB)` 启用 PostgreSQL JSONB

## 3. 索引设计原则

### 3.1 PostgreSQL 索引类型

| 查询模式 | 索引类型 | 写法 |
|----------|---------|------|
| 主键查询 | 自动（UUID B-tree） | `primary_key=True` |
| 等值查询 | B-tree | `Field(index=True)` |
| 唯一约束 | UNIQUE B-tree | `Field(unique=True)` |
| JSONB 键查询 | **GIN** | 在 Alembic 迁移中手动创建 |
| 全文搜索 | **GIN (tsvector)** | 在 Alembic 迁移中手动创建 |
| 向量相似搜索 | **HNSW** (pgvector) | 在 Alembic 迁移中手动创建 |
| 模糊匹配 (LIKE) | **GIN trgm** | 需 `CREATE EXTENSION pg_trgm` |

### 3.2 索引决策表

| 场景 | 建索引? | 理由 |
|------|---------|------|
| WHERE 高频字段 | ✅ B-tree | 查询加速 |
| 外键关联字段 | ✅ B-tree | JOIN 加速 |
| ORDER BY 字段 | ✅ B-tree | 排序加速 |
| JSONB 中频繁查询的键 | ✅ GIN | `metadata_json->>'resolution'` 等 |
| 低基数字段 (<10种值) | ❌ | 索引收益低 |
| 频繁更新的字段 | ⚠️ 谨慎 | 写放大 |
| 向量 embedding | ✅ HNSW | pgvector 专用索引 |

### 3.3 组合索引与高级索引示例

```sql
-- B-tree 组合索引（在 SQLModel __table_args__ 中定义）
CREATE INDEX ix_provider_type_active ON provider_configs (provider_type, is_active);

-- JSONB GIN 索引（metadata_json 中任意键的查询）
CREATE INDEX ix_asset_nodes_metadata ON asset_nodes USING gin (metadata_json jsonb_path_ops);

-- 全文搜索 GIN 索引
CREATE INDEX ix_asset_nodes_fts ON asset_nodes USING gin (to_tsvector('simple', name || ' ' || coalesce(metadata_json::text, '')));

-- pgvector HNSW 索引（余弦相似度）
CREATE INDEX ix_asset_embeddings_hnsw ON asset_embeddings USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 200);
```

> **AI 注意**：GIN、HNSW、trgm 索引必须在 Alembic 迁移脚本中手动编写（`op.create_index` 或 `op.execute`），SQLModel 的 `Field(index=True)` 只能创建 B-tree 索引。

## 4. 数据迁移策略（Alembic）

> **唯一允许的 schema 变更方式就是 Alembic。禁止 `SQLModel.metadata.create_all()`。**

### 4.1 核心工作流

```bash
# 1. 开发：修改 SQLModel 模型定义
# 2. 生成迁移
alembic revision --autogenerate -m "add_xxx_table"

# 3. 人工 review 生成的迁移脚本！
#    - 检查字段类型映射是否正确
#    - 补充非标准索引（GIN/HNSW/trgm）
#    - 确认 upgrade() 和 downgrade() 都可执行

# 4. 执行
alembic upgrade head

# 5. 回滚（仅开发环境）
alembic downgrade -1
```

### 4.2 迁移文件结构示例

```python
# alembic/versions/xxx_add_asset_embeddings.py
revision = 'a1b2c3d4e5f6'

def upgrade():
    op.create_table('asset_embeddings',
        sa.Column('id', postgresql.UUID(), primary_key=True),
        sa.Column('asset_node_id', postgresql.UUID(), sa.ForeignKey('asset_nodes.id'), unique=True),
        sa.Column('embedding', pgvector.sqlalchemy.Vector(384)),
        sa.Column('embedding_model', sa.String(100), server_default='paraphrase-multilingual-MiniLM-L12-v2'),
        sa.Column('created_at', sa.DateTime(timezone=True), server_default=sa.func.now()),
    )
    # 非标准索引：手动创建
    op.execute("""
        CREATE INDEX ix_asset_embeddings_hnsw ON asset_embeddings
        USING hnsw (embedding vector_cosine_ops) WITH (m = 16, ef_construction = 200);
    """)

def downgrade():
    op.drop_index('ix_asset_embeddings_hnsw')
    op.drop_table('asset_embeddings')
```

### 4.3 安全变更原则

- ✅ 新增字段：`Optional[T]` + `default=None`（向后兼容）
- ✅ 新增表：独立迁移，含所有索引
- ✅ 新增非标准索引：`op.execute()` 手动 SQL
- ❌ 禁止删除或重命名已有列（会破坏旧版本代码）
- ❌ 禁止修改已有字段类型（用新字段 + 数据迁移替代）
- ❌ 禁止手动直接连库执行 DDL

### 4.4 初始迁移 (Phase 0)

```bash
# 从零开始或从 SQLite 迁移时
alembic revision -m "init_postgresql_schema"  # 不带 --autogenerate，手写所有建表语句
alembic upgrade head
```

### 5.1 获取 Session

```python
from sqlalchemy.ext.asyncio import AsyncSession

@router.get("/items")
async def list_items(
    session: AsyncSession = Depends(get_async_session)

        select(Item).where(Item.is_active == True).limit(20)
```

### 5.2 写操作模式
```python
# ✅ 单个写入（推荐）
async def create_task(self, data: TaskCreate) -> Task:
    task = Task.model_validate(data)
    self.session.add(task)
    await self.session.commit()
    await self.session.refresh(task)
    return task

# ✅ 批量写入（自动 commit/rollback）
async def batch_create(self, items: list[dict]) -> None:
    async with self.session.begin():
        for item in items:
            self.session.add(Item(**item))

# ✅ 原生 SQL（pgvector 向量搜索等）
from sqlalchemy import text

result = await session.execute(text("""
    SELECT a.*, 1 - cosine_distance(e.embedding, :query_vec) AS similarity
    FROM asset_nodes a
    JOIN asset_embeddings e ON a.id = e.asset_node_id
    ORDER BY similarity DESC LIMIT :top_k
"""), {"query_vec": embedding, "top_k": 20})
```

### 5.3 连接池配置

```python
# backend/app/db/database.py
DATABASE_URL = os.getenv("DATABASE_URL", "postgresql+asyncpg://ylcraft:ylcraft_dev@localhost:5432/ylcraft")

async_engine = create_async_engine(
    DATABASE_URL,
    pool_size=20,           # 常规连接数
    max_overflow=10,        # 超出 pool_size 时的临时连接
    pool_pre_ping=True,     # 使用前检查连接有效性
    echo=False              # 生产关闭 SQL 日志
)
```

### 5.4 关键原则
- 🔒 Session 由 FastAPI `Depends` 注入，不在函数内创建
- 🔒 写操作后必须 `commit` + `refresh`
- 🔒 大事务用 `async with session.begin()` 自动管理
- 🔒 避免长时间持有 session（用连接池自动回收）
- 🔒 向量搜索用参数化 `text()` SQL，**禁止字符串拼接**

## 6. 查询优化规则

### 6.1 推荐查询模式

```python
# ✅ ORM 查询（优先使用）
items = await session.exec(
    select(Item)
    .where(Item.is_active == True)
    .order_by(Item.created_at.desc())
    .limit(20)
)

# ✅ 关联预加载（防 N+1）
items = await session.exec(
    select(Item)
    .options(selectinload(Item.tags))      # 一对多
    .options(joinedload(Item.category))     # 多对一
)

# ✅ Keyset 分页（比 OFFSET 更稳定）
items = await session.exec(
    select(Item)
    .where(Item.created_at < cursor)        # cursor = 上一页最后一条的 created_at
    .order_by(Item.created_at.desc())
    .limit(20)
)

# ✅ 递归 CTE（标签树等层级查询）
sql = text("""
    WITH RECURSIVE tag_tree AS (
        SELECT id, name, parent_id, 0 as depth FROM tags WHERE id = :tag_id
        UNION ALL
        SELECT t.id, t.name, t.parent_id, tt.depth + 1
        FROM tags t JOIN tag_tree tt ON t.parent_id = tt.id
    )
    SELECT * FROM tag_tree;
""")

# ✅ JSONB 查询
items = await session.exec(
    select(AssetNode).where(
        AssetNode.metadata_json["resolution"].astext == "1920x1080"
    )
)
```

### 6.2 禁止的查询模式

```python
# ❌ 禁止：字符串拼接 SQL
sql = f"SELECT * FROM items WHERE name = '{user_input}'"  # SQL 注入！

# ❌ 禁止：循环中逐条查询
for item_id in ids:
    item = await session.get(Item, item_id)  # N+1 问题！

# ❌ 禁止：全表扫描后 Python 过滤
all_items = await session.exec(select(Item))
filtered = [i for i in all_items if i.status == "active"]  # 应该在 SQL 中过滤
```

### 6.3 性能分析

## 7. UUID 主键规范

### 7.1 为什么用 UUID 而不是自增整数？

| 对比 | 自增整数 | UUID |
|------|---------|------|
| ID 唯一性 | ⚠️ 仅库内唯一 | ✅ 全局唯一 |
| 分布式合并 | ❌ 冲突风险 | ✅ 无冲突 |
| 前端预生成 | ❌ 需等 DB | ✅ 前端可预生成 ID |
| 安全问题 | ❌ ID 可枚举 | ✅ 不可猜测 |
| 索引性能 | ✅ 略好（B-tree 更紧凑） | ⚠️ 稍慢（16字节 vs 4/8字节） |
| 存储空间 | ✅ 4-8 字节 | ⚠️ 16 字节 |

> **决策**：YLCraft 选 UUID 是因为资产中枢需要前端预生成节点 ID（性能）、支持未来多数据源合并、谱系 DAG 构建无需担心 ID 冲突。

### 7.2 UUID 模型定义

```python
import uuid
from sqlalchemy.dialects.postgresql import UUID

class AssetNode(SQLModel, table=True):
    __tablename__ = "asset_nodes"

    id: uuid.UUID = Field(
        default_factory=uuid.uuid4,
        primary_key=True,
        sa_type=UUID(as_uuid=True)   # PostgreSQL 原生 UUID 类型
    )
    parent_id: Optional[uuid.UUID] = Field(
        default=None,
        foreign_key="asset_nodes.id",
        sa_type=UUID(as_uuid=True)
    )
```

## 8. JSONB 使用规范

### 8.1 JSONB vs JSON

| 特性 | JSON | JSONB |
|------|------|-------|
| 存储格式 | 纯文本 | 二进制解析后存储 |
| 索引支持 | ❌ | ✅ GIN 索引 |
| 查询性能 | ⚠️ 每次解析 | ✅ 已解析，快速 |
| 键顺序 | 保留原序 | 不保留 |
| 重复键 | 保留 | 仅保留最后一个 |

> **强制使用 JSONB**，不用 JSON。

### 8.2 JSONB 模型定义

```python
from sqlalchemy import Column
from sqlalchemy.dialects.postgresql import JSONB

class AssetNode(SQLModel, table=True):
    __tablename__ = "asset_nodes"

    metadata_json: dict = Field(
        default={},
        sa_column=Column(JSONB)  # 显式声明 JSONB
    )
    tags_json: list = Field(
        default=[],
        sa_column=Column(JSONB)
    )
```

### 8.3 JSONB 查询示例

```python
# 查询 metadata_json 中 resolution 为 "1920x1080" 的资产
stmt = select(AssetNode).where(
    AssetNode.metadata_json["resolution"].astext == "1920x1080"

    AssetNode.tags_json.contains(["cyberpunk", "night"])
```

```python
# 搜索时用 jieba 分词预处理
import jieba

def to_tsquery_zh(text: str) -> str:
    """中文分词 → PostgreSQL tsquery 格式"""
    words = jieba.cut(text)
    return " & ".join(words)  # '赛博朋克 & 夜景 & 高质量'

# 查询
sql = text("""
    SELECT *, ts_rank(to_tsvector('zh', name || ' ' || description), 
                      to_tsquery('zh', :query)) AS rank
    FROM asset_nodes
    WHERE to_tsvector('zh', name || ' ' || description) @@ to_tsquery('zh', :query)
    ORDER BY rank DESC
""")
```

## 10. AI 连接器（AIConnector）模型配置

### 10.1 模型概述
`AIConnector` 是 YLCraft 项目管理 AI 模型配置的核心模型，替代了旧版的 `providers.yaml` 方式。
- **表名**：`ai_connectors`
- **位置**：`backend/app/db/models/ai_connector.py`
- **前端配置界面**：`frontend/src/pages/settings/index.tsx`

### 10.2 关键字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `provider` | str | AI 提供商（如 openai、siliconflow、gemini、generic） |
| `name` | str | 连接显示名称（如 OpenAI-Main） |
| `provider_type` | enum | 提供商类型：llm、image、video、tts、stt、embedding |
| `api_key` | str | API Key（加密存储） |
| `base_url` | Optional[str] | API 基础 URL（用于代理/自托管） |
| `default_model` | str | 默认模型（如 gpt-4o、sdxl） |
| `available_models` | str | 可用模型列表（JSON 字符串） |
| `support_vision_input` | bool | **关键**：是否支持视觉输入（多模态模型） |
| `support_reference_image` | bool | **关键**：图像生成是否支持参考图 |
| `is_active` | bool | 是否启用 |
| `is_default` | bool | 是否设为默认连接 |

### 10.3 新增字段时的规范

当需要为 AIConnector 新增配置字段时，必须同时更新以下内容：
1. **模型定义**：`AIConnectorBase`、`AIConnectorCreate`、`AIConnectorUpdate`、`AIConnectorResponse` 四个类都要更新
2. **前端表单**：`settings/index.tsx` 中的编辑/新增表单要添加对应字段
3. **前端表单重置**：编辑和新增时的 `Form.setFieldsValue` 都要添加对应字段
4. **数据库迁移**：创建 Alembic 迁移文件，或使用 `docker exec` 手动执行 SQL（仅开发环境）

> **示例**：本次新增的 `support_vision_input` 字段，需要同时更新四个模型类和前端表单

### 10.4 支持视觉的 LLM 配置流程

1. 进入设置 → 模型管理
2. 新增或编辑 LLM 类型的连接器
3. 开启 "支持视觉输入" 开关
4. 保存配置
5. 在多平台生图页面选择该模型时，参考图上传按钮会自动显示

### 10.5 敏感数据存储

#### 10.5.1 安全分级

| 数据级别 | 内容 | 存储方式 |
|----------|------|---------|
| **机密** | API Key、Token、Cookie | `ApiKeyStore` 加密存储 |
| **敏感** | 密码 | bcrypt 哈希（如有用户系统） |
| **普通** | 配置、元数据 | 明文存储或 JSONB |

#### 10.5.2 API Key 操作
```python
from app.core.config import ApiKeyStore

key_store = ApiKeyStore()
```

> **AI 注意**：禁止将 API Key 明文存入配置文件、数据库或日志。
