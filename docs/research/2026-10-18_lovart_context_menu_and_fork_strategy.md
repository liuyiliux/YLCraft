## 二、🔴 「编辑文字」面板的实际样子（一手截图）

点「编辑文字」后，弹出的是**一个文字清单**：

```
编辑文字
┌──────────────────────────────┐
│ 奉天逸洋                      │
│ FENGTIANYIYANG                │
│ 朝牌                          │
│ 老面烤饼                      │
│ 传统烤饼 · 老面发酵           │
│ 酥香可口 麦香浓郁             │
│ 精选小麦…                     │
│ …（可滚动）                   │
└──────────────────────────────┘
        [取消]  [立即使用 ⚡14]
```

**它做的是：**

1. **OCR 把图里每一处文字都识别出来**
2. **列成清单让用户选**（不是让你在图上点，是给列表）
3. 选完点「立即使用」，**花 14 积分**去重绘那一处文字

> 🔴 **这解释了优设测评说的"拆完标题字变纯文字"** ——
> 因为它走的是 **OCR 识别 + 重新渲染**，原图的字体效果、描边、阴影、透视全部丢失，
> 只保留文字内容本身。

**所以「编辑文字」的本质不是"编辑图层里的文字对象"，是"识别文字 → 抹掉 → 用新文字重画"。**

## 三、🔴 这个菜单告诉我们什么（最重要的判断）

**12 个菜单项里，8 个是 AI 操作，只有 4 个是手工的（调整/裁剪/翻转/自定义）。**

| 类型 | 菜单项 |
| --- | --- |
| **AI 操作** | 图层拆分 / 编辑文字 / 多角度 / 动态图片 / 移动对象 / 扩展 / 矢量（半算法） |
| **手工操作** | 调整 / 裁剪 / 翻转与旋转 / Mockup（模板） |

**结论：Lovart 的"编辑器"其实是"AI 操作台"。**
Photoshop 那套图层/蒙版/通道/曲线，它基本没有（也没有必要有）。

**这个判断直接决定我们该抄什么：**

> ❌ 不要花力气抄一个 PS 克隆
> ✅ 要抄的是"选中一个成品 → 弹出它能做的 AI 操作"

## 四、你说的"代码抄过来个性化"——逐许可判断

你的意思是**不嵌入，而是 fork / 抄代码改**。那判断标准就变成了**能不能闭源分支**：

| 项目 | Star | 许可 | 能 fork 闭源吗 | 判断 |
| --- | --- | --- | --- | --- |
| **excalidraw** | 134,049 | ✅ MIT | **能** | ✅ 可抄可改可闭源 |
| **tui.image-editor** | 7,671 | ✅ MIT | **能** | ✅ 可抄 |
| **filerobot-image-editor** | 1,921 | ✅ MIT | **能** | ✅ 可抄 |
| **Pinta** | 4,097 | ✅ MIT | **能** | ✅ 可抄（C#，参考算法） |
| **penpot** | 61,280 | MPL-2.0 | ⚠️ **改的文件要开源** | 🟡 可抄但要守规矩 |
| **miniPaint** | 3,478 | ⚠️ Other | **未知** | 🟡 得先查清楚 |
| **Krita** | 10,572 | 🔴 GPL-3.0 | **不能**（衍生必须 GPL） | ❌ 只能参考思路 |
| **GIMP** | 6,521 | 🔴 GPL | **不能** | ❌ 同上 |
| **darktable** | 13,289 | 🔴 GPL-3.0 | **不能** | ❌ 同上 |
| **tldraw** | 50,961 | 🔴 自定义 | **不能**（免费带水印） | ❌ 要商用授权 |

### 🔴 一句话

**"抄代码个性化"这条路，只有 MIT 的四个能安全走：**
`excalidraw` / `tui.image-editor` / `filerobot` / `Pinta`

**GPL 的那三个（Krita/GIMP/darktable）抄思路可以，抄代码不行** ——
因为一旦分发衍生作品，整个产品必须开源。

## 五、那我们到底该抄什么、抄哪一层

### 该抄的（高价值 + 可抄）

| # | 抄什么 | 从哪抄 | 为什么 |
| --- | --- | --- | --- |
| 1 | 🔴 **"选中成品 → 弹出 AI 操作菜单"这个交互** | Lovart（自研，不涉及许可） | 这是它真正的产品形态 |
| 2 | **画布底座** | excalidraw（MIT） | 无限画布、缩放、选择、连接，成熟 |
| 3 | **图片编辑的 UI 骨架** | tui.image-editor（MIT） | 裁剪/滤镜/文字/形状的组件现成 |
| 4 | **矢量化算法** | 用 `vtracer` / `potrace`（开源） | 它那个「矢量 ⚡9」就是这么做的 |
| 5 | **去背景** | 我们已有（118 处命中） | 不用抄 |

### 不该抄的

| ❌ 别抄 | 为什么 |
| --- | --- |
| PS 那一套（图层树/通道/曲线/液化） | Lovart 自己都没做，用户也不需要 |
| Krita/GIMP 的代码 | GPL 传染 |
| tldraw | 商用要授权，且水印 |

### 🔴 真正要自己做的那 8 个 AI 操作

**这些没有开源平替，必须自己接模型：**

| 操作 | 技术路线 |
| --- | --- |
| 图层拆分 | 分割模型（SAM 类）→ 分主体/背景/文字层 |
| 编辑文字 | OCR 定位 → 抹除（inpaint）→ 重新渲染文字 |
| 多角度 | 多视角生成模型 |
| 动态图片 | 图生视频（我们已有 `video-gen`） |
| 移动对象 | 分割 → 抠出 → 贴回 + 光影融合 |
| 扩展 | outpainting |
| 矢量 | vtracer / potrace（算法，非 AI） |
| Mockup | 模板合成（手工） |

## 六、我的建议（回答"要不要 fork"）

**不建议 fork 一整个 PS 克隆。**

理由：
1. Lovart 自己都证明了**用户要的不是 PS**，是"选中就能改"
2. 一个 PS 克隆有几万行，fork 过来改的成本比写还高
3. 手工编辑部分（裁剪/翻转/调整）**用 tui.image-editor 的现成组件就够了**

**建议的架构：**

```
┌─────────────────────────────────────────────┐
│  画布层：excalidraw（MIT，fork 改）           │
│    无限画布 · 选择 · 缩放 · 多物件           │
├─────────────────────────────────────────────┤
│  选中态工具条（自研，抄 Lovart 的交互形态）    │
│    快捷编辑 / 放大 / 去背景 / 编辑文字 / ...  │
├─────────────────────────────────────────────┤
│  编辑面板：tui.image-editor 的组件（MIT）     │
│    裁剪 · 滤镜 · 文字 · 形状                 │
├─────────────────────────────────────────────┤
│  AI 操作层（自研，接我们已有的 provider）      │
│    分层 · 改字 · 扩图 · 多角度 · 矢量         │
├─────────────────────────────────────────────┤
│  底层：我们的 Asset Hub（已有）               │
│    版本 · 血缘 · 资产复用                    │
└─────────────────────────────────────────────┘
```

**四层里，只有"画布层"和"编辑面板"是抄的，其余都是我们自己的。**
