## 三、🔴 最值得抄的五条

### 1. 技能是首页主入口，不是藏在设置里

> 「**用 Skill 快速开始**」下面直接摆 6 个技能卡：
> Amazon 商品主图 / Amazon A+ 内容页 / Logo 系统 / 品牌延展物 / UGC 广告视频导演 / 动态海报

**对照我们**：13 个 skill 只能在**配置层绑定**，用户在首页和对话里看不到。

### 2. 🔴 技能卡片用「真实成品图」，不是图标

每个技能卡是一张**做好的成品预览**（商品主图九宫格、A+ 长图、Logo 系统图、海报…）。

**这是"让人知道产出长什么样"最直接的方式。**
我们的 skill 列表是文字 + 描述，用户得读完才知道是干嘛的。

### 3. 🔴 案例卡带「Skill 案例」标签

> 淘宝商品视觉 `Skill 案例`
> 营销活动生成器 `Skill 案例`
> 海报设计 `Skill 案例`

**技能和案例绑在一起展示** —— 用户看到成品，同时知道"这是哪个技能做的"。

### 4. 🔴 底部 composer 常驻

不管是首页还是滚动到底部，**「告诉 Lovart 你的设计想法」永远在底部**。

**对照我们**：只有 `/agent` 页面能输入，其他页面想用 Agent 得先跳过去。

### 5. 分类按「用途」分，不按「功能」分

> 电商 / 社交媒体 / 品牌 / 创意 / 网站

**对照我们**：`AI 创作` / `编辑制作` / `世界观` / `采集与下载` —— **按功能分**。

用用途分，用户想的是"我要做电商主图"，不是"我要用图片生成"。

## 四、其他值得注意的做法

| 做法 | 说明 |
| --- | --- |
| **工具用动宾短语** | 去背景 / 延长视频 / 放大 / 精准编辑 / 样机（不是"抠图工具"） |
| **每个工具带成品预览** | 不是图标，是效果图 |
| **浏览器插件** | 「随处捕捉灵感 · 网页图片一键存到画布」+ `安装插件` 按钮 |
| **探索区有 Pinterest 源** | 直接接外部图片源 |
| **定价按"并发任务"分档** | 2/4/8/10 个并发任务 —— 按**同时能干几件事**收费 |
| **「品牌套件」是额度单位** | 5/10/30/100 个品牌套件 —— 把"品牌"当成可计数的资源 |

> 💡 **「品牌套件」这个计量很有意思**：它暗示每个品牌（客户）有一套独立的视觉资产，
> 和我们「创作项目」的概念类似，但它做成了**可计数的额度**。

## 五、对我们的直接价值

### 5.1 它验证了我们一个判断

**我们一直说"skill 是内容不是代码"，Lovart 做得更彻底——把 skill 做成了商品橱窗。**

### 5.2 三条可以立刻用在 v2 原型上的

| # | 改什么 | 影响哪个屏 |
| --- | --- | --- |
| 1 | 🔴 **首页/工作台加「用技能快速开始」，每张卡配成品图** | 新增一屏，或改 `story` 首页 |
| 2 | 🔴 **技能卡显示真实产出预览** | 技能库页面 |
| 3 | **底部 composer 常驻**（不只 Agent 页有） | 全局布局 |

### 5.3 它没解决、我们也缺的

它首页很漂亮，但**登录后才有工作区** —— 我判断不出它的画布长什么样。
所以**这条不能当"画布参考"用**，只能当"入口和技能陈列"参考。

## 七、一句话

**Lovart 教我们的不是"画布怎么做"，是"技能怎么摆到用户面前"。**

它把技能当成**商品**：有成品图、有案例、有分类、有快速开始。
我们的技能现在像**配置文件**：要读文字、要去设置里绑。

**这个差距比画布差距更值得先补。**
