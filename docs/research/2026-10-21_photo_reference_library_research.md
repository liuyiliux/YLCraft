# 摄影参考库 / 姿势库 竞品调研

> 调研时间：2026-10-21
> 用户需求：把拍照姿势、审美、光影、调色参考存起来，批量上传（100-500 张）、
> 打标签、方便检索，能从播放器截帧入库，还要「有利于审核的截图能保存学习」。
>
> 本文是「别人怎么做的」这一半；「摄影师需要什么」见
> `2026-10-21_photographer_needs_and_script_ai.md`。

# 一、⭐ 最重要的发现：姿势库解决不了真正的痛点

SLR Lounge 在发布 Cue & Capture 时写了两句很狠的话：

> **「你可以学了几年摆姿，存了几百张参考图……
> 但当两个真人站在你面前时，脑子还是一片空白。」**
>
> **「这不是知识问题，是检索问题。」**
> （This is **not a knowledge problem. It is a retrieval problem.**）

> **「图库给你的是一张成品照片。它不告诉你怎么把两个紧张的人从现在站的地方
> 带到那个结果，更不告诉你过程中该说什么。」**

另一位移拍摄影师说得更具体：

> 「照着 Pinterest 复刻，结果新人还是僵、还是尴尬、还是无聊。
> pose app 缺的是 **context**——身高差 6'2"/5'1"、紧张、风大，同一个姿势就会崩。」

## 1.1 这对我们的含义

**「把姿势图存起来」只能解决「看」，解决不了「说」。**

真正的缺口是：

```
看到一张好姿势（有图）
  ↓  ← 这里断了：不知道自己现场该怎么摆、该说什么
拍出来（没图）
```

所以每一个姿势条目，如果只有图，价值是很低的。
**必须带「怎么摆」和「怎么说」。**

## 1.2 目前最完整的「姿势 → 口令」结构：Cue & Capture 四段式

2026 年 9 月上线的 Cue & Capture，每个姿势是一张卡片，四段：

| 段 | 内容 | 例 |
|---|---|---|
| **setup** | 身体怎么放，写成**物理指令** | 不是"放松"，而是"肩膀下沉两寸，像刚深呼吸完" |
| **cue** | **现场原话**，标明对谁说、什么语气 | |
| **capture** | 机位高度、拍几张、哪里拍紧哪里拍松 | |
| **what could go wrong** | 这个姿势最常见的 1–2 种失败 | |

> **要抄结构，不要抄内容**（内容是婚礼英文语境）。

## 1.3 明确的产品空位

调研的结论：**没有找到**「上传一张姿势图 → 自动识别身体部位 → 生成中文口令」的产品。

最接近的 AI 产品是「姿势迁移」（把参考图的姿势复制到生成图里），**输出是图，不是话**。

**这就是我们的机会：姿势图 → 结构化中文口令（setup / cue / capture / 失败点）。**

# 二、分类维度：行业实际怎么分（和我原来的建议不一样）

## 2.1 我原来的建议是错的

我之前给用户提的是「身体部位特写」也做一个维度。
**调研结论：没有一家主流产品把身体部位当一级分类。**

- Posing App 把 Head/Hand/Leg positioning 放在「技巧」里
- ModelPoser 把 hand placement 做成子分类
- 中老年教程整篇都是部位微调

> **部位是「调整手段」，不是「检索入口」。**
> 做一级导航会把库切碎。

## 2.2 行业实际的维度权重（从高到低）

| 权重 | 维度 | 说明 |
|---|---|---|
| **1** | **人数** | 单人 / 双人 / 多人（家庭、伴娘伴郎、团体）—— **决定姿势能不能复用** |
| **2** | **人群/关系** | 新娘、新郎、儿童、老人、coser、伴娘伴郎、父母 —— 决定口令和尺度 |
| **3** | **场景/流程** | 影棚/外景/民政局/教堂/家中；仪式节点 —— 决定「什么时候用」 |
| **4** | **姿态族/动作** | 站/坐/靠/走/拥抱/回头/蹲/躺/跳/互动 —— 决定检索 |
| **5** | **风格/情绪** | 可爱/帅气/优雅/自信/松弛/电影感 —— **是标签，不是目录** |
| **6** | 身体部位 | 手、下巴、腿、重心、肩线 —— **只做筛选 chip，不做一级** |

## 2.3 各产品的实际分类（横向对比）

| 产品 | 一级维度 | 风格/情绪 | 备注 |
|---|---|---|---|
| **Posing App**（300+ 姿势，2012 至今） | **人群/关系**：Children / Couples / Portraits / Women / Men / Groups / Weddings | 无（Glamour 单独付费包） | **用线稿不用照片**，官方理由：轮廓更容易被素人复刻 |
| **Atlegras**（7000+ 姿势） | 姿态 + 人群 + 场景 + 风格 + 节日 混合 | 有（Elegant/Expressive/Confident/Vintage） | 唯一把 mood 做成可搜索维度的摄影向产品；可上传自己的参考混排 |
| **Cue & Capture** | **主体**：couples/bride/groom/bridesmaids/groomsmen/wedding party/family | 无 | 官方说「按系统组织，不按 vibe，**所以筛选才有意义**」 |
| **ModelPoser**（140+） | 手部放置、坐姿、斜倚 | 无 | 核心是 **Ghosting Overlay**：参考半透明叠在实时相机上 |
| **Magic Poser**（3000+） | 11 个预设类别（未公开） | 无 | **面向画师，不是摄影师** |
| **set.a.light 3D** | 性别 + 站/坐/躺 | 无 | 本质是**灯光模拟器**，姿势是附属 |
| **WorldCosplay**（650 万图） | 作品 → 角色 → 标签 | 无 | **2024-07-31 已停服** |
| **Shotdeck**（影视） | 镜头语言：framing/lighting/color/composition/location/**emotion** | 有（emotion 是正式标签） | 30+ 类别、50+ 关键词 |

**关键借鉴**：Cue & Capture 那句「按系统组织，不按 vibe，所以筛选才有意义」——
**情绪/风格必须做成标签，不能做成目录**，否则筛选就失效了。

## 2.4 「100 个姿势」清单长什么样

- **婚纱/情侣**：几乎都按**关系分组**（couple → bride solo → groom solo → bridal party → family formals → parents），
  每组再分 **anchored**（站定看镜头）和 **motion**（走、转、摆）。
  一个 90° 对站姿势能拆出 10+ 张。
- **台湾婚纱**：按**动作**分 8 类（拥抱、深情对望、亲吻、牵手、背影、自然互动、背新娘、单人）。
  文章开头写「好想要一本婚紗100姿勢教科書」—— 需求真实存在。
- **书**：编号目录形态，每条 = 一张图 + 一句提示，**几乎没有情绪标签**。

# 三、按题材的差异化做法（用户明确要的四个题材）

## 3.1 Coser：组织单位是「角色/作品」，不是姿势

- cos-compass 的 50 姿势清单按**角色气质**分：
  基础 10（任何角色）/ 帅气系 10（战士、冷酷）/ 可爱系 10（魔法少女、偶像）/
  2 人·团体 10 / 场景别 10。每条给一句「加分提示」（脚尖同向、下巴微收、连拍抓跳跃）。
- 它直接写出 coser 的痛点：**「ポーズ迷子」（姿势迷路）**
  ——「官方画里没有的姿势想不出来」「每次都是同一个姿势」「和摄影师一起时不知道摆什么，僵住」。
- 使用方式：「**拍摄前存进手机，和摄影师共享**；或者对着镜子练」。
- 平台侧（WorldCosplay / 半次元）**按作品/角色/标签组织，没有姿势维度**
  —— 所以「按角色找姿势」目前只能靠搜索引擎。

> **产品含义**：coser 题材必须多一层「作品/角色」标签，
> 否则同一套「回头、拔剑、跳跃」无法区分是哪个角色的味道。

## 3.2 情侣：卖的不是姿势，是「互动任务」

Paperlust 的核心方法论：

> **「Expression coaching beats pose directing:**
> **给对方一件要做的事或一句要说的话，而不是一个要保持的形状。」**

具体清单都是任务化的：forehead touch、almost-kiss、
whisper（「the laugh that follows is never performed」）、walking shot、full embrace。

> **产品含义**：姿势图对情侣是不够的——图给的是结果，摄影师需要的是「让他们做什么/说什么」。

## 3.3 老年人：姿势少、口令多、目标是「松弛」

今日头条中老年教程把「僵硬」拆得很细：

> 「双脚并拢，手贴裤缝，肩膀抬高，脸上挂着刻意的笑。」

解法全是**单点、口语、一次一个**：

> 「一次只提醒一个动作，比如『右脚往前一点』或者『脸转回来一点』。
> **指令越多，人越容易忙乱。**」

其余是身体部位级微调：一侧肩靠近相机、鼻尖和视线一起转、下巴略向前向下、
手轻碰围巾/包带/帽檐、手臂和身体留缝、重心放后腿、坐椅子前 1/3、腿斜向一侧。

还有「不要喊看镜头笑一个」的替代：整理衣袖、扶帽子、往前走两步再回头、叫名字再转身、开连拍。

> **本质不是姿势库，是「口令库 + 纠错库」。**

## 3.4 领证跟拍：按「仪式流程」组织，不是按姿势

- 民政局内（填表/按手印/递证瞬间）
- 宣誓台（持证对视、额头相抵、轻吻脸颊、搞怪）
- 外景/车内（奔跑、牵手转圈、躺姿、车窗贴囍字、戒指特写）
- 还有「不露脸的高级感」（结婚证遮脸、剪影、逆光轮廓）和「时间轴叙事」

> **产品含义**：领证题材的检索入口应该是**流程节点**——摄影师到了现场按节点找参考。

# 四、现场怎么用（决定产品形态）

## 4.1 手机是绝对主力

一位摄影师专门写文解释「我为什么在你面前掏手机」：

> 「看 shot list、临时搜一个更合适的姿势……
> **与其说一堆让人困惑的口头指令，我不如给你看手机上的一张参考图。**」

## 4.2 载体证据强度

| 载体 | 证据强度 | 说明 |
|---|---|---|
| **手机**（图/列表/App） | **强** | 多个独立来源，是现场默认设备 |
| 打印/PDF 拍摄案 | 中 | 中文教程明确推荐；适合标注和离线 |
| App 内 board/勾选清单 | 中 | 2026 新产品在做，属于差异化 |
| 实时叠图 | 中 | ModelPoser 单点创新 |
| iPad | **弱** | **没找到直接证词** |

## 4.3 拍前动作

- 建 Pinterest **private board**，按 Light / Colour / Location / Styling / **Posing** 分 section；
  邀请客户/妆造/副机位；**永久参考板和单次项目板分开**。
- 让客户自己建 private board 回传喜欢的姿势/服装/色调。
- 做拍摄案：打开 PPT，找 15 张以上样片，标构图占比、焦段、光线、前景背景、
  **「姿态怎样引导模特摆到位」**，然后**打印成 PDF 或打成纸**。
- coser 侧：把 50 姿势清单存进手机，拍前和摄影师共享，对着镜子练。

# 五、我们的产品建议

## 5.1 分类：按「题材 × 人数」做一级

直接落成：

| 维度 | 值 | 做一级？ |
|---|---|---|
| **题材** | coser / 老年人 / 领证跟拍 / 情侣写真 | ✅ 一级（用户已有） |
| **人数** | 单人 / 双人 / 多人 | ✅ 一级 |
| **姿势族** | 站 / 坐 / 靠 / 走 / 拥抱 / 回头 / 蹲 / 躺 / 跳 / 互动 | ✅ 二级 |
| **感觉** | 松弛 / 优雅 / 可爱 / 帅气 / 电影感 / 仪式感 / 搞怪 | 标签，不设目录 |
| **身体部位** | 手 / 下巴 / 腿 / 重心 / 肩线 | **只做筛选 chip** |
| **来源** | 视频（同一视频=一组）/ 网页 / 自己拍 | 标签 |
| **角色/作品**（coser 专用） | 具体作品名 + 角色名 | ✅ 二级（题材=coser 时才出现） |

## 5.2 每条姿势至少两个字段

1. **图**（照片）
2. **「怎么摆」的一句话**

进阶是 Cue & Capture 四段式：`setup / cue / capture / 失败点`。

**线稿思路值得考虑**：Posing App 用线稿不用照片，理由是「轮廓更容易被素人复刻」——
对「给客户看」的场景很有价值。可以考虑「照片 + 自动/手动线稿」双版本。

## 5.3 ⭐ 视频截帧要做成「组」，不是「散图」

- 工具层已证明可行：Frame Grab 能按间隔或按张数批量导出静帧；
  DWPose 能把一批帧逐帧存成 OpenPose JSON。
- **但没有产品把「一条视频」当成一个姿势集合的容器。这是最清晰的差异化。**

建议流程：
```
上传/播放视频 → 自动抽关键帧（去模糊、去重复、按动作变化选帧）
            → 生成一个「组」
            → 组级打一次标签（题材/人数/角色/感觉）
            → 组内每帧可单独调
            → 选 3-8 张「代表帧」，避免一次导入几百张垃圾
```

对 coser 尤其成立：一条打戏/变身视频，天然就是一组连续姿势。

> ⚠️ 注意：用户上一轮明确说过「不要，一次一帧就行」。
> 但那是问「要不要连续截多帧自动成组」时答的，场景是**播放器截帧**。
> 这里的建议是**视频导入时批量抽帧成组**（不同的入口）。
> **这两件事需要在需求确认时再问一次，别自己改主意。**

## 5.4 口令库是护城河，必须中文化、题材化

| 题材 | 口令特征 |
|---|---|
| 老年 | 慢、一次一个部位、给手找事做、少说「看镜头笑一个」 |
| 情侣 | 给任务不给形状（whisper / almost-kiss / 走三步回头 / 拥抱时收紧再笑开） |
| 领证 | 按流程节点（「把证举到胸口，互相看，不要看镜头」） |
| coser | 角色感 + 武器/披风/镜头感（「手向镜头伸、下巴收、眼神越过镜头」） |

结构：`cue`（一句原话）+ `body_part`（改哪里）+ `intensity`（改多少）+ `failure`（常见崩点）

## 5.5 现场模式：手机、单手、离线

- 大图 + 左右滑 + 分组 board + 勾选「拍过了」
- **离线可用**（棚拍/民政局/外景经常没网）
- 一键导出 PDF
- 分享链接给客户
- 叠图优先级**低于**「能快速翻到那张图」

## 5.6 三条「不要做」

1. **不要把 3D 模型当核心**。3D 工具的用户是画师
   （Magic Poser 说自己服务 artists，PoseIt 说自己是 drawing mannequin）；
   摄影师的真实动作是「找一张别人拍过的图」，不是「摆一个不存在的人」。
2. **不要依赖已关停平台**。WorldCosplay（2024-07-31 停服）、半次元（2023-07-12 停运）；
   姿势库必须能本地保存/导出，并保留来源链接。
3. **不要做「按身体部位」的一级导航**，会把库切碎。

## 5.7 版权要前置

coser 图、视频截帧、网图都涉及授权。每条记录建议带：
**来源 URL / 作者 / 授权状态（仅个人参考 / 已获授权 / 可公开）/ 是否含人脸**。

> Coser 圈对转载和商用很敏感，**这一点做不好会直接失去种子用户**。

## 5.8 竞争格局（截至 2026-10）

| 产品 | 位置 | 缺什么 |
|---|---|---|
| **Atlegras** | 7000+ 图，可上传自己的参考，按 subject/mood/location 搜索 | 没有中文题材、没有视频成组、没有口令 |
| **Cue & Capture** | 口令 + board + 筛选，最像「现场指挥工具」 | 只做婚礼/情侣，英文 |
| **ModelPoser** | 叠图，单点创新 | 单点 |
| **Pinterest** | 最大流量入口 | 不可检索、内容会消失、无结构 |

> **空位：中文题材（领证 / 老年 / coser）+ 视频成组 + 结构化口令 + 现场模式。
> 这四个交集目前没人做。**

# 六、调研限制（哪些是「没找到」，不是「不存在」）

1. **Pinterest 需登录/JS**：「没有官方姿势分类」的依据是 `/ideas/poses/` 落到通用 Explore +
   公开 board 的相关搜索，属**强观察**，不是官方声明。
2. **App 商店文案是厂商自述**：「11 类」「7000+」「140+」都来自官方描述，未逐条核对。
3. **Cospix 未能验证**：站点返回 403/422，只看到标题 "The End of Cospix"，未据其下结论。
4. **Krea 没有 pose 功能**：这是「官方文档里没有」，不等于产品里绝对没有入口。
5. **没做摄影师访谈**：所有「痛点」都是从公开文章、知乎回答、厂商文案归纳，
   **不是统计样本**；样本偏英语婚礼摄影和中文人像教程。
6. **「一条视频截多帧当一组」没有现成产品**：这是**检索结论**，不是市场结论。

# 八、「审美学习」类产品调研（第三路）

## 8.1 ⭐ 第一个结论：「审美学习」不是一个真实的产品品类

英文里也没有完全对应的词，最接近的是 visual training / photo critique /
aesthetic assessment / inspiration library。

真实产品把它拆成了**四种彼此独立的功能**：

| 对应 | 代表产品 | 它实际做的事 | 停在哪 |
|---|---|---|---|
| **收藏 / 灵感库** | Eagle、PureRef、Are.na、Pinterest | 存图、标签、搜索 | **存完没有下一步** |
| **分析 / 点评** | Adobe Project Indigo、PickEpic、Overlook、YAN、AI摄影管家 | 给一张照片打分、写评语、给重拍建议 | 评的是「你拍的这张」，**不是「你存的这张」** |
| **对比 / 选择** | WhichOne AI、PickEpic、GuruShots | 多张里选最好 | 帮你决定，**不教你怎么看** |
| **复盘 / 回顾** | Daily Pieces、Eagle 随机模式、Famous Paintings Trainer | 回看、随机重遇、间隔重复 | 要么自我认识，要么记知识，**不是审美判断** |

> **用户说「我要开始审美学习」，产品给他的往往只是一个更漂亮的收藏夹。**

## 8.2 第二个结论：没有产品做成「参考图 → 审美判断」的闭环

按「存 → 分析 → 练 → 反馈 → 回看」五步看：

| 产品 | 存参考 | 分析 | 练 | 反馈 | 回看 | 判断 |
|---|---|---|---|---|---|---|
| **PickEpic** | 无 | 5 维评分+评语 | 30 挑战 | 分数+建议 | 部分 | **最接近拍摄练习闭环** |
| Overlook | 无 | 3 维 | 50+ 挑战 | 点评 | 部分 | 同上，更小 |
| Adobe Project Indigo | 无 | 构图/光线/色彩/情绪 | 无 | 重拍+后期建议 | 无 | **单次点评，不是学习系统** |
| YAN | 无 | 5 维+雷达+视觉标注 | 无 | 点评 | 无 | 分析强，学习弱 |
| Daily Pieces | 有 | AI 提问 | 无 | 无 | 周报月报 | 反思闭环，非技能闭环 |
| Eagle / PureRef | 有 | 无 | 无 | 无 | 随机重遇 | **收藏闭环** |

**「收藏夹变成技能」的可验证案例：没找到。**

反例倒是很硬：

> 一位 Eagle 重度用户存了 **5 万多份素材**，原话：
> 「随手保存只要一秒，整理一份却要十几秒」，最后「几万份灵感就在硬盘里长眠。
> **真急着用，还不如打开 Pinterest 重新搜**。」

> 知乎：「通篇看 → 放大看 → 点赞/转发 → 截屏/收藏 → **躺在手机里吃灰**。」

> 「**收藏一万张图，不如解构一百张图**」；图库不是「图片仓库」，要变成「弹药库」。

> Eagle 官方博客自己也承认：**收集和整理本身，并不保证你变快或设计变好**；
> 真正需要的是「仔细看、和别的方案比较、按当前条件判断」。

## 8.3 AI 分析照片能拆到多细（真实产品的输出维度）

| 产品 | 输出维度 |
|---|---|
| **Adobe Project Indigo** | 构图、光线、色彩、情绪影响；另给重拍建议 + Lightroom 参数 |
| **PickEpic** | 美学、构图、光线、锐度、色彩平衡（0–10 分）；4 种模式 |
| **YAN** | 构图、光线、色彩和谐、清晰度、情绪叙事；**视觉标注**（直接指出画面哪个元素该改） |
| **AI摄影管家**（开源） | 构图、光影、色彩、清晰度、主体、情绪、故事、发布价值（8 维） |
| **Everypixel** | 单一「这张图很棒的几率」；**官方明确说不测美，只测亮度/对比度/噪点等技术面** |
| **AADB（研究数据集）** | 11 属性：平衡元素、内容、色彩和谐、景深、光线、动态模糊、主体突出、三分法、鲜艳色彩、重复、对称 |

### ⚠️ 一个重要限制：AI 打分不该被当成客观真理

AADB 的 11 个属性是「专业摄影师参与定义」的，但论文里 **5 个标注者的平均一致性
Kendall's W 只有 0.5322**，只能算中等一致。

> **连人类对「这张图构图好不好」都没有高度共识，AI 的分数更不该被当成客观真理。**

**AI 能拆到**：哪个区域、哪个元素、造成了什么问题、下一次改什么（craft 层）。
**拆不到**：这张图对你意味着什么、在你的风格/客户/系列里为什么成立（intention 层）。

## 8.4 ⭐⭐ 如果只做一个功能：做「入库时写一句：这张图我要偷什么」

不是 AI 评分，不是间隔重复，不是二选一训练。

**就一个字段**：保存一张图之后，用一句话写下「我要从它身上拿走的那一项」，
**不超过 40 字**，配 6 个快捷 chip：**光 / 构图 / 色彩 / 情绪 / 元素 / 标准**。

可选再加：
- 一条「**我不学什么**」（反参考）
- 「**找感觉 / 对脚本**」
- 「**可实现 / 不可实现**」

### 好例子 vs 坏例子

| 好 | 坏 |
|---|---|
| 「逆光把发丝和背景分开，脸留暗部」 | 「好看」 |
| 「阴影加青、高光加蓝、整体降饱和」 | 「高级」 |
| 「眼睛不要太大，下巴不要过尖，肤色不要偏绿」 | 「氛围感」 |
| 「前景用纱/玻璃做一层雾，人物只占三分之一」 | 「日系」 |

> 坏例子的共同点：**没有信息量，等于没写。**

### 为什么是它（五条理由）

1. **唯一一个在「保存那一刻」改变用户行为的功能。** 其他功能都依赖这个字段——
   没它，AI 只能给通用点评，复习只能重新刷图，对比只能凭感觉。
2. **把「好看」翻译成「可操作特征」。** 这正对着一个普遍困境：
   只知道好看、不知道该学哪一项——解法不是看更多，是每条都记下好在哪。
3. **直接对抗「被牵着走」**：你写的是**自己的判断**，不是图的 aura；
   写完图可以归档，判断留下来。
4. **轻**：不需要 AI、不需要冷启动、不需要每天打卡；一张图 5 秒。
5. **会沉淀成「标准」**：30–50 条之后能聚成「我的标准」
   （眼睛多大算自然、下巴多尖算过、肤色多白算假）——这就是人像需要的那套「度」。

### 为什么不是别的

| 方案 | 为什么不做核心 |
|---|---|
| AI 评分 | 给的是通用 craft 反馈，不知道你的意图/客户/场景；**而且它鼓励你继续消费，不鼓励你判断** |
| 间隔重复 | 审美判断没有唯一正确答案；**没有 note 的复习只是重新刷图** |
| 二选一对比 | 能练辨别力，但不沉淀库；而且用户不会每天做 |
| 自动标签 / 以图搜图 | 解决「找得到」，不解决「学得会」 |

### 验证指标（建议）

- **7 天**：新保存图片的 note 填写率 ≥ 60%
- **30 天**：至少 30% 的 note 被带进拍摄方案/分镜（说明真的被复用）
- **60 天**：用户能用自己的 note 说出一套「我的标准」，而不是只会说「好看」

## 8.5 「看多了被牵着走」：产品端基本是空白

### 这个反作用是真的

- 插画师 Nadine Kolodziey：过度关注在线灵感会让思路「趋于千篇一律」，
  「**别人的作品开始影响你的判断和直觉**」
- Depix 把这叫 **anchoring bias（锚定）**：参考图放久了，
  就从「灵感」变成「**天花板**」——你不再问「它应该是什么」，只问「我们能多接近它」
- 资深摄影师的常见顾虑：过度分析他人作品会干扰自己的判断（业界与教学材料中反复出现）。

### 但「少看」不是解

知乎「初学者要不要多看片子」的高赞回答是反过来的：**「必须多看，没有例外」**；
认为「看了会限制思路」是「自欺欺人」。

> **真正的结论：被动地看会被带偏，主动地拆不会。问题不在输入量，在「看完之后有没有变成自己的判断」。**

### 六个可落地的解法（产品端几乎没人做）

| # | 解法 | 怎么落 |
|---|---|---|
| 1 | **分流** | 入库时强制选「找感觉 / 对脚本」；找感觉的看完归档，不长期挂在眼前 |
| 2 | **写原则，不写形容词** | 不存「高级感」，存「阴影加青、高光加蓝、降饱和」 |
| 3 | **反参考** | 除了「我要什么」，再记一条「**我不要什么**」 |
| 4 | **关掉参考再创作** | 拍之前先收起来，按原则拍；拍完再并排对比 |
| 5 | **和自己的照片比** | 每周选 1 张标杆，模仿核心技巧拍一组，对比「差在哪」 |
| 6 | **控制输入源** | 少刷算法流，多跟固定的、经时间验证的来源 |

## 8.6 三条必须调整的设计（对之前方案的修正）

### ① 核心字段不是标签，是「一句话偷师点」

> **标签解决检索，句子解决学习。**

标签可以后置、可以 AI 建议；**那句话必须用户在保存时写**。

### ② 不要做间隔重复，做「写方案时随手翻到」

素材库的真实用途不是「每天复习」，而是
**写拍摄方案脑子短路时，能随手翻到自己的库**。

→ 应该把参考库和摄影策划台连起来，**而不是做一个 Anki**。
轻量的「每周 5 张」可以作为后续仪式，不是核心。

### ③ AI 做「追问」，不做「评分」

与其给一张图打 6.5 分，不如在用户写完 note 后问：
- 「还有哪个维度你没注意到？」
- 「如果换成你的场景，这一条怎么用？」
- 「这条和某某风格卡是否一致？」

**输出应该是「可操作特征」（阴影加青/高光加蓝/肤色偏蓝绿），不是 0–100。**

## 8.7 「审核截图」和「审美参考」不要混

> 如果「审核」指别人给你的审片意见截图，那是「**错误库**」：
> 截图 + 哪里错 + 正确做法 + 标签「踩过的坑」。
>
> 如果指自己的成片，那是「**作品库**」：成片 + 参数/地点/脚本 + 当时的判断。
>
> **两者 schema 不同，混在一个收藏夹里会互相污染。**

## 8.8 定位警告：不要做成「另一个 Eagle」

> Eagle 已经赢了「存」，PureRef 赢了「摆」。
> 我们的差异应该是：**每次存图的一次判断 + 写方案时能翻到的弹药库**。
> 如果只做「更大更全的库」，就会重复「5 万份素材长眠在硬盘里」的命运。

## 8.9 一句话总结

> **人像摄影的「审美学习」最终不是「更多参考」，而是「一套可对照的度」。
> 这个度只能从「存一张 → 写一句 → 拍一次 → 比一次」里长出来，
> 不能从 AI 的分数里长出来。**

## 8.10 调研限制

- 没有找到「每天一张大师作品 + 拆解为什么好」的产品（DailyArt 最接近，但它是艺术史故事）
- 没有找到把 Anki/间隔重复用于「审美判断」的产品（只有艺术品识别记忆）
- 没有找到「收藏夹自动变成技能」的可验证案例
- 没有找到明确解决「看多了被牵着走」的产品功能（只有零散的方法论文章）

# 九、ShotDeck 类「视觉参考检索」产品调研（第四路）

## 9.1 ShotDeck 的真实结构：不是「30 个筛选器」

官网宣传「over 30 categories with more than 50 keywords」，
但看它的产品截图，准确说法是：

> **21 个筛选面 + 1 个自由词搜索 + 1 棵层级地点树 + 1 组可检索的自由 TAGS**

| 类型 | 内容 |
|---|---|
| **21 个结构化筛选面** | Genre、Color、Interior/Exterior、Time of Day、Time Period、Aspect Ratio、Format、Composition、Lighting、Lighting Type、Shot Type、Frame Size、Lens Size、Number of People、Gender、Age、Ethnicity + 3 个内部运营字段 + Date Range |
| **自由词搜索** | 顶部 `Add search term`，关键词即时变 chip |
| **层级地点树** | `STORY LOCATION: Earth > North America > Mexico > Mexico City`、`SET: Car (Moving) > Driver's Seat` |
| **TAGS（自由词，非受控）** | 例：`eye light, eyebrows raised, eyes, front light, looking to the side, profile view` |

**⭐ 关键：这是「双层结构」——**
> **结构化 facet 保证可组合的精确过滤，自由词保证长尾不被词表压死。**

而且**类目是逐年长出来的**（2019 年 CineD 报道时是「over 20 categories」，2026 年是 30+）
—— **词表应该是可生长的，不是一次定死**。

## 9.2 它怎么打标：纯人工，但前提我们不具备

- 官网：「We've **hand-tagged** every image in over 30 categories…」
- 帮助中心：「**only the ShotDeck team adds images**… each one carefully curated and tagged by us」
- 选片硬约束：「**只能收能拿到高质量源的片子**」

> 这条策略的关键不是「人工比 AI 好」，而是**它把规模问题转化掉了**：
> 内容源有限（一年值得拉片的电影就那么多），每部只抽几十到几百帧，所以人工打得完。
>
> **反过来：用户自己上传的 100–500 张私人图，没有这个前提，人工全量打标必然失败。**
> 这就是「能抄词表、不能抄流程」的分界线。

## 9.3 ⭐⭐ 「标签打不完」的五种解法（整份调研最该带走的一节）

**没有一家是「让用户把标签打完」。**

| # | 解法 | 代表 | 成立条件 | 对我们的价值 |
|---|---|---|---|---|
| **1** | 专业人工打标 + **卡死内容源** | ShotDeck | 内容有限、可复用、有人付费 | 抄**词表**，**绝不能抄流程** |
| **2** | 干脆不打视觉标签，用「**来源对象**」当索引 | FilmGrab | 内容本身高质量、「片子」就是最强语义单元 | **「系列/项目」就是我们的 FilmGrab 式索引**——一次拍摄天然是分组，不需要给每张打 20 个标签 |
| **3** | **AI 自动打 + 受控词表兜底** | StillsLab / Savee / Cosmos | —— | **可计算维度先自动跑，人工只补场景/关系/意图**。这是唯一能在 500 张量级跑通的路线 |
| **4** | 不打标，用「**找相似**」替代 | Cosmos / Savee | —— | **入库时先找最近邻 → 继承邻居标签 → 人只改不填**。这是把「打不完」变成「改一改」的关键 |
| **5** | **只组织、不打标**——集合/看板 + 风格向量 | StudioBinder / Krea / Midjourney | —— | 给一条「零打标也能用」的路径：分进系列就能按系列走 |

> **纪律（五家共同遵守）**：
> **受控词表只覆盖「高频 + 可判定」的少数维度，长尾一律交给自由词或相似检索。**

**解法 4 的原话**（对我们最有用）：
- Cosmos：「**Start with an image you love and find more like it.**」
- Savee：「**Related content** —— when you save something you love, Savee shows you visually related inspiration.」

**解法 5 的量化参考**：Krea 情绪板**最多 250 张**一起分析，输出的是一个「风格」，不是 250 条标签。

## 9.4 必做的 5 个维度（再多就是负担）

| 必做维度 | 怎么做（关键取舍） |
|---|---|
| **① 人物与关系** | 枚举而非自由词：`单人/双人/三人以上` × `coser/老年/情侣/亲友`。**人数和人脸年龄段让 AI 数，不让人填** |
| **② 光** | 拆 3 个词：**光质**（硬/柔/混合）、**方向**（顺/侧/逆/顶）、**时段**（清晨/白天/黄金时刻/蓝调/夜）。可从 EXIF + 图像统计半自动推，人工只确认 |
| **③ 色调** | **不做 20 个色名**，做「1 条主色板 + 冷暖/饱和/对比三个值」；支持按色值搜 |
| **④ 景别/构图** | 景别（大特写/特写/半身/全身/环境人像）+ 构图只留 4 个：`居中/三分/留白/前景遮挡`。**不要学 ShotDeck 的 Lens Size 全套** |
| **⑤ 情绪/氛围** | **不做下拉框**（填不完、各人理解不同）。用「色调 + 光 + 表情标签」合成一个可解释的氛围，再加**一个自由词输入**，存下来成为你自己的词表 |

**人像摄影师的检索语句长什么样**：
> 「**两个人在民政局门口、下午逆光、暖调**」
> 不是「Composition: Left heavy」。

所以维度优先级：**① 谁 + 在哪 → ② 光 → ③ 色调 → ④ 景别构图 → ⑤ 情绪**。

## 9.5 可以省的（省下来是「打标预算」和「界面面积」）

| 可以省 | 理由 |
|---|---|
| 相机 / 镜头型号 | 人像找参考**不看机身**；EXIF 自动读进来当「可搜不必填」就够 |
| 人种 / Ethnicity | 敏感、填不准，**建议不做** |
| Imported by / Published by / Edited by | 纯内部运营字段 |
| **地区层级树** | 维护成本极高、覆盖永远不全。换成「地点自由词 + 场景类型枚举」 |
| 故事年代 Time Period | 影视拉片才需要 |
| 画幅比 / 格式 | **自动提取即可，不要出现在筛选栏** |
| 镜头运动 / 技法 | Eyecandy 那套服务「解释运镜」，我们是静帧参考库，第一阶段不做 |

## 9.6 ⭐ 批量入库（100–500 张）的关键流程

> 把打标做成「**改**」，不是「填」。

| 步骤 | 做什么 |
|---|---|
| **1 上传即分组** | 一次上传默认落进一个「批次/系列」——**这是唯一强制的标签** |
| **2 自动算** | 颜色板、明暗、画幅、人脸数、人脸年龄、清晰度、重复图——全部后台跑，用户看到的是**已填好的表单** |
| **3 ⭐ 最近邻继承** | 新图入库先找库内最近邻，**把邻居的场景/关系/光/情绪抄过来 → 标成「待确认」**。人只需在网格里连点「对/不对」，或改一两个字段。**这是把 500 张的录入成本从 500 次降到 50 次的核心** |
| **4 批量套用** | 框选一批 → 一次性设「时段=黄昏、光质=逆光、场景=民政局门口」。**同一批拍摄这几个字段往往完全一样**，这是最高杠杆操作 |
| **5 「待确认」队列** | 给一个「**未确认 N 张**」入口，让她知道还剩多少，而不是感觉永远打不完 |

## 9.7 截帧入库：**没有一家做，纯空白**

调研结论：ShotDeck 是自己拉片不给用户上传；Eyecandy 给片段但不入个人库。
**「从播放器截帧直接入库」目前是空的。**

建议做成：
- 播放器里一个快捷键 → **自动取前后各 1–2 秒的 3–5 张候选帧**让她挑（避免手抖抓到糊帧）
- 入库时**自动带上时间码 + 片名/来源**
  （ShotDeck 的 `SHOT TIME: 0:12:29` 就是干这个的，**这个字段必须有**，否则以后找不到出处）
- 入库后**立刻跑 9.6 的自动流程**，不要让她截完还要再进另一个页面打标

## 9.8 ⭐ 另一个空白：参考图 vs 自己成片的对照

| 谁做了 | 在哪做 |
|---|---|
| **Lightroom Classic 的 Reference View** | **在修图软件里，不在参考图库类产品里** |
| StillsLab | 参考库产品里唯一做了双图对比的（slider/网格/并排元数据） |
| ShotDeck / FilmGrab / ScreenMusings / Savee / Cosmos | **都没有** |

Lightroom Reference View 的交互（值得抄）：
- 点图片下方 `R|A` 图标或按 **Shift+R** → 切成 2-up
- **参考图静态不可编辑，当前图可编辑**
- 可从胶片条拖图进参考位，或右键 `Set as Reference Photo`
- **切模块会清空参考图，要点锁图标锁住**
- 选裁剪工具会直接退出该模式

> **结论：这是空白位，也是最容易做出差异化的一个功能点。**
> 她拍完能立刻知道「差在哪：是光位、是色温、还是构图留白」。

## 9.9 检索入口怎么摆（照抄行业已验证的形状）

- **首屏只放一个搜索框**（自由词）+ **5 个 facet 的第一层**，其余折叠
- 已选条件做成 **chip，可单个 ×**，显示「**命中 N 张 / 共 M 张**」而不是「约」
- **每张图悬停就出「找相似」**，不要藏在详情页
- **首屏第一动作永远是「打几个字」**，不是「展开筛选器」

> 证据：ShotDeck 搜索框在最顶、21 个面在左栏折叠折叠；Savee/Cosmos 干脆把搜索框做成唯一入口。

## 9.10 其它值得知道的

- **FilmGrab**：一个人 2010 年至今在做，近 4000 部片、1.86 亿浏览；「每张图我手工挑、手工编目」；
  **「我拒绝用 AI 或机器人」**。导航即全部检索能力：`Browse By Artist`（导演/摄影/美术/服装）、
  `Browse By Category`（画幅/国家/类型/年份）。**它没有任何「光/构图/色调」标签。**
- **ScreenMusings**：唯一把「颜色」做成一级入口的截图站（Color Lab），
  但它是「按颜色语义浏览精选片单」，**不是「在 10 万张图里按色值过滤」**——这两件事经常被混为一谈。
- **Eyecandy**：唯一把「镜头运动/剪辑技法」做主检索轴，返回的是**视频片段**不是截图。
- **StillsLab**（2026 新竞品）：以图搜图当主打（免费 10 次/天）、支持 hex 色值/AND-OR-排除、
  **双图对比**、4K 免费下载。—— 竞品自述，需打折看。
- **StudioBinder Mood Boards** 值得抄四点：
  ① **「All images are searchable and reusable across projects, eliminating the need to re-upload」**（中央素材池 + 看板引用）
  ② 看板可放**文字元素**（因为「参考图需要一句解释」）
  ③ 图片可就地编辑（裁剪/曝光/**13 个预设滤镜**/标注）
  ④ **用「互动」当排序信号**：可筛「已收藏 / 有评论 / 还没人理」

## 9.11 一句话总结

> **ShotDeck 值得抄「facet + 自由词」的双层结构和 deck/导出的交付形态；
> 不能抄「人工全量打标 + 只收自有内容」。**
>
> **Savee/Cosmos 值得抄「图搜 + 颜色」作为一等公民。**
>
> **Krea/Midjourney 值得抄「一组图 = 一个风格档案」，让零打标也能产出可复用的东西。**
>
> **我们的差异化压在两个没人做的地方：播放器截帧直入 + 参考图与成片的对照。**
