## 一、它是什么

**「AI修图大师」** —— AI 修图工具，不是拍摄工具。

| 项 | 内容 |
|---|---|
| 定位原话 | 「让 AI 先看懂你的照片该怎么修，再由你决定改哪里、改多少」 |
| 技术栈 | Nuxt 4 + Nuxt UI v4，**纯前端 SPA，没有自建后端** |
| 桌面版 | Tauri 2 打包，Windows WebView2 |
| 数据 | 工程存浏览器 IndexedDB，**不托管图片** |
| AI 接入 | PawBuddy 账户（自家网关）或自带 OpenAI 兼容接口 |
| 代号 | `com.k99k5.ai-photo-master` |
| 产品名 | AI修图大师 |

## 二、功能清单

### 2.1 AI 读图与建议

- 三类建议：**参数化调色**（全图或局部）、**生成式重绘**、**构图裁剪**
- 每条建议**一键采纳为图层**，再继续微调
- 分析过程流式显示：展示 `reasoning_content` / `<think>` 标签里的思考过程 + 正在写出的建议标题，**不显示原始 JSON**
- 结构化输出三级降级：`json_schema` → `json_object` → 纯提示词

### 2.2 编辑

| 能力 | 细节 |
|---|---|
| **区域调色图层** | 曝光/对比度/高光/阴影/黑白色阶/色温/色调/自然饱和度/饱和度/清晰度/锐化 |
| **区域限定** | 全图 / 矩形 / 椭圆（可羽化）/ 线性渐变 / 画笔（含擦除、反转、强度） |
| **局部重绘** | 圈区域 + 写指令，每次生成多张候选；只替换蒙版内像素，**蒙版外与原图逐位一致** |
| **裁剪与水平校正** | 旋转后裁剪框自动收缩到无空白角的最大区域 |
| **非破坏式** | 图层开关/排序/删除，撤销重做，按住 `\` 对比原图 |
| **自动保存** | IndexedDB，停顿 0.6 秒写入 |

### 2.3 导出

Worker 分块渲染，**导出尺寸与原图一致**；JPEG/PNG/WebP，JPEG 保留 EXIF。

### 2.4 桌面版特有

- **覆盖写回原图**（`Ctrl+S`），不弹对话框
- 每次都从工程里保留的**未修改原图**重新渲染，反复保存**不累积压缩损失**
- 只运行一个实例，再启动把已有窗口带到前台

## 三、⭐ 技术取舍（它自己写的「为什么不直接读图→蒙版→images/edits」）

**这三条是踩过坑才知道的。**

### 3.1 蒙版只是「提示」

> 「GPT Image 会**重画整张输入图**，蒙版外也可能变化。」

**它的解法**：
1. 只把**蒙版附近的区域裁出来**送去编辑
2. 结果回来后在**环带上做色彩统计匹配**
3. 再以**羽化蒙版作为 alpha** 贴回原图

### 3.2 编辑分辨率有上限

> 要求宽高是 16 的倍数、比例 ≤ 3:1、最大 **3840×2160**。

**解法**：裁剪后再编辑，**保留原图全分辨率**。

### 3.3 调色不该交给模型

> 「参数化 GPU 管线**无损、实时、零成本**，参数随时可改，不必重新生成。」

## 四、⭐ 四条产品原则（原文）

> - **建议是起点而非结果**：AI 给出的每一项都要落成用户能看见、能改、能关掉的图层
> - **照片优先**：界面颜色和装饰不能干扰对照片色彩的判断
> - **本地优先**：能在浏览器内完成的处理绝不外发，外发前让用户知道发给了谁
> - **可逆**：任何操作都能撤销、关闭或对比原图

## 五、和我们什么关系

### 5.1 不是竞品，是上下游

| | 它 | 我们 |
|---|---|---|
| 阶段 | **拍完之后** | **拍之前 + 拍的时候** |
| 输入 | 一张照片 | 一句话 / 一个地点 / 一个人 |
| AI 干什么 | 看图告诉你**怎么修** | 算光线、给方案、排分镜、说口令 |
| 输出 | 修好的图 | 让你去拍 |

### 5.2 ⭐ 我们的「后期交接单」正好是它缺的上下文

我们做的那张交接单写着：

```
这组要什么       秋天小清新，暖但不是假的暖，皮肤要真实
拍的时候什么条件  黄金 16:26-17:05 · 逆光 · 云量12% · 85mm f/1.8
已经知道要修的    脸部逆光偏暗，提亮但别丢轮廓
客户提过的要求    不要太磨皮（小林第3次说了）
修图顺序         修瑕疵→限动态范围→磨皮→肤色→调色
```

**它没有。它只能「看图猜你要什么」。**

## 六、已经融进我们原型的部分

### 6.1 新文件：`docs/prototypes/canvas/image-editor-v2.html`

**在原修图原型（纯参数式）基础上，加了它的核心机制。**

| 加的东西 | 来源 |
|---|---|
| **三栏布局**（左建议+图层 / 中画布 / 右参数） | 它的编辑器结构 |
| **AI 建议 → 采纳 → 图层** | 它的「建议是起点而非结果」 |
| 建议卡显示：**标题 / 为什么 / 来源（读图推的·构图推算）/ 只影响哪里** | 它的建议 UI |
| 建议三态：待采纳（虚线）→ 已采纳（绿边）→ 已忽略（灰 + 可恢复） | 它的采纳/忽略 |
| **图层列表**：可开关（◉/○）、可删除、显示区域 | 它的图层面板 |
| **区域限定**：全图 / 矩形 / 椭圆 / 线性渐变 / 画笔 | 它的区域模型 |
| **按住 `\` 对比原图** | 它的对比 |
| **局部遮罩可视化**（椭圆虚线圈出脸部） | 它的蒙版 |
| **照片优先**：界面全部中性灰，只有一处强调色且不在画布附近 | 它的原则 |

**保留了原型的「页面与节点是兄弟」能力对照栏** —— 这是那一页存在的意义。

### 6.2 关键设计：建议 → 图层的数据流

```js
// 建议 = 一份「待采纳的参数」
{ id, kind, title, why, src, region, params, levels, crop, state }

// 采纳 → 推入图层数组
adopt(id) → LAYERS.push({...})

// 图层可关 / 可删
toggleLayer(i)  // 关掉不影响原图
delLayer(i)     // 删掉自动退回「已忽略」，能恢复

// 合成 = 图层叠加 + 手动参数
compose() → 曝光相加、对比相乘、色阶取最后一个
```

**采纳了还能改、能关、能删、能恢复** —— 这就是「建议不是结果」。

## 七、还没做的（值得做但本轮没做）

| # | 内容 | 说明 |
|---|---|---|
| 1 | **局部重绘（inpaint）** | 它的核心能力之一，我们完全没有 |
| 2 | **裁剪 + 水平校正** | 我们只有「拉直」，没有裁剪框 |
| 3 | **撤销 / 重做** | 只有「全部重置」 |
| 4 | **高光/阴影/清晰度/锐化** | 参数只有曝光/对比/饱和/色温/色阶 |
| 5 | **区域限定真的生效** | 现在只是 UI 占位，参数还是全图 |
| 6 | **蒙版羽化** | 只有形状，没有羽化参数 |
| 7 | **导出全分辨率** | 原型没有导出 |

## 八、一句总结

> **它是「拍完之后」的工具，我们是「拍之前」的工具。**
> **它缺的是「你拍的时候怎么想的」——那正是我们手里的东西。**
