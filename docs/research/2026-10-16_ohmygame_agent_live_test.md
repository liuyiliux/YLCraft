### 2.1 🔴 五个值得抄的报告习惯

| # | 它的做法 | 为什么好 |
| --- | --- | --- |
| 1 | **带文件路径 + 节点 id** | 用户能自己去核对，不用信它 |
| 2 | **主动交代"原有 image 节点保留未动"** | 预防"它是不是乱删东西了"的疑虑 |
| 3 | 🔴 **主动声明"未做任何图片生成"** | **明确说自己没做什么** |
| 4 | 🔴 **跑 `canvas_check` 并报"校验通过"** | 自检有工具、有据可查 |
| 5 | **`更改了 2 个文件 +14 -0`** | 像 git diff，可展开 |

> **第 3 条最值得学** —— 我们实测抓到的 YLCraft 问题是
> 「点确认不生效但界面不解释」；
> **而这里是 Agent 主动交代边界。**

### 2.2 它写的内容本身就专业

Agent 生成的"一致性提示词说明"里包含（原文要点）：

- **为什么要固定**：模型对措辞高度敏感，一个角色只换个说法（如"女孩"改成"暗红发色"），发型/脸型/服装细节可能整体漂移 → 把核心特征写成**一段固定文本**，在所有节点原样复用
- **建议包含的六类要素**：主体身份 / 外观特征 / 风格与媒介 / 光照与色彩 / 构图与视角约束 / **负面约束**
- **负面约束举例**：不要出现的元素，如**画外手指、文字水印、多余人物**
- **使用规则**：① 固定段原样复制，只在末尾追加重描述本次差异 ② **顺序保持稳定**（主体→外观→风格→光照→构图）③ 用具体名词和数值 ④ **每轮只改一个变量** ⑤ 放在 text/document 节点，用其他节点的 `promptSource` 引用它
- **常见陷阱**：各节点各写一版"意思相同"的描述；固定段过长淹没关键特征（**建议 3–6 句**）

> 💡 **这跟我们调研到的所有"一致性"结论完全对上**：
> LTX 的 Elements、Dashtoon 的角色映射、V2EX 用户自发的「先把角色固化成参考图」——
> **业界共识就是"固定段 + 原样复用 + 每轮只改一个变量"**。

## 三、🔴 「每个工作区都是文件」—— 实测验证

Agent 报告里提到的路径**真实存在**：

```
%APPDATA%\ohmygame\data\projects\3514b17c-.../workspace/canvas/
  ├── assets/
  ├── index.json
  ├── jobs...
  ├── boards/9457bb79-....json      ← Agent 新建的节点
  ├── edits...
  └── schema...
```

`boards/*.json` 实际内容（节选）：

```jsonc
{
  "version": 1,
  "viewport": { "width": 1280, "height": 720 },
  "nodes": [
    { "id": "45c03fcb-…", "type": "image",
      "data": { "prompt": "", "resolution": "1K", "aspectRatio": "1:1", "images": [] } },
    { "id": "b1f7c2a4-…", "type": "text",
      "data": { "text": "# 一致性提示词（Consistency Prompt）说明…", "instruction": "" },
      "title": "一致性提示词说明" }
  ]
}
```

**结论：完全属实。** 画布就是 JSON 文件，Agent 直接读写它，前端渲染同一份。
**这就是"Agent 与可视化编辑器读写同一批文件"的实际形态。**

> 💡 **对我们的意义**：
> 我们的画布数据在 Postgres 里，Agent 通过工具读写。
> **如果改成"文件 + schema"，Agent 与前端就能共用一份，不用担心"Agent 改了前端看不到"。**
> —— 这是 OhMyGame 最值得学的一条架构决策。

## 六、对我们的三条实操结论

1. 🔴 **我们的画布数据在 Postgres，Agent 通过工具读写** ——
   若改成"文件 + schema"（或至少**保证 Agent 改完前端能立刻看到**），
   可消除一类"Agent 说改了、界面没变"的问题。

2. 🔴 **报告要带"我没做什么"** ——
   OhMyGame 的 Agent 主动说「**未做任何图片生成**」。
   我们的 Agent 实测报的是「返回字段：success、normalized_request、visual_plan」——
   **方向完全相反。**

3. 🔴 **一致性提示词的行业标准写法已确认**：
   **固定段 + 原样复用 + 每轮只改一个变量 + 固定顺序 + 必须有负面约束**。
   我们的角色视觉档案应该按这个结构组织。
