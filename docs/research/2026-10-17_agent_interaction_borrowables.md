# 大白话：智能体（Agent）这块能借鉴什么（2026-10-17）

> 补之前漏掉的一块。之前一直在讲输入框和画布，**Agent 本身的设计说得太少。**
> 本文只讲**我亲眼看到过的**（OhMyGame 跑通 / BeefTV 源码 / ArtCraft 界面），
> 并逐条对照我们现在的样子。

---

## 一、先说我们自己的 Agent 现在有什么

从 `frontend/src/pages/agent/index.tsx`（4,458 行）实读：

| 能力 | 状态 |
| --- | --- |
| 智能体选择器 | ✅ `placeholder="选择智能体"` |
| 模型选择器 | ✅ `placeholder="默认模型"` |
| 迭代预算 | ✅ 「达到上限后自动总结已完成和下一步」 |
| 工具权限配置 | ✅ 可勾选允许调用的工具 |
| 技能绑定 | ✅ 配置层能绑 |
| 步骤折叠 | ✅ `step_type` → 中文标签映射（匹配 Skill / 模型响应 / 消耗模型…） |
| 失败建议 | ✅ `buildStepFailureAdvice` 会给排查方向 |
| **输入框传附件** | ❌ 没有 |
| **`@` 引用已有素材** | ❌ 没有 |
| **对话里临时选技能** | ❌ 没有（技能只能在配置层绑死） |
| **工具结果可读展示** | ❌ 被压成「返回字段：url、local_path…」 |
| **错误说人话** | ❌ 实测甩过 SQL |

**结论：我们的 Agent「配置」很强，「对话」很弱。**
配置项比 BeefTV 还多（迭代预算、工具权限我们都有），
但**用户真正在用的那一侧——对话——缺东西**。

## 二、🔴 最值钱的一条：OhMyGame 的「报告格式」

这是我在整个调研里看到的**最好的一份 Agent 报告**。原文（我实测截的）：

> **图片没能生成出来，原因不在画布，而在模型连接配置。** 我已把配置修好，但需要你重启应用后才生效。
>
> **排查过程**
> - 节点 45c03fcb-… 已设为你的提示词、agnes-image-2.1-flash、1K、1:1。
> - 第一次生成报 `Invalid models.json; fix it before editing models`。
> - 检查 pi-agent/models.json：JSON 本身合法，但 agnes 系列模型被注册成了纯对话模型…
> - 检查 data/model-visibility.json：custom-agnes-01 条目存在，但 models 是空数组…
>
> **已做的修改**
> - data/model-visibility.json（原文件已备份为 .bak）：…
>
> **需要你操作**
> - 请重启 OhMyGame（model-visibility.json 只在启动时读取一次）。
>
> **另外提醒一句：我改的是全局应用配置，不只是本项目。如果……告诉我，我可以把改动回滚成备份版本。**

### 它做对的 7 件事

| # | 做法 | 为什么重要 |
| --- | --- | --- |
| 1 | 🔴 **第一句先定性**：原因不在画布，而在配置 | 用户不用读完全文才知道"该怪谁" |
| 2 | **排查过程**分点，每点一句结论 | 可复核 |
| 3 | **已做的修改**列文件 + 内容 | 知道它动过什么 |
| 4 | 🔴 **需要你操作**（重启）单独列出 | **明确"卡在哪一步、要谁来做"** |
| 5 | 🔴 **改动规模**：`更改了 5 个文件 +122 -0` | 一眼看出动了多少 |
| 6 | 🔴 **影响范围 + 退路**：「我改的是全局配置…可以回滚成备份版本」 | **主动交代副作用** |
| 7 | 🔴 **能力边界**：「我这个模型不支持读图，没法亲眼核对画面内容」 | **不装懂** |

### 它的另一份报告（更狠的那次）

> **模型本身可用**：我直接调用 POST … 返回 200，并拿到了真实图片（1.19 MB PNG）
> **应用的图像适配器与 agnes 不兼容**：会**硬编码发送** `quality:"medium"` 和 `output_format:"webp"`…**这两行写在打包代码里，没有任何设置项能关掉**
> 写了一个本地中转 `agnes_shim.js`…**这个中转进程重启电脑就没了**
> **更干净的做法是换一个原生兼容 OpenAI 图像协议的服务**…那样完全不用中转
> **要我现在把中转做成常驻、还是你倾向换服务？**

**这一段的价值：它先证明"上游能用"，再证明"是应用的问题"，最后承认"我的绕行方案不干净"，并把选择权交回来。**

## 三、BeefTV 的「工具契约」——21 个操作的写法

它没有把工具写死在代码里，而是**从后端注册表动态生成**。21 个 op 里有六条设计原则：

| # | 原则 | 原文证据 |
| --- | --- | --- |
| 1 | 🔴 **成本边界写进工具描述** | 反复出现「**不生成、不扣费**」「**只登记提议**」 |
| 2 | 🔴 **读写分离** | `canvas.generation.propose` 标 **ReadOnly** —— 提议无副作用 |
| 3 | **乐观锁** | 写操作全带 **revision CAS** |
| 4 | **幂等** | 「重复连接**幂等返回**」「幂等回执」 |
| 5 | **批量要么全成要么全败** | 「**未知行整批拒绝**」 |
| 6 | **服务端分配 ID** | 「行 ID 与镜号**由服务端分配**」 |

> 💡 **第 1 条最该抄**：Agent 从工具签名就知道这一步花不花钱，
> 不用"赌"。我们的工具有 cost 级别（`costly: '消耗模型'`），
> 但**没写在给模型看的描述里**，只在 UI 上标。

## 四、BeefTV 的「对话层安全」——三条硬约束

从 `agent-host/operation-bridge.mjs` 源码读到：

| 机制 | 作用 |
| --- | --- |
| 🔴 `turn_intent_changed` | **用户中途改需求 → 阻止写入，要求先重读** |
| `rebaseOntoWriteChain` | 并发写**重基到最新版本**（不覆盖别人刚写的） |
| `request-budget.mjs` | **每轮工具有预算上限**（`spendToolStep` / `budgetError`） |
| `operation_id_reused_with_different_payload` | 同一 operationId 换了载荷 → 报错 |

> 💡 **`turn_intent_changed` 这条我们完全没有**。
> 用户说"改标题"改到一半又说"算了先改别的"，
> 我们的 Agent 可能还在按旧意图写。

## 五、BeefTV 的「Agent 面板」布局

实测截图看到的：

```
┌────────────────────────┬──────────────────────┐
│                        │ BeefTV Agent  [▣][↻][✕]│
│      画布               │ ┌──────────────────┐ │
│   双击生成节点           │ │错误+就地重试按钮  │ │
│                        │ └──────────────────┘ │
│                        │ ┌──────────────────┐ │
│                        │ │描述你的想法，或用 @…│ │
│                        │ │📎 ✦ 画布素材       │ │
│                        │ │[模型▾][当前画布▾][↑]│ │
│                        │ └──────────────────┘ │
└────────────────────────┴──────────────────────┘
```

**四个细节：**
1. 🔴 **面板可拖宽**（`调整 Agent 宽度`）
2. 🔴 **`当前画布` scope 选择器** —— 明确 Agent 现在操作哪个对象
3. 🔴 **`📎 附件` + `✦ 画布素材` 两个入口分开** —— 本地文件 vs 已有素材
4. 🔴 ** `选择技能` 在输入框层** —— 用户能临时换技能，不用去配置页

> 我们的 composer 只有：智能体选择 + 模型选择 + 文本框 + 发送。
> **没有 scope 提示、没有附件、没有技能快选。**

## 六、OhMyGame 的「工具调用展示」

实测看到的：

```
使用了多个 powershell 工具          ← 折叠
Image models require a specific imageApi…   ← 可展开看它当时在想什么
工作 了 4 分 2 秒                    ← 运行时长
更改了 5 个文件  +122  -0            ← 改动规模（可点开）
```

**三条：**
1. **工具调用折叠**（我们也有）
2. 🔴 **中间推理可展开**（我们只显示"模型响应"，看不到它在想什么）
3. 🔴 **改动规模常驻**（`+122 -0`），不是藏在详情里

## 七、⚠️ 反例：BeefTV 的 403

> `Request failed with status code 403`

**它把原始 HTTP 状态码直接甩给用户**，没说"密钥无效"、"额度不足"还是"模型不支持"。

**而它其实有 `问题诊断` 按钮**，只是这个即时错误没走那条路。

**我们更糟**——实测甩过 SQL。

## 八、对照表：Agent 这块我们该补什么

| 优先级 | 补什么 | 来源 | 为什么 |
| --- | --- | --- | --- |
| **P0** | 🔴 **报告格式四段式**（定性 → 过程 → 改了什么 → 还要你做什么）+ 改动规模 + 影响范围 + 能力边界 | OhMyGame 实测 | 这是**最直接提升信任**的一条，且不需要改架构 |
| **P0** | 🔴 **错误说人话**（不甩 SQL / 不甩状态码） | OhMyGame 正例 vs BeefTV 反例 | 现在就是坏的 |
| **P1** | 🔴 **工具描述里写成本边界** | BeefTV 21 op | 让模型自己知道哪步花钱 |
| **P1** | 🔴 **`turn_intent_changed`**：用户改主意就停写重读 | BeefTV 源码 | 防"按旧意图继续改" |
| **P1** | **工具结果可读展示**（不再压成"返回字段：url"） | BeefTV 有界面 / 我们被压缩 | 用户看不懂工具干了啥 |
| **P2** | **composer 加 scope 提示 + 附件 + 技能快选** | BeefTV 面板 | 一次说清"改哪儿" |
| **P2** | **面板可拖宽** | BeefTV | 长报告要空间 |
| **P3** | **读写分离 / ReadOnly 轮次** | BeefTV | 复杂，但值得规划 |

## 九、一句话

**智能体这块可借鉴的比输入框多得多。**

输入框缺附件只是"少了个入口"，
**而报告格式、错误人话、成本边界、改主意就停——这些是"Agent 值不值得信"的根本。**

而且**第一条（报告格式）几乎不用改架构**，就是改提示词 + 改渲染。
这是性价比最高的一条。
