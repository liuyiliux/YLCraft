### 1.3 ComfyUI 工作流市场（一手）

页面原话：「**由全球创作者基于 COMFYUI 打造，满足真实行业需求**」

分类实抓：`ComfyUI 热门内容` / `精选工具` / `图像设计` / `全部工作流`

**热门工作流样例（标题即产品）**：
- 全能视频X-编辑视频-官方稳定版
- **一键生成多角色对话动画片，QWEN3-TTS + LTX-2 工作流！**
- **AI唱歌数字人对口型 RCM + INFINITE TALK**
- **QWEN3VL + NEXT SCENE（自动分镜）+ 视频生成 V2 版**
- **SEEDANCE2.0 全能参考视频（创建 ID）**
- 最强动漫视频生成 DASIWAV9（支持单图/首尾帧/三图首尾帧）
- 电商详情页生成 V3（可指定语言）直出 10 张

**模式特征**：**工作流本身就是商品** —— 创作者发布、用户直接运行、创作者拿收益分成。

## 三、对我们的意义（**已按"ComfyUI 只是占位"更正**）

> ⚠️ 所有者更正（2026-10-15）：**本项目的 ComfyUI 工作流尚未真正实现，目前只是占位。**
> 因此下面第一条**不是"接一个节点就行"**，而是"要先判断值不值得做"。

### 3.1 ComfyUI 相关 —— 需要先决策，不是直接接

我一开始的判断（"RunningHub 可以当作一个节点接进我们的多节点调度"）**说早了**。

实际情况是：
- 我们后端**有**完整的 ComfyUI API 表面（`backend/app/api/v1/comfyui.py`：
  workflows / models / loras / controlnets / progress / queue / **nodes** / templates /
  presets / tasks / generate），节点模型带 `server_url`、`capabilities`、
  `max_resolution`、`priority`、可设默认。
- **但工作流本身没有真实现**（所有者确认）。

**所以真正的问题是**：我们要不要**自己实现 ComfyUI 工作流**？
如果 RunningHub 已经把"工作流市场"做成熟了，**也许不该重造** ——
可以选"接外部平台"而不是"自建工作流编辑器"。

**这个决策我给不了，需要你定。** 两条路的取舍：

| 路线 | 好处 | 代价 |
| --- | --- | --- |
| 自建 ComfyUI 工作流 | 完全可控、和资产中枢深度打通 | 工作量大；要维护节点/模型/依赖；生态比不过平台 |
| 接 RunningHub 这类平台 | 立刻有海量现成工作流；无需维护 GPU | 依赖第三方、成本按秒/会员计、数据出境、被平台绑定 |

### 3.2 RHSTORY 证明"漫剧链路"是真实需求

RHSTORY 的功能点（文案→提示词 / 批量资产 / 批量分镜）**和我们的漫画链路一一对应**。
结合剪映 Hub，这已经是**第二个**把"批量资产 + 分镜 + 提示词"做成一站式的产品。

**结论不变**：资产注入和批量生成是**行业基线**，不是加分项。

### 3.3 仙宫云解决了我们一个**具体的历史卡点**

`docs/README.md` 记录：`unirig-local-rigging-service` 的 Phase 2+ 被暂缓，
原因是「**当前机器 6GB 显存，低于上游 8GB 最低要求，用户暂不购买设备**」。

**仙宫云正是这个问题的现成答案**：按量计费租 GPU，不用买设备就能跑
绑骨/3D 这类吃显存的任务。

**待核实**：具体 GPU 型号价格、是否支持我们的 CUDA 版本、数据传输成本。
**但方向上是通的** —— 这比"等买设备"现实得多。

### 3.4 关于邀请码

- 邀请码本身只影响**你注册时他拿返利**，**不影响平台能力判断**。
- 我上一轮因为"带邀请码"就把它归为"推广页跳过"，**这个推理是错的** ——
  推广链接和平台质量是两件事。
