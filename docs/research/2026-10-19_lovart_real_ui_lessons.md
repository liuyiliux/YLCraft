# 从 Lovart 四张实拍学到的（2026-10-19）

> 你给了四张 Lovart 真实界面：Agent 设置页 / 设计委托 / 项目列表 / 画布。
> **其中一张直接推翻了我刚做的 Agent 报告设计。**

---

## 一、🔴 最重要的纠正：Lovart 的报告不是"自检"，是"设计解说"

### 我做的（v10）

```
做好了，新图放在右边。原图保留，磨皮没过，光位跟着原图走。
[原图保留] [脸没变形] [光位一致] [背景可再暗一点]
```

**这是"我验证了什么"。**

### Lovart 实际做的

```
海报已生成完成！

海报特点：
· 品牌展示：顶部醒目位置展示"奉天逸洋"品牌名，采用传统书法风格
· 产品呈现：中央展示金黄诱人的朝牌，表面烤痕和黑芝麻清晰可见
· 文化元素：融入传统烤炉、祥云纹样、水墨山水背景，体现民间面食文化底蕴
· 辅助信息："奉天朝牌（传统烤饼）"、"匠心手作"、"地道美味"等文案增强品牌感
· 食材展示：周围摆放黑芝麻、面粉等原料，突出手工制作

海报尺寸为 1792×2400 像素，适合用于店铺宣传、社交媒体推广或印刷使用。
如需调整文案内容、配色风格或添加其他信息，告诉我。
```

**这是"我怎么设计的、为什么这么设计"。**

### 差别在哪

| | 我的（验证式） | Lovart 的（解说式） |
| --- | --- | --- |
| 回答的问题 | "你确定做好了吗" | 🔴 **"它长什么样、为什么这样"** |
| 用户拿到什么 | 一个保证 | **一段能拿去跟人解释的东西** |
| 谁来判断好坏 | 我声明 | **用户看成品** |
| 结尾 | 撤销/版本差异按钮 | **"要改哪儿告诉我"** |

### 为什么 Lovart 对

**创作类产出，用户不需要"我验证过了"，需要"我知道你做了什么、好看在哪"。**

而且那段话**能直接拿去用** —— 发给客户、写进提案、贴到小红书上。
"磨皮没过、光位一致"这种话，用户拿去没用。

### 结论

| 位置 | 应该放什么 |
| --- | --- |
| **对话里** | 🔴 **设计解说**（做了什么设计决策 + 尺寸/用途 + 邀请调整） |
| **执行轨迹 / 详情里** | 我验证了什么、没验证什么（技术细节） |
| **不要** | 把"自检 chip"放在对话主位 |

> 我上一轮查的 IUI '26 分类法没错 ——「推理透明」「不确定性」确实是独立类别。
> **但那是给"操作类 agent"的分类法（点按钮、填表）。创作类不一样。**

## 二、Lovart 有而我没有的四个东西

### 1. Agent 记忆 + 自进化技能

设置页里「**我学会的**」：

```
记忆   自进化技能   进化日志
```

「**我能主动做的**」里有：

| 能力 | 说明 |
| --- | --- |
| **自动更新记忆** | 说过的偏好、传过的作品集，Arti 都记着，不用再交代 |
| **自进化技能** | 你做顺手的流程，Arti 会存成技能，用得上的主动提给你 |

🔴 **这条对我们特别重要。**

我们一直在讨论"模板"，但 Lovart 的做法是：**你不用自己去建模板，你做着做着，它自己存下来**。

```
你做第 3 次类似的修图
  ↓
Agent：这个流程你又做了一遍，要我存成技能吗？
  ↓
下次：「要不要用上次那个 Cos 精修流程」
```

**这比"新建画布时选模板"主动得多。**

### 2. Agent 能主动干活（带开关）

| 主动能力 | 说明 |
| --- | --- |
| **画布巡检** | 定期翻看你的画布，发现问题提前告诉你 |
| **设计调研** | 新项目？全网找参考，整理成报告 |
| **反馈改稿** | 同事/甲方在画布上留的意见，一键发给它，直接改 |

**"画布巡检"这一条我们完全可以做** —— 我们有 `WorkflowTrace`、有节点状态，
可以做到"你的第 5 镜角色和前面不一致"、"这两个节点连错了"。

### 3. 设计委托（定时周期任务）

`/schedules` 页面：**「设计委托给 Arti / 长活、慢活、每周都要做的活。定好一次，齐活。」**

- 每日视觉灵感雷达
- 每周电商竞品跟踪
- 每日营销节点筹备

🔴 **这是"模板"之外另一种复用方式：时间维度的复用。**

对我们的映射：
- 「每周更新角色服装参考」
- 「每月检查全片角色一致性」
- 「每天抓一次竞品短剧封面」

### 4. 项目列表用拼图缩略图

一个项目 = **多张图拼在一起**的缩略图，不是单张封面。

含义：**一眼看出这个项目做了多少东西**。
我们现在的项目列表是单图封面，信息量少。

## 五、一个要重新想的问题

我刚把 Agent 报告设计成「✓我确认了 / ⚠我没法确认」两组（上一条回复里说的）。

**看到 Lovart 之后，我觉得那个方案要废弃。**

理由：
- 那套是**操作类 agent**的思路（做表格、填表单，要确认没出错）
- 我们是**创作类**（出图、出片，好坏要用户看）
- **创作类的核心不是"我没出错"，是"我做了个什么东西"**

**但"我没法确认"这部分不是全丢** —— 它应该变成**邀请**：

```
如需调整文案内容、配色风格或添加其他信息，告诉我。
```

而不是：

```
⚠ 我没法确认效果
```

**前者是服务，后者是免责。** 这是关键差别。
