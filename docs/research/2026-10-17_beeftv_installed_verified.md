## 〇、先纠正我自己的一个错误

上一轮我说「文章说 BeefTV 是 Wails 桌面软件是**错的**，实际是 Docker Web 服务」——
**这个判断我错了。**

`QUICKSTART.md` 明确写了**两种形态**：

> 「**构建桌面版**：环境要求 Go 1.25、Bun，以及 Wails 所需系统组件。
> Windows 输出 `backend\cmd\desktop\build\bin\BeefTV.exe`」
> 「首次打开后直接进入本地工作区，**不需要注册或登录**」

**所以：桌面版（Wails）是主形态，Docker 是服务端形态。文章没说错，是我看漏了。**

## 一、怎么跑起来的（踩了 3 个坑）

### 坑 1：Docker 守护进程没启动
`docker --version` 有，但 `docker info` 连不上。
Docker Desktop 装在 `F:\Docker\Docker desktop.exe`（不是默认路径）。

### 坑 2：🔴 阿里云镜像源返回 403，挡死所有官方镜像
```
unexpected status from HEAD request to https://zd2qonk0.mirror.aliyuncs.com/... : 403 Forbidden
```
改了 `~/.docker/daemon.json` 清空 `registry-mirrors`**也没生效**
（`docker info` 仍显示该镜像；重启 Docker Desktop + `wsl --shutdown` 都没用
—— 说明 Docker Desktop 在别处注入，我没找到那个位置）。

**绕过办法**：用能通的镜像站拉取后**打本地 tag**：
```powershell
docker pull docker.1ms.run/library/alpine:3.22
docker tag  docker.1ms.run/library/alpine:3.22 alpine:3.22
# 同理处理 nginx:1.27-alpine / oven/bun:1.3.13 / golang:1.25-alpine
```

### 坑 3：`# syntax=docker/dockerfile:1.7` 也要走镜像
删掉两个 Dockerfile 首行的 `# syntax=` 指令即可（本地副本，不动上游）。

**最终结果**：`docker compose up -d` 后 backend + web 都 healthy，
`http://localhost:3000` 返回 200。

> 🔴 **发现：BeefTV 后端二进制叫 `infinite-canvas-backend`**
> —— 说明 **BeefTV 与 Infinite Canvas 同源**（同一个代码基）。

### 3.2 🔴 添加节点菜单

**创作节点**：文本 / 图片 / 视频 / 音频 / **导演台** /
智能剪辑 `正在开发` / 逐帧拉片 `正在开发` / 脚本 `正在开发`

**导入资源**：上传 / **从生成历史选择** / 素材库

三个关键设计：

| # | 设计 | 为什么好 |
| --- | --- | --- |
| 1 | 🔴 **「正在开发」明确标注** | **不假装有** |
| 2 | 🔴 **「导演台」是节点类型，不是独立页面** | 一个画布可放多个导演台并连线 |
| 3 | 🔴 **「从生成历史选择」是一等公民** | 历史产出直接能当输入 |

> **第 2 点对我们冲击最大**：我们把 Previs 做成独立页面，
> 它是**画布上的一种节点** —— 意味着它可以被连线、被复用、和图文节点混排。

### 四个值得抄的点

| # | 设计 | 说明 |
| --- | --- | --- |
| 1 | 🔴 **默认模型按用途分四类** | 生图 / 视频 / 文本 / **助手** |
| 2 | 🔴 **「助手模型」可「跟随默认文本模型」** | 少配一次 |
| 3 | 🔴 **`● 已保存，尚未测试`** | **原生区分"已配置"和"已验证"** —— 正是我 skill 里的 L1/L2 |
| 4 | **`模型目录地址` 直接显示** | `https://…/v1/models`，排错时能直接点开验 |

### 添加服务的向导（两步）

**第一步**：选择服务商 —— **「第三方模型服务（OpenAI 兼容 API · 中转服务）」排在第一位**，
另有 OpenAI / Google Gemini / **火山方舟（文本·即梦图片·Seedance 视频）**。

字段：连接名称 / API Key / 服务地址 + `高级设置`。

> 🔴 两句提示写得很好：
> 「用户可以自行添加第三方模型服务，**但是 BeefTV 无法确保所有第三方模型服务的兼容性**」
> 「**选择无鉴权协议（例如 Ollama）后可以留空。读取模型目录仍需要密钥。**」

**第二步**：选择模型 —— 按 `全部/文本/图片/视频/音频` 筛选，
每个模型标 `文本 · 未测试`，右上 `已选 N 个`，底部 `保存后，可在创作页选择这些模型`。

## 五、⚠️ 一个反面案例：错误信息不说人话

我配置好模型后让 Agent 干活，它返回：

> **`Request failed with status code 403`**

**这就是我一直在批判的"原始错误码直接甩给用户"** ——
它没有说「密钥无效」「额度不足」还是「该模型不支持此接口」。

对照：
- **OhMyGame** 的 Agent 会分层排查并写清"原因不在画布，而在配置"
- **ArtCraft** 有 `问题诊断`
- **BeefTV** 这里只给了 `403`

> **但 BeefTV 有 `问题诊断` 按钮**，只是这个即时错误没走那条路。

## 六、BeefTV vs 我们 vs 其他家

| 维度 | BeefTV | YLCraft |
| --- | --- | --- |
| 画布节点类型 | 文本/图片/视频/音频/**导演台** | 更多（含平台搜索、成图等） |
| 连线关系类型 | 有（可隐藏） | ✅ **更细**（reference/context/generation/sequence + 端口校验 + 循环检测） |
| 版本记录 | ✅ | ❌ |
| 生成历史 | ✅（还是输入源） | ⚠️ 有事件日志，非"可选为输入" |
| 小地图 | ✅ | ❌ |
| 网格吸附 / 自动整理 | ✅ / ✅ | ❌ / ❌ |
| `@` 引用素材 | ✅ | ❌（`ChatRequest` 无字段） |
| 模型四类默认 | ✅ | ⚠️ 有 provider，无"助手模型跟随文本" |
| 保存状态写明"本地" | ✅ | ⚠️ 只写"已保存" |
| 错误说人话 | ⚠️ 此处是 403 | ❌ 实测甩 SQL |

> **结论**：**我们的连线内核更强，但"用起来的顺手工具"全面落后。**
