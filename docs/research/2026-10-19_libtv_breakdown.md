# LibTV 拆解：比 Lovart 更接近我们的对标（2026-10-19）

> 来源：LibLib 官方《LibTV 使用指南》飞书文档（用户提供链接，已读正文 + 45 条用户评论）
> <https://resonate.feishu.cn/wiki/Loxfw6XHziYRk0kKzdjcFfp9nhb>
> **结论：LibTV = 无限画布 + 五类节点 + 工作流 + 视频/音频生成 + Agent。
> 这就是我们想做的「漫剧模式」，而且它把坑都踩过了。**

---

## 一、它是什么

| 维度 | LibTV | Lovart |
| --- | --- | --- |
| 画布 | **无限画布（节点式）** | 无限画布（自由摆放） |
| 节点 | 🔴 **5 类节点 + 连线 + 打组** | ❌ 无节点 |
| 内容类型 | 图 / **视频** / **音频** / 脚本 | 图 / 视频 |
| 工作流 | ✅ **有，可整组重跑** | ❌ 无 |
| Agent | 有（可接 Skills） | 有（Arti） |
| 目标用户 | **短剧/漫剧/视频创作** | 电商/设计/海报 |

🔴 **LibTV 是"漫剧模式"的活样本。** 我们之前讨论的"agent + 工作流搭不搭"，它给了部分答案：
**能共存，但用户门槛很高**（下面有证据）。

---

## 二、五大基础节点（官方定义）

> 「无限画布是我们创作的主战场」
> - **新建节点**：支持 **文本、图片、视频、音频、脚本** 5 种基本节点
> - **节点编辑**：对节点进行**修改、删除、复用**，以及**不同节点的联系**

| 节点 | 官方说明 |
| --- | --- |
| 📝 **文本节点** | 承载、展示文本信息，来源可以是用户手动输入、模型生成 |
| 🖼️ **图片节点** | 生成/承载图片 |
| 🎥 **视频节点** | 生成视频 |
| 🎵 **音频节点** | **文本生成音乐、音效，以及文字转语音** |
| 🎬 **脚本节点** | 承载分镜脚本（有新版/旧版 Beta） |

**新建方式**：画布空白处**双击** → 弹出「添加节点」菜单
→ `文本 / 图片 / 视频 / 音频 / 脚本 Beta` + `添加资源：上传 / 从图库选择`

**支持直接拖入**：图片、视频、音频文件拖到画布即成节点。

> 🔴 **对照我们**：我们规划的节点是 `文本/图片/LLM/生图/批量生图/图片处理/搜索/素材`，
> **缺视频节点、缺音频节点、缺脚本节点**。而 LibTV 说这三类是"基本节点"。

---

## 三、🔴 底部快捷创建条（这个设计很关键）

画布底部常驻一排快捷入口：

```
[故事脚本生成]  [角色三视图]  [首帧图生视频]  [音频生视频]
```

**它的意义**：用户不用先想"我要什么节点"，直接点一个**任务**。

> 这跟我们"模板 = 预连好的节点图"是同一个思路，
> 但**入口形态不同**：我们放在"新建画布时选"，它放在**画布底部随时可点**。

---

## 四、🔴 工作流：不是"画节点"，是"打组重跑"

官方对工作流的说明里，最核心的是一条：

| 功能 | 简述 |
| --- | --- |
| **整组执行** | **对已打组的、且具备前后逻辑关系的工作流，点击后可以进行全部的重新执行。** |

截图说明：**「修改角色设定与视频动态提示词后，整组自动执行」**

🔴 **这解决了我们纠结的"工作流门槛"问题：**

```
用户看到的：  一堆节点 → 选中 → 打组 → 改一下 → 点「整组执行」
用户不理解的：端口、依赖顺序、执行轨迹
```

**用户不需要懂 DAG，只需要懂"这几个是一组，改了要一起重跑"。**

> 💡 我们的 v6 节点图是"让用户看懂连线"，LibTV 是"让用户组起来重跑"。
> **后者门槛低得多。**

## 五、Slash 快捷功能（漫剧核心能力，6 个）

| 功能 | 说明 | 对我们的价值 |
| --- | --- | --- |
| 💖 **多机位九宫格** | 一张图 → 9 个机位 | 🔴 **漫剧必备**：一场戏多个机位 |
| 💖 **剧情推演四宫格** | 剧情往下推演 4 格 | 🔴 **漫剧必备**：情节发展 |
| 💖 **25宫格连贯分镜** | 一次出 25 格连贯分镜 | 🔴 **漫剧核心**：这就是"分镜墙" |
| **电影级光影矫正** | 光影统一 | 🔴 一致性痛点 |
| 💖 **角色三视图生成** | 角色正面/侧面/背面 | 🔴 **一致性基础** |
| **画面推演-3秒后** | 推演 3 秒后的画面 | 🟡 视频用 |

**六个里有四个带 💖（重点功能），全部是"多图/多角度/连贯"类能力。**

> 🔴 **这印证了一件事**：漫剧用户真正要的不是"生成一张好图"，
> 是**"一次给我 9 个机位 / 25 格连贯分镜 / 角色的三视图"** —— **批量 + 一致性**。

## 六、其它值得抄的功能

### 6.1 智能引用 AutoLink 🔥

节点之间自动建立引用关系（具体机制文档里是视频，没读到细节）。

### 6.2 画布左侧栏：图库文件夹 + 历史记录

| 功能 | 说明 |
| --- | --- |
| **图库文件夹** | 「点击某个文件夹，可以把文件夹中所有内容加载到画布上」<br>例：建一个香水文件夹，把这个香水**不同视图的图全部加载**，方便参考不同视角生成一致性的视频 |
| **历史记录** | LibTV 内生成的**所有图片、视频、音频**都会出现在这里；<br>可**查看、发布到当前画布**；<br>支持**批量下载 / 批量删除 / 批量使用（最多 10 个）** |

🔴 **"文件夹整个加载到画布做一致性参考"这个做法很实** —— 我们的素材库可以直接对应。

### 6.3 小地图导航 / 项目菜单栏 / 个人中心

常规，不展开。

## 七、🔴 45 条用户评论：真实的坑（最有价值）

这些是**付费用户的原话**，比任何功能清单都值钱。

### 7.1 门槛问题（最严重）

> 「你们能不能出一个能完成出一整个视频的教程视频，**看了整个文档，还是迷迷糊糊的，作为新手用户，完全不知道该怎么弄，琢磨了好久**。」

🔴 **有完整文档 + 视频教程，用户还是不会用。** 这是"节点+工作流"路线的天然代价。

### 7.2 一致性是最大痛点

> 「**分镜脚本里咋没有场景图和道具图呀，需要控制一致性**」
> 「用剧本生成脚本的，**脚本里的角色图是空的，非得手动一张张自己上传吗？**」
> 「测了脚本生成分镜，一次是脚本里无角色图，选了风格后生出的**风格完全不一致**（出现了真人画面）；又测了在脚本里放角色三视图的，这回风格一致了，**结果生出来的分镜图跟镜头描述毫无关系**」

### 7.3 节点命名是刚需

> 「图片节点标题不能自己修改吗？**满屏幕图片节点1.2345的**。我要创建好多人物，最后是标题能自己修改，这样后面生出的节点图片都是延伸的」
>
> 官方回复：「**节点名称双击可以修改**」

🔴 **用户找不到"改名字"这个功能** —— 说明**默认命名必须可读**（不能是"图片节点1"）。

### 7.4 Agent 与画布脱节（跟我们直接相关）

> 「龙虾的 Skills 接入 LibTV 的 Agent，我上传图片，给出指令"**用这张图作为首帧生成视频**"，**图片无法被 Lib Agent 识别**，不是图生视频，是文生视频。」

🔴 **Agent 看不到画布上的图** —— 这正是我们 v10/v11 要解决的核心问题（@ 引用素材）。

### 7.5 没有中止

> 「**点错了没办法终止吗**」 → 官方：「目前还没有，但是会尽快上线」

### 7.6 交互手感

> 「无限画布倒是爽，但是**页面放大缩小太难受了**」
> 「快捷键可以改吗 **画布缩放 想要直接能滚轮缩放!!!!!**」

### 7.7 长内容限制

> 「脚本功能有限制？**长一点的剧本（五分钟）**文本输入后，要么**生成空的**，要么就生成**一分钟左右的**」

### 7.8 模板需求（跟我们一样）

> 「**脚本模板挺不错的，可以先做一个适用于 seedance2.0 的模板功能，把参考用的素材空出来，其他的用户复制过去就能用**」

🔴 **这就是"模板 = 预连好的图 + 留空的素材槽"** —— 跟我们 v8 的模板卡设计一致。

### 7.9 其他

- 智能分镜无法 @ 主体库人物
- 图生视频没有"是否生成声音"选项
- 上传本地图片/视频到画布总是不成功
- 扩图需要提示词输入窗口
- 创建的主体怎么删除
- 价格/积分换算争议（SD2 15秒 405 积分）

## 八、对我们设计的直接影响

### 8.1 必须补的节点（我们原规划没有）

| 节点 | 为什么 |
| --- | --- |
| 🔴 **视频节点** | LibTV 说是"基本节点"，我们标"待补" |
| 🔴 **音频节点** | 文本生成音乐/音效/语音，漫剧必需（旁白、BGM） |
| 🔴 **脚本节点** | 承载分镜脚本，漫剧的核心载体 |

### 8.2 必须做的快捷能力（漫剧模式）

| 能力 | 说明 |
| --- | --- |
| **多机位九宫格** | 一场戏 9 个机位 |
| **剧情推演四宫格** | 情节往下推 |
| **25宫格连贯分镜** | 一次出 25 格 |
| **角色三视图生成** | 一致性基础 |
| **电影级光影矫正** | 一致性 |

### 8.3 工作流的正确界面：**打组 + 整组执行**

不是"让用户画节点连线"，是：
```
选中几个节点 → 打组 → 改参数 → 「整组执行」
```

### 8.4 默认命名必须可读

LibTV 用户被"图片节点1、2、3、4、5"逼疯。
**我们的节点默认名要带内容**（如"分镜 3 · 窗边午后"），不是类型+序号。

### 8.5 门槛是我们最大的机会

**LibTV 有完整文档 + 视频教程，用户还是"完全不知道该怎么弄"。**

这正是 `DESIGN.md` 第一条约束「降低门槛」的价值证明 —— **我们的差异化不是功能更多，是让外行看得懂。**

### 8.6 一致性要靠"结构化"解决，不是靠提示词

用户吐槽"放了角色三视图就一致了，但内容又不对了" ——
说明**一致性和内容控制要分开解决**：
- 一致性 → 角色/场景/道具库 + 引用（我们的 Asset Hub）
- 内容控制 → 分镜脚本结构化（我们的分镜表）
