# 各平台交互优点汇总（2026-10-15）

> **目的**：所有者要的是「各平台**交互的优点**」，不是功能清单。
> **方法**：浏览器实抓 + 截图目视。每条注明**一手**（我实际看到界面）/`二手`（他人转述）。
> **用途**：`ylcraft-interaction-quality` 技能的素材库；改 UI 时的参照。

## 〇、一句话总纲

**好的创作工具，把复杂度藏起来，把"用户想要的结果"露出来。**

| 平台 | 它把什么"露"出来 | 它把什么"藏"起来 |
| --- | --- | --- |
| 即梦 | **`/` 技能 + `@` 主体**（直接在输入框里） | 模型参数、工作流 |

| LTX Studio | 4 步（建项目→生图→动画→分镜） | 生成参数 |
| Claude Artifacts | 产物本身（开在对话旁） | 对话流 |

```
┌─────────┬──────────────────────────────────────────────┐
│ 创作     │           你好，今天想要创作什么？              │

│ 主体     │  │ [+] 输入想法、剧本或上传参考，支持 / 使用   │  │
│ ─────── │  │     技能，@ 添加主体，和 Agent 一起创作     │  │
│ 对话     │  │                                        │  │
│  默认创作 │  │ Agent模式▾  自动  技能  灵感搜索  @    🎤 ↑│  │
│ 画布     │  └────────────────────────────────────────┘  │
│  暂无     │  /电影级长镜头运镜 New  /创作分镜 New         │

│         │  /导演 Hot   更多技能 >                      │
└─────────┴──────────────────────────────────────────────┘
```

**左侧只有 6 项导航。** 主区就是**一个输入框** + 一排技能 chip。

### 1.2 值得抄的 7 个交互点

#### ✅ 1）输入框的 placeholder 就是操作说明书

> 原文：「输入想法、剧本或上传参考，支持 **/** 使用技能，**@** 添加主体，和 Agent 一起创作」

**一句话教会用户全部用法，不需要教程。**
（对照：我们产品内**完全没有引导**。）

#### ✅ 2）两个符号 = 两种能力，而且符号就摆在输入框上

- `/` → 使用技能
- `@` → 添加主体（引用资产）

输入框左下角还有对应的**可点击按钮**（`技能`、`@`），
**不会打字的用户也能点**。**符号 + 按钮双通道。**

#### ✅ 3）技能菜单是「原地弹出」，每个技能带一句话说明

点「技能」后，直接在输入框上方弹出列表（**不跳页、不弹模态框**）：

| 技能 | 说明（原文摘录） |
| --- | --- |
| **视频反解** | 「拆解参考视频的**镜头语言、光影色调与声音节奏**，一键…」 |
| **创作分镜** | 「面向 Seedance 视频模型的专业级**虚拟导演与提示词工…**」 |
| **全流程广告片导演** | 「输入你的广告需求或一份 Brief，即可从**创意、脚本、…**」 |
| **剧情短片** | 「视频创作标准工作流程，涵盖从**内容大纲到最终成片的…**」 |
| **电商套图** | 「根据商品信息、核心卖点与电商展示需求…」 |
| **海报设计** | … |

**三条关键设计**：
- **技能名是"任务名"不是"功能名"**（视频反解 / 剧情短片 / 电商套图）
- **每个技能一句话说明**（用户不用点进去猜）
- **标「官方」**，区分官方技能与社区技能

> 对照：我们有 `backend/app/skills/` 下 13 个 skill，
> **但用户在界面上看不到它们、也没有说明**。

#### ✅ 4）技能 chip 带 `New` / `Hot` 标记

`/创作分镜 New`、`/叙事短片导演分镜 Hot`、`/微表情导演 Hot`

**用徽标引导发现新能力**，而不是让用户自己去翻。

#### ✅ 5）「主体」是一级菜单 —— 资产是一等公民

左侧导航里 **`主体`** 与 `创作`/`探索`/`资产` 并列。
点进去是独立的**主体管理页**（网格 + 新建主体 + 筛选/时间/排序）。

而 `@ 添加主体` 就是**在对话里引用这些主体**。

> **这就是所有者说的"在对话框里可以加图片（素材库-资产对应的渲染）"。**
> 即梦把它做成了**核心交互**，不是附加功能。

#### ✅ 6）「Agent 模式」是一个可切换的模式，不是一个独立页面

输入框里 `Agent 模式 ▾` —— 用户可以**在同一个框里**决定要不要 Agent 参与。

> 对照：我们把 Agent 做成了**独立页面**（4458 行）。

#### ✅ 7）作品展示带「查看创作过程」

探索页的作品卡片上有 **`00:48 查看创作过程`** 按钮 ——
**点开能看到这个作品是怎么做出来的。**

> 这与 OpenMontage 的 `▶ REPLAY RUN`（一键回放整个制作过程）是同一个思路。

### 1.3 它的商业设计（顺带观察，非交互）

- 顶部常驻促销条（`备战双11！Seedance 2.5 低至 ￥0.19/秒`）

- `AI短剧创作计划` / `即梦片场` / `创作者成长计划` —— **有短剧扶持计划**

## 二之六、Google Flow TV —— ⭐ 「看得见提示词，一键复用」

> **一手**。2026-10-15 换 VPN 后实测 `labs.google` Flow TV，截图目视。

### ⚠️ 先说清楚：Flow 主体**你这个账号用不了**

| 事实 | 证据 |
| --- | --- |
| VPN 正常 | IP `96.47.161.75`，国家 **US** |
| 账号有历史作品 | 横幅：「您最早的作品即将过期。选择启用即可保留。」 |
| **但 Flow 主体拒绝服务** | 「**Flow 尚未在您所在的国家/地区推出。**」 |

**判断**：这**很可能不是 IP 限制，而是账号地区限制**
（Google 服务常按账号注册地区判定）`推测`。

**但 `Flow TV` 可以进**，而且它本身是个很好的交互设计。

### Flow TV 是什么

**像一个「AI 作品电视台」**：有**频道（CHANNEL）**，按主题组织作品集
（实测某个频道整屏都是"巨大化脚/鞋 ASMR"主题）。

### 🔴 最值得抄的两点

| # | 功能 | 实测 |
| --- | --- | --- |
| 1 | **显示生成提示词** | 有 **`Hide Prompt`** 开关，打开就显示这条视频的原始提示词全文。实测显示：「ASMR video following an ostrich walking on a vast landscape made of Thousands of worn, sun-bleached opened cardboard boxes—crispy edges, deep folds, soft crunches and fibrous tearing underfoot. Against sunrise sky line.」 |
| 2 | 🔴 **`Reuse Prompt`（复用提示词）** | 一个链接按钮，**直接拿这条提示词去创作** |

**并且标注了生成方式**：`Text to Video` + `Veo 3` 两个标签。

> 💡 **这是「提示词参考」做到极致的形态**：
> **看到好作品 → 看它的提示词 → 一键复用去生成。**
>
> 对照我们：有「提示词参考库」（本地同步/双语/多图/筛选/画布集成），
> **但没有"看别人作品的提示词并一键复用"这个闭环。**

### 其他交互细节

- 播放器控制：随机频道 / 上一条 / 暂停 / 下一条 / 循环整个频道 / 静音 / 全屏
- **灯箱视图 ↔ 网格视图**切换
- `CHANNEL` 频道切换（上一个/下一个/查看全部）
- 顶部：搜索框 + `Create with Flow` + Discord + 帮助
- 无音视频时显示「`Unmute to hear audio`」提示

## 六、Claude Artifacts —— 「产物判定 + 指哪改哪」

> **一手**（官方文档全文）。

| 优点 | 原文 |
| --- | --- |
| **明确"什么该变产物"** | 显著自包含（>15 行）/ 用户想编辑复用 / 脱离对话仍成立 / 用户会回头再看 |
| **产物开在对话旁** | 「opens **beside your conversation**」 |
| **产物集中可找回** | 「saved to the Artifacts tab… **find it again from any conversation**」 |
| **指哪改哪** | 「Claude makes the edit **where you marked it**, so you don't have to describe which section you mean」 |
| **错误旁给修复按钮** | 「'**Try fixing with Claude**' button near the error message」 |
| **分支探索** | 编辑早期消息 → 不同版本，「**without losing previous work**」 |

## 七、OpenMontage —— 「对话管沟通，看板管事实」

> **一手**（README 全文）。

| 优点 | 原文 |
| --- | --- |
| **对话 vs 实况分离** | 「Chat tells you what the agent **said**. Backlot shows you what the production is actually **doing**」 |
| **批准是强制的** | 「Human approval gates are **enforced, not suggested**」 |
| **渲染前校验** | 违背 delivery promise → **阻止渲染**，「before wasting GPU time」 |
| **产出后自审** | ffprobe + **抽 4 帧** + 音频分析；失败则**不予展示** |
| **过程可回放** | `▶ REPLAY RUN`，**scrubbable end to end** |
| **零配置看板** | 「**derives everything from the project files the pipeline already writes**」 |
| **决策留理由** | 「alternatives considered, confidence scores, and reasoning」 |

## 八、Google Flow —— ⚠️ 反面教材（改版被骂 60+ 条）

用户原话，说明**改版失败长什么样**：

| 原话 | 教训 |
| --- | --- |
| 「**where are the assets?**」 | 资产找不到了 |
| 「Yes things are **more easily accessible** but it just **feels cluttered**」 | 更好找了但更乱 |
| 「no entiendo la **lógica**」 | 心智模型说不清 |
| 「just **buried in a different spot**」 | 功能被埋 |
| ✅「all the images are **stored under one sidebar now easily accessible**」 | **资产集中是唯一被夸的点** |

**结论：用户骂的不是"丑"，是"找不到"和"不懂逻辑"。**
