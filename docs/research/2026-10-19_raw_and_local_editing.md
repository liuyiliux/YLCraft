# 质疑一：「我们不是做原型吗，巡检检什么」

## 我做了什么

在画布原型里加了个**巡检面板**：扫 6 镜 → 发现 5 个问题 → 分「能小改」和「必须重画」两堆 → 给修法和价格。

## 问题在哪

🔴 **我在上游（真生成）还没通的情况下，做了下游（生成后质检）的界面。**

```
真实链路：  生成 → 巡检 → 修 → 再审 → 交付
                        ↑
                  我在这加了个面板
                  但前面「生成」是假的（demoFill 造数据）
```

**所以这个面板现在只能验证「交互长什么样」，不能验证「这么做对不对」。**

## 更该做的

| 现在 | 更该做 |
| --- | --- |
| 做巡检面板（下游） | 先让**生成 → 出一版 → 你能改**跑通（主链路） |
| 5 个问题写死 | 真扫（但真扫要先有真图） |
| 价格标在界面上 | 先把**哪些操作真的花钱**搞清楚（质疑二） |

## 但巡检面板本身没错

它的价值是**把「怎么给你选修法」这个交互先定下来**：
- 证据（数字）要说
- 「为什么」要说
- 便宜的和必须重画的分开
- 「只能重画」不装

**这部分设计是对的，只是时候不对、价格标错了。**

# 质疑二：🔴「编辑光线什么的不都是调的生图接口吗，没有区别」

**你说对了，这是我的一个实质性错误。**

## 我之前说的

```
只改光照方向   ⚡3
重画这一镜     ⚡14
```

我假定了「改光照」比「重画」便宜 4.7 倍。

## 实际是

**两个都调同一个生图接口（比如 gpt-image-2 或 flux）。**

| | 改光照 | 重画 |
| --- | --- | --- |
| 调哪个接口 | gpt-image-2（inpaint 模式） | gpt-image-2（整图生成） |
| 输入尺寸 | 一样 | 一样 |
| 输出尺寸 | 一样 | 一样 |
| **价格** | 🔴 **一样** | 🔴 **一样** |

**大多数生图 API 按「输出分辨率 × 质量」计费，不按「你改了多少」。**
局部重绘（inpaint）和整图生成，只要输出尺寸相同，价格基本一样。

**所以「⚡3 vs ⚡14」是我编的。**

## 那什么才是真的免费

| 操作 | 技术上怎么做 | 真实成本 |
| --- | --- | --- |
| **裁剪 / 旋转 / 缩放** | Pillow / ffmpeg | ✅ **零** |
| **调色（亮度/对比/饱和/色温）** | 本地矩阵运算 / LUT | ✅ **零** |
| **曲线 / 色阶 / 直方图** | 本地查表（LUT） | ✅ **零** |
| **锐化 / 降噪（基础）** | 本地卷积 | ✅ **零** |
| **RAW 解码** | rawpy（本地） | ✅ **零** |
| 改光照方向 | 生图接口 | 💰 和重画同价 |
| 局部重绘 | 生图接口 | 💰 同上 |
| 整图重画 | 生图接口 | 💰 同上 |

🔴 **唯一真实的分界线：本地能做的 = 免费；必须调模型的 = 花钱。**

**"改光照" 属于后者，我之前把它错当成前者了。**

## 修正后的分层

```
第 1 层：本地运算          → 免费，且不破坏原图（因为是像素级变换）
第 2 层：本地模型（人脸/CLIP）→ 免费，但要显卡，慢
第 3 层：云端生图模型        → 花钱，改多改少都一个价
```

## 那巡检的「修法」还有意义吗

**有，但价值不是省钱，是这三条：**

| 价值 | 说明 |
| --- | --- |
| **① 会不会破坏原图** | 调色不动脸；重画会变脸 |
| **② 要不要重跑下游** | 调色后不用重校脸；重画后必须重新校脸、重检一致性 |
| **③ 可不可逆** | 调色能调回来；重画不能 |

**所以面板该改的是：不写「⚡3 vs ⚡14」，改说「不会变脸 vs 会变脸」「要重新校脸 vs 不用」。**

# 第三件事：RAW 格式能不能做

## 像素蛋糕确实做了

官方说法（[帮助中心](https://wiki.pixcakeai.com/tutorials-guides/258.html)）：

> 像素蛋糕支持直接导入 RAW 格式文件，软件在读取时会自动解析原始数据，
> 导入后可以直接进入精修流程，省去了格式转换这个中间步骤。
>
> 优势：支持主流相机品牌 RAW、**可以在后期调整曝光和白平衡而不损失画质**

支持的格式：
| 品牌 | 扩展名 |
| --- | --- |
| 佳能 | `.CR2` / `.CR3` |
| 尼康 | `.NEF` |
| 索尼 | `.ARW` |
| 富士 | `.RAF` |
| 通用 | `.DNG` |

## 🔴 但先问一句：我们要不要做 RAW

**我们的核心场景是 AI 生成图，生成出来的是 PNG —— 没有 RAW。**

RAW 对我们的价值只有一个：**入口**。

| 谁会给 RAW | 场景 |
| --- | --- |
| **Coser / 摄影师** | 拍好的原片扔进来当参考图 / 直接精修 |
| **电商** | 产品摄影原片 |
| **短剧剧组** | 剧照 |

**所以 RAW 是「专业用户把相机原片接进来」的能力，不是生成链路的必需品。**

## 技术上完全可行

### 方案 A：Python 端（后端）—— 推荐

**rawpy**（LibRaw 的 Python 封装）：

| 项 | 情况 |
| --- | --- |
| 许可 | **MIT** ✅（对我们友好） |
| 平台 | Windows / macOS / Linux 都有 wheel |
| Python | >= 3.9 |
| 依赖体积 | ~1-3 MB |

关键 API：

```python
import rawpy, imageio.v3 as iio

with rawpy.imread('shot.cr3') as raw:
    # ① 16-bit 线性输出 —— 这是 RAW 编辑的核心
    rgb = raw.postprocess(
        gamma=(1,1),        # 不套 gamma → 拿线性数据
        no_auto_bright=True,
        output_bps=16       # 16 位，够调
    )
iio.imwrite('linear.tiff', rgb)
```

🔴 **`gamma=(1,1)` + `output_bps=16` 这两行是关键** ——
拿了线性 16-bit 数据，才能真正像 Lightroom 那样**调曝光不炸高光**。

如果拿 sRGB 8-bit，调曝光就是在已压缩的数据上二次损失。

**还有一个性能技巧：**
```python
thumb = raw.extract_thumb()   # 相机内嵌的 JPEG 缩略图，瞬间出
```
→ **先显示缩略图让你看，全质量在后台算**。不然一张 RAW 解码 2-5 秒，你等不了。

### 方案 B：浏览器端（WASM）

存在 `libraw-wasm` / `rawconvert-wasm` 这类包。

| 优点 | 缺点 |
| --- | --- |
| 不上传原始文件 | WASM 体积大（几 MB） |
| 前端直接预览 | 性能不如后端 |

**建议：后端解码，前端只拿预览和参数。**

## 曲线编辑怎么做

### 本质：一个查找表（LUT）

```
输入值（0~65535） → 曲线 → 输出值（0~65535）
```

**存一张 65536 项的映射表，应用就是数组索引。**
30 万像素的图，numpy 一次索引几毫秒。

### 曲线怎么生成表

```python
import numpy as np
from scipy.interpolate import PchipInterpolator   # 单调三次，不会过冲

def build_lut(points, size=65536):
    """points: [(x,y), ...] 归一化 0~1，必须单调递增"""
    xs = np.array([p[0] for p in points])
    ys = np.array([p[1] for p in points])
    f = PchipInterpolator(xs, ys)          # Pchip 保证不过冲
    t = np.linspace(0, 1, size)
    return np.clip(f(t) * (size-1), 0, size-1).astype(np.uint16)

def apply_lut(img, lut):
    return lut[img]      # img 是 uint16，直接索引
```

🔴 **用 `PchipInterpolator` 不用 `CubicSpline`** ——
普通三次样条会在控制点之间**过冲**（overshoot），曲线会冒出 0-1 之外，
表现为画面莫名的色斑。Pchip 是单调保形的。

### 前端曲线控件

曲线就是 SVG/Canvas 上一个可拖的点列表：

```
输出
1.0 ┤                          ●
    │                     ●
0.5 ┤              ●
    │        ●
    │  ●
0.0 └──┬────┬────┬────┬────┬──→ 输入
      0   0.25 0.5 0.75  1.0
```

拖点 → 重新算 LUT → 重绘预览。**全程本地，零成本，可撤销。**

### 这才是真正"免费且不破坏原图"的编辑

| 能力 | 实现 | 成本 |
| --- | --- | --- |
| 曲线（RGB 合成 / 分通道） | LUT | 0 |
| 色阶（黑白场 + gamma） | LUT | 0 |
| 曝光 | 线性域乘法（所以要先拿线性数据） | 0 |
| 白平衡 | 线性域通道增益 | 0 |
| HSL | 局部 LUT | 0 |
| 直方图 | numpy histogram | 0 |

**这些都不调任何模型。**

# 修正后的结论

## 我们真正该有的三层

```
第 1 层 本地精调（免费，可逆，不破坏原图）
  曲线 / 色阶 / 曝光 / 白平衡 / 裁剪 / 锐化 / RAW 解码
  → 这一层做得越厚，用户越不需要调模型
  → 这才是真正的"省钱"

第 2 层 本地模型（免费但慢）
  人脸相似度 / CLIP 打分 / 简单抠图
  → 用来做巡检的一致性判断

第 3 层 云端生图（花钱，改多改少同价）
  局部重绘 / 改光照 / 整图重画
  → 这一层不要假装能分层定价
```

## 巡检面板要改的地方

| 现在（错的） | 改成 |
| --- | --- |
| 只改光照 ⚡3 / 重画 ⚡14 | 只改光照（**不会变脸**）/ 重画（**会变脸，要重校脸**） |
| 调色 ⚡2 | 调色 **免费**（本地） |
| 扩展画布 ⚡4 | 扩展画布 **要调模型**（和重画同价） |

🔴 **不再用"便宜/贵"分组，改用「本地能修」vs「要调模型」分组。**
