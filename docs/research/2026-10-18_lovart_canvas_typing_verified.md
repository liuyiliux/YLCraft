## 二、🔴 所以 Lovart 的结构是

```
画布（只有一种，tldraw 那个）
    ▲
    │ 生成结果落进来
    │
Skill（= 能力入口，带表单）
    ├── 亚马逊产品主图
    │      └── 模板（变体）：女装 / 男装 / … 共 6 个
    ├── Amazon A+ 内容
    └── 标志系统
```

**三层，但都不是"画布类型"：**

| 层 | 是什么 | 例子 |
| --- | --- | --- |
| **画布** | 只有一种 | tldraw 那块 |
| **Skill** | 能力入口 + 表单 | Amazon 商品主图 |
| **模板** | Skill 内部的**视觉变体** | 女装 / 男装 |

## 三、✅ 我上一条建议错在哪

我在 `CANVAS_POSITIONING.md` 里说：

> 「画布要分模板：漫剧画布 / 电商画布 / 海报画布 / 自由画布」
> 「因为数据结构差异太大」

**实测证明：Lovart 没有这么做。它只有一个画布。**

**它的做法是：用 Skill + 表单** 来承载"不同用途"的差异，而不是造不同的画布。

**这也解释了它的定价为什么按「并发任务」和「品牌套件」** ——
因为它卖的是**能力调用**，不是画布类型。

## 四、那"数据结构差异"这个理由还成立吗

我在原文档里说：漫剧要镜号/时长，电商要 SKU/尺寸，所以需要不同画布。

**实测后要修正：**

| 差异 | 放哪 | 为什么 |
| --- | --- | --- |
| 镜号 / 时长 / 机位 | **Skill 的表单 + 一个「分镜表」节点** | 这是**生成前的输入**，不是画布结构 |
| SKU / 卖点 / 尺寸 | **Skill 的表单** | 同上，是输入参数 |
| 品牌规范 | **Skill 的上下文** | 是约束，不是画布类型 |

**结论：这些差异大部分是"输入参数"的差异，不是"画布能装什么"的差异。**

> 🔴 **原判断"一个画布硬塞会变成什么都能干但什么都不好用"——这句仍然成立，但解法不是分画布，是把复杂度挡在 Skill 表单里。**

## 五、修正后的建议

### 画布：一种

```
画布引擎 + 一个画布类型
  节点：图片 / 视频 / 文本 / 音频 / 图层组
  能力：选择/拖拽/图层/版本/连线
```

**不分"漫剧画布 / 电商画布"。**

### 用途差异：靠 Skill + 表单

```
Skill = 能力入口
  ├── 名称 / 说明 / 案例图 / 作者
  ├── 表单（这个能力需要用户填什么）
  ├── 模板（视觉变体：女装/男装、16:9/9:16…）
  └── 生成后：结果落到画布
```

**这正好接上我们已有的 Skill 体系** —— 我们 `backend/app/skills/` 下已经有 SKILL.md，
只是**没有表单、没有模板变体、没有案例图**。

### 那"分镜"呢

**分镜不需要特殊画布，它需要：**
1. 一个 **Skill**（叙事短片导演分镜）
2. 一个 **表单**（题材/风格/时长/比例）
3. 生成出一个 **分镜表**（可以是画布上的一个结构化节点，也可以是独立视图）
4. 分镜表里每一镜 → 生成图片 → 落到画布

**这比"造一个漫剧画布"省得多，而且和 Lovart 的模型一致。**

---

## 六、但对我们的一个提醒

Lovart 这个模型有个前提：**它的用户是"上传素材 → 套模板 → 出成品"**。
所以表单足够。

**我们的短剧链路更长**（小说→世界→角色→剧本→分镜→图→视频→出片），
**光靠表单可能不够** —— 中间那些步骤需要"看得见的工作面"。

**所以我们的画布可能不是"一种能力的工作面"，而是"整条链路的工作面"。**
这一点 Lovart 没给我们答案（它的链路短）。
