## 2.1 基本事实

| 项 | 内容 | 来源强度 |
|---|---|---|
| 归属 | **字节跳动**（包名 `com.ss.android.ugc.sicily_cm`） | **强**（应用宝官方包名） |

| 状态 | 曾停运，**2025 年卷土重来** | 媒体报导（摘要级） |

## 2.2 ⚠️ 一个必须纠正的认知

**用户原话是「可颂机位」，把可颂理解成小红书旗下的机位产品。**

**实际上**：
- 可颂是**字节跳动**的（不是小红书）
- 它是**摄影社区**（对标小红书），**不是专门的机位 App**
- 「机位」可能是社区里的一个内容类别，不是独立产品形态

> **这个区别重要**：如果它是社区，那它的「机位」是**用户发的内容**，不是结构化数据。
> 我们想要的是「结构化机位知识库」，它可能不提供。

## 2.3 没查到的

- **「机位」功能的具体形态**：是地图标点？还是发帖带定位？**没查到**
- 有没有结构化的「某地某时拍什么」
- 数据接口 / API：**没有**

# 三、开源方案（这部分我实测过）

## 3.1 ✅ 太阳位置计算 —— 已验证可用

| 方案 | 语言 | 说明 |
|---|---|---|
| **suncalc** | JS (npm) | 最流行，轻量 |
| **Astral** | Python | 功能全，含 sunrise/sunset/twilight |
| **pysolar** | Python | 高精度 |
| **NOAA 算法** | 任意 | **我自己在原型里实现了，并交叉验证通过** |

**我的实现已经验证**：
- 11-08 颐和园日落 17:05，与 sunrise-sunset.org 官方 API **完全一致**

## 3.2 ✅ 地形遮挡 —— 已验证可用

| 方案 | 说明 |
|---|---|
| **`gdal_viewshed`** | GDAL 自带命令行工具，输入 DEM 栅格 + 观察点，输出视线可见范围 |
| **Open-Elevation API** | 免费公开，我**实测通了**（颐和园区域返回正常高程） |

**我的实现已经验证**：
- 从昆明湖畔沿方位采样，算出正北地形仰角 3.32°、西南 0.30°

## 3.3 ✅ 地理编码 —— 已验证可用

**OpenStreetMap Nominatim**：把「颐和园」转成经纬度，实测通了。

## 3.4 ✅ 地图渲染 —— 项目已有

**Leaflet + react-leaflet 已装在 `frontend/package.json`**。

# 四、⭐ 最重要的结论：我们要做的东西，技术上完全可以自己实现

## 4.1 完整技术链路（我逐个验证过）

```
用户输入「秋天去颐和园」
  ↓
✅ Nominatim 地理编码 → 39.9901, 116.2647
  ↓
✅ NOAA 算法 → 该日该时刻太阳方位/高度
  ↓
✅ Open-Elevation 沿方位采样 → 地形仰角
  ↓
✅ 太阳高度 vs 地形仰角 → 这个方向能不能拍到光
  ↓
✅ 对比太阳方位和拍摄方向 → 是不是逆光
  ↓
输出「几点、站哪、朝哪拍」
```

**全链路都是公开数据 + 纯计算，可以免费跑通。**

## 4.2 和巧摄的差异

| 维度 | 巧摄 | 我们 |
|---|---|---|
| 题材 | **风光** | **人像** |
| 核心问题 | 太阳从哪个山头升起 | **这个人在这，光从哪来** |
| 需要的地形 | 大尺度山体 | 小尺度场地（公园/街角/室内） |
| 需要的数据 | DEM 高程 | 高程 + **建筑遮挡** + **人流** |
| 已知的强项 | 太阳月亮银河计算、AR 取景 | 待建 |

## 4.3 ⚠️ 我们比巧摄多需要什么

| 需求 | 巧摄有吗 | 我们需要吗 |
|---|---|---|
| 太阳/月亮位置 | ✅ | ✅ |
| 地形遮挡 | 应该有 | ✅ |
| **建筑遮挡** | ❓ 未知 | ⚠️ **城市人像必须** |
| **人流/机位占用** | ❌ 不需要 | ⚠️ **人像场景强需要** |
| **引导口令** | ❌ 不相关 | ✅ **我们的差异化** |
| **参考图 vs 实拍对照** | ❌ | ✅ **我们的差异化** |

# 五、给产品的建议

## 5.1 立刻能做的

1. **把 Open-Elevation 接入后端** —— 做地形仰角计算 API
2. **把 Nominatim 接入** —— 地点搜索转坐标
3. **建筑遮挡先不做** —— 数据难拿，先用「地形 + 人工录入已知遮挡」应付
4. **机位人工录入** —— 与其等别人建库，不如让你自己标

## 5.2 不要做的

- ❌ **不要做风光摄影**（巧摄已经赢了）
- ❌ **不要做通用摄影社区**（可颂/小红书已经在做）
- ❌ **不要试图爬可颂的机位数据**（它是字节的社区，数据不一定开放）

## 5.3 我们的独特位置

> **人像 + 引导口令 + 参考对照 + 元素清单**
>
> 这四样**没有一个竞品同时做**。
