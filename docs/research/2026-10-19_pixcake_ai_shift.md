# 像素蛋糕 PixCake：往 AI 靠拢的路径（2026-10-19）

> 来源：官方帮助中心 <https://www.pixcakeai.com/guide/127932>（创意模块功能说明）
> + <https://www.pixcakeai.com/guide/230951>（AI 追色 2.0）、AI 工具箱页
>
> **一句话：它把一个"修图软件"做成了"场景化 AI 工具箱 + 按需付费"。**
> 这对我们有两个直接可用的东西：**功能命名法** 和 **按场景选模型决策表**。

## 一、它的 AI 功能目录（实读，完整）

### 分类方式：按「修什么」分，不按技术分

| 大类 | 功能 |
| --- | --- |
| **人像** | AI 面部重绘（极速/标准）、闭眼修复、AI 瘦肚子、AI 加腹肌、证件照换衣服 |
| **消除** | 创成式填充、AI 祛路人、智能消除（快速/生成式）、AI 祛体毛 |
| **修复** | AI 超清、**AI 补草地**、**沙滩美化**、智能道具修复、AI 老照片修复、**AI 衣服精修**、**鞋子祛污**、**裙子蓬松**、**裙摆平整** |
| **场景** | **AI 追色 2.0**（追光追色 / 追场景）、AI 布景、AI 换天空、春日樱花、夏日晴空、秋天落叶、冬日雪景 |
| **光影** | 自然光、AI 补光、柔化阴影、夕阳光、发光、镜头虚化 |
| **创意玩法** | AI 背景扩图 |

### 🔴 第一个洞察：命名极度场景化

对比一下：

| 通用功能名（我们现在的） | 像素蛋糕叫法 |
| --- | --- |
| 局部重绘 | **AI 补草地** / **鞋子祛污** / **裙摆平整** |
| 扩图 | **AI 背景扩图** |
| 抠图 | **AI 祛路人** / **AI 祛体毛** |
| 风格迁移 | **AI 追色 2.0** |
| 变形 | **裙子蓬松** / **AI 瘦肚子** / **AI 加腹肌** |

**"裙子蓬松"比"局部重绘"更能让人知道该点哪个。**

🔴 **这直接影响我们 32 项图片能力的命名** —— 我们的"局部重绘 / 扩展画布 / 变换体态"太抽象了。

**但注意**：它这么命名是因为**用户群极窄**（影楼修图师，痛点高度统一）。
我们面向更广，所以要**两层命名**：
- 上层：场景化名字（裙子蓬松）
- 下层：通用能力（局部重绘）

## 二、🔴 最有价值的：AI 追色的「按场景选模型」决策表

这是整份材料里**对我们最有用的一张表**：

| 适用场景 | 推荐模型 | 特性与优势 | 注意事项 |
| --- | --- | --- | --- |
| **固定棚拍 / 场景一致**<br>（背景、道具、打光基本一致） | 追色 1.0 | 速度快，**无损画质**，色彩/影调**可分开调** | ❌ **无法改变光线方向** |
| **场景一致但光线/天气不同**<br>（同个景点阴天变晴天） | 追色 2.0<br>（追色追光） | 保持原尺寸，背景改动少，**智能补光**，还原样片打光逻辑，支持程度滑杆 0-100 | ❌ 不支持色彩/影调独立调节 |
| **场景差异大 / 极限换天**<br>（日照金山、夜转昼） | 追色 2.0<br>（追场景） | **还原度最高**，可凭空生成复杂光影与背景 | 仅 4K 输出，不支持程度调节 |

### 为什么这张表对我们关键

我们一直卡在「12 镜怎么保证一致」。**这张表给了框架：按"变化量"选模型，不是一刀切。**

映射到我们的场景：

| 我们的场景 | 变化量 | 该用 |
| --- | --- | --- |
| 同一角色、同一场景、只换机位 | 小 | 不该重新生成 —— **改机位就好** |
| 同一角色、同一场景、不同时间（白天→夜） | 中 | 该用「换光照」类能力（不是重画） |
| 同一角色、不同场景 | 大 | 需要**角色参考图锁定 + 重新生成** |
| 不同角色、同场景 | 大 | 需要场景参考图 |

🔴 **这直接补进了我们的巡检逻辑**：巡检发现"光照不一致"时，
**不该重画整张，该用"改光照方向"这种低变化量操作** —— 便宜且不破坏原图。

## 三、它的商业模式：两档效率定价

```
排队生成：会员免费（不限次，但要等）
加速生成：消耗「创意点数」（马上出）
```

点数从 **3 点/次（证件照换衣服）** 到 **160 点/次（AI 衣服精修 4K）**。

| 工具 | 排队 | 加速 |
| --- | --- | --- |
| 闭眼修复 | 会员免费 | 限时免费 |
| 证件照换衣服 | 会员免费 | 3 点 |
| AI 面部重绘（极速） | 会员免费 | 5 点 |
| AI 面部重绘（标准） | 会员免费 | 10 点 |
| AI 瘦肚子 | 会员免费 | 40 点 |
| AI 老照片修复 | 会员免费 | 40 点 |
| AI 衣服精修 4K | 会员免费 | 160 点 |

### 🔴 这个模式对我们的启示

**我们现在只有"多少钱"，没有"多久"。**

| 我们的现状 | 可以加什么 |
| --- | --- |
| 点一下 = 扣钱 = 马上出 | 加一档「**慢慢来，不要钱**」 |
| 用户不知道等多久 | 「排队约 3 分钟」/「加速约 20 秒」 |

**为什么这对我们特别合适**：
我们的 Agent 会批量生成（12 镜、25 宫格）。
**用户完全可能接受"等 5 分钟省 100 块"** —— 尤其是一次出 12 张的时候。

这也和 LibTV 那条呼应：「Agent 天然要多调几倍模型，单次调用太贵 Agent 就不成立」。
**给个免费排队档，Agent 才敢放开了试。**

## 四、其他值得抄的细节

| 功能 | 做法 | 我们的状态 |
| --- | --- | --- |
| **程度滑杆 0-100** | 融合度可调 | ❌ 没有。我们的 AI 操作都是"0 或 100" |
| **原图 / 生成图对比** | 可切对比查看 | 🟡 只在巡检里有 |
| **保存为新照片 / 保存为新图层** | 🔴 **非破坏性** | 🟡 我们提过图层模型但没做 |
| **生成记录面板** | 左侧列出每次生成，可删可重试 | ❌ 没有 |
| **虚拟副本** | 编辑前先建副本 | ❌ 没有 |
| **批量应用效果至其他图片** | 一次调好的效果批量套 | ❌ 没有（12 镜急需） |
| **样片推荐 / 我的样片** | 系统库 + 自己上传 | 🟡 我们只有上传参考图 |
| **多图层自由编辑** | 分层 | 🟡 设计过没做 |
| **第三方创作者工具包** | 创作者卖工具包，年订阅 | ❌ 没有（生态级） |
| **对接 ERP / 联机拍摄 / 协同工作流** | 影楼企业流程 | — 与我们场景不同 |

## 五、它和我们最本质的区别

| | 像素蛋糕 | 我们 |
| --- | --- | --- |
| 起点 | **一张已经拍好的照片** | **一句话 / 一个剧本** |
| 核心动作 | 修（改已有的） | **生成 + 修** |
| 一致性靠什么 | 原图就在那 | **参考图 + 要素锁定 + 巡检** |
| 用户 | 影楼修图师 | 漫剧/短剧/电商/Coser |

**所以它的"修"那一套不能照搬，但三件事可以直接用：**

1. **场景化命名**（裙子蓬松式）
2. **按变化量选操作**（追色那张表的逻辑）
3. **两档效率定价**（排队免费 / 加速付费）

## 六、落地建议

| 优先 | 做什么 | 理由 |
| --- | --- | --- |
| P1 | **图片能力加场景化命名** | 我们的 32 项太抽象，改成"两层名" |
| P2 | **巡检结果按"变化量"给修复方案** | 光照不一致 → 改光照，不重画 |
| P3 | **程度滑杆** | 所有 AI 操作都该有"改多少" |
| P4 | **排队免费 / 加速付费两档** | 12 镜批量时用户可能愿意等 |
| P5 | **保存为新图层** | 非破坏性，改坏了能退 |
| P6 | **批量应用** | 12 镜刚需 |

## 七、这次调研暴露的我自己的问题

上一轮我从 Lovart 抄了「局部重绘 / 扩展画布 / 变换体态」这些**通用名**，
但像素蛋糕证明：**用户是按场景找功能的，不是按技术找的。**

🔴 **这个教训要进基调**：
> 功能命名不要用技术词（局部重绘、图生图、ControlNet），
> 要用用户脑子里的那件事（**把地补上草、把裙子弄平、把路人去掉**）。
