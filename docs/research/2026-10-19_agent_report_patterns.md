# 别的平台怎么表达「做了什么 / 没验证什么」

> 起因：我做了两个 chip（`原图保留` 绿 / `效果你亲眼看一下` 黄），你问"这是什么"。
> 我去查了别家怎么做 —— 结论是**这两个东西该分开，我的排版把它们并列了是错的**。

---

## 一、先看一份硬材料的分类法

IUI '26 有篇论文，把 9 个真实的 computer-use agent（Claude Computer Use、Adept、OpenAI Operator、
AIlice、Magentic-UI、UI-TARS、Project Mariner、TaxyAI、AutoGLM）逐个装起来用了 30 分钟，
然后归纳出「Agent 活动的可解释性」应该分成 6 个子类：

| 子类 | 具体要表达什么 |
| --- | --- |
| **可见性** | 动作发生在哪、**历史是否留存可回看** |
| **动作描述** | 做了什么、**有没有调别的工具** |
| **推理透明** | 思考过程、查了什么知识、🔴 **模型的不确定性（uncertainty）** |
| **下一步预览** | 即将要做什么 |
| **计划呈现** | 整体计划、以及重新规划时怎么告知 |
| **运行状态** | 上一步确认、结束时成功/失败、状态通知 |

**同一篇论文的「心智模型」部分还有两个：**

| 子类 | 要表达什么 |
| --- | --- |
| 🔴 **Agent 的范围** | 它能访问/控制到什么、能调哪些外部工具 |
| 🔴 **风险** | 涉及什么个人数据、有哪些风险、怎么缓解 |

> 来源：[Mapping the Design Space of User Experience for Computer Use Agents (IUI '26)](https://arxiv.org/html/2602.07283v1)

## 二、直接回答：我那俩 chip 分属两个不同类别

| 我的 chip | 归类 | 属于 |
| --- | --- | --- |
| 🟢 **原图保留** | "我确认了这件事" | **动作描述 / 运行状态确认** |
| 🟡 **效果你亲眼看一下** | "我没法确认这件事" | 🔴 **推理透明 → 模型的不确定性** + **Agent 的范围** |

**学术界把这两件事拆开，我把它们并列了。**

所以你说"这是什么"是对的 —— **它读起来像同一类东西，实际不是。**

## 三、各平台实际怎么做的

### 3.1 Claude Code / Cursor / Copilot —— 有明确的坑

社区里有个很扎心的总结：

> **"A failing test is information. A test that never ran, reported as a pass,
> is worse than having no tests at all, because now you believe something."**
> （失败的测试是信息；**没跑却报成通过**，比没有测试更糟，因为你开始相信它了）

**它们会犯的三种"假通过"**：
1. 命令没找到（猜 `npm test`，实际用 `pnpm vitest run`），报错被折进总结成"没有失败"
2. 加了 `--passWithNoTests` 标志 → 0 个测试、退出码 0、绿勾
3. 命令后面挂了 `|| true` → 永远成功

**社区给出的检验标准（很值得抄）：**

| 要它给 | 好答案 | 坏答案 |
| --- | --- | --- |
| 跑的什么命令 | 具体字符串 | 转述，或不给 |
| 输出 | **计数**："42 passed, 0 failed" | **只说"测试通过"** |
| 退出码 | `0`，并说出来 | 不提 |

> **"如果你只拿到 'pass' 这个词和别的什么都没有，就当作未验证。"**

来源：[Your agent said the tests passed. Check whether they ran.](https://dev.to/david_lee_bf42eec7236085d/your-agent-said-the-tests-passed-check-whether-they-ran-4njm)

🔴 **这条对我们的启发极大**：我们的 chip 不该只说「原图保留」，
应该说**证据**：「原图保留（画布上仍有 6 张，未覆盖）」。

### 3.2 Manus —— 时间线 + 交付物

任务执行时是**时间线**（思考 → 动作 → 结果），结束时给**交付物清单**。
用户看的是"它做过哪些步"和"最后交给我什么"，不是一段总结。

### 3.3 Devin —— 分区

Session 里分 `plan` / `reasoning` / `terminal` / `browser`。
**做了什么**和**想了什么**分开放，不混在一段话里。

### 3.4 Coze / Dify 等工作流平台 —— Trace 面板

每个节点一行：**输入 / 输出 / 耗时 / 状态（成功·失败·跳过）**。
看的是"哪一步出的问题"，不是"整体成没成功"。

### 3.5 Lovart —— 基本不做验证声明

它靠**看成品**判断。因为一次就出一张图，好不好一眼就知道，不需要 agent 声明。
**这也解释了为什么它界面干净** —— 它把"验证"交给了用户的肉眼。

### 3.6 我们自己调研过的两家

| 平台 | 做法 |
| --- | --- |
| **BeefTV** | **「已保存」vs「已测试」两档状态** —— 明确区分"存了"和"能用吗" |
| **OhMyGame** | 报告四段式：结论 / 做了什么 / 🔴 **没做什么** / 需要你 + 改动规模 `+122 -0` + 运行时长 |

**BeefTV 那个两档状态，就是我这个问题的正解雏形。**

## 五、所以该怎么改（回到那两个 chip）

**核心问题**：我把「我保证的」和「你要看的」放在同一行 chip 里了。

### 建议改法：按类别分组

```
做好了，新图放在右边。

✓ 我确认了
  原图没动 · 画布上还是 6 张
  新图 170×236，已加入画布

⚠ 我没法确认（要你看）
  磨皮有没有过
  像不像本人

[ 撤销这次 ] [ 对比原图 ]
```

**注意两处改进：**

| 改动 | 为什么 |
| --- | --- |
| 从 chip 变成**分组的两小块** | 对应分类法里两个不同类别，不该并列 |
| 「原图保留」后面**加了证据**（还是 6 张） | 学 Claude Code 那套：**给数字，别只给形容词** |

### 更狠一点（可选）

学 BeefTV 做**两档状态**：

```
● 已保存到本地     ← 存了
○ 未测试            ← 还没验证
```

点进去能看：这次改了什么、跑了哪些检查、哪些没跑。

---

## 六、一句话总结

**别家没有一个把"我确认的"和"你要看的"混在一行。**

- **做得好的是 Claude Code**：把"没跑"和"通过"用**证据**区分开
- **做得好的是 BeefTV**：把"已保存"和"已测试"**分两档**
- **做得好的是 OhMyGame**：把"没做什么"**单独一段**
- **Lovart 干脆不做**：因为它一次一张，你一眼就知道好不好

**我那两个 chip 方向对，但排版错。改成两组，并按 Claude Code 那套补证据。**
