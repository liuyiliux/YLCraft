# 产品结构设计：画布是"组装面"，不是"万能入口"（2026-10-17）

> 回答一个问题：**画布要不要统合其他功能？**
> 本文给出：现状诊断 → 三个选项的取舍 → 目标结构 → 界面 → 交互 → 模块划分 → 分阶段落地。

---

## 二、三个选项

### 选项 A：画布统合一切（画布变成唯一入口）

```
打开应用 → 直接是一个大画布
所有生成 = 画布上加点
所有编辑 = 画布上双击节点
```

**优点**：结构极简，认知负担低
**缺点**：
- 🔴 **44 个页面要全部改造成节点**，工程量巨大且在造轮子
- 🔴 `crawler` / `download` / `accounts` / `novel-search` 这些**根本不适合放画布**
- 🔴 和业界做法**相反**（ArtCraft 19 个工具是启动器，不是单画布）
- 🔴 用户"我就想生成一张图"要先进画布，**多一步**

**结论：❌ 不选。**

### 选项 B：保持现状（画布就是一个工具）

**优点**：零风险
**缺点**：上面 1.2 的五个问题一个都不解决

**结论：❌ 不选。**

### 选项 C：✅ **画布做"组装面"，工具做"生产点"，中间修一条通道**

```
采集层（素材进得来）  →  创作层（素材变作品）  →  组装层（作品拼成片）
  独立页面，不变        独立页面，不变，但        ← 画布在这里
                       每个产物都能"加入画布"
```

**核心主张：画布不抢工具的活，工具不抢画布的活。**

- **工具负责"做出来"**（快、单一目标、参数化）
- **画布负责"连起来"**（慢、表达关系、可复用）
- **两者之间有一条明确的通道**

**为什么选它**：
1. 业界都这么做（BeefTV 7 个独立入口 + 画布；ArtCraft 19 个工具 + 3D Stage）
2. 工程量可控（不加新页面，只加一条通道 + 一处改造）
3. 用户心智不变（"我要生图"还是去生图）

**结论：✅ 选 C。**

## 四、界面设计

### 4.1 导航怎么变（小改，不加页面）

**改动 1：画布挂到项目下，不再平级**

```
现在：  ▾ 创作工作台 → 角色 / 3D预演 / 创作画布
目标：  [创作项目] 里每个项目展开 → 该项目的画布列表
```

**改动 2：画布页面顶部加"项目上下文条"**

```
┌──────────────────────────────────────────────────────────┐
│ [← 返回项目]  《我的短剧》 / 画布 3 ▾    [版本记录] [整理] │
├──────────────────────────────────────────────────────────┤
│                                                          │
│                     画布内容...                           │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### 4.2 🔴 通道长什么样：产物卡片上的「加入画布」

**在 AI 图片 / 视频生成 / 素材库 的每张结果卡片上：**

```
┌─────────────────┐
│                 │
│     [图片]       │
│                 │
├─────────────────┤
│ 加入画布 ▾       │  ← 新增
└─────────────────┘
      ↓ 点开
┌──────────────────────────┐
│ 加入画布                  │
│ ─────────────────────    │
│ ▸ 当前画布《分镜 A》       │  ← 默认，一键
│ ▸ 其他画布…               │
│ ─────────────────────    │
│ 加入方式：                │
│   ○ 作为图片节点           │  ← 默认
│   ○ 作为参考素材           │
│   ○ 作为分镜脚本的一镜      │
└──────────────────────────┘
```

**为什么要有"加入方式"**：
BeefTV 的资产动词是分类型的（`Drag to Scene` vs `Add to Character`），
**同一个东西放进去的语义不同**。一张图，可以是"要生成的图"，也可以是"参考图"。

### 4.4 版本记录面板（P0）

点「版本记录」右侧滑出：

```
┌──────────────────────────────────┐
│ 版本记录                     [✕] │
├──────────────────────────────────┤
│ 🔍 搜索版本…                      │
├──────────────────────────────────┤
│ ● 现在                            │
│   12 个节点 · 自动保存            │
│ ───────────────────────────────  │
│ ○ 21:30  Agent 修改了分镜         │  ← 谁改的
│   +6 -2 · 12 个节点               │  ← 改了啥
│   [查看] [恢复]                    │
│ ───────────────────────────────  │
│ ○ 20:15  手动编辑                 │
│   +2 -0 · 8 个节点                │
│   [查看] [恢复]                    │
│ ───────────────────────────────  │
│ ○ 19:40  初始创建                 │
│   5 个节点                        │
└──────────────────────────────────┘
```

**三个关键设计：**
1. 🔴 **标"谁改的"**（Agent / 手动）—— 因为 Agent 一次改 9 个文件，必须知道哪次是它
2. 🔴 **标改动规模**（`+6 -2`）—— 沿用 OhMyGame 报告里的做法
3. **「查看」不跳转**，直接在画布上叠加显示那一版（可比对）

## 五、交互设计：三条通道

### 通道 1：工具 → 画布（新增）

| 入口 | 动作 | 落地 |
| --- | --- | --- |
| AI 图片结果卡片 | 加入画布 ▾ | 选画布 + 选方式 |
| 视频生成结果 | 加入画布 ▾ | 同上 |
| 素材库选中多张 | 批量加入画布 | 同上 |
| 生成历史 | 从历史选择 | 画布内直接调 |

### 通道 2：画布 ↔ 其他页面（双向）

| 画布里的节点 | 双击后 |
| --- | --- |
| 图片节点 | 打开图片编辑器（全屏） |
| 视频节点 | 打开播放器 |
| 3D 预演节点 | 打开 Previs（全屏） |
| 分镜脚本节点 | 打开分镜表格编辑器 |

**反向**：这些页面右上角都有「返回画布」。

### 通道 3：画布 → 成片（新增）

```
[出片] → 时间线面板 → 按顺序排 Clip → [渲染] → 成片进素材库
```

│   └── ...
└── models/
    └── canvas_version.py            ← 新增：版本表

### 6.2 数据表（新增 1 张）

```sql
canvas_versions (
  id            uuid PK
  canvas_id     uuid FK
  version_no    int          -- 递增
  document      jsonb        -- 完整快照
  change_kind   varchar      -- 'auto' | 'manual' | 'agent'
  change_summary jsonb       -- {added: 6, removed: 2, nodes: 12}
  created_by    varchar      -- 'user' | agent run id
  created_at    timestamptz
)
-- 索引：(canvas_id, version_no desc)
```

**存储策略（防版本爆炸）**：
- 每 5 分钟自动存一次（有改动才存）
- Agent 每次运行**结束**存一次（标 `agent`）
- 手动"存版本"随时
- **保留策略**：最近 50 个 + 每天 1 个 + 每周 1 个，超出自动清理

## 七、分阶段落地（每阶段都能单独验证）

### 阶段 1：画布版本记录（P0，最紧急）

**为什么先做**：Agent 一次改 9 个文件，用户**没有后悔药**。

**做什么**：
- 表 `canvas_versions`
- 三个 API：列表 / 详情 / 恢复
- `VersionHistoryPanel` + 自动保存钩子
- 工具栏「版本记录」按钮

**怎么验证**：改画布 → 关浏览器 → 重开 → 能看到历史并恢复

### 阶段 2：加入画布通道（P0）

**做什么**：
- `AddToCanvasMenu` 组件
- `intake_service` 统一入口
- 挂到图片/视频/素材库三处

**怎么验证**：在 AI 图片生成一张 → 点加入画布 → 切到画布能看到

### 阶段 3：自动整理 + 隐藏连线 + 小地图（P1）

**做什么**：三个减噪工具

### 阶段 4：3D 预演变节点（P2）

**做什么**：Previs 内嵌进画布节点，独立页保留

### 阶段 5：出片（P2）

**做什么**：画布时间线 + 渲染

## 八、不做什么（明确划界）

| 不做 | 为什么 |
| --- | --- |
| ❌ 把 44 个页面都改成节点 | 工程量巨大，且采集/阅读类根本不适合 |
| ❌ 删掉独立工具页面 | 用户的"我要生成一张图"心智不会变 |
| ❌ 画布做成全站首页 | 采集和管理类工作是日常，不该先进画布 |
| ❌ 现在做 Image to Location / Angles | 新维度，工程量大，先解决"落地"问题 |

---

## 九、一句话

**画布不统合功能，它统合"产物之间的关系"。**

- 工具继续各干各的（保持 44 个页面）
- 但每个产物都能**一句话送进画布**
- 画布负责**连起来、可回滚、能出片**

**这样既不用重写，又解决了"工具是散的"这个真问题。**
