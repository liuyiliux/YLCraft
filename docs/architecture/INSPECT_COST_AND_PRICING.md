# 巡检花不花钱？价格怎么算？（2026-10-19）

> 回答三个问题：
> 1. 价格应该跟选的模型走，从配置取
> 2. 镜头墙原型 → 做
> 3. **巡检是用 LLM 吗？花费高不高？**

---

## 一、价格：我们已经有字段，但不够用

### 现状（代码实查）

`backend/app/db/models/ai_connector.py`：

```python
price_per_call: Optional[float]  # 每次调用费用（美元）
total_cost: float                # 累计消耗（美元）
```

**已经有按次计价的字段了。** 所以"价格从配置来"在数据层是通的。

### 🔴 但生成类不能按"次"算

生图是**按张**，生视频是**按秒**：

| 类型 | 计价单位 | 例子 |
| --- | --- | --- |
| LLM | 按 token | 输入 $0.15/1M token |
| 生图 | **按张** | GPT Image 2 ≈ $0.03/张 |
| 生视频 | **按秒** | Seedance 768P ≈ ¥0.09/秒 |
| 生音频 | **按字符/秒** | — |

**需要补的字段：**

```python
price_per_unit: float
unit: Literal["call", "image", "second", "1k_tokens", "character"]
```

**然后原型里的价格就能这样算：**

```
重出这一镜 → GPT Image 2 → 1 张 → $0.03 → 显示 ⚡14
重新打光   → NanoBanana → 1 张 → $0.005 → 显示 ⚡3
```

**同一件事，换个模型价格差 6 倍** —— 这正是你说的"价格跟模型走"。

> ✅ **原型要改**：修复按钮上标的不该是硬编码的 `⚡3`，
> 而是「**模型名 + 按配置算出来的价**」。

---

## 二、🔴 巡检花不花钱：**大部分不花**

**直觉上"巡检"像是要调 LLM 逐张看图。实际上不该这么做。**

### 巡检应该分三层

| 层 | 检查什么 | 用什么 | 成本 |
| --- | --- | --- | --- |
| **L1 结构化** | 分辨率 / 比例 / 格式 / 时长 / 帧率 / 命名 | **纯代码 + ffprobe** | 🔵 **0** |
| **L2 视觉特征** | 人脸像不像 / 风格一致 / 文字一致 / 光位 / 色调 | **本地小模型**（人脸 embedding / CLIP / OCR）+ 向量距离 | 🔵 **≈0**（本地推理，不调 API） |
| **L3 语义** | 画面符合不符镜头描述 / 剧情连续 | **多模态 LLM** | 🟡 **花钱** |

### v12 原型里那三个问题，分属哪一层

| 问题 | 层 | 用什么 | 花费 |
| --- | --- | --- | --- |
| ① 角色脸和前面不一致 | **L2** | 人脸 embedding 余弦距离（0.62 vs 阈值 0.85） | **0** |
| ② 主光方向反了 | **L2** | 图像亮度分布 / 梯度主方向 | **0** |
| ③ 分辨率和其他不一致 | **L1** | 读图片元数据 | **0** |

🔴 **也就是说：v12 那三个问题全都不用 LLM，成本是 0。**

### 什么才真的要 LLM

| 检查项 | 为什么必须 LLM |
| --- | --- |
| 「这画面符合'女主角站在窗边午后暖光'吗」 | **语义判断**，没法用数字表达 |
| 「第 3 镜和第 4 镜剧情接得上吗」 | 要理解剧情 |
| 「这张图有什么问题」（开放式） | 无预设检查项 |

### 分级降级（省钱的关键）

```
L1 + L2 全量扫（免费）
   ↓ 只挑出"可疑"的
L3 只对可疑项调多模态模型（花钱但少量）
```

**举例**：20 个镜头
- L1+L2 全扫：**0 成本**，筛出 3 个可疑
- L3 只查那 3 张：约 **¥0.02~0.08**

**对比：20 张全部送多模态 LLM** ≈ **¥0.1~0.5/次**
**用 L1+L2 先筛** ≈ **¥0.02~0.08/次**，省 5~10 倍。

### 成本量级参考

| 方案 | 20 镜一次巡检 |
| --- | --- |
| 全 L3（每张都送多模态） | ~¥0.1~0.5 |
| **L1+L2 全扫 + L3 只查可疑** | **~¥0.02~0.08** |
| **只有 L1+L2** | **¥0** |

> 具体数字取决于接的模型。**关键结论是：巡检的绝大部分不需要 LLM。**

## 三、我们现在的存量能力

### ✅ 有的

| 能力 | 在哪 | 能干什么 |
| --- | --- | --- |
| **嵌入模型配置** | `ai_connector.py`：`embedding` 类型 + `embedding_dimension` + `normalize_embeddings` | 🔵 **可以配 CLIP/文本嵌入模型** |
| **分支/分割模型** | `services/live2d/segmentation.py`：BIREFNET / U2NET / SAM | 抠图、区域提取 |
| **按次计价字段** | `price_per_call` + `total_cost` | 成本统计 |
| **pgvector 数据库** | Postgres + pgvector | 🔵 **可以做向量相似度检索** |

### ❌ 缺的

| 缺什么 | 说明 |
| --- | --- |
| **人脸 embedding** | 需要接 ArcFace / InsightFace 之类的模型 |
| **CLIP 图像 embedding** | 配置里有 `embedding` 类型，但没接具体图像模型 |
| **OCR** | 风格/文字一致性检查需要 |
| **图像统计** | 亮度分布/光位方向，OpenCV 就够，但没写 |
| **计价单位** | 只有 `price_per_call`，缺按张/按秒 |

### 一个好消息

**`ai_connector.py` 里的 `embedding` 类型 + pgvector 已经存在。**
→ **CLIP 图像 embedding 相似度这条路是通的**，只是没接模型。

---

## 四、结论

1. **价格必须从模型配置算**，而且要补「按张 / 按秒」的计价单位
2. **巡检不该全用 LLM** —— 我们 v12 那三类问题（脸/光位/分辨率）**全是 0 成本**
3. **LLM 只用在语义检查**（"符不符合描述"），而且**只对筛出来的可疑项用**
4. 我们**已有 embedding 配置 + pgvector**，CLIP 这条路只差接模型
