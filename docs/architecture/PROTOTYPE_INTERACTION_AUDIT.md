# 我们的原型：交互是不是太多了？（2026-10-19）

> 你问：根据调研过的项目评价，我们现在的原型是不是"好多交互"？
> **答案：交互数量不多（比 Lovart 少），但"看着多"是真的 —— 问题不在数量，在分散。**

---

## 一、先给数字（可数，不凭感觉）

### 我们的五个原型

| 原型 | 静态按钮 | 右键/菜单项 | 动态绑定元素 | **合计** |
| --- | --- | --- | --- | --- |
| 自由画布 v11 | 11 | 9 | 9 | **29** |
| 镜头墙 v13 | 7 | 0 | 10 | **17** |
| 巡检 v12 | 8 | 0 | 3 | **11** |
| 节点图 v6 | 15 | 0 | — | **15** |
| 完整版（无 Agent 那版） | 36 | 13 | — | **49** |

### 对照三个平台（从调研文档里数的）

| 平台 | 构成 | **合计** |
| --- | --- | --- |
| **Lovart** | 底部工具栏 11 + 选中浮条 7 + 右键 12 + 参数行 4 + 左侧导航 9 + 主动功能 5 | **≈48** |
| **LibTV** | 5 类节点 + 底部快捷创建 4 + Slash 6 + 历史记录/图库 + 组操作 | **≈40+** |
| **Toonflow** | 8 节点 + 10 Agent 工具 + 插件市场 + 3D 导台 + MCP | **≈50+** |

🔴 **结论一：我们的交互数量比他们少。**

甚至我们的单模式原型（v11 的 29 个）**只有 Lovart 的六成**。

---

## 二、那为什么"感觉好多"？

### 原因 1：🔴 **四个原型 = 四种界面，没有统一**

用户打开我们的原型，看到的是：

```
v6  节点图      → 左边节点库 + 中间画布 + 底部工具条 + 顶部视图切换
v11 自由画布    → 左边画布 + 右边 Agent + 底部工具条 + 参数行 + 顶栏
v12 巡检        → 左边镜头 + 右边 Agent + 顶部巡检按钮
v13 镜头墙      → 上图下时间线 + 右边 Agent
```

**四套布局，四套按钮位置，四套命名。**

这才是"好多交互"的真实来源 —— **不是按钮多，是每次都要重新找按钮在哪。**

### 原因 2：同屏区域太多

我们的 v13 一屏有 **5 个区域**：

```
顶栏 / 信息条 / 镜头网格 / 时间线 / Agent 面板
```

Lovart 一屏只有 **2 个**：画布 + Agent。

| 平台 | 同屏区域数 |
| --- | --- |
| Lovart | 2（画布、Agent） |
| LibTV | 2（画布、Agent） |
| **我们 v13** | **5** |

### 原因 3：入口分散，而且不可发现

| 想做的事 | 入口在哪 | 用户能找到吗 |
| --- | --- | --- |
| 生成一张 | **对话**（或底部工具栏） | 🟡 得试 |
| 改一张 | **点图放大后底部** | 🟡 |
| 换模板 | **顶栏「模板」** | 🟡 |
| 巡检 | **顶栏「巡检」** | 🟡 |
| 换模式 | **顶栏分段控件** | ✅ |
| 加一镜 | 信息条右侧「+加一镜」 | 🟡 |
| 换顺序 | **拖拽**（没有任何按钮提示） | 🔴 **扫不到** |

🔴 **LibTV 用户的原话**：
> 「**看了整个文档，还是迷迷糊糊的，作为新手用户，完全不知道该怎么弄，琢磨了好久。**」
> 「图片节点标题不能自己修改吗？**满屏幕图片节点1.2345的**」

**他们的功能都能找到文档，但用户还是找不到界面上的入口。我们已经有同样的风险。**

## 三、按"默认路径步数"评价（这才是真实体验）

**交互数量是"功能量"，步数才是"体验"。**

### 任务 A：做一张 Cos 精修图

| 平台 | 路径 | 步数 |
| --- | --- | --- |
| Lovart | 打开 → 上传 → 说一句 → 等 → 点图 → 右键改 | **6** |
| **我们 v11** | 打开 → 上传 → 说一句 → 等 → 点图放大 → 底部工具 | **6** |

✅ **相当，这一点做对了。**

### 任务 B：做一集 12 镜短剧

| 平台 | 路径 | 步数 |
| --- | --- | --- |
| LibTV | 新建 → 建脚本节点 → 输剧本 → 生成分镜 → 逐镜生成 → 打组 → 出片 | **7+** |
| **我们 v13** | 新建 → 选模板 → 脚本 → 分镜 → 逐镜生成 → 巡检 → 出片 | **7+** |

✅ **也相当。**

### 任务 C：改第 3 镜

| 平台 | 路径 | 步数 |
| --- | --- | --- |
| LibTV | 找到节点（满屏编号）→ 点开 → 改参数 → 重跑 | **4**（找节点最痛） |
| **我们 v13** | 看镜头墙 → 点 03 → 改 | **3** |

✅ **我们更快** —— 因为镜号是连续可读的，不是"图片节点 1.2.3.4.5"。

## 六、🔴 最该砍的交互（具体清单）

**砍，不是加。** 按"能不能删"排：

| # | 砍什么 | 为什么 |
| --- | --- | --- |
| **1** | **四个原型合成一个** | 这是"感觉多"的根源 |
| **2** | **节点图从主界面移走** | 用户不需要看连线，改打组重跑（LibTV 做法） |
| **3** | **底部工具条 9 个 → 4 个** | 选择/移动/文字/生成，其他收进「⋯」 |
| **4** | **参数行 5 个选择器 → 2 个 + 「更多」** | 图像/比例常改，模型/张数不常改 |
| **5** | **右键菜单 10 项 → 6 项** | 常用的留下，其余进「更多」 |
| **6** | **同屏区域 5 → 3** | 顶栏 / 主内容 / Agent，时间线收进底栏 |

### 一定要加的一个东西（抵消交互删减）

🔴 **「下一步做什么」的引导**

LibTV 用户最痛的是「不知道该干嘛」。我们可以在**空画布 / 刚建画布**时给：

```
┌────────────────────────────────┐
│  从一个想法开始                 │
│                                │
│  [写剧本]  [上传参考图]         │
│  [用模板]  [直接说给我听]       │
└────────────────────────────────┘
```

**四个入口，选一个。** 用户永远知道下一步。

---

## 七、结论（一句话）

> **交互数量不是问题（29 vs Lovart 48），
> 问题是"四个原型四种界面"+"一屏挤 5 个区域"+"入口藏在拖拽里"。**

**所以下一步不该是加功能，是：**
1. **合并成一个可切换的原型**（镜头墙 / 自由画布 / 高级）
2. **把同屏区域从 5 减到 3**
3. **补「下一步做什么」的引导**
