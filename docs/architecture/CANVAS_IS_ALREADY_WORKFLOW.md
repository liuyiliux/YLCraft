## 一、已经有的（代码实证）

### 1. 十种基础节点（类型化端口）

| 节点 | 输入 | 输出 |
| --- | --- | --- |
| `text` 文本 | — | 文本 |
| `prompt` 提示词 | 上下文（任意，可多个） | Prompt |
| `llm` 大模型 | Prompt（必填） | 回答 |
| `image` 图片 | 来源 | 图片 |
| `image_model` 生图 | Prompt / 参考图(多) / 首图 | 图片 / 图片集 |

**端口有 `dataType`**：`text` / `image` / `asset` / `json` / `any`
**端口有 `multiple` / `required`** —— 这就是类型化连线，和 ComfyUI 一个路子。

## 三、那真正的缺口是什么（三条）

### 缺口 1：🔴 模板是**硬编码**的，不是数据

```typescript
if (templateId === 'idea_to_image') return createDemoDocument(title)
const batchPrompts: Partial<Record<CanvasStarterTemplateId, string>> = {...}
const nodes: CanvasNode[] = templateId === 'search_reference' || isBatchTemplate ? ... : ...
const connections: CanvasConnection[] = ...
```

**问题：**
- 加一个新模板 = **改代码**（写一个新分支）
- 这正好违背你说的"不用重新改代码"
- 用户自己搭好的图，**存不成模板**
- 模板不能分享、不能版本化

**这才是要改的地方**：模板从"代码里的 if 分支"变成"数据库里的一条记录"。

### 缺口 2：🔴 节点只覆盖"生图"这一段

现在的 10 个节点，全在**图像生成**这个环节：
文本 → 提示词 → LLM → 生图 → 批量生图 → 图像处理 → 搜索 → 选素材

**我们链路前面那 7 步没有节点：**
```
❌ 提取世界观   ❌ 画世界地图   ❌ 建角色
❌ 写大纲       ❌ 写剧本       ❌ 拆分镜
❌ 生成视频     ❌ 剪辑出片
```

**所以现在只能用画布做"出图"，做不了整条链路。**

### 缺口 3：没有"模板管理"

- 没有模板列表页
- 没有"这套图存为模板"
- 没有"从模板新建"之外的入口（不能分享、不能收藏）

## 四、修正后的路线（和前面完全不同）

### ❌ 不做的

| 不做 | 为什么 |
| --- | --- |
| 不做工作流引擎 | **已经有了** |
| 不做节点连线系统 | **已经有了**（比大多数平台还强） |
| 不画"十步链路图" | 前面结论不变（阶段框不可操作） |

### ✅ 要做的（按价值排）

| # | 做什么 | 为什么 | 改动量 |
| --- | --- | --- | --- |
| **1** | 🔴 **模板从硬编码 → 数据表** | 加模板不改代码 = 你最初的意思 | 中（建表 + 迁移 6 个现有模板 + 读取改造） |
| **2** | 🔴 **「这套图存为模板」** | 用户搭一次能复用 | 中（序列化 + 保存 + 列表页） |
| **3** | 🔴 **补领域节点**（提取角色 / 写剧本 / 拆分镜 / 生成视频 / 出片） | 才能覆盖整条链路 | **大**（每个节点要接后端能力） |
| 4 | 模板列表 + 分享 | 生态 | 小-中 |
| 5 | 分镜表节点（结构化，带镜号/时长） | 漫剧必需 | 中 |

**顺序建议：1 → 2 → 3 → 5 → 4**

> **1 和 2 是"让机制可用"，3 是"让机制有用"。**
> 先做 1、2，你能立刻看到"加模板不改代码"的效果。

## 五、一个必须说清的判断

**我们不是"要做一个工作流画布"，而是"已经有一个工作流画布，但它的模板是焊死的"。**

这两句话的工程量差 10 倍。

**如果按前面讨论的"要不要做工作流"去立项，会做一堆重复的东西。**
**正确的立项是：把已成熟的引擎"打开"，让它能装新模板、新节点。**
