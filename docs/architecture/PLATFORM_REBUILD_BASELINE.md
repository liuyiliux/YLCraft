# YLCraft 平台重构基调（2026-10-19）

> **这份文档是重构的宪法。**
> 来自六家平台的一手调研（Lovart / LibTV / Toonflow / BeefTV / ArtCraft / OhMyGame）
> + 一篇学术分类法（IUI '26）
> + 我们自己踩过的坑。
>
> **凡是冲突，以本文为准。**

---

## 零、一句话基调

> **我们的对手不是"功能更多的平台"，是"用户看不懂的平台"。**
> **所以：门槛优先于能力，克制优先于丰富。**

---

## 一、六家平台的优缺点（调研结论）

| 平台 | 值得抄 | 教训（别抄） |
| --- | --- | --- |
| **Lovart** | 界面只有 **2 个区域**（画布 + Agent）<br>点图就地编辑<br>**Agent 讲"设计解说"不讲自检**<br>**画布巡检**（跨图一致性）<br>自定义工具栏（★置顶）<br>记忆 + 自进化技能 | 无工作流 —— 纯对话撑不住多镜头/一致性 |
| **LibTV** | 五类节点全（文本/图/视频/音频/脚本）<br>**打组重跑**（不是画连线）<br>Slash 六项（多机位/三视图/25宫格）<br>文件夹整组加载<br>历史批量用 | 🔴 **门槛高**：用户原话「看了整个文档还是迷迷糊糊，完全不知道该怎么弄」<br>🔴 节点命名混乱「满屏幕图片节点1.2345」<br>🔴 不能中止<br>🔴 缩放难受 |
| **Toonflow** | **内容节点 / 生成节点分离**<br>**10 个 Agent 工具（含 18 个画布操作）**<br>节点插件化（`packages/nodes/*`）<br>3D 导演台共享 scene + 多方案 diff<br>**工具返回 `valid` 才允许声称完成** | 要文档 + 视频教程才会用<br>本地工具，无后端业务 |
| **BeefTV** | **「已保存」vs「已测试」两档状态**<br>隐藏连线 / 小地图 / 版本记录<br>状态用小圆点不用色块 | — |
| **ArtCraft** | **成本 chip 常驻**<br>分段控件（Build\|Record）<br>工具分组带分隔线 | — |
| **OhMyGame** | **报告四段式**：结论 / 做了什么 / 🔴**没做什么** / 需要你<br>改动规模 `+122 -0`、运行时长<br>引擎术语 vs 编辑器术语两套词 | — |

**IUI '26 分类法**（9 个 agent 实测归纳）把"可解释性"拆成六类：
可见性 / 动作描述 / **推理透明（含不确定性）** / 下一步预览 / 计划呈现 / 运行状态。
→ 证明「我确认的」和「我没法确认的」**本来就不是一类，不能并列**。

## 二、产品基调（4 条）

### P1. 🔴 门槛优先于能力

**原则**：加任何功能前先问一句 —— **外行能不能不看文档就会用？**

| 依据 | 反面教材 |
| --- | --- |
| `DESIGN.md` 第一条约束「降低门槛」 | LibTV 有完整文档 + 视频教程，用户仍说「完全不知道该怎么弄」 |
| Lovart 只留 2 个区域 | 我们的导航 8 组 44 项摊平 |

**检查**：
- [ ] 这个功能，新用户第一次打开能找到吗？
- [ ] 需要读文档才能用吗？
- [ ] 默认值合理吗（不用配置就能出结果）？

### P2. 🔴 默认一条路，进阶才分岔

**原则**：默认视图只保留主路径；高级能力折叠，但**不藏死**。

| 依据 | 反面教材 |
| --- | --- |
| Lovart 画布只有画布 + Agent | LibTV 一来就是节点图 + 5 类节点 |
| Toonflow 的 8 节点要教程 | — |

**检查**：
- [ ] 首屏能不能只看到一条清晰的路？
- [ ] 高级功能在哪里，找得到吗（不是藏起来，是折叠）？
- [ ] 参数默认露出 ≤3 个？

### P3. 同一能力，两个入口

**原则**：**页面对话式**（坐下来慢慢做）+ **节点流程式**（搭好自动跑）并存。
两者**都调同一份后端能力**，互不依赖。

| 依据 | 反面教材 |
| --- | --- |
| Toonflow：页面 + 节点 + Agent 三入口 | 我们之前想"页面抽 run() 给画布调"——侵入式，方向错 |

**检查**：
- [ ] 这个能力有"手工"和"自动"两个入口吗？
- [ ] 两个入口结果一致吗（参数能全量传）？

### P4. 🔴 加新用途 = 加配置

**原则**：加用途不该改核心代码。

| 做法 | 改哪 |
| --- | --- |
| 加基础节点 | 加一个节点类型 |
| **加复杂节点（包装已有页面）** | **画布侧加一个 spec，页面不动** |
| 加模板 | 连好的图存成模板 |
| 加技能 | SKILL.md |

| 依据 | 反面教材 |
| --- | --- |
| Toonflow 插件化（`packages/nodes/*`）+ 插件市场 | 我们之前的模板硬编码在 `createCanvasStarterDocument` 的 if 分支里 |

**检查**：
- [ ] 加这个功能要改几个文件？超过 3 个说明结构不对；
- [ ] 能不能用配置表达，而不是写代码？

## 三、交互基调（5 条）

### I1. 🔴 说人话：讲"设计"，不讲"验证"

**原则**：Agent 汇报**不要贴自检 chip**，要讲「我做了什么设计、为什么」。

| ❌ 别这样（我做过） | ✅ 这样（Lovart 实拍） |
| --- | --- |
| `[原图保留][脸没变形][光位一致]` | `磨皮：保留了皮肤纹理和毛孔，没有磨成塑料感`<br>`背景：主光位跟着原图走`<br>`如需调整…告诉我` |

**依据**：Lovart 2.0 实测报告结构 = 完成 → 3~5 条设计要点 → 尺寸/用途 → 邀请调整
**反面**：把"我确认的"和"我没法确认的"并列成 chip（IUI '26 证明这是两类）

**检查**：
- [ ] 这段话用户能直接拿去发给客户吗？
- [ ] 说的是"为什么这么设计"，还是"我检查过了"？

### I2. 🔴 检查必须是独立动作，且带证据

**原则**：不做"生成后自动贴一句"，要做「**巡检**」这个独立动作。

| 做法 | 依据 |
| --- | --- |
| 检查**一整套**（不是单张） | Lovart 画布巡检：「一套图，单张看着还行，放到一起就可能发现字体、风格不一样」 |
| 每个问题**带可验证数字** | Toonflow：「必须确认 `valid` 为 true 才能声称完成」 |
| 问题**定位到具体位置** | Lovart：回到画布看「'好'字跟封面笔迹没对上」 |
| 分级：要修 / 建议 | 我们自己的 |

**检查**：
- [ ] 检查结果是"我觉得有问题"还是"相似度 0.62 低于 0.85"？
- [ ] 能不能一键跳到出问题的地方？

### I3. 价格永远可见，且来自配置

| 做法 | 依据 |
| --- | --- |
| 成本 chip 常驻 | ArtCraft `Costs 14` |
| 每项操作标价 | Lovart 右键菜单 `矢量 ⚡9` / `编辑文字 ⚡14` |
| 按价格分组，不按功能分组 | 我们自己的（便宜→贵，用户一眼知道哪组贵） |
| **价格从模型配置算** | 我们 `ai_connector.py` 已有 `price_per_call`，要补 `price_per_unit` + `unit` |

**检查**：
- [ ] 点之前知道花多少吗？
- [ ] 换模型价格会跟着变吗（不是硬编码）？

### I4. 状态分级，不用色块刺激

| 做法 | 依据 |
| --- | --- |
| 状态用**小圆点**，不用彩色 tag | BeefTV |
| 区分「已保存」和「已测试」 | BeefTV 两档 |
| 失败态用"缺"表达，不是大红块 | 我们自己的（灰化 + 「403」角标） |

### I5. 空态必须有下一步

**原则**：空白页是最容易流失的地方。

| 做法 | 依据 |
| --- | --- |
| 4 个入口，选一个就能开始 | 我们 v14 |
| 「从一个想法开始」不是「暂无数据」 | — |

**检查**：
- [ ] 空态能点的地方 ≥3 个？
- [ ] 每个入口都有明确产物？

## 四、工程基调（3 条）

### E1. 🔴 页面与节点是兄弟

```
        后端能力（同一份 API）
              ▲          ▲
      ┌───────┴──┐  ┌────┴─────────┐
      │ 页面 (UI) │  │ 画布节点       │
      └──────────┘  └───────────────┘
```

**页面完全不知道画布的存在。画布侧写 spec 去理解页面能力。**

| ❌ 错 | ✅ 对 |
| --- | --- |
| 页面抽 `run()` 给画布调（侵入） | 画布侧 spec 描述「这页能干什么、怎么调」 |
| 在页面里加"导出为节点" | spec 在画布侧维护 |

**唯一例外**：纯前端计算的能力（如 `image-editor` 的裁剪/滤镜）→ 抽成**共享纯函数**，页面只改 import。

### E2. 🔴 拖拽期间不重建被拖 DOM

**这条我踩了两次，必须写进基调。**

```js
// ❌ 错：pointerdown 里重建，正在拖的元素消失
gSel = id; renderGraph();

// ✅ 对：只改 class，拖完再重建
gSel = id;
el.parentNode.querySelectorAll('.x').forEach(x => x.classList.toggle('sel', ...));
```

**检查**：拖拽时元素会不会"跳一下就不动了"？

### E3. 未知就标未知

**原则**：灰掉的功能要**说明为什么**，不要假装有，也不要藏起来。

| 做法 | 依据 |
| --- | --- |
| 灰项 + 底部一行说明 | 我们 v14：「灰掉的三项：画面推演要视频模型、矢量/Mockup 暂不做」 |
| 未验证就写"未验证" | `AGENTS.md` 报告规则 |
| 报告里必须有「没做什么」 | OhMyGame 四段式 |

## 五、违规清单（快速自检）

| 症状 | 违反 | 改法 |
| --- | --- | --- |
| 界面一屏 ≥4 个区块 | P2 | 折叠到 2~3 个 |
| 用户要看文档才会用 | P1 | 空态引导 + 默认值 |
| 加功能改了 5 个文件 | P4 | 抽出配置/spec |
| Agent 汇报贴了一串 chip | I1 | 改成设计解说 |
| 说"已检查通过"但没有数字 | I2 | 给证据 |
| 价格硬编码 | I3 | 从配置读 |
| 状态用大红大绿块 | I4 | 换小圆点 |
| 空页面只有"暂无数据" | I5 | 给 3 个入口 |
| 页面里出现 `canvasNodeId` / `source_node_id` | I1 + E1 | 引擎术语不外露 |
| 拖拽不跟手 | E2 | 查是否重建了 DOM |
| 功能灰着但不解释 | E3 | 写明原因 |

## 六、和三层模型的关系

| 层 | 谁用 | 基调管什么 |
| --- | --- | --- |
| **基础功能 L1** | 两个入口都会调 | I3（价格）、E1（兄弟关系） |
| **组合功能 L2** | 页面 | P1/P2（门槛）、I1/I2（Agent 表达） |
| **画布 L3** | 节点 | P4（加配置）、E2（拖拽） |

**三层在架构里，导航按任务分：工具 / 工作台 / 画布。**

## 七、这份基调怎么用

1. **写新功能前**：对照第二节 P1-P4 过一遍
2. **做 UI 前**：对照第三节 I1-I5
3. **改代码前**：对照第四节 E1-E3
4. **提交前**：走一遍第五节的违规清单
