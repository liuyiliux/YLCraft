# 链路长，画布要不要承担"链路可见"（2026-10-18）

> 讨论稿。Lovart 的链路是 `上传素材 → 套模板 → 出成品`，三步。
> 我们是 `小说 → 世界 → 角色 → 大纲 → 剧本 → 分镜 → 图 → 视频 → 剪辑 → 出片`，十步。
> **所以"画布要不要画链路"这个问题，只有我们能回答。**

---

## 一、先把"链路长"具体化

我们现在的实际形态（`DENIGN.md` + 44 个页面）：

| 阶段 | 现在在哪个页面 |
| --- | --- |
| 小说源 / 书源 | `/novel-search` `/novel-bookshelf` `/book-source` |
| 世界提取 | `/novel-world` |
| 世界地图 | `/world-map` |
| 角色 | `/characters` `/character-detail` |
| 大纲 / 章节 / 正文 | `/story`（项目总览 + 单章工作室） |
| 剧本 / 分镜 | `/story` 里 |
| 图 | `/image-gen` |
| 视频 | `/video-gen` |
| 剪辑 / 字幕 / 配乐 | `/clip` `/clip-ops` `/subtitle` `/bgm` |
| 出片 | `/publish` |
| 画布 | `/canvas` |
| 任务状态 | `/tasks` |
| 素材 | `/assets` |

**所以"链路可见性"其实已经分散在 `/story` + `/tasks` + `/assets` 里了。**

## 二、四个选项

### 选项 A：画布 = 链路全景（每个阶段一个节点）

```
[小说源] → [世界观] → [角色] → [剧本] → [分镜] → [图] → [视频] → [成片]
```

**优点**：一眼看到整条链路、知道卡在哪
**缺点**：
- 🔴 和 `/story` 项目总览**重复**
- 🔴 这些阶段**不是"要组装的产物"**，是"流程阶段"。放在画布上你也不能拖它们
- 🔴 44 个页面已经能做这些事了，画布再画一遍是第三遍

**结论：❌ 不做。**

### 选项 B：画布 = 只管产物组装（Lovart 模式）

画布上只有：图片、视频、文本、图层组。
看不到"这个镜头从哪来"。

**优点**：干净、专注、和 Lovart 一致
**缺点**：
- 🔴 我们链路长，**用户会问"这张图是哪一场的"**
- 🔴 少了最重要的信息：**这个产物属于哪一环**

**结论：⚠️ 不够，但方向对。**

### 选项 C：✅ 画布只放产物，但每个产物**带溯源**

画布上还是只有产物节点，但每个节点**能展开看它从哪来**：

```
┌─ 分镜 3 · 窗边午后 ─────────────┐
│                                 │
│   [图片]                         │
│                                 │
│ 来源 ▾                           │
│   剧本：第 3 场 · 窗边独坐         │
│   角色：女主角（角色库 #a1f）      │
│   提示词：来自「分镜导演」技能      │
│   上游：分镜表第 3 行             │
└─────────────────────────────────┘
```

**优点**：
- 画布保持干净（只放产物）
- 溯源**按需展开**，不占地方
- 复用我们 Asset Hub 已有的**血缘**能力

**结论：✅ 这是主干。**

### 选项 D：同一画布，多种**视图**

不是多种画布，是**同一份数据的几种看法**：

| 视图 | 看什么 | 什么时候用 |
| --- | --- | --- |
| **画布视图** | 自由摆放、连线 | 组装、试排布 |
| **镜头墙** | 所有分镜按顺序排成网格 | 看节奏、看连贯性 |
| **时间线** | 按时间排 | 出片前调顺序 |

**优点**：不用造三种画布，只做三个视图
**缺点**：工程量在"视图"上，但比造三种画布小得多

**结论：✅ 值得做，但排在后面。**

## 三、我建议的答案

### 画布**不承担**"链路全景"，那是项目总览的活

**链路可见性分三层，各归各：**

| 层 | 在哪看 | 看什么 |
| --- | --- | --- |
| **项目级** | `/story` 项目总览 | 十步走到哪了、哪个阶段卡住 |
| **产物级** | 画布节点「来源 ▾」 | 这个图从哪来（剧本/角色/提示词） |
| **任务级** | `/tasks` | 异步任务跑没跑完 |

**画布只管"这一段要组装的东西"。**

### 🔴 但有个关键区分：阶段节点 vs 引用节点

这是我想到的最重要的一条规则：

| 类型 | 是什么 | 进不进画布 |
| --- | --- | --- |
| **阶段节点** | 小说源 / 世界观 / 角色库 / 大纲 | ❌ **不进** |
| **引用节点** | 这场戏的角色卡、这场戏的剧本片段、这张图的参考图 | ✅ **进** |

**为什么？**

- 阶段节点是**流程**，你没法在画布上"拖它"
- 引用节点是**素材**，组装时你确实要把角色卡拖到画布上看

**举例**：
- ❌ 不要把"世界观"作为一个节点放在画布上
- ✅ 要把"女主角的角色卡"作为参考节点放在画布上

## 四、为什么不做选项 A（链路全景）

三条理由：

1. **和 `/story` 重复** —— 项目总览已经在做这件事
2. **阶段不可操作** —— 你在画布上拖"世界观"能干什么？
3. **会变成一张看不懂的大图** —— 十步 × 多个项目 = 一屏蜘蛛网

**但反过来，"镜头墙"是有价值的**（选项 D）：
- 看整条片子的**节奏**
- 看**连贯性**（角色有没有变）
- 这是**真实的创作需求**，不是流程可视化

**所以：不要链路图，要镜头墙。** 这两件事经常被混为一谈。

---

## 五、对我们产品的一个提醒

**我们最大的差异化可能在"链路"，但"链路"的正确表达不是画布。**

`DESIGN.md` 说我们有"小说→世界→角色→分镜"这条链，
**这条链的竞争壁垒在"每一环的质量"，不在"能不能画出来"。**

- 画一条链路图，谁都能画
- 但"从小说自动提取世界观、生成一致的角色、产出可拍的分镜" —— 这个没几家能做

**所以画布不该是链路图，该是"链路的最后一环：把产物组装成片"。**

## 七、一句话

**链路可见性 ≠ 画布画链路。**

**项目总览看链路，画布看产物，节点里的「来源」看单点溯源。**

**而"镜头墙"是真正有价值的东西 —— 它不是链路图，是节奏图。**
