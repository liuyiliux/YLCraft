## 一、🔴 先纠一个可能的大坑：许可对不上

### 事实

| 来源 | 说 |
| --- | --- |
| `frontend/src/components/canvas/NOTICE.md` | 「adapted from `basketikun/infinite-canvas` … **License: GNU Affero General Public License v3.0**」<br>「should be treated as **AGPL-3.0-compatible derived work**」 |
| 上游仓库实际 `LICENSE` 文件 | **`MIT License`**<br>`Copyright (c) 2026 basketikun` |
| GitHub API 识别 | `MIT` |
| 规模 | **7,748 star** |

### 这意味着什么

**MIT 是最宽松的许可** —— 可以改、可以闭源、可以商用，只要保留版权声明。

**我们的 NOTICE 写成了 AGPL，等于自己给自己上了枷锁：**
- AGPL 要求我们**整套服务端代码都要开源**
- 但上游根本没那么要求

### 两种可能

| 可能 | 说明 |
| --- | --- |
| **A. NOTICE 写错了** | 当初抄的时候看错了，或者抄的是别的项目的许可 |
| **B. 抄的时候加了 AGPL 的部分** | 我们除了 infinite-canvas，还混了别的 AGPL 代码 |

**必须查清是哪种。** 查法：
1. 对比我们的 `InfiniteCanvasSurface.tsx`（39.4 KB）和上游源码
2. 看有没有来自其他地方（比如我们之前研究里提到的 `tigerowo/infinite-canvas`，那是 **AGPL-3.0**）的代码

> ⚠️ **注意：我们调研里出现过两个同名项目**
> - `basketikun/infinite-canvas` —— **MIT**，7,748★
> - `tigerowo/infinite-canvas` —— **AGPL-3.0**，1,210★
>
> **很可能当初抄的是后者，或者两者混了。** 这是必须查的。

## 二、技术选型：三条路

### 选项 1：继续改 `basketikun/infinite-canvas`（MIT）

**现状**：我们已经在用它（视口/世界层/网格/缩放平移）。

**它的定位**（上游 description 原文）：
> 「面向 AI 创作的开源无限画布工作台，集成 **AI 生图、参考图编辑、视频生成、Agent 智能助手**」

**这几乎就是我们要做的东西。**

| 优势 | 劣势 |
| --- | --- |
| ✅ **已经在用**，改动最小 | ⚠️ 它的数据模型未必合我们的（我们要节点图 + 图层） |
| ✅ MIT，随便改 | ⚠️ 7.7k star 的项目可能迭代快，跟版本有成本 |
| ✅ 定位完全对得上（AI 创作画布） | |
| ✅ 有参考图编辑、Agent 这类我们想要的 | |

### 选项 2：换成 React Flow（`xyflow/xyflow`，38,705★，MIT）

**现状**：**我们前端没装任何画布库**（`package.json` 里 0 个匹配 `flow|canvas|konva|fabric`）。

**React Flow 是节点图的事实标准**：
- 38,705 star
- MIT
- 专门做节点图（不是自由画布）
- 生态大、文档全

| 优势 | 劣势 |
| --- | --- |
| ✅ **节点图是它的本职** | 🔴 **要重写整个画布**（我们 7,487 行） |
| ✅ MIT，无包袱 | 🔴 丢掉已有的端口校验/循环检测/关系类型 |
| ✅ 手写节点卡片，样式完全可控 | |

### 选项 3：双视图 —— 同一份数据两种渲染

**这正好是你问的第 3 个问题。**

```
同一份 canvas.document
    ├── 节点图视图（React Flow 或现有实现）
    └── 卡片墙视图（Lovart 那种图片卡片）
```

| 优势 | 劣势 |
| --- | --- |
| ✅ 满足你喜欢的 Lovart 卡片样式 | 两套渲染都要维护 |
| ✅ 看流程用节点图，看成品用卡片墙 | |

## 三、我的建议

### 🔴 先查许可，这决定后面一切

**如果确认是 MIT**（NOTICE 写错）：
→ **继续用 `basketikun/infinite-canvas`，不重写。** 我们 7,487 行有大量自己的东西（端口校验、循环检测、relation 类型、WorkflowTrace），这些不在上游，重写等于白扔。

**如果确实混了 AGPL 代码**：
→ 要么把那一部分替换掉，要么接受 AGPL。

### 关于第 3 个问题：Lovart 卡片样式能切换

**能，而且我认为应该做成"两个视图"而不是"换掉节点图"：**

```
画布顶栏：  [编辑 | 运行]         [节点图 | 卡片墙]
```

| 视图 | 什么时候用 | 长什么样 |
| --- | --- | --- |
| **节点图** | 搭流程、看数据流、debug | 现在 v6 原型 |
| **卡片墙** | 看成图、挑素材、给客户看 | Lovart 那种大图卡 |

**同一份数据，两种看法。** 类似 ArtCraft 的 `Build | Record` 切换。

**但要注意**：卡片墙看不到"这张图是怎么来的"，适合**成品筛选**，不适合**搭流程**。
