# Agent 和工作流到底搭不搭（2026-10-19 关键判断）

> 你问的：**「agent 这个和工作流是不是不太相符？Lovart 是直接对话生成图、放大图上编辑，我们这个 agent 加工作流是不是不太搭？」**
>
> **结论：你的直觉对。Agent + 节点图工作流做成两个并列界面，是错配。**
> **但工作流本身不是错的 —— 错的是把它当成「用户的界面」。**

---

## 一、先把两种模式摆清楚

### Lovart 的模式：Agent = 唯一界面

```
对话 → 图生成出来 → 图摆在画布上 → 点图放大 → 在图上编辑
```

**用户从头到尾只接触两样东西：话，和图。**

- 没有节点
- 没有连线
- 没有"数据流向"
- 用户不需要知道"这一张图经过了哪几步"

**为什么它能这么干净？** 因为 Lovart 主要做**单次成品**：
电商主图、海报、营销图。一张一张出，每张独立，天然不需要"结构"。

### 我们现在的模式：两条界面并行

```
画布（节点图 + 连线 + 端口 + 执行轨迹）   ←→   Agent 侧栏（对话 + 报告）
```

**用户要同时理解两个东西**：话怎么说，和 图怎么连。

**这就是你说的"不搭"。** 而且是真不搭：

| 冲突点 | 说明 |
| --- | --- |
| **心智模型冲突** | 对话是"我说你做"，节点图是"我搭你跑"。两个相反的姿态 |
| **注意力分裂** | 用户不知道"我该在哪儿干活" |
| **门槛冲突** | `DESIGN.md` 要求"用户不必理解 Tool schema"，但节点图本身就是 schema |
| **报告和画布抢戏** | Agent 报告说"我改了什么"，但画布上用户看不出改了哪儿 |

## 二、但我们也不能纯抄 Lovart —— 场景不同

**我们的场景是"多镜头连续内容"，不是"单张成品"。**

| | Lovart 场景 | 我们的场景 |
| --- | --- | --- |
| 产出 | 一张主图 / 一张海报 | **20 个镜头，要连贯** |
| 一致性 | 不需要 | 🔴 **角色/场景要跨镜一致** |
| 重复性 | 每次不一样 | 🔴 **同样的模板要反复用** |
| 批量 | 少量 | 🔴 **批量角色/场景/道具** |
| 修改 | 整体重出 | 🔴 **只改第 3 镜，别动其他** |

**纯对话在这些地方会崩：**

1. **看不见全局** —— 20 个镜头靠聊天记录找？找不到
2. **改不动局部** —— "把第 3 镜左边那个人挪一下"，纯对话做不到精确
3. **复不了现** —— 这次做对了，下次怎么一模一样再来一遍？
4. **控制不了成本** —— 一句话触发 10 次生成，钱怎么算？

**所以工作流要存在 —— 但不该出现在用户面前。**

## 三、正确的分工

> **Agent 是界面，工作流是引擎。**

```
┌─────────────────────────────────────────────────┐
│  用户能看到的                                     │
│                                                  │
│   ┌──────────┐        ┌──────────────────┐      │
│   │  内容视图  │        │   Agent 对话      │      │
│   │  镜头 / 图  │   ←→   │  （主输入）        │      │
│   └──────────┘        └──────────────────┘      │
│                                                  │
│   ┌──────────┐                                   │
│   │  模板选择  │  ← 一次性，选完就不看了           │
│   └──────────┘                                   │
├─────────────────────────────────────────────────┤
│  用户看不到的（引擎）                              │
│                                                  │
│   节点图 / 端口 / 依赖 / 执行轨迹 / 重试 / 成本      │
└─────────────────────────────────────────────────┘
```

### 三条界面规则

| 规则 | 做法 |
| --- | --- |
| 🔴 **默认看到的是内容，不是结构** | 打开画布就是镜头/图片，不是节点框 |
| 🔴 **Agent 是主输入** | 对话 + @ 引用 + 点图就地编辑 |
| 🔴 **工作流藏在"选模板"和"高级视图"后面** | 普通用户永远不用看图 |

## 四、那"节点图"怎么办

**它没被删掉，只是降级了。**

| 视图 | 谁看 | 什么时候 |
| --- | --- | --- |
| **内容视图**（默认） | 所有人 | 日常，看镜头、挑图、编辑 |
| **模板卡片** | 所有人 | 新建画布时选一次 |
| **节点图**（高级） | 想改流程的人 | 点「高级 ▾ → 看流程」才出现 |

**节点图的价值还在**：
- 你想改"先出图再抠图"还是"边出边抠" → 进高级视图改一次
- 某一步失败了要看是哪步 → 进高级视图
- 想把这套流程存成模板 → 进高级视图

**但它不是日常界面。**

> 🔴 **这正好回到底层那条判断：**
> 「模板 = 预连好的节点图，用户选模板不选节点」
> 你之前说的"做好基础节点+提供不同模板"，本意就是这样 —— **节点是给做模板的人用的**。

## 五、"放大图片上编辑"—— 你说得对，这个我们必须有

Lovart 这个交互是对的，而且比我们现在的"双击节点进图层编辑器"顺得多：

### Lovart 的做法

```
点图 → 图片放大（几乎全屏）→ 右键/工具条就地操作 → 返回
```

**它的好在**：
- **无层级跳转感** —— 不是"进入某个页面"，是"把这张图放大"
- **周围还有上下文** —— 附近几张图还看得见
- **操作直接挂在图上** —— 不挂在节点上

### 我们应该改成

```
点 图片/镜头 → 居中放大（带柔和的展开动画）
                ├─ 右键：局部重绘 / 扩展 / 抠主体 / 多角度 / 换装
                ├─ 顶部：重新打光 / 图层 / 保存到素材库
                └─ Esc 或点旁边：关掉，回到内容视图
```

**关键差别**：**放大的是「这张图」，不是「这个节点」。**
用户脑子里没有"节点"这个概念。

## 六、修正后的完整模型

```
                      用户说什么
                          │
                          ▼
        ┌────────────────────────────────┐
        │        Agent（唯一入口）         │
        │  对话 / @引用 / 点图就地编辑     │
        └───────────────┬────────────────┘
                        │ 内部调用
                        ▼
        ┌────────────────────────────────┐
        │   工作流引擎（用户不可见）        │
        │   节点 / 依赖 / 执行 / 重试      │
        │   成本核算 / 产物落盘            │
        └───────────────┬────────────────┘
                        │ 产出
                        ▼
        ┌────────────────────────────────┐
        │   内容视图（用户看到的画布）      │
        │   镜头墙 / 图片 / 可放大可编辑    │
        └────────────────────────────────┘

   旁路：新建时选模板 → 拿到一套预连好的引擎配置
        想改流程 → 「高级 ▾」才看节点图
```

## 九、还没解决的一个真问题

**内容视图怎么表达"顺序"和"连贯性"？**

Lovart 是自由摆放，不需要顺序。但我们要"第 1 镜 → 第 2 镜 → 第 3 镜"。

两个候选：

| 方案 | 长什么样 | 好处 | 坏处 |
| --- | --- | --- | --- |
| **镜头墙**（网格 + 镜号） | 一排排格子，每格一个镜头，带编号 | 一眼看全片节奏 | 看不出连贯关系 |
| **自由画布**（像 Lovart） | 图自由摆，可拖 | 灵活、可用空间表达关系 | 顺序要靠人维护 |

**我倾向：镜头墙为主 + 允许切自由画布。** 但这个需要你看一眼再定。
