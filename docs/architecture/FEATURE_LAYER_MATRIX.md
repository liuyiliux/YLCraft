# 功能归属矩阵：这轮加的东西哪些是「基础」

> 你的提醒：「**我们的设计是基础、页面、画布同步**」
>
> 这轮加的十几个功能，如果不定位，实现的时候就会各写一套。
> **这份就是把每个能力钉到三层里，说清"同一件事在哪层出现、什么形态"。**

---

# 一、先回到三层定义（你的原话）

| 层 | 你的定义 | 特征 |
| --- | --- | --- |
| **L1 基础** | 「图片裁剪，AI 生图这种**一个点**的，**没复杂逻辑**的」 | 一次输入一次输出，没有流程 |
| **L2 页面组合** | 「创建项目这种**页面上拼接了功能**的」 | 多个 L1 按界面拼起来，有步骤 |
| **L3 画布** | 「用**基础节点和复杂节点拼接**出来的」 | 可编排、可复用、可连线 |

## 🔴 核心规则 E1：页面与节点是兄弟

> **同一件事，画布不该"调用页面"，页面也不该"提取成节点"。**
> **两者都调同一个 L1 能力，各自有各自的壳。**

```
              ┌──────────────┐
              │  L1 能力定义  │   ← 只有一份
              │  CAPS / 接口  │
              └──────┬───────┘
                     │
        ┌────────────┼────────────┐
        ↓            ↓            ↓
   L1 页面入口   L2 页面组合   L3 画布节点
   （工具页）    （流程页）    （基础/复杂节点）
```

**这轮我做的很多界面，其实是"壳"** —— 真正的资产是它们背后那个 L1 能力。

# 二、归属矩阵（这轮全部功能）

## 2.1 搜索 / 知识获取

| 能力 | L1（能力） | L2（页面） | L3（画布） |
| --- | --- | --- | --- |
| `web_search` | ✅ **能力本体**<br>queries[] + intent | 独立搜索页（还没做） | Agent 对话里触发 → **画布节点** |
| `web_asset` 下载图 | ✅ **能力本体** | — | 存入素材库 → 喂给生图节点 |
| **要素抽取**（appearance/reference-image） | ✅ **能力本体**<br>抽出来的结构化要素 | **搜索流程页**（我做的那个卡片） | 要素锁定节点 |
| **主体 schema**（6 种类型） | ✅ **数据定义**<br>人像/商品/场景/海报/UI/混合 | 搜索页里选类型 | 节点参数里的类型选择 |
| **要素 editable**（改/填/加/删） | ✅ **能力**（改的是结构） | 搜索页组件 | 节点参数面板复用 |

🔴 **关键判断**：搜索链路的「抽要素」是 **L1 能力**。
那个长得像流程的卡片，只是**它在 L2 的一种呈现**。
画布里换个壳（要素锁定节点）就沿用同一个能力。

## 2.2 图片处理

| 能力 | L1 | L2 | L3 |
| --- | --- | --- | --- |
| **31 项操作**（裁剪/滤镜/局部重绘…） | ✅ **每一项都是 L1** | 图片编辑页的工具栏 | 点图浮条 + 右键菜单 |
| **本地精调**（曝光/色阶/曲线/分通道） | ✅ **一个 L1 能力**<br>（输入参数 → 输出图） | 精调面板（右侧滑块+曲线） | 「调色节点」的参数面板 |
| **RAW 导入**（16bit 线性解码） | ✅ **一个 L1 能力** | 导入页（我做的 5 步） | 拖 RAW 进画布 → 素材节点 |
| **导出合成**（层按序合并） | ✅ **一个 L1 能力** | 导出页（我做的占位） | 出片节点的导出设置 |

🔴 **重要**：**本地精调不是"一个页面功能"，它是一个后端能力。**
```
POST /api/image/adjust
  { asset_id, exposure, contrast, temp, levels{}, curves{} }
  → { new_asset_id }
```
- 图片编辑页调它
- 画布的调色节点也调它
- **同一个接口，两处入口**

## 2.3 质检 / 巡检

| 能力 | L1 | L2 | L3 |
| --- | --- | --- | --- |
| **巡检算法**（L1免费/L2本地模型/L3语义） | ✅ **一个 L1 能力** | — | — |
| **巡检报告**（问题+证据+修法） | 数据来自 L1 | **巡检页**（我做的面板） | 画布「巡检」按钮（同一份报告） |
| **本地能修 vs 调模型** 的分组 | ✅ **判断逻辑在 L1**<br>（哪些问题本地能修） | 报告里的分组 | 同 |

🔴 **「本地能修 vs 要调模型」这个判断必须放在 L1** ——
因为画布批量跑的时候，也要靠它决定"哪些自动修、哪些停下来问人"。

## 2.4 编辑基础设施

| 能力 | L1 | L2 | L3 |
| --- | --- | --- | --- |
| **图层数据模型**（非破坏，层=参数） | ✅ **数据结构**（文档层） | 图层面板 | 同（画布的每张图也有层） |
| **撤销历史**（快照栈） | ✅ **基础设施** | 历史面板 | 同 |
| **提示词库** | ✅ **资产**（和素材库同级） | 词库页（我做的） | 输入框 @ 引用 |
| **主体类型自动判断** | ✅ **一个 L1 判断函数** | 切类型的地方 | 同 |

## 2.5 这轮没做但属于 L1 的（从三层定义推出来）

| 应该有哪些 L1 能力 | 为什么 |
| --- | --- |
| `image.crop / rotate / filter` | 6 项本地操作 |
| `image.adjust` | 曲线/色阶/曝光/白平衡 |
| `image.raw_decode` | RAW → 16bit 线性 |
| `image.export` | 层合成 + 编码 |
| `image.inspect` | 巡检 |
| `search.web / search.asset` | 两个搜索工具 |
| `extract.elements` | 要素抽取 |
| `video.*` | 我们的老本行 |

**这些才应该写进 `CAPS`** —— 不是界面。

# 三、🔴 这轮的一个认知错误

## 我做的很多是「L2/L3 的壳」，不是 L1

| 我做的 | 实际是什么 | 缺什么 |
| --- | --- | --- |
| 搜索卡片 | L2 页面（一种呈现） | **背后的 `web_search` 能力定义** |
| 要素编辑 | L2 组件 | **`extract.elements` 的返回结构** |
| 本地精调面板 | L2 组件 | **`image.adjust` 接口** |
| 巡检面板 | L2 页面 | **`image.inspect` 接口 + 判断规则** |
| 导出面板 | L2/L3 共用 | **`image.export` 合成实现** |
| 图层面板 | L2/L3 共用 | **文档层存储格式** |

**所以这轮原型 = 把壳占住了，但 L1 的能力清单没同步更新。**

🔴 **该补的动作**：把上面这些能力写进 `CAPS`（能力定义层），
让 L2/L3 的壳都指同一个 `capKey`。

## 这轮做对的

| 做对的 | 为什么对 |
| --- | --- |
| **6 种主体 schema** | ✅ 这是 **L1 数据定义**，放对了层 |
| **AI 适配度能分级**（本地/调模型） | ✅ 判断逻辑该在 L1 |
| **主链路状态联动** | ✅ L3 的职责（编排状态） |
| **点图浮条** | ✅ 明确是 L3 交互（画布特有） |

# 四、同一件事在三层分别长什么样（例子）

## 例 1：曲线调色

| 层 | 形态 | 交互 |
| --- | --- | --- |
| **L1** | `image.adjust({exposure, levels, curves})` | 无界面 |
| **L2** | 图片编辑页 → 右侧面板拖动滑块 | 见即所得，逐个调 |
| **L3** | 「调色节点」→ 节点参数面板 | 连线批量跑 12 镜 |

**三层都是同一个接口。L3 的节点参数面板可以直接复用 L2 的面板组件。**

## 例 2：要素抽取

| 层 | 形态 | 交互 |
| --- | --- | --- |
| **L1** | `extract.elements({source, intent})` → 结构化要素 | 无界面 |
| **L2** | 搜索流程页 → 搜→抽→改→生成 | 一步一步 |
| **L3** | 「要素锁定节点」→ 输出要素给别人用 | 连线 |

## 例 3：巡检

| 层 | 形态 |
| --- | --- |
| **L1** | `image.inspect({asset_ids})` → 问题列表 + 证据 + 修法 |
| **L2** | 巡检页 → 看报告、点修 |
| **L3** | 巡检节点 → 出问题就停下来问 / 小问题自动修 |

# 五、对后面实现的指导

## 5.1 先做 L1 能力清单

**做界面之前，先把 `CAPS` 补全。** 每个能力要写清：

```ts
{
  key: 'image.adjust',
  name: '本地精调',
  layer: 'local',              // 本地运算 → 免费
  inputs: ['asset_id', 'params'],
  params: {
    exposure: { type:'number', range:[-2,2] },
    levels: { black, white, gamma },
    curves: { rgb, r, g, b }
  },
  output: 'asset_id',
  cost: 0,
  // 🔴 三层复用同一份定义
  pageEntry: '/image-editor',       // L2 入口
  nodeType: 'adjust',               // L3 节点类型
  skillEntry: null
}
```

## 5.2 壳可以粗糙，能力必须清楚

原型阶段壳体（面板/卡片）随便画，
但**每个壳背后必须能指到一个 `capKey`**。

**指不到的壳 = 假的，实现时要推翻。**

## 5.3 判断归属的三问

拿到一个新功能，问三句：

1. **它是一件事还是一个流程？**
   - 一件事 → L1
   - 有步骤 → L2
2. **它需不需要"参数"？参数是不是就那么几个？**
   - 是 → L1
   - 参数会随流程变 → L2
3. **画布上能不能把它做成一个节点？**
   - 能 → 那它肯定是 L1
   - 不能（比如"创建项目"） → 它只是 L2
