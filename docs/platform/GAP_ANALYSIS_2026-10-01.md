# 功能缺口盘点（2026-10-01）

> 用户问"下面功能还有哪些需要做的"。这份是**代码层实测盘点**，
> 不是猜测 —— 每条都标注了怎么查出来的。

| 抖音 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |

| 番茄 | ✅ | ✅ | — | — | — | ⚠️ 作家后台另有一套 |

**真实缺口**：
1. `kuaishou.get_user_profile` 未实现（搜到博主后点进去看资料会失败）
2. `bilibili` 的"我的数据"没走统一 `/users/me`（走老 `/bilibili/up/*`）——
   能用，但不统一
3. `fanqie` 只有 search/detail（它是小说站，用户维度语义不同）
4. YouTube / Telegram **没有"我的数据"** —— 这是**设计如此**
   （免登录平台没有"我的账号"概念），不是缺口

## 二、前端入口矩阵（扫各页面 PLATFORMS 数组）

| 页面 | 支持平台 |
|------|---------|
| 采集 `/crawler` | xhs, dy, ks, bili, wb, twitter, youtube, telegram, wechat_mp ✅ **最全** |
| 账号中心 `/accounts` | 全部（含 fanqie/wechat_mp/youtube/telegram） ✅ |
| 我的数据 `/my-platform-data` | bili, douyin, xiaohongshu, weibo, twitter, **kuaishou** |
| 博主中心 `/platform-users` | bili, douyin, xiaohongshu, kuaishou |

**真实缺口**：
5. **YouTube / Telegram 在「博主中心」没有入口** ——
   后端**已实现** `search_users`/`get_user_profile`/`get_user_videos`，
   属"业务可用但 UI 无入口"（skill 点名的坑）
6. **微博在博主中心没有入口**（后端 `search_users` 已实现）
7. **快手在博主中心点用户会弹错误** —— 后端没有 `get_user_profile`
   （实测确认：快手**没有**"按 id 查博主资料"的接口）

**已确认「不该加」的（不是缺口）**：
- YouTube / Telegram **不进「我的数据」页** ——
  那个页面是"查**自己**的账号"，而这两个平台**免登录**、
  没有"我的账号"概念。加了反而让用户困惑。
- 番茄不进「我的数据」—— 它是小说站，作家后台是另一套。

## 三、下载链路

| 项 | 现状 |
|----|------|
| 专用下载器 | 只有 **bilibili / douyin / twitter** 三个 |
| 其余平台 | 走 **yt-dlp 兜底** |
| 视频解析 | `/api/v1/download/parse`（yt-dlp 枚举清晰度） |
| 图片下载 | `/api/v1/download/download-images` |
| 防盗链 | `proxy.py::_guess_referer` 按**域名**猜 Referer ✅（按平台写死会漏） |
| 订阅/定时 | **没有** |
| 断点续传 | **没有** |
| 增量采集 | **没有**（每次全量搜） |
| 采集结果去重 | 靠 `source_url` 唯一（用于素材导入），**搜索层无去重** |

## 四、其它明显没做的

7. **YouTube / Telegram 的详情抽屉** 没做专门渲染
   （Telegram 消息有 HTML 富文本、图集、转发等特殊结构）
8. **评论采集** 完全没做（各平台都没做）
9. **定时/订阅采集** 没做
10. **Telegram 群组**（`t.me/s` 只对广播频道有效，群组要登录）
11. **小红书风控**（461）仍是被动——有"去官网搜"降级出口

## 五、优先级建议（我的判断）

### P0 —— 立刻能做，纯属"漏了"
- **#5**：把 YouTube/Telegram 加进博主中心和我的数据页（后端已实现，只差前端下拉）
- **#1**：快手 `get_user_profile`（搜博主后点进去能看到资料）

### P1 —— 体验明显提升
- **#7**：Telegram/YouTube 详情抽屉（现在点进去渲染可能不好看）
- **#10**：评论采集（用户常问"能不能看评论"）

### P2 —— 工程化（不是功能）
- 增量采集 / 去重 / 定时任务 / 断点续传

### 不做（明确排除）
- YouTube/Telegram 的"我的数据"（没有这个概念）
- 番茄的用户维度（它是作家后台）
