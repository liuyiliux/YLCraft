**真实缺口**：
1. `kuaishou.get_user_profile` 未实现 —— ⚠️ **已实测确认这不是"漏做"**：
   快手**没有**"按 id 查博主资料"的接口（用搜索反查 userId 也不行，
   搜索按昵称/内容索引，不按 uid）。所以这里是**平台的限制**，
   代码里已如实说明，不再当缺口。
2. `bilibili` 的"我的数据"没走统一 `/users/me`（走老 `/bilibili/up/*`）——
   能用，但不统一
3. `fanqie` 只有 search/detail（它是小说站，用户维度语义不同）
4. YouTube / Telegram **没有"我的数据"** —— 这是**设计如此**
   （免登录平台没有"我的账号"概念），不是缺口
5. **微博子回复拿不到**（2026-10-01 实测 + 交叉验证）：
   顶层评论的 `comments` 字段实测为空（20 条里 0 条带），
   `/comments/hotFlowChild` 返回 `ok=0`（需额外参数）。
   交叉验证 MediaCrawler（★66k）同样只读 `comments` 字段，
   且它的 `ENABLE_GET_SUB_COMMENTS` **默认关着**。
   → 如实报 501（不返回空列表），原因写在代码里。
6. **Telegram 评论无解**：`t.me/s` 预览页不含评论，
   取评论要走 MTProto，且公开频道的评论通常在**关联群组**里（语义不同）。

## 三、下载链路

| 项 | 现状 |
|----|------|
| 专用下载器 | 只有 **bilibili / douyin / twitter** 三个 |
| 其余平台 | 走 **yt-dlp 兜底** |

| 图片下载 | `/api/v1/download/download-images` |
| 防盗链 | `proxy.py::_guess_referer` 按**域名**猜 Referer ✅（按平台写死会漏） |
| 订阅/定时 | **没有** |
| 断点续传 | **没有** |
| 增量采集 | **没有**（每次全量搜） |
| 采集结果去重 | 靠 `source_url` 唯一（用于素材导入），**搜索层无去重** |
