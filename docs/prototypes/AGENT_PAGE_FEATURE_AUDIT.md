## 一、先纠正我自己的错误

v1 我只看代码，写下「右栏 4 段被换掉了」。**实测发现真页面右栏根本没显示**：

```jsx
<aside style={{ display: 'none' }}>          // index.tsx:3486
gridTemplateColumns: '252px minmax(0, 1fr)'  // index.tsx:877 —— 只有两列
```

**真页面是两栏，右 Inspector 是隐藏的死代码。**
→ 原型 v5 的三栏 + 右面板是**新设计，不是丢失**。
→ 教训：**读代码看不出「被 display:none 关掉」**。这就是必须实测的价值。

## 四、真页面自身的毛病（原型该顺手修掉，不是照抄）

| # | 毛病 | 实测证据 | 违反 |
|---|---|---|---|
| 1 | **SQL 原文甩给用户** | 对话里原文：`结果摘要：{"error": "{builtins.ValueError} badly formed hexadecimal UUID string\n[SQL: SELECT asset_nodes.id AS …"}` | 铁律 2 |
| 2 | **工具结果压成 JSON 字符串** | 同上，`{"error": …}` 直接铺在正文 | 铁律 1 |
| 3 | **引擎术语外露** | 「后端会创建 **run**」「执行**预算**」「**线程已锁定**」 | 门禁 I1 |
| 4 | **智能体设定 tab 名英文** | `Profile / Model / Tools / Memory / Default Context` | 一致性 |
| 5 | **空态入口不像按钮** | 4 个入口挤成两行下划线文字，看着像正文 | I5 勉强过 |
| 6 | 左栏会话标题用极窄等宽字体 | 实测截图，像日志转储 | 审美 |

## 五、结论

1. **骨架不用重做**：真页面本来就是「左栏 + 主区」两栏，原型三栏是加法不是减法。
2. **真正的丢失集中在「运行可观测性」**：指标条 + 轨迹视图 + 停止。这三样是用户判断
   「AI 到底干了什么、花了多少」的唯一依据，**不能丢**（铁律 14）。
3. **空态曾是硬丢**（真页面 4 个入口，原型 0 个）—— 已于 2026-11-01 补成 2×2 卡片，
   且没有照抄真页面「挤成两行文字」的毛病（见上面缺点 #5）。
4. **原型不必照抄真页面的毛病**：SQL 甩脸、JSON 直出、run/预算/线程 这些术语，
   原型已经是更好的写法，落地时**不要回退**。

## 六、多角度：真代码里有没有

**有，但不是原型画的那个东西。**

| 真代码 | 证据 | 是什么 |
|---|---|---|
| `POST /{character_id}/portrait/versions/{version_id}/slice-grid` | `characters.py:1277` | 3×3 网格图**按方位切 9 个子素材** |
| `GET /{character_id}/portrait/slices` | `characters.py:1185` | 列出已切子素材 |
| `turnaround` 9 标签：正面/侧面/背面/3⁄4侧面/背侧3⁄4/俯视/仰视/面部特写/全身 | `characters.py:913` | **正好 9 个方位** |
| `expression` 9 / `pose` 9 | `characters.py:910-911` | 表情 / 姿态网格 |

全库 `multi.?angle` / `zero123` / `sv3d` / `novel.?view` / `3dgs` 在 `backend/app`、
`frontend/src` **0 命中** → **没有**「对任意图连续换视角」的模型。
（`orbit` 命中全是 3D 查看器 / 动图环绕 / 预演运镜，与图片多角度无关。）

**结论**：9 方位 = 现成能力（入口在角色立绘，需提到任意结果图）；
球体拖拽连续性 = **真新功能**，落地前必须选模型。原型里应把两者**视觉上分开**。
