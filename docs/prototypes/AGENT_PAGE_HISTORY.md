## 1. 左栏：去掉「会话」这个词

### 之前

```
会话 60
┌──────────────────────┐
│ 生成一张只露坐姿的全身照 │
│ 17:23 · 9 步          │
└──────────────────────┘
（后面还有 59 条）
```

**问题**：用户要记住「第几个会话里有哪件事」，这正是文章说的
> 「用户不必去想"Session X 的上下文中是否有 Y 信息"」

### 现在

```
对话                            ＋
秋天颐和园              2 在跑
 ● 生成一张只露坐姿的全身照
   后台 1 个任务在跑
 ○ 再来一张横构图
   等你要不要确认
短剧 · 第 3 集          1 在跑
 ● 检查大纲完成情况
   后台 1 个任务在跑
没有项目
 ○ 给素材加确认卡
   昨天完成
────────────────────────
你在 2 个对话里有 2 个任务在跑
```

**三个改动**：
1. **按项目分组**——用户按「我在做哪个项目」找，不是按「第几个会话」
2. **状态用点显示**——● 在跑 / ○ 空闲，一眼看清有没有活
3. **底部汇总**——「2 个对话里有 2 个任务」，用户知道总共有多少活

## 2. 全双工：后台任务条

在主对话底部加一条：

```
⚙ 后台 2 个任务在跑   [图片生成 62%] [素材检索 快要完成]      你可以继续说，不用等
```

**这是文章 4.1 的直接体现**：
> 「前台对话响应与后台任务执行得以解耦，Agent 在后台运行耗时任务的同时也能响应人类输入。」

**输入框 placeholder 也改了**：
> 「继续说… 后台任务跑着也能发 · Enter 发送」

## 3. Watchdog 条

```
⚠ 图片生成已经 4 分钟没新进展，看起来卡住了   [让它去查] [先不管]
```

**对应文章第 6 节**：
> 「许多异常并非进程崩溃，而是模型在执行中陷入无效循环或偏离目标。」

**关键**：这是 **Agent 主动告诉你**，不是你去翻日志发现。

## 4. 投机执行条

```
✦ 你还在挑图的时候，Agent 已经先把两个改写方案备好了   [用方案一] [用方案二]
```

**对应文章 3.4 节**：
> 「在还不确定结果是否会被采用时，根据环境信号在后台提前尝试，
> 通过消耗额外的后台算力来减少人类的等待与介入成本。」

## 5. ⭐ 视图切换（最重要的改动）

### 之前

结果图下面有个「去画布编辑」按钮 —— 点了会**跳到另一个页面**。

### 现在

顶栏有两个 tab：

```
[创作] [画布]   画布 · 秋天颐和园          和创作视图是同一个对话
```

点「画布」，中间主对话区**原地变成画布**：
- 左栏对话还在
- 右栏素材库还在
- **底部输入框还能用**

画布视图顶部有一句说明：

> **这里是画布视图** · 和上面的创作视图是**同一个对话**，
> 你在画布上做的每一步，回到创作视图都能接着聊

**这直接落实文章 8.2 的论断**：
> 「用户看到的一个会话在**底层未必只对应一个 Session**。」

**不用再纠结合并还是分开——是同一对话的两个视图。**

## 7. 2026-11-01 第二轮：审美修正（v5 → v6）

> 起因：用户指着截图问「这个为什么这么长」、「底部 chips 太长」→「都改」。
> 全部纯视觉/结构样式，**没动信息架构、没碰生产代码**。

| # | 改了什么 | 之前 | 现在 |
|---|---|---|---|
| 1 | 次要文字对比度 | `--tx2 #a2a2b0` / `--tx3 #6b6b7a` | `#b9bac8` / `#8b8c9e` —— 原值在 `#08080a` 底上实测几乎不可读 |
| 2 | 结果图占位 | 近黑渐变，缩到 170px 是 4 个空盒子 | 主体亮区 + 地平线 + 环境色三层，冷暖分开 |
| 3 | 素材格占位 | 同上 | 同上 |
| 4 | 状态条 | 淡色底 + 边框 + 两行，像一块牌子 | 6px 圆点 + 一行（详见主文件第 2 节）|
| 5 | 左栏会话项 | 标题一行 + 状态一行 | 单行：圆点 / 标题 / 状态三段并排 |
| 6 | 页面底部内部说明 | `position:fixed` 胶囊压住输入框 chip 行 | 删除，出处记到主文件第 1 节 |

### ⚠️ 第 5 条上一轮改到一半留下的坑

只改了 CSS（`.sitem{display:flex}` + `.sitem-m{margin-left:auto}`），
**HTML 还是旧的 `.sitem-row` 包裹结构**，于是：

- `.sitem-row` 自己是个 flex 块，`margin-left:auto` 只把它推到 `.sitem-row` 右边
- 标题一长整行就溢出，**第一项的状态被裁掉**（实测只剩「后台 1 个」）

修法：删掉 `.sitem-row` 包裹层，让 `.sitem-t{flex:1;min-width:0}` 真正生效；
状态文案同时从「后台 1 个在跑」压成「1 个在跑」，给标题多 30px。

**教训：改 flex 布局必须连 DOM 结构一起改，只看 CSS 会得到「样式改了但位置不对」。**
验证方式也不能靠肉眼 —— 要读 `scrollWidth/clientWidth` 和右边界坐标。

### 实测（Chrome 1600×950，断言取 DOM 值）

| 项 | 结果 |
|---|---|
| 会话项 | 32px × 5 条，全部单行 |
| 第一项标题 | `scrollWidth == clientWidth`（没被截断）|
| 第一项状态 | 右边界 227 ≤ 项右边界 237（完整在容器内）|
| 状态条四档 | 高 34–37px，圆点色 黄/青/紫/红 全对 |
| 视图切换 | `#canvasView` none → flex → none |
| 多角度弹窗 | 9 方位 + 3 滑块 + 球体 + 相机，Esc 关闭正常 |
| 底部说明条 | `.mark` 已不存在 |
| 控制台 | 0 报错（唯一 404 是 favicon，非页面资源）|

### 追加：状态条又改了一轮（用户第二次说「还是长」）

改完单行后用户截图又圈了一遍：「这个提示还是长啊」。**说明第一次判断错了** ——
我以为「长」= 两行，实际是「**它占满整栏宽度**」。

| 维度 | 第一次 | 第二次 |
|---|---|---|
| 底色/边框 | 去掉（对）| — |
| 行数 | 两行 → 一行（对，但不够）| — |
| **宽度** | 仍 `stretch` 占满 954px | `align-self:flex-start`，**跟着内容走** |
| 副文案 | 跟在主句后（还占宽度）| 挪进 `title`，鼠标停才看 |
| 按钮 | 两个方块按钮 | 每档**一个**，并进句子 `· 换个模型`（虚线表示可点）|

实测：253 / 199 / 151 / 214 px（占中栏 27% / 21% / 16% / 22%），原来 390px 满栏。

**教训：用户说「长」时，先问是行数多还是占得宽。** 只看行数会改错方向。

### 追加：第三次 —— 对齐（用户问「为什么不能和上面一样居中好看」）

上一轮把宽度压短了，但用的是 `margin:0 26px` —— **贴着中栏左边**。
而正文、结果图、绿色确认条都在 `.chat-inner`（`max-width:760px; margin:0 auto`）里居中。
1600 视口下两者差 **97px**，视觉上就是「上面一群东西对齐，下面这条自己往左突出来」。

改法：`.statbar` 换成同一套列 —— `width:100%; max-width:760px; margin:0 auto; padding:7px 26px`。

实测三档视口，`contentLeft` 完全相等：

| 视口 | `.chat-inner` contentLeft | `.statbar` contentLeft |
|---|---|---|
| 1600 | 369 | 369 |
| 1280 | 272 | 272 |
| 1100 | 272 | 272 |

**教训：「短」和「对齐」是两件事。** 缩短是缩小信息量，对齐是让它进入内容的竖向秩序 ——
两个都要，只做一个会被打回。

## 8. 2026-11-01 第三轮：补空态

核对表里唯一的「硬丢」：真页面空态有 **4 个可点入口**，而原型 `class="empty"` 出现 **0 次**
（`.empty` / `.sug` 那些样式 2026-10 就写好了，从来没被用上）。

**没有照抄真页面。** 核对表自己把那条列成了缺点 #5 ——
「4 个入口挤成两行下划线文字，看着像正文」。所以做成 2×2 卡片，每条一个任务名 + 一句说明：

| 卡片 | 说明 |
|---|---|
| 列出最近的创作项目 | 看手上几个项目分别做到哪一步 |
| 检查短剧第 3 集进度 | 对一遍分镜，标出还没拍的那些 |
| 把项目圣经同步到最新 | 世界观、角色、风格一次对齐 |
| 搜一张小林的立绘 | 按标签在素材库里找，直接预览 |

点一下**填进输入框**（`fillChat`），不直接执行 —— 用户还能改；这是即梦那套「技能原地弹出」的做法。

### 入口与返回

| 动作 | 结果 |
|---|---|
| 左栏 `＋` | `newChat()` → 空态 + 标题「新对话」+ meta 清空 + **状态条隐藏** |
| 点任意会话项 | `openChat(this)` → 回到对话，标题跟会话走，状态条恢复 |

空态时 `chat-body` 加 `.body-empty` 变 flex 垂直居中 —— 否则内容挤在顶部、下面空一大片。

实测：三种视口卡片尺寸见 `AGENT_PAGE_SA.md` 第 2.5 节；点卡片→输入框有值；
点会话→标题/meta/状态条全部恢复；控制台 0 报错。

## 9. 2026-11-01 第四轮：跑起来能停

核对表 #7，三件「高」里改动最小的一件：真页面 loading 时发送键变红变停止
（`index.tsx:3166`），原型原来**停不下**。

照真页面做成**同一个按钮两个状态**，不新增控件。联动三处：点发送 → 追加消息并滚到底；
状态条自动切「在跑」档；点方块 → 回复改成「已经出来的部分保留着，不是白跑」+ 状态条收起。

两个防假的细节：

- **空输入点发送不发**，只把焦点放回输入框 —— 不能让人点了没反应还以为在跑
- **Enter 发送 / Shift+Enter 换行**真做 —— placeholder 里写着，就不该是假的

实测：空输入点按钮无任何变化；输入后 → 按钮红 / 状态条 info / placeholder 变 /
meta 变「跑着呢」；再点 → 全部恢复、状态条 none。控制台 0 报错。
（形态表见 `AGENT_PAGE_SA.md` 第 2.6 节。）

## 10. 2026-11-01 第五轮：指标条

核对表 #1：真页面输入框下有八项指标，原型一项都没有 —— 用户不知道这次跑了多久、多少字、多少钱。

**没有搬八项**：八项铺开就是一条长条，正是前面被打回两次的那种形态。
只留三项（耗时 / 字数 / 钱），全量进 `title`；并且塞进**已有的** `.comp-row2` 右侧，
**不新增一行** —— 输入框下面再加一条就三层了。

四态：历史值 `⏱ 1.9 分 · 10.7 万字 · ⚡14` → 在跑按秒涨 → 停下结算 → 新对话归零。
实测四态切换正确、按 0.5s 累计、控制台 0 报错。
