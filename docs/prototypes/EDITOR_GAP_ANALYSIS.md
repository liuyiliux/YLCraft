## 2.2 肤色检查怎么做的

课程原话：
> 「鼠标移到脸上，仔细看一看，**肤色有没有偏蓝偏绿的痕迹**。」
> 「这**绿色跟红色已经很接近了**，这是不合适的。」
> 「我们**首要的任务就是自然**。」

实现：取脸区（中间 40%×30%）平均色，判断比例

| 条件 | 提示 |
|---|---|
| 红−绿 < 8 | 太不红，偏灰/偏青 |
| 红−绿 > 75 | 太红，可能通道溢出 |
| 绿−蓝 < 5 | 蓝太多，肤色偏蓝 |
| 绿−蓝 > 65 | 绿太多，偏绿/偏黄 |
| **绿 > 红×0.85** | **「绿快追上红了 —— 这就是课程说的不合适」** |

## 2.3 下手别太狠怎么做的

课程原话：「大家调色总是调不好，**就是下手太狠**。」

8 个参数各设阈值，超了就出黄条：

| 参数 | 安全范围 |
|---|---|
| 曝光 | ±0.6EV |
| 对比度 | 0.8 ~ 1.25 |
| 饱和度 | 0.7 ~ 1.3 |
| 高光 | −0.8 ~ 0.6 |
| 阴影 | −0.6 ~ 0.7 |
| 清晰度 | ±0.6 |
| 锐化 | < 0.65 |
| 降噪 | < 0.7 |

## 2.4 修图顺序怎么做的

课程原话：
> 「这顺序不对，**这顺序错了**。」
> 「**啥都没做，皮肤也没调，啥都没做，你就调色了**。」

五步清单，点一下标记做完：
```
1 修瑕疵      → 痘痘 / 纹 / 不要的东西先清干净
2 限动态范围  → 曲线先保留最亮最黑
3 磨皮        → 高低频，不能破坏光
4 肤色调整    → 可选颜色，别偏蓝偏绿
5 调色风格化  → 颜色分级 / 预设
```

**如果后面做了、前面没做** → 那一步标黄「前一步还没做」
**如果只勾了第 5 步** → 底部出课程原话警告

# 八、v44 追加：把旧版磨皮/液化接进来 + EXIF + 自动保存

> 这一轮把「旧版有但新面板用不上」的三件接完了，
> 并补了 PhotoMaster 最后两个工程细节。

## 8.1 磨皮接进新面板

**旧版 `26-retouch.js` 里有一套纯 canvas 的高低频算法，质量比 CSS 滤镜好得多：**

```
① 低频 = 可分离盒式模糊 ×3（近似高斯，O(n)，极快）
② 高频 = 原图 - 低频
③ 合成：高频幅度大的（边缘/五官）保留，小的（噪点/毛孔）压掉
```

**这就是「磨皮但不糊五官」的原理**，也是课程说的「磨皮不能破坏光」的基础。

### 新面板里的实现

```js
leBoxBlur1D()   // 前缀和，O(n)
leBoxBlur3()    // 三次盒式 ≈ 高斯
leSkinSmooth()  // 高频阈值保边
```

**交互**：强度 0~100% + 半径 1~12，实时预览。

**实测**：
- 平坦区（200）→ 磨后 200（不变）
- 边缘（250）→ 磨后 250（保留）

**保边生效。**

## 8.2 液化接进新面板

**旧版 `rtLiquify` 是纯像素位移函数**：在半径内按 `(1-d/r)²` 的权重反向采样。

```js
leLiquifyPixels(cur, w, h, cx, cy, dx, dy, radius, strength)
```

**交互**：开液化 → 在图上按住往要推的方向拖 → 实时变形。
大小 20~160px，强度 10~100%。

**实测**：推后像素从 100 变到 216，**确实变形了**。

## 8.3 EXIF 保留

PhotoMaster 的做法：「JPEG 原图可保留 EXIF」。

### 实现

```js
leExtractExif(jpegBytes)  // 找 APP1 段（marker 0xFFE1，含 "Exif\0\0"）
leInjectExif(jpeg, exif)  // SOI 后面原样塞回去
```

**打开面板时**读一次原图的 EXIF，导出 JPEG 时注入。

**实测**：
- 提取：18 字节（假 JPEG 的 APP1 段）
- 注入：22 字节，开头 `[255,216,255,225]` = SOI + APP1 ✅

## 8.4 自动保存

PhotoMaster 的做法：「工程存 IndexedDB，停顿 0.6 秒写入」。

**我们用 localStorage**（原型够用），键名 `ylcraft_le_autosave_v1`：

```js
leAutoSave()      // 停顿 600ms 写入
leRestoreSaved()  // 打开时恢复
leClearSaved()    // 清掉
```

**存的内容**：参数 / 图层 / 建议状态 / 修图顺序 / 裁切框。

**实测**：写入 703 字节，含 `exposure: 0.33` ✅

# 十一、v45 收尾：把最后 4 项也补了

## 11.1 区域反转

```js
fx.style.maskComposite = 'exclude';   // 遮罩反着用
```

**图层行加了 `⇄` 按钮**，点一下从「只影响区域内」变成「只影响区域外」。

**实测**：`maskComposite` 变成 `exclude` ✅

## 11.2 旋转

左转 / 右转 / 复位，90° 一步。**导出按旋转后的方向。**

**踩的坑**：一开始 90° 旋转后图片被压扁 —— 因为容器的 `aspect-ratio`
没跟着换成倒数。修法：旋转时把 `aspectRatio` 设成 `auto`，
再用 `maxWidth/maxHeight` 限制。

**实测**：90° 后 640×804（竖图转到横），无压扁 ✅

## 11.3 结构化输出三级降级

PhotoMaster 的做法：`json_schema` → `json_object` → 纯提示词。

```js
LE_SCHEMA_LEVELS = ['json_schema', 'json_object', 'prompt_only']
leSchemaTry(level)   // 不同级别生成不同请求体
leSchemaDetect()     // 探测支持哪一级
```

**面板里能看到检测结果**：
```
✓ json_schema 支持
当前用：json_schema
```

> ⚠️ 原型里是**假设都支持**，真实环境要发一个最小请求试。

## 11.4 流式显示

PhotoMaster 的做法：「实时展示思考过程 + 正在写出的标题，不显示原始 JSON」。

**演示版**：6 行流式输出，三色区分

| 颜色 | 类型 |
|---|---|
| 灰斜体 | 思考过程 |
| 青色 `★` | 建议标题 |
| 绿 `✓` | 完成 |

> ⚠️ 原型里是**定时器模拟**，真实环境要接 SSE。

## 11.5 顺手修的两个 bug

| bug | 原因 | 修法 |
|---|---|---|
| **同一个建议采纳 3 次生成 3 个图层** | `leAdopt` 没查重 | 加 `LE_LAYERS.some(L => L.id === s.id)` 判断，已存在就只选中 |
| **旋转 90° 图片被压扁** | 容器 `aspect-ratio` 没换 | 旋转时设 `aspectRatio: auto` |

# 十四、v46：最后 6 项也补了（PS 差距清零）

## 14.1 可选颜色（PS 的招牌功能）

**9 个色相范围 × 4 个 CMYK 通道**：红/黄/绿/青/蓝/洋红/白/中性/黑。

```js
leSelColorApply(r, g, b, sc)   // 像素级
```

**原理**：
- 先判断像素落在哪个范围（亮度高→白、低→黑、饱和低→中性，否则按色相找最近的）
- 然后按 CMYK 移：**青=减红、品红=减绿、黄=减蓝、黑=整体压暗**

**实测**：`(0.8, 0.4, 0.4)` + 红色加品红 0.5 → `(0.91, 0.18, 0.51)`
（红更红、绿更少、蓝增加 = 品红方向 ✅）

## 14.2 色彩平衡

**阴影 / 中间调 / 高光三段 × 三对轴**（青-红 / 品红-绿 / 黄-蓝）。

```js
leColorBalApply(r, g, b, cb)   // 像素级
```

**权重按亮度算**：
```js
w1(阴影) = max(0, 1 - lum*2.2)
w3(高光) = max(0, (lum-0.55)*2.2)
w2(中间) = 1 - w1 - w3
```

**实测**：
- 暗部 `0.15` + 阴影偏红 → R `0.271` / B `0.029` ✅
- 亮部 `0.9` + 高光偏蓝 → B `1.000` ✅

> 中间调 0.5 测试时返回原值 —— **这是对的**，因为 0.5 亮度正好落中间调，
> 我测试时把偏移设在阴影段了。
