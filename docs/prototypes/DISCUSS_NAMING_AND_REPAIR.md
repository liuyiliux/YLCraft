# 问题 1：图片能力「两层命名」怎么设

## 1.1 现在的问题（32 项，命名偏技术）

```
AI 修改
  画面批注改图      ← 这个词只有我们自己懂
  局部重绘          ← 技术词
  重新打光          ← 还行
  AI 调色           ← 还行

派生
  扩展画布          ← 半技术
  去背景 / 抠主体    ← 两种叫法挤在一起，说明拿不准
  画同款            ← 还行
  变体 ×4           ← 技术
  图层拆分          ← 技术
  图生 3D           ← 技术
```

**对比像素蛋糕**：`AI 补草地` / `裙子蓬松` / `鞋子祛污` / `裙摆平整` / `AI 瘦肚子`

## 1.2 🔴 但这里有个真实的权衡，不能照抄

| | 像素蛋糕 | 我们 |
| --- | --- | --- |
| 用户群 | 影楼修图师（**很窄**） | 漫剧 / 短剧 / 电商 / Coser / 设计（**很宽**） |
| 痛点 | 高度统一 | 各不一样 |
| 场景命名 | ✅ 完美 | ⚠️ **会收窄认知** |

**具体风险：**

```
叫「补草地」→ 用户以为只能补草地，其实能补任何东西
叫「裙子蓬松」→ 电商用户以为跟自己无关
```

**所以不能纯场景化。要两层。**

## 1.3 三个方案

### 方案 A：组名场景化，项名不动

```
修人物      磨皮 / 瘦脸 / 换表情
修场景      补地面 / 换天空 / 去路人
修商品      祛污渍 / 拉平褶皱 / 换背景
```

| 优点 | 缺点 |
| --- | --- |
| 改动小 | 项名还是技术词，点的时候还是不知道选哪个 |
| 组名好懂 | 解决不了"局部重绘"这个困惑 |

### 方案 B：项名两层（主名场景化 + 副名技术）

```
修人物
  磨皮                 皮肤纹理 + 明暗过渡
  换表情               局部重绘 · 指定表情
  闭眼修复             局部重绘 · 眼睛区域
  
修场景
  补地面和草地          局部重绘 · 智能填充
  换天空               局部重绘 · 天空区域 + 光照联动
  去路人               局部重绘 · 智能消除
  
生成新的
  扩展画布              outpaint
  变体 ×4               同提示词出 4 张
  图生 3D               TripoSR
```

**关键：主名给人看，副名给懂的人确认。**

| 优点 | 缺点 |
| --- | --- |
| ✅ 一眼知道点哪个 | 列表变长（每个占两行） |
| ✅ 副名说明"这是通用的"，不收窄 | 需要为每项想场景名 |
| ✅ 搜索能搜两个名 | |

### 方案 C：合并同类（先减少项数，再命名）

🔴 **这是我觉得最该先讨论的。**

看现在的「AI 修改」4 项：

```
画面批注改图   圈一块 + 写意见
局部重绘       框选一块 + 描述
重新打光       改光位
AI 调色        说"冷一点/暖一点"
```

**这四个本质是同一件事：只改图的一部分，不改主体。**

区别只是**输入方式**：
| | 输入什么 |
| --- | --- |
| 画面批注 | 圈选 + 文字意见 |
| 局部重绘 | 框选 + 描述 |
| 重新打光 | 光位参数 |
| AI 调色 | 颜色词 |

**像素蛋糕把它们拆成 20 多个，是因为每个都有独立模型 + 独立输入界面。
我们拆成 4 个，其实用户面对的是"我想改这里，怎么改？"**

所以方案 C 是：

```
┌─ 改这一块 ────────────────────────┐
│  （选中一块之后，问你"怎么改"）       │
│                                   │
│   ○ 描述要变成什么   ← 局部重绘      │
│   ○ 圈出问题写意见   ← 画面批注      │
│   ○ 我说个方向       ← 打光/调色     │
│                                   │
│  [开始改]                         │
└───────────────────────────────────┘
```

**菜单从 4 项变成 1 项「改这一块」。**

## 1.4 我倾向：**C 为主，B 为辅**

| 步骤 | 做什么 |
| --- | --- |
| 1 | 先按方案 C **合并同类**（32 项 → 约 20 项） |
| 2 | 剩下的用方案 B **两层命名** |
| 3 | 组名改成「改人物 / 改场景 / 改商品 / 生成新的 / 批量 / 输出」 |

## 1.5 需要你定的三件事

| # | 问题 | 我的建议 |
| --- | --- | --- |
| 1 | 「AI 修改」4 项要不要合并成「改这一块」 | **要** —— 用户想的是"改这里"，不是"用哪种算法" |
| 2 | 主名要不要场景化（补草地式） | **要，但不能太窄** —— 加"和"字（补地面和草地）说明通用 |
| 3 | 副名要不要保留技术名 | **要** —— 找人问"有没有 outpainting"时能搜到 |

# 问题 2：巡检按「变化量」给修复方案

## 2.1 现在的问题：巡检只说"有问题"，没说"怎么修便宜"

现在的巡检（v12 原型）：

```
问题 2：光照方向不一致
  光源左 210° · 其余镜头 右 35°
                    [修复]  ← 点了会发生什么？不知道
```

**用户点了「修复」，最坏情况是整张重画 —— ⚡14，而且脸会变。**

## 2.2 像素蛋糕那张表的启示

它的「追色」分三档，**按"变化量"选操作**：

| 变化量 | 用什么 | 代价 |
| --- | --- | --- |
| 场景一致，只调色 | 追色 1.0 | 便宜，**画质无损**，但不能改光 |
| 场景一致，光线变 | 追色 2.0 追光 | 中，智能补光 |
| 场景差异大 | 追色 2.0 追场景 | 贵，但能凭空生成 |

**同一个需求（"让这张跟样片一样"），按变化量给了三条路，代价差一个数量级。**

## 2.3 我们的巡检问题 → 变化量分级

| 巡检发现的问题 | 变化量 | 最小修复 | 代价 | 会破坏原图吗 |
| --- | --- | --- | --- | --- |
| **色调偏冷/偏暖** | 极小 | 调色 | ⚡2 | ❌ 不会 |
| **光照方向不一致** | 小 | 改光照方向 | ⚡3 | ❌ 不会 |
| **尺寸/比例不对** | 小 | 扩展画布 | ⚡4 | ❌ 不会（只加密边缘） |
| **构图偏了** | 小~中 | 裁剪 | 免费 | ❌ 会切掉一点 |
| **背景不该出现** | 中 | 局部重绘那块 | ⚡3 | 🟡 那块会变 |
| **人物在画面里位置不对** | 中 | 局部重绘 / 移动对象 | ⚡3 | 🟡 |
| **人脸不一致（0.62）** | 🔴 大 | **只能重画** | ⚡14 | 🔴 会变脸 |
| **服装细节错** | 🔴 大 | 重画 | ⚡14 | 🔴 |
| **内容完全错** | 🔴 大 | 重画 | ⚡14 | 🔴 |

## 2.4 🔴 关键设计：**渐进修复链**

```
问题：光照方向不一致

修复方案（从便宜到贵，从小到大）：
  ① 改光照方向    ⚡3    不改变脸和构图
  ② 重画这一镜    ⚡14   彻底，但会变脸、要重新校脸

  [推荐 ①]  —— 便宜 4.7 倍，且不会变脸

  如果 ① 之后巡检仍有问题 → 自动提示升级到 ②
```

**这样用户第一次点「修复」不会被扣 ⚡14。**

## 2.5 三个需要讨论的点

### 点 1：变化量靠什么判断？

| 方式 | 优点 | 缺点 |
| --- | --- | --- |
| **规则表**（问题类型 → 变化量） | 稳定、可预测、免费 | 覆盖不全 |
| 模型判断 | 灵活 | 不稳定，还要花钱 |

**我建议：规则表为主**（上表就是初版），模型只在"规则判断不了"时兜底。

### 点 2：什么情况必须承认"只能重画"？

**必须明说的三类：**
1. **人脸不像** —— 局部重绘改脸会变更多人
2. **内容错** —— 画的是猫，要的是狗
3. **整体风格错** —— 不是调色能救的

🔴 **不能为了"显得便宜"硬给一个救不了的方案。**
这比"直接说重画"更糟 —— 用户花了 ⚡3，结果还是得 ⚡14。

### 点 3：批量修复怎么排？

12 镜里 5 个有问题，每个问题变化量不同。三个策略：

| 策略 | 做法 | 适合 |
| --- | --- | --- |
| **全量最小** | 5 个问题全用最小变化量 | 想省钱、能接受"差一点点" |
| **分级处理** | 小变化量的先修，大变化量的报告给你定 | ✅ **我推荐** |
| 全量重画 | 全重画 | 追求质量、不在乎钱 |

**推荐「分级处理」的理由**：
便宜的先自动修掉（你可能根本不在意），贵的列出来让你决定（因为贵且会变脸）。

界面大概长这样：

```
巡检发现 5 个问题

✅ 能小改修掉（3 个）—— 共 ⚡8，不会变脸
   · 第 1 镜 色调偏冷        ⚡2
   · 第 4 镜 光照方向不一致   ⚡3
   · 第 6 镜 尺寸不对        ⚡4
   [全部修掉 · ⚡8]

⚠️ 需要重画（2 个）—— 共 ⚡28，会变脸
   · 第 3 镜 人脸不一致 0.62  ⚡14
   · 第 5 镜 服装细节错      ⚡14
   [重画这 2 镜 · ⚡28]  [先不修]
```

## 2.6 需要你定的三件事

| # | 问题 | 我的建议 |
| --- | --- | --- |
| 1 | 变化量靠规则还是模型 | **规则表**（稳定、免费） |
| 2 | 「只能重画」要不要明说 | 🔴 **必须明说**，不能给救不了的便宜方案 |
| 3 | 批量修复策略 | **分级处理**：便宜先修，贵的让你定 |

# 两个问题的关系

其实说的是同一件事：

> **同一个目标，有多种做法，代价差一个数量级。**
>
> - 图片能力命名：让用户知道**有哪几种做法**（而不是只看到"局部重绘"）
> - 巡检修复方案：让用户知道**最便宜的那种是哪个**

**所以两者可以一起改：图片能力改成「场景 + 变化量」双标签，巡检直接用这个标签。**

```
图片能力列表
  补地面和草地      局部重绘 · 变化量中 · ⚡3
  调色             本地/云 · 变化量极小 · ⚡2
  扩展画布         outpaint · 变化量小 · ⚡4
  重画这一镜       整图生成 · 🔴 变化量大 · ⚡14
```

**这样巡检说"推荐改光照"时，用户已经知道"改光照 = 变化量小 = 不会变脸"。**
