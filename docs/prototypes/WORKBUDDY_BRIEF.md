# 摄影工作室工作台 · 产品简报

> 给 workbuddy 1024 造物活动用。**这份是「给人看的产品说明」，不是技术文档。**
> 完整需求在 `PHOTO_REFERENCE_LIBRARY_REQUIREMENTS.md`（11 万字），这里只讲必要的。

---

## 一、这是什么

**一个给独立人像摄影师用的工作台。** 覆盖一次拍摄从"想拍什么"到"交给后期"的全过程。

**不是**：修图软件（修图另有画布，这里只交接）、**不是**：图库管理、**不是**：客户 CRM。

**核心洞察**：
> 摄影师最大的浪费不是拍得不好，是**拍完才想起来该拍什么**。
> 所以这个产品的重心在**拍之前**——把想法变成能照着执行的清单。

---

## 二、用户是谁

| | |
|---|---|
| **主要用户** | 独立人像摄影师，接客片，一个人干完前期+后期 |
| **技术水平** | 会用相机、会用 Lightroom，但不一定懂理论 |
| **痛点** | ① 每次开拍前脑子空 ② 拍完忘了当时想拍什么 ③ 跟后期（或自己隔几天）交接丢信息 |
| **不解决** | 团队协作、多门店管理、财务 |

---

## 三、核心流程（这是最重要的部分）

```
① 平时攒灵感              ② 接单后做策划           ③ 现场            ④ 拍完
┌──────────┐          ┌──────────────┐      ┌────────┐      ┌────────┐
│  参考库   │ ──挂图──▶ │   脚本策划    │ ───▶ │ 现场模式 │ ───▶ │  交接   │
│ 审美/反思 │          │  8 个 Tab     │      │ 手机看  │      │ 给后期  │
│ /作品     │          │              │      │        │      │        │
└──────────┘          └──────────────┘      └────────┘      └────────┘
                            │                                      │
                            └────────── 打印成纸 ──────────────────┘
                                        （可自定义拼内容）
```

**关键设计**：每个环节都能"只做一点"。用户不来劲儿的时候可以只攒灵感，
忙的时候可以直接跳到打印。

## 四、四个页面说清

### 4.1 参考库（平时攒）

三个库，各有各的用途：

| 库 | 放什么 | 关键动作 |
|---|---|---|
| **审美** | 别人的好片子（电影截帧、大师作品、网上刷到的）| 每张写一句「**我要偷什么**」|
| **反思** | 自己踩过的坑 | 写「什么情况下会重犯」，下次遇到自动提醒 |
| **作品** | 自己的成片 | 参数自动从照片读，写一句「当时为什么这么拍」|

**「偷师点」是这个产品最核心的一个小设计** ——
不看图好看不好看，看**能从中学到什么**。每张图必须写一句话才能入库。

**另一种入库方式**：看到视频里的好画面 → **截帧入库**（本地解码，取 3-5 帧）。

### 4.2 脚本策划（接单后做，8 个 Tab）

**这是最重的页面，也是产品的核心。**

| Tab | 干什么 | 为什么需要 |
|---|---|---|
| **建议** | AI 看完方案给 9 条建议，可采纳/忽略/改 | 用户自己想不到的角度 |
| **方案** | 选专题模板 + **挂参考图** | 定调子 |
| **元素** | 这次由什么东西组成（场景/服装/光/动态/道具/姿态/表情/色彩）| 元素的精度决定片子的精度 |
| **分镜** | 每一镜：景别+画面+光位+为什么+怎么按+风险 | 现场照着拍 |
| **必带** | 分组清单（自带/现场买/别忘），带打勾框 | 少带一样就白跑 |
| **拍摄** | 焦段/光圈/快门/白平衡/光质，每个都解释"影响什么" | 不是给参数，是给判断 |
| **交接** | 给后期的说明：这组要什么、已知要修、客户要求、修图顺序 | 不丢信息 |
| **打印** | **自己拼要印的内容**（8 块可选 / 3 种版式）| 现场看纸 |

**每个 Tab 都可编辑**——加、删、改。

### 4.3 现场模式（手机端）

拍摄当天在手机上打开，一屏一屏看：
- 当前这一镜要什么
- 6 个拍摄参数（快门/光圈/ISO/焦段/白平衡/光质）
- 直方图（**示例数据**，真实现要接相机）
- 必带清单抽屉
- 口令（跟模特怎么说）

**设计约束**：现场光线强、手上可能有东西、网络可能差。所以字要大、操作要少。

### 4.4 学习手册（知识库）

14 章 110 个知识点，是**平台的预制内容**，不是用户自己写的。
放在知识库里，因为这样 AI 建议时能引用它。

## 五、几个关键设计决策（这些是产品的"味道"）

### ① 界面不说空话，说"为什么"

每个参数、每个建议都带解释，且**标明来源**：

```
采纳建议后看到：
┌────────────────────────────────────┐
│ 光圈收到 f/2.2，别开 f/1.8          │
│ f/1.8 在 85mm 上景深只有 4cm 左右，  │
│ 眼睛对上焦后鼻尖和耳朵都会虚。       │
│ ⓘ 计算得出：85mm + 1.5m → 景深计算  │
└────────────────────────────────────┘
```

来源分三类，**必须标**：
- **计算得出**（有公式/数据）
- **推理**（从你的方案推的，没数据）
- **猜测**（纯经验，可能错）

**这条是为了让用户知道该不该信。** 不标来源的 AI 建议是在骗人。

### ② 用户的判断永远保留

AI 的建议是「建议」不是「结论」：
- 采纳之后**随时能撤回**
- 忽略的还在「已忽略」里，能恢复
- 采纳了会写进元素和分镜，但用户能改

### ③ 打印是一等公民

独立摄影师很多还在用纸。所以：
- 打印内容**用户自己拼**（8 个块随便选，顺序自己排）
- 3 种版式：紧凑（揣兜里）/ 舒展 / 一页一块（能撕页分发）
- 参考图 3 种排法：九宫格 + 偷师点 / 大图 2 页 / 图 + 空白写
- 浏览器原生打印，**自带「另存为 PDF」**，不引 PDF 库

### ④ 不确定的东西要标出来

例：
> ⚠️ **这批里有一个是猜的**
> 你选了「老年」，但库里关于「老年」的口令结论只有 3 条，
> 而且都来自公开教程，没有你自己的实战验证过。建议拍完补一条你自己的。

**产品不假装什么都知道。**

## 六、视觉基调

| 项 | 值 |
|---|---|
| 主色 | 琥珀金 `#fbbf24`（摄影/暖光）|
| 三套主题 | 深海 `#09090b`+`#22d3ee` / 月光 `#0d0b10`+`#a78bfa` / 晨曦 `#f8f7f4`+`#0d9488` |
| 字号 | h1 32 / h2 24 / h3 20 / h4 18 / 正文 16 / 说明 14 / **最小 12** |
| 风格 | 深色优先、低饱和、留白多、无圆角阴影堆砌 |

**为什么深色**：摄影师在暗房/晚上修图，亮色界面会干扰对照片颜色的判断。

## 七、请你帮我看什么

**具体到这四件事**（比"帮我优化"有用）：

### 1. 信息层级对不对

- 脚本策划 8 个 Tab 是不是太多了？哪个可以合并？
- 参考库里「偷师点」是不是应该更突出？
- 打印工作台三栏，主操作（预览并打印）够不够明显？

### 2. 空状态 / 加载 / 错误

现在只有参考库有真正的空状态。**其他地方缺不缺？**
比如：还没选方案时分镜页显示什么？上传失败提示什么？

### 3. 现场模式够不够"能用"

假设你在户外、太阳很晒、一只手拿相机：
- 字够不够大
- 操作够不够少
- 断网了怎么办

### 4. 哪个页面最让人"卡住"

用户从打开到打印，哪一步最可能放弃？

## 八、不要改的东西（已经被用户拍板过）

| 约束 | 原因 |
|---|---|
| 最小字号 12px | 低了看不清 |
| 深色优先 | 修图时不能干扰 |
| 建议必须标来源 | 不标来源是在骗人 |
| 采纳可撤回 | 用户判断优先 |
| 打印可自定义 | 用户明确要求"自由拼接" |
| 参考图必须有偷师点 | 这是产品的核心设计 |

## 九、技术情况（给工程师看，其他人可跳过）

- **纯静态 HTML**，无框架、无构建
- `photo-ref/index.html` 单文件 380 KB，8 个 Tab + 6 个弹窗
- 数据存 `localStorage`（原型阶段）
- 打印用 `window.print()` + 专门样式表，自带另存 PDF
- 批量上传用 `FileReader` + `URL.createObjectURL`，**图片存在浏览器里**
- 截帧用 `<video>` + `canvas.drawImage`，**本地解码，不上传**
- 真实后端：**尚未接入**，接什么由后端决定
