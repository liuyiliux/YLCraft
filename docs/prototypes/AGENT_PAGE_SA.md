## 0. 原则（用户定的，最重要）

> 「我们设计原型就是为了做一个**审美统一**的平台，**只要之前功能大体都在就行**，
> 之前迁移时候微调」

| 要什么 | 不要什么 |
|---|---|
| **审美统一**（全平台一套视觉语言） | 各页面各长各的 |
| **功能大体都在** | 迁移时把功能做丢 |
| 迁移时**微调** | 迁移时重新发明 |

**⚠️ 血的教训**：做 3D 导演台原型时我没要真截图，凭空设计，
把「位置/目标点 + 26 类运镜 + T值 + 对焦 + 景深」简化成「3 个角度按钮」，
**功能做丢了**。做任何页面原型前，**先要截图**。

## 1. 页面结构

```
┌──────────┬────────────────────────────────────┬────────────┐
│ 对话      │  主对话（创作视图 / 画布视图）        │ 上下文面板   │
│ 按项目分组 │                                    │ 4 个面板    │
│ 246px    │                                    │ 400px      │
└──────────┴────────────────────────────────────┴────────────┘
```

**构成参考**（原来写在页面底部一条 fixed 胶囊里，2026-11-01 移到这里 ——
那句话是给做原型的人看的，不该渲染在界面上，用户会当成一排多余的 chip）：

| 区域 | 抄谁 |
|---|---|
| 中栏主对话 | Codex / DSH Web |
| 右栏上下文面板 | 画布智能体面板 |
| 结果区横向 4 张 | 即梦 |

### 左栏：对话（不叫「会话」）

**按项目分组**，不是按时间列 60 条会话。

```
对话                            ＋
秋天颐和园              2 在跑
 ● 生成一张只露坐姿的全身照      1 个在跑
 ○ 再来一张横构图              等确认
短剧 · 第 3 集          1 在跑
 ● 检查大纲完成情况             1 个在跑
没有项目
 ○ 给素材加确认卡              昨天完成
```

**一条 = 一行**（2026-11-01 改）：圆点 / 标题 / 状态是三段并排，
标题放不下就省略号，状态永远靠右不被挤掉。
之前是「标题一行 + 状态一行」，一屏塞 5 条就满。

状态用 ●○ 小圆点（I4），底部汇总「你在 2 个对话里有 2 个任务在跑」。

### 中栏：两个视图（同一对话）

顶栏 `[创作] [画布]` 两个 tab —— **点「画布」原地切换，不跳页**。

画布视图顶部写着「和上面的创作视图是**同一个对话**」。
依据：Super-agent 8.2「用户看到的一个会话在底层未必只对应一个 Session」。

### 右栏：上下文面板（4 个，跟着任务变）

| 面板 | 内容 | 自动跟随时机 |
|---|---|---|
| **素材库** | 图片/视频/角色 + 筛选 + 搜索 | Agent 在生成/找素材 |
| **创作项目** | 项目名 + 章节列表 + 这轮用到的元素 | 在写章节/做分镜 |
| **任务队列** | 生成中/完成/失败 + 进度条 | 有任务在跑 |
| **世界观** | 地图示意 + 实体列表 | 在改设定 |

右上角 `[自动 ▾]`：自动 = 跟着任务变；手动 = 你选哪个就是哪个。
**底座常驻「这次在做什么」**（项目 + 已生成几张 + 花了多少 + 查看项目），
切到哪个面板都不会迷路。

## 2. ⭐ 状态条：只有一条

**这一条是被用户指出后改的**。之前为了演示三个概念，把三条横幅堆在输入框上方：

```
⚙ 后台 2 个任务在跑 · 你可以继续说
⚠ 图片生成已经 4 分钟没新进展，看起来卡住了
✦ 你还在挑图，Agent 已经先把两个改写方案备好了
```

**三个问题**：一屏 3 个区块（违反 P2）、三个同时抢注意力（违反 I4）、
而且逻辑矛盾（既说在跑又说卡住）。

**现在：一条，只说最该说的那一件事，按优先级**

| 优先级 | 什么时候 | 圆点颜色 |
|---|---|---|
| 1 | 任务**出问题**（模型下线 / 连不上） | 红 |
| 2 | 任务**卡住** | 黄 |
| 3 | 任务**正常在跑** | 青（呼吸闪） |
| 4 | **提前备好了**方案 | 紫 |

右上角 `⟳` 切换看四档（原型用，真实现按情况自动选）。它被压到 `opacity:.28`，
不抢注意力 —— 真实界面没有这个按钮。

### 形状：一句话，不是一块牌子（2026-11-01 改了两轮）

**第一轮**：原来是淡红/淡黄底色 + 边框 + 横跨整栏，副文案 `display:block` 又把它撑成两行。
改成无底色 + 6px 圆点定级 + 单行。

**第二轮**：还是被说「这个提示还是长啊」。查下来根子不是行数，是**它占满了整栏宽度**，
而且按钮是方块，读起来像一排控件。再改：

```
● GPT Image 2 可能已下线 · 换个模型        ← 253px / 954px = 27%，右边大片留白
```

| 规则 | 做法 |
|---|---|
| 定级 | **6px 圆点**换颜色，不铺底色、不加边框（I4：状态用小圆点，不用色块）|
| **对齐** | 和 `.chat-inner` **同一列**：`max-width:760px; margin:0 auto; padding:7px 26px` —— 左边缘与正文、结果图、确认条全部对齐 |
| 宽度 | 盒子跟内容列同宽，但**没有底色**，视觉上只有一句话靠左；不要用 `margin:0 26px`（那会贴左，比内容左移 97px）|
| 副文案 | **不进页面，进 `title`**：鼠标停上去才看（`供应商说「模型不存在」…`）|
| 动作 | 每档**最多一个**，且**并进句子**：`· 换个模型`，虚线提示可点 —— 不是方块按钮 |
| 主句 | 只留结论（`后台 2 个任务在跑 · 图片生成 62%` → `后台 2 个在跑 · 62%`）|

实测四档文字宽 **87–140px**、盒高统一 34px，左边缘与内容列完全一致
（1600 视口：两者 `contentLeft` 都是 369px）。
原始版本是 390px 且贴左、横跨整栏。

**⚠️ 如果还嫌长，下一步是改语义而不是继续压宽度**：
「模型下线」是一次性**事件**，本来就不该常驻 —— 可以改成出现几秒自动收起，
或直接说在对话里。现在留着是为了演示四档。

## 4. ⭐ 确认卡：四档权限

问题：现在的确认「每次都问」且点了不生效。查代码（`runtime/tools.py`）：

```python
CONFIRMATION_RISK_LEVELS = {"write", "delete", "costly"}
AUTO_CONFIRMED_WRITE_TOOLS = {3 个工具，写死在代码里}
```

白名单写死、没有会话内记住、costly 每次必问。

**原型四档**：

```
以后这类操作
 ○ 本次对话不再问      这一轮里再花钱不打断你
 ● 这个工具永远不问     换对话也生效 · 能在设置里撤销
 ○ 低于 ⚡50 自动过     超过这个额度才问你
 ○ 每次都问           最安全，但会很烦
```

选完顶部出授权条：「✓ 本会话已授权：这个工具永远不问  [撤销]」

**⚠️ 安全底线**：`delete` 类每会话只记一次，且明确提示「删除不可撤销」。

## 5. ⚠️ 模型下拉必须复用公共组件

**真实现前必读 `docs/architecture/FRONTEND_SHARED_COMPONENTS.md`。**

不许手写第三份。用组件 `frontend/src/components/ai/ProviderModelSelect.tsx`
\+ 规则 `frontend/src/utils/modelSelection.ts`：

| 函数 | 规则 |
|---|---|
| `pickDefaultConnector()` | 默认连接器 = `is_default` 优先，**不能取 `items[0]`** |
| `resolveModelSelection()` | 默认模型 = `model` 优先，其次 `default_model` |
| `resolveModelCandidates()` | 候选去空去重，默认排第一 |

**三个真实踩过的坑**：
1. 默认连接器不能取 `items[0]` —— 可能是没启动的本地反代 → `All connection attempts failed`
2. 默认模型有两个字段名（`model` / `default_model`）—— 两个都得认
3. `available_models` 可能过期 —— 永远不能覆盖默认模型
