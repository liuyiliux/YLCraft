| 要什么 | 不要什么 |
|---|---|

| **功能大体都在** | 迁移时把功能做丢 |
| 迁移时**微调** | 迁移时重新发明 |

**⚠️ 血的教训**：做 3D 导演台原型时没要真截图就凭空设计，把「位置/目标点 + 26 类运镜

## 1. 页面结构

```
对话 246px  │  主对话（创作 / 画布 两个视图）  │  上下文面板 400px
按项目分组   │                                │  4 个，跟着任务变
```

**构成参考**：中栏主对话抄 Codex / DSH Web，右栏抄画布智能体面板，结果区横向 4 张照即梦。
（这些原来写在页面底部一条 `position:fixed` 胶囊里，会被当成多余的 chip —— 已删。）

### 左栏：对话（不叫「会话」）

**按项目分组**，不是按时间列 60 条会话。

```
对话                            ＋
秋天颐和园              2 在跑
 ● 生成一张只露坐姿的全身照      1 个在跑
 ○ 再来一张横构图              等确认
短剧 · 第 3 集          1 在跑
 ● 检查大纲完成情况             1 个在跑
没有项目
 ○ 给素材加确认卡              昨天完成
```

**一条 = 一行**（2026-11-01 改）：圆点 / 标题 / 状态是三段并排，
标题放不下就省略号，状态永远靠右不被挤掉。
之前是「标题一行 + 状态一行」，一屏塞 5 条就满。

状态用 ●○ 小圆点（I4），底部汇总「你在 2 个对话里有 2 个任务在跑」。

### 中栏：两个视图（同一对话）

顶栏 `[创作] [画布]` 两个 tab —— **点「画布」原地切换，不跳页**。

画布视图顶部写着「和上面的创作视图是**同一个对话**」。
依据：Super-agent 8.2「用户看到的一个会话在底层未必只对应一个 Session」。

### 右栏：上下文面板（4 个，跟着任务变）

| 面板 | 内容 | 自动跟随时机 |
|---|---|---|
| **素材库** | 图片/视频/角色 + 筛选 + 搜索 | Agent 在生成/找素材 |
| **创作项目** | 项目名 + 章节列表 + 这轮用到的元素 | 在写章节/做分镜 |
| **任务队列** | 生成中/完成/失败 + 进度条 | 有任务在跑 |
| **世界观** | 地图示意 + 实体列表 | 在改设定 |

右上角 `[自动 ▾]`：自动 = 跟着任务变；手动 = 你选哪个就是哪个。
**底座常驻「这次在做什么」**（项目 + 已生成几张 + 花了多少 + 查看项目），
切到哪个面板都不会迷路。

## 2. ⭐ 状态条：只有一条

**这一条是被用户指出后改的**。之前为了演示三个概念，把三条横幅堆在输入框上方：

```
⚙ 后台 2 个任务在跑 · 你可以继续说
⚠ 图片生成已经 4 分钟没新进展，看起来卡住了
✦ 你还在挑图，Agent 已经先把两个改写方案备好了
```

**三个问题**：一屏 3 个区块（违反 P2）、三个同时抢注意力（违反 I4）、
而且逻辑矛盾（既说在跑又说卡住）。

**现在：一条，只说最该说的那一件事，按优先级**

| 优先级 | 什么时候 | 圆点颜色 |
|---|---|---|
| 1 | 任务**出问题**（模型下线 / 连不上） | 红 |
| 2 | 任务**卡住** | 黄 |
| 3 | 任务**正常在跑** | 青（呼吸闪） |
| 4 | **提前备好了**方案 | 紫 |

右上角 `⟳` 切换看四档（原型用，真实现按情况自动选）。它被压到 `opacity:.28`，
不抢注意力 —— 真实界面没有这个按钮。

### 形状：一句话，不是一块牌子

```
● GPT Image 2 可能已下线 · 换个模型
```

| 规则 | 做法 |
|---|---|
| 定级 | **6px 圆点**换颜色，不铺底色、不加边框（I4：状态用小圆点，不用色块）|
| **对齐** | 和 `.chat-inner` **同一列**：`max-width:760px; margin:0 auto; padding:7px 26px` —— 左边缘与正文、结果图、确认条全部对齐。**不要用 `margin:0 26px`**（那会贴左，1600 宽下比内容左移 97px）|
| 副文案 | **不进页面，进 `title`**：鼠标停上去才看（`供应商说「模型不存在」…`）|
| 动作 | 每档**最多一个**，且**并进句子**：`· 换个模型`，虚线提示可点 —— 不是方块按钮 |
| 主句 | 只留结论（`后台 2 个任务在跑 · 图片生成 62%` → `后台 2 个在跑 · 62%`）|

实测四档文字宽 87–140px、盒高 34px，与内容列 `contentLeft` 完全相等。

**⚠️ 如果还嫌长，下一步是改语义而不是继续压宽度**：
「模型下线」是一次性**事件**，本来就不该常驻 —— 可以改成出现几秒自动收起，
或直接说在对话里。现在留着是为了演示四档。

## 2.5 空态：4 个入口做成卡片（2026-11-01 补）

新对话时（左栏 `＋`）中栏换成空态。这是核对表里**唯一「确认丢了」**的能力：
真页面有 4 个可点入口，原型原来 `class="empty"` 出现 **0 次**（样式写了但没人用）。

中间是 `✦ 让智能体先接管一个明确任务` + 一句说明，下面 **2×2 卡片**：
列出最近的创作项目 / 检查短剧第 3 集进度 / 把项目圣经同步到最新 / 搜一张小林的立绘。

| 规则 | 做法 |
|---|---|
| 形态 | **2×2 卡片**，每张 = 任务名 + 一句「它能干什么」。真页面是两行下划线文字、像正文（核对表缺点 #5），**别照抄** |
| 命名 | 用**任务名**不用功能名（照即梦）：`检查短剧第 3 集进度`，不是「进度查询」|
| 点击 | 填进输入框（`fillChat`），**不直接执行** —— 用户还能改 |
| 空态时 | 标题变「新对话」、meta 清空、**状态条隐藏**（没任务就没有状态）|
| 返回 | 点左栏任意会话 → `openChat()`，标题跟着那条会话走 |
| 居中 | `chat-body` 加 `.body-empty` 变成 flex 居中，否则内容挤在顶部、下面空一大片 |

实测：1600 卡片 276×62、1280 267×62、1100 177×78（说明折两行但不裁切）。

## 2.6 跑起来能停（2026-11-01 补）

核对表 #7：真页面 loading 时**发送键变红变停止**（`index.tsx:3166`）；原型原来停不下。

| 状态 | 发送键 | 状态条 | 输入框提示 |
|---|---|---|---|
| 空闲 | 青色 `↑` | 按优先级显示 | `继续说… Enter 发送` |
| 在跑 | **红色 `■`**（同一个按钮，不新增控件）| 自动切「在跑」档 | `正在跑… 点方块停下` |
| 停下 | 恢复 `↑` | **收起**（没任务了）| 恢复原样 |

- 点发送 → 追加「用户的话 + `正在想▍`」到对话末尾并滚到底
- **空输入点发送不发**，只把焦点放回输入框 —— 不假装在跑
- Enter 发送 / Shift+Enter 换行：placeholder 写了就得真做到
- 停下时回复改成「已经出来的部分保留着，不是白跑」—— 别让人以为白花钱

## 2.7 花了多少，一眼看得见（2026-11-01 补）

核对表 #1：真页面输入框下面有一条八项指标（Run/步骤/工具/耗时/LLM/Token/成本/缓存命中），
原型一项都没有 —— 用户不知道这次花了多久、多少字、多少钱。

**没有照搬八项**（一屏塞满反而看不清），只留三项，全量进 `title`：

> 平时看到 `⏱ 1.9 分 · 10.7 万字 · ⚡14`；hover 才是
> `9 步 · 2 工具 · 1 分 54 秒 · LLM 2 次 · 107,082 token · 缓存命中 48%`。

| 时机 | 显示 |
|---|---|
| 空闲（历史对话）| `⏱ 1.9 分 · 10.7 万字 · ⚡14` |
| 在跑 | `⏱ N 秒 · 生成中…`（按秒涨，当场知道跑了多久）|
| 停下 | `⏱ N 秒 · ⚡2 · 停下了`（**结算**，别让人以为白花钱）|
| 新对话 | `本轮 ⚡0` |

放在 `.comp-row2` 右侧，**不新增一行** —— 输入框下面再多一条就成了三层。

## 3. ⭐ 结果呈现

### 横向 4 张（照即梦）

```
┌───┐┌───┐┌───┐┌───┐   ← 悬停出操作条（↓ ＋ ✎）；点任意一张弹多角度
└───┘└───┘└───┘└───┘
一次生成 4 张 · 2048×3072 · png                        ⚡14

你可以试试这样改：[把背景换成海边日落↗] [再生成一版古风造型↗]
[↻重新编辑] [⟳再次生成] [展开详情 ›]
```

### 点任意一张图 → **弹出多角度圆球**

```
┌─ 多角度 · 基于「竖图 · 靠窗侧坐」 ────────────✕─┐
│    ○ 球体          │ 9 个方位按钮                │
│    📷 相机小球(可拖) │ 水平 ──●── 315°             │
│      ┌────┐        │ 俯仰 ──●── 30°              │
│      │ 图 │        │ 远近 ─●─── 标准             │
├────────────────────┴──────────────────────────┤
│ ✦1  会生成一张新图，和原图连线         [生成]  │
└───────────────────────────────────────────────┘
```

- 相机小球**可以拖**（「绕人走一圈」比记角度直观）；点方位 ↔ 滑块**双向联动**；Esc 或点背景关闭

### 编辑交给画布，不在结果页做

即梦把编辑塞在结果页（局部重绘/扩图/消除笔）。
**我们不该学** —— 我们有专业画布。结果页只放「去画布编辑 ›」。

## 4. ⭐ 确认卡：四档权限

现状问题：确认「每次都问」且点了不生效（`runtime/tools.py` 里白名单写死、没有会话内记住、
`costly` 每次必问）。**原型要解决的是"问得对不对"，不是把确认删掉。**

```
以后这类操作
 ○ 本次对话不再问      这一轮里再花钱不打断你
 ● 这个工具永远不问     换对话也生效 · 能在设置里撤销
 ○ 低于 ⚡50 自动过     超过这个额度才问你
 ○ 每次都问           最安全，但会很烦
```

选完顶部出授权条：「✓ 本会话已授权：这个工具永远不问  [撤销]」

**⚠️ 安全底线**：`delete` 类每会话只记一次，且明确提示「删除不可撤销」。

## 5. ⚠️ 模型下拉必须复用公共组件

**真实现前必读 `docs/architecture/FRONTEND_SHARED_COMPONENTS.md`。**

不许手写第三份。用组件 `frontend/src/components/ai/ProviderModelSelect.tsx`
\+ 规则 `frontend/src/utils/modelSelection.ts`：

| 函数 | 规则 |
|---|---|
| `pickDefaultConnector()` | 默认连接器 = `is_default` 优先，**不能取 `items[0]`**（可能是没启动的本地反代 → `All connection attempts failed`）|
| `resolveModelSelection()` | 默认模型 = `model` 优先，其次 `default_model`（两个字段名都得认）|
| `resolveModelCandidates()` | 候选去空去重，默认排第一；`available_models` 可能过期，**永远不能覆盖默认模型** |
