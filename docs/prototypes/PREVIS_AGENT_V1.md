## 2. ⭐ v2 的两处关键改动

### 2.1 效果 + 参数，两者都给

改动卡顶部先给**一句人话**，下面再给**可核对的数字**：

```
┌──────────────────────────────────────────────┐
│ 我想这么改                          1 处      │
├──────────────────────────────────────────────┤
│ 看起来会变成                                   │
│ 人物在画面里大了一点，背景压得更平，            │  ← 效果（人话）
│ 没那么乱，机位从正面转到了右前方。              │
├──────────────────────────────────────────────┤
│ ☑ 机位 主视角                                 │
│     角度  正面      →  右前方                  │  ← 参数（可核对）
│     焦距  35mm      →  50mm                   │
│     距离  3.2 米    →  2.1 米                  │
├──────────────────────────────────────────────┤
│ ✎ 这几个数字你可以直接拖                        │
│   焦距  ──────●────        50mm               │  ← 微调
│   距离  ────●──────        2.1 米              │
└──────────────────────────────────────────────┘
```

**关键**：效果那句话**是从参数算出来的**，不是写死的。

```js
function buildEffect(from, to){
  const ratio = from.distance / to.distance;
  if (ratio > 1.35) parts.push('人物在画面里<b>大了一点</b>');
  if (to.focal > from.focal + 8) parts.push('背景<b>压得更平</b>，没那么乱');
  if (from.angle !== to.angle) parts.push('机位从' + ... + '转到了...');
}
```

**所以你拖滑块时，那句话会实时变。** 实测：
- 距离从 2.1 拖到 5.0 → 「大了一点」变成「**小了一些**」

### 2.2 手动操作：两条路都能走

| 路径 | 入口 | 说明 |
|---|---|---|
| **AI 提议 → 你微调** | 改动卡里的滑块 | 它给个初值，你拖到你满意 |
| **你自己来** | 视口下方「手动调整」 | **完全不经过 AI** |

手动条按选中的对象变：

```
手动调整  [主视角]              你也可以直接改，不用跟它说
角度 [左侧][正面][右前方]   焦距 ──●── 35mm   距离 ──●── 3.2 米
```

- 选**主视角** → 角度 / 焦距 / 距离
- 选**小林** → 朝向 / 动作
- 选**书桌** → 在画面里 / 移走

**两条路改的是同一份场景状态**（`scene` 对象），所以：
- 你手动拖了距离，再让 AI 提议，它读到的就是新值
- AI 应用后，手动条上的数字**也跟着更新**

## 3. 改动卡的其他设计

| 设计 | 为什么 |
|---|---|
| **逐条「现在 → 改成」** | 不是「已调整机位」，是能核对的数字 |
| **写明影响面**「会动到镜头 3、镜头 5」| 改之前就知道后果 |
| **写明能力边界**「灯光不在我的能力里」| 不假装什么都能做 |
| **只有一个按钮** | 符合「同一动作只允许一个按钮」|
| **应用后卡片不消失** | 改动记录永久留在对话里 |

应用后：

```
已应用                    第 7 版 → 第 8 版
看起来会变成
人物在画面里大了一点，…机位从正面转到了右前方。

☑ 机位 主视角
    角度 正面→右前方 / 焦距 35mm→50mm / 距离 3.2米→2.1米

改动已经存进这个场景了              [撤销这次]
```

## 4. 助手汇报：五项

| 项 | 内容 |
|---|---|
| **做了** | 机位主视角：右前方 50mm 2.1 米；场景从第 7 版存成第 8 版 |
| **没做** | 没动小林的朝向和动作；没动书桌；没改另外两个镜头 |
| **自检** | 机位没穿进人物身体、没有对象跑出画面 —— 3 项都过了 |
| **规模** | 1 处改动 · 影响 2 个镜头 · 用时 0.6 秒 |
| **你来改** | 觉得哪不对，视口下面的滑块你可以直接拖，不用再跟我说 |

**最后一项是 v2 新加的** —— 明确告诉用户「你有手动这条路」。

## 5. 遵守的门禁（都实测过）

| 门禁 | 怎么做的 | 验证 |
|---|---|---|
| **界面不许泄漏引擎术语** | `set_camera`→机位、`revision`→第 N 版、`poseJoints`→姿势角度 | ✅ 扫 8 个词，**泄漏 0** |
| **同一动作只有一个按钮** | 卡片底部只有「应用这 N 处改动」 | ✅ |
| **状态用小圆点不用色块** | 「已应用」用绿点 | ✅ |
| **空态给 ≥3 入口** | 3 个，每个带「会改什么」 | ✅ |
| **Agent 汇报四项**（+1） | 做了/没做/自检/规模/你来改 | ✅ 5 条 |
| **判据只能是画面** | 应用后视口从「正面·35mm·3.2米」真的变成「右前方·50mm·2.1米」 | ✅ DOM 实测 |
| **参数诚信** | 拖滑块 → 视口缩放真的变（`scale(1.25)`）| ✅ |

## 6. ⚠️ 修过的两个问题

### ① 逻辑自相矛盾（v1）

一边显示「**已应用**」，一边写「这个机位是**锁着的**，改不了」。

改成真的边界：**「灯光不在我的能力里」**。

**教训**：说「它改不了什么」必须是真的边界，不能和刚做完的事打架。

### ② 说明条挡住手动条（v2）

左下角浮动的原型说明条，正好盖住「手动调整」的「左侧」按钮，
**看起来像只有两个角度**（实测确认三个都在，只是被挡）。

删掉浮动说明条 —— 说明写在文件头注释和本文档里就够了。

**教训**：浮动元素要检查有没有挡住交互控件。
