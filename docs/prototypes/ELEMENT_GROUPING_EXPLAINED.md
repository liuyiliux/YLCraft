# 「要素分组」是什么意思（讲解）

> 你问：「这个要素五组一会给我讲解下什么意思」
>
> 我说的原文是「P7 要素分组（五官 / 服装 / 配饰 / 风格）」—— 是**四组**，
> 可能记成五组了。这里讲清它解决什么问题。

---

## 一、现在的问题：所有要素平铺成一列

现在的界面长这样：

```
外观要素 （点一下就能改 · 缺的自己填 · 没有的可以加）

  发型    银白色 长直发 过腰                [1]
  瞳色    红色 竖瞳                        [2]
  服装    黑色高领长风衣 银扣               [3]
  标志物  左眼下 泪痕状疤痕                 [1]
  整体    冷色调 高对比 逆光                [2]
  脸型    — 搜到的资料没写         缺 · 点我填
  体型    — 只有半身图，判断不了     缺 · 点我填
  饰品    银色耳环                   我加的
```

**7~8 项还行。但真实场景会有 20~30 项。**

一个角色的完整外观可能有：

```
发型、发长、发色、发质
瞳色、瞳型、眼神
脸型、脸宽、下巴、颧骨
肤色、肌理
上装、下装、外套、鞋
配饰（耳饰/颈饰/手饰/腰带）
身高、体型、肩宽
整体色调、光比、氛围
```

**二十多项平铺一列，会变成什么样：**

1. **找不到** —— 想改"瞳色"，要在一堆行里翻
2. **缺项看不出来** —— 20 行里藏 3 个"缺"，眼睛扫不到
3. **提示词顺序乱** —— 拼接时按数组顺序，出来的提示词东一句西一句
4. **加项不知道加哪** —— 点「＋加一项」只能追加到末尾，"耳饰"跑到"整体风格"后面

---

## 二、「要素分组」是什么

**把要素按"它在画面里管什么"分成几组，每组内部有序。**

### 我提的四组

| 组 | 管什么 | 包含哪些项 |
| --- | --- | --- |
| **① 五官** | 脸长什么样 | 脸型、瞳色、瞳型、肤色、表情 |
| **② 发型** | 头发 | 发型、发长、发色、发质 |
| **③ 服装** | 身上穿的 | 上装、下装、外套、鞋 |
| **④ 配饰** | 外加的东西 | 耳饰、颈饰、手饰、腰带、标志物 |
| **⑤ 风格** | 整体调性 | 色调、光比、氛围、画风 |

（如果算上「体型」也可以是第五组 —— 这可能就是"五组"的来源）

### 分组之后长这样

```
┌─ 五官 ─────────────────────────────────┐
│  脸型    鹅蛋脸 微尖           我加的     │
│  瞳色    红色 竖瞳              [2]     │
│  肤色    — 没搜到             缺·点我填  │
│                                        │
│  ▸ 全部齐了（2/2）                       │
└────────────────────────────────────────┘

┌─ 发型 ─────────────────────────────────┐
│  发型    银白色 长直发 过腰      [1]     │
└────────────────────────────────────────┘

┌─ 服装 ─────────────────────────────────┐
│  外套    黑色高领长风衣 银扣      [3]     │
│  鞋      — 没搜到             缺·点我填  │
└────────────────────────────────────────┘

┌─ 配饰 ─────────────────────────────────┐
│  饰品    银色耳环              我加的     │
│  标志物  左眼下 泪痕状疤痕        [1]     │
└────────────────────────────────────────┘

┌─ 风格 ─────────────────────────────────┐
│  整体    冷色调 高对比 逆光       [2]     │
└────────────────────────────────────────┘
```

**默认全部展开；嫌长可以只展开有问题的组。**

## 三、分组解决哪四个问题

### 3.1 找得到

想看"脸"，就展开「五官」组 —— 不用在 20 行里翻。

### 3.2 缺项一眼看见

组标题上直接标：`五官 2/3 · 缺 1` —— **不用展开就知道这组有问题。**
甚至可以：**只显示有缺项的组**（一个筛选项）。

### 3.3 🔴 提示词顺序天然正确

**这是最实在的好处。**

提示词不是随便拼的，有习惯顺序。业界通用的顺序大致是：

```
主体 → 五官/脸 → 发型 → 服装 → 配饰 → 姿态 → 环境 → 风格/光照 → 质量词
```

**如果不分组，拼出来可能是：**
```
冷色调高对比逆光 · 银色耳环 · 眼型细长 · 黑色风衣 · 银白长发 · 尖下巴
```
（风格词跑最前面，模型会把它当整体基调，反而弱化了脸）

**分组后按组顺序拼：**
```
鹅蛋脸微尖 · 红色竖瞳 · 银白色长直发过腰 · 黑色高领长风衣银扣 ·
银色耳环 · 左眼下泪痕状疤痕 · 冷色调高对比逆光
```
（组顺序 = 提示词顺序，符合模型习惯）

🔴 **所以分组不只是"整理界面"，是在修提示词质量。**

### 3.4 加项知道加哪

点「＋ 加一项」→ 出现在**对应组里**，而不是追加到末尾。

## 四、实现要点（真做时）

```ts
interface ElemGroup {
  id: 'face' | 'hair' | 'outfit' | 'accessory' | 'style';
  label: string;
  order: number;          // 🔴 这个 order 决定提示词里的顺序
  fields: ['脸型','瞳色','肤色', ...];   // 这组该有哪些项
}

// 要素
interface Elem {
  group: string;          // 属于哪组
  k: string;              // 项名
  v: string;              // 值
  src: string | null;     // 来源 [1] / null=用户填
  edited: boolean;
  addedByMe: boolean;
}
```

**两个关键设计：**

| 设计 | 为什么 |
| --- | --- |
| 组有 `order` | 拼提示词时按 order 排，不按用户添加顺序 |
| 组有 `fields` 白名单 | 能算出"这组缺哪些"，而不是只知道"总共缺几个" |

**有了 `fields` 白名单，就能做"完整性检查"：**

```
五官组应有 3 项（脸型/瞳色/肤色），搜到 2 项
→ 组标题显示「五官 2/3」
→ 提示"肤色没搜到，影响大不大？"
```

**这比"缺 2 项"精确得多** —— 缺的是"肤色"和缺的是"耳饰"，影响完全不同。

## 五、什么时候做

| 时机 | 说明 |
| --- | --- |
| **要素 ≤10 项时** | 平铺还行，分组收益不大 |
| 🔴 **要素 >15 项时** | 必须分组 |
| 要多角色批量时 | 更要分组（每个角色一组） |

**所以这不是"现在就得做"，是"要素变多时必须做"。**

在原型里，我建议**先做"组标题 + 组内可折叠 + 缺项计数"三件事**，
不做太细（比如不急着做 `fields` 白名单校验）。

---

## 六、一句话

> **要素分组 = 把"一长串标签"变成"按画面位置分好的几个抽屉"。**
> **抽屉有顺序 → 提示词顺序对；抽屉标缺项 → 一眼看出哪没搜到；抽屉可折叠 → 20 项也不乱。**
