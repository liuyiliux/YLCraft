# 摄影参考库 · 需求规格（草案 v1，待确认）

> 2026-10-21
> 用户三条原始需求：
> 1. 拍照姿势需要保存，支持批量上传，上传时可打标签和修改标签
> 2. 这属于工具类还是什么类
> 3. 素材库播放器 / 小红书等详情播放器需要能点截图当前帧，保存到审美学习或姿势学习参考里
>
> 用户补充：「我是想的，提供入口，然后你或者其他 agent 帮我上传」

# 一、分类定位（回答需求 2）

**它不是「工具类」。**

| 分类 | 是什么 | 典型产品 | 我们的 |
|---|---|---|---|
| 工具类 | 有输入→输出的一次性运算 | 修图、生成、转码 | 已有（本地调整、超分…） |
| **资产类（DAM）** | **存 → 找 → 用**，长期积累 | Eagle、Lightroom Catalog | **本次要做的** |
| 流程类 | 推进一个有时限的任务 | 项目管理、CRM | 摄影策划台（规划用） |

**结论：属于「资产类（DAM）」，要配一个 L1 通用采集能力。**

```
L1 基础能力   ── 截帧 capture（任何播放器可挂）
L2 页面组合   ── 参考库 reference（资产页的一种）+ 摄影策划台 photo-plan
L3 画布       ── 不参与
```

# 三、需求清单（A→D）

## A. Agent 入库工具 `import_assets`（用户最想要）

**为什么这是第一优先**：用户一次要传 100–500 张，
UI 上传的工作量是「一张张确认标签」，而 agent 上传是「说一句话，批量做完」。

### 工具签名（草案）

```python
@register_tool(
    name="import_assets",
    description="把一批本地文件/图片导入素材库，可批量打标签。返回入库报告。",
    parameters={
        "paths": ["D:/ref/coser/*.jpg", ...],   # 支持 glob 或目录
        "tags": {                                 # 按维度分组
            "题材": ["coser"],
            "人数": ["单人"],
            "感觉": ["清纯"],
            "角色作品": ["原神-雷电将军"],
        },
        "collection": "姿势库",                   # 可选：归入某个收藏集
        "source_url": "https://...",             # 可选：来源
        "dry_run": True,                          # 默认 True！先出报告不写库
    },
)
```

### 两阶段：先报告，再入库（用户明确要求）

```
阶段 1  dry_run=True（默认）
        → 读文件 → 读图内容 → 推测标签
        → 返回报告：
          「共 512 张；识别出 12 个角色、4 种风格；
            其中 8 组（24 张）高度相似，疑似重复；
            37 张无法判断题材（需人工）；
            预计入库 512 张，占用 xx MB」

阶段 2  用户确认 → dry_run=False
        → 真正入库 → 返回明细
```

**这个「先报告」是用户明确选的**，不是我自己定的。

### 需要配套的

- 工具实现要复用现有 `POST /upload` 的入库逻辑（不重写）
- 标签写入走现有 `AssetTagLink`，`source="ai"`、`confidence=<模型给的值>`
- 用户手动改过的标签，`source` 改为 `manual`，**以后 AI 不再覆盖**

## B. 批量上传（UI）

- 一次 100–500 张（用户选的档位）
- **队列 + 并发 3-4 + 进度 + 失败重试**
- **先勾一批标签再整批套用**，再单独调个别错的
- 去重：dHash 指纹，相似的在入库前标出来

## C. L1 通用截帧能力

用户选的是「**以后所有播放器都要有**」→ 必须做成通用能力，不是每个播放器各写一遍。

```ts
// 新建 hooks/useFrameCapture.ts
const { capture } = useFrameCapture(videoRef)
capture({ target: 'pose' })   // 返回 Blob + 元数据
```

### ⚠️ 必须提前解决的技术坑

平台详情视频走 `/api/v1/proxy/video` 代理。
**如果直连 CDN，canvas 会被污染，`toBlob` 抛 `SecurityError`。**
→ 截帧必须只从代理源取帧，且 `<video crossOrigin="anonymous">`。
**这一点要在实现前先验证，否则做完发现全失败。**

用户选的采集方式：**截时弹小窗选用途**（姿势 / 审美 / 光影 / 调色）。

截帧入库时自动带：来源平台、博主、笔记、**第几秒**。

## D. 标签体系（5 个维度）

⚠️ **这一节等另两份调研回来后可能微调**（Shotdeck 的维度设计、审美学习的维度）。

基于现有树形 `Tag` 表，不用改结构：

| 维度 | 值 | 依据 |
|---|---|---|
| **题材** | coser / 老年人 / 领证跟拍 / 情侣写真 | 用户给的 |
| **人数** | 单人 / 双人 / 多人 | 行业第一权重（决定姿势能否复用） |
| **姿势族** | 站/坐/靠/走/拥抱/回头/蹲/躺/跳/互动 | 检索入口 |
| **感觉** | 松弛/优雅/可爱/帅气/电影感/仪式感/搞怪 | **只做标签不做目录** |
| **场景** | 室内/户外/民政局/影棚/街边 | 决定「什么时候用」 |
| **用途** | 姿势/审美/光影/调色 | 一个库多视图 |
| **角色作品** | coser 专用（作品名 + 角色名） | coser 圈的组织单位 |
| ~~身体部位~~ | 手/下巴/腿/重心/肩线 | **只做筛选 chip，不做一级** |

**为什么身体部位不做一级**：调研发现没有一家主流产品这么做
（Posing App 放「技巧」、ModelPoser 放子分类）。
部位是「调整手段」，不是「检索入口」，做一级会把库切碎。

**标签输入方式**（用户选的）：**受控词表 + 自由备注**。
- 受控词表用于统计和筛选
- 免费备注放「这张好在哪」这种没法结构化的东西

# 四、⭐ 一个必须正视的产品判断

调研发现现有姿势库产品都在解决「看」，但摄影师的真实痛点是「**说**」。

> SLR Lounge：「你可以学了几年摆姿，存了几百张参考图，
> 但当两个真人站在你面前时，脑子还是一片空白。
> **这不是知识问题，是检索问题。**」
>
> 「图库给你的是一张成品照片。它不告诉你**怎么把两个紧张的人**从现在的位置带到那个结果，
> 更不告诉你**过程中该说什么**。」

## 对需求的含义

**如果只做「存图 + 打标签」，做不到差异，因为 Eagle 已经够了。**

建议每个姿势条目至少带两块：

| 字段 | 内容 | 必要性 |
|---|---|---|
| 图 | 参考照片 | 必须 |
| **怎么摆** | 一句话物理指令 | **必须**（否则只是个图片库） |
| **怎么说** | 现场原话（cue） | 强烈建议 |
| 常见崩点 | 这个姿势最容易失败在哪 | 可选 |

参考结构（抄 Cue & Capture，不抄内容）：
`setup`（身体怎么放）→ `cue`（现场原话）→ `capture`（机位/张数）→ `failure`（崩点）

## 而且这正好能接上 AI

**明确的产品空位**：没有产品做「**上传姿势图 → 自动生成中文口令**」。

→ 这就是 `import_assets` 之后最值得做的 AI 能力：
**入库时顺手生成「怎么摆 + 怎么说」**。

# 四·补 ⭐⭐ 另一个更重要的判断（审美学习调研后新增）

## 4.1 「审美学习」不是一个真实的产品品类

外部调研的结论：英文里也没有完全对应的词。
真实产品把它拆成了**四种独立功能**，而且最常见、最成熟的是「收藏」：

| 对应 | 代表 | 停在哪 |
|---|---|---|
| 收藏 / 灵感库 | Eagle、PureRef、Pinterest | **存完没有下一步** |
| 分析 / 点评 | Adobe Project Indigo、PickEpic、YAN | 评的是「你拍的这张」，**不是「你存的这张」** |
| 对比 / 选择 | WhichOne、GuruShots | 帮你决定，**不教你怎么看** |
| 复盘 / 回顾 | Daily Pieces、Eagle 随机模式 | 自我认识，**不是审美判断** |

> **用户说「我要开始审美学习」，产品给他的往往只是一个更漂亮的收藏夹。**

## 4.2 「收藏夹变成技能」没有可验证的成功案例

反例倒是很硬：

> 一位 Eagle 重度用户存了 **5 万多份素材**：「随手保存只要一秒，整理一份却要十几秒」，
> 最后「几万份灵感就在硬盘里长眠。**真急着用，还不如打开 Pinterest 重新搜**。」

> 「**收藏一万张图，不如解构一百张图**。」

> Eagle 官方博客自己承认：**收集和整理本身，并不保证你变快或设计变好。**

## 4.3 ⭐ 因此核心字段要改：不是标签，是「一句话偷师点」

**原方案的核心是「标签体系」。调研后建议改成：**

> **标签解决检索，句子解决学习。**

保存一张图时，写一句「**我要从它身上拿走的那一项**」，
**不超过 40 字**，配 6 个快捷 chip：**光 / 构图 / 色彩 / 情绪 / 元素 / 标准**。

| 好例子 | 坏例子 |
|---|---|
| 「逆光把发丝和背景分开，脸留暗部」 | 「好看」 |
| 「阴影加青、高光加蓝、整体降饱和」 | 「高级」 |
| 「眼睛不要太大，下巴不要过尖，肤色不要偏绿」 | 「氛围感」 |
| 「前景用纱/玻璃做一层雾，人物只占三分之一」 | 「日系」 |

> 坏例子的共同点：**没有信息量，等于没写。**

**为什么这是唯一该做核心的功能**：

1. **唯一一个在「保存那一刻」改变用户行为的功能**——其他功能都依赖它
2. **把「好看」翻译成「可操作特征」**——正对着「只知道好看、不知道该学哪一项」这个普遍困境
3. **直接对抗「被牵着走」**——写的是自己的判断，写完图可归档、判断留下来
4. **轻**：不需要 AI、不需要每天打卡，一张图 5 秒
5. **会沉淀成「标准」**：30–50 条之后聚成「我的标准」（眼睛多大算自然、肤色多白算假）

## 4.4 三个「不要做」

| 方案 | 为什么不做核心 |
|---|---|
| **AI 评分** | 给的是通用反馈，不知道你的意图/客户/场景；**而且它鼓励你继续消费，不鼓励你判断** |
| **间隔重复（Anki 式）** | 审美判断没有唯一正确答案；**没有 note 的复习只是重新刷图** |
| **自动标签 / 以图搜图** | 解决「找得到」，不解决「学得会」 |

> AI 要做的是**追问**，不是**评分**。写完 note 后问：
> 「还有哪个维度你没注意到？」「换成你的场景这一条怎么用？」
> 输出应该是「可操作特征」（阴影加青/高光加蓝），不是 0–100。

**补充数据**：AADB 数据集里 5 个标注者的平均一致性 Kendall's W 只有 **0.5322**
——**连人类对「构图好不好」都没有高度共识，AI 的分数更不该当真理。**

## 4.5 「看多了被牵着走」要变成产品机制

这是摄影教学中反复提到的一条：过度分析他人作品，会干扰自己的判断。

但「少看」不是解——真正的结论是：
**被动地看会被带偏，主动地拆不会。问题不在输入量，在「看完之后有没有变成自己的判断」。**

| # | 机制 | 具体做法 |
|---|---|---|
| 1 | **分流** | 入库时强制选「**找感觉 / 对脚本**」；找感觉的看完归档，不长期挂在眼前 |
| 2 | **写原则不写形容词** | 不存「高级感」，存「阴影加青、高光加蓝、降饱和」 |
| 3 | **反参考** | 除了「我要什么」，再记一条「**我不要什么**」 |
| 4 | **关掉参考再创作** | 拍之前先收起来按原则拍，拍完再并排对比（不是边看边拍） |

## 4.6 ⚠️ 「审核截图」和「审美参考」不能混

| 如果是 | 那就是 | Schema |
|---|---|---|
| 别人给你的**审片意见截图** | **错误库** | 截图 + 哪里错 + 正确做法 + 标签「踩过的坑」 |
| 自己的**成片** | **作品库** | 成片 + 参数/地点/脚本 + 当时的判断 |

> **两者 schema 不同，混在一个收藏夹里会互相污染。**

## 4.7 定位警告：不要做成「另一个 Eagle」

> Eagle 已经赢了「存」，PureRef 赢了「摆」。
> 我们的差异应该是：**每次存图的一次判断 + 写方案时能翻到的弹药库**。
> 如果只做「更大更全的库」，就会重复「5 万份素材长眠在硬盘里」的命运。

# 九、v3 修订：ShotDeck 调研后的具体化

> 四份调研全部回来了。这一版把「标签体系」和「批量入库」写成**可实现的规格**。

## 9.1 标签体系定稿（5 个必做维度，照 ShotDeck 的取舍）

| # | 维度 | 取值 | 谁来填 |
|---|---|---|---|
| **①** | **人物与关系** | `单人 / 双人 / 三人以上` × `coser / 老年 / 情侣 / 亲友` | **人数和人脸年龄让 AI 数** |
| **②** | **光** | 光质（硬/柔/混合）× 方向（顺/侧/逆/顶）× 时段（清晨/白天/黄金时刻/蓝调/夜） | EXIF + 图像统计**半自动**，人工确认 |
| **③** | **色调** | 1 条主色板 + 冷暖/饱和/对比三个值；支持按色值搜 | **全自动** |
| **④** | **景别/构图** | 景别（大特写/特写/半身/全身/环境人像）+ 构图（居中/三分/留白/前景遮挡） | 半自动 |
| **⑤** | **情绪/氛围** | **不做下拉框**：用「色调 + 光 + 表情」合成 + **一个自由词** | 合成 + 用户自由词 |

**外加两个必填/可选**：
- **系列（批次）**：**唯一强制的标签**——一次上传默认落进一个「系列」
- **偷师点**：一句话，≤40 字（v2 定的核心字段）

### 明确不做的维度（省打标预算和界面面积）

| 不做 | 理由 |
|---|---|
| 相机 / 镜头型号 | 人像找参考不看机身；EXIF 自动读当「可搜不必填」 |
| 人种 | 敏感、填不准 |
| 地区层级树 | 维护成本极高；换「地点自由词 + 场景类型枚举」 |
| 故事年代 / 画幅比 / 格式 | 影视拉片或自动提取才需要 |
| 镜头运动 / 技法 | 那是 Eyecandy 的活，我们是静帧库 |

## 9.2 ⭐ 批量入库的核心机制：把打标做成「改」，不是「填」

**这是从 500 次录入降到 50 次的关键。**

```
① 上传即分组：一次上传 → 一个「系列」（唯一强制标签）
② 自动算：主色板、明暗、画幅、人脸数、人脸年龄、清晰度、重复图
③ 最近邻继承：新图找库内最近邻 → 把邻居的场景/关系/光/情绪抄过来
              → 标成「待确认」→ 人只连点「对/不对」
④ 批量套用：框选一批 → 一次设「时段=黄昏、光质=逆光、场景=民政局门口」
⑤ 「待确认 N 张」队列：让她知道还剩多少，而不是感觉永远打不完
```

**第 ③ 步是核心**：行业里 Cosmos/Savee 都验证过「找相似」这条路
（Cosmos 原话「Start with an image you love and find more like it」）。

## 9.3 截帧入库（已确认是空白，要做）

- 快捷键 → **自动取前后各 1–2 秒的 3–5 张候选帧**让她挑（避免抓到糊帧）
- **必须自动带时间码 + 来源**（ShotDeck 的 `SHOT TIME: 0:12:29` 就是干这个的）
- 入库后**立刻跑 9.2 的自动流程**，不要让她截完还要再进另一个页面打标

## 9.4 ⭐ 建议把「参考图 vs 成片对照」放进第一版

| 谁做了 | 在哪 |
|---|---|
| Lightroom Reference View | **在修图软件里，不在参考库产品里** |
| StillsLab | 参考库产品里唯一做了双图对比的 |
| ShotDeck / FilmGrab / ScreenMusings / Savee / Cosmos | **都没有** |

**这是空白位，也是最容易做出差异化的一个点。**
她拍完能立刻知道「差在哪：是光位、是色温、还是构图留白」。

**交互照 Lightroom**：
- `Shift+R` 或点 `R|A` 图标 → 2-up
- **参考图静态不可编辑，当前图可编辑**
- 切模块会清空参考图 → 要能**锁定**

→ **需要你决定：进不进第一版？** 我建议进。

## 9.5 检索入口的摆法（照行业已验证的形状）

- **首屏只放一个搜索框**（自由词）+ 5 个 facet 的第一层，其余折叠
- 已选条件做成 **chip，可单个 ×**，显示「**命中 N 张 / 共 M 张**」
- **每张图悬停就出「找相似」**，不要藏在详情页
- 首屏第一动作永远是「打几个字」，不是「展开筛选器」

## 9.6 v3 实施顺序（更新）

| 阶段 | 做什么 |
|---|---|
| **P0** | 「偷师点」字段 + 「找感觉/对脚本」分流 + 「反参考」 |
| **P0** | 系列（批次）+ 「待确认」队列 |
| **P0** | 自动算维度（主色板/明暗/人脸数/重复图）+ **最近邻继承** |

| **P1** | **参考图 vs 成片对照**（若你同意进第一版） |

# 十一、v4 修订（用户反馈 + 摄影方法论补强）

## 11.1 ⭐ 三个库，不是两个（用户指出我漏了最重要的那个）

| 库 | 放什么 | 用途 | 我之前的问题 |
|---|---|---|---|
| **好库** | **别人的好片子**：电影截帧、大师作品、别人拍得好的 | **学 / 找参考** | **❌ 我漏了** |
| **不好库**（错误库） | 别人给你的审核意见截图、自己拍坏的 | 别再犯 | ✅ 提了 |
| **我的库**（作品库） | 自己的成片 | 复盘看进步 | ✅ 提了 |

**「审美学习」本来指的就是第一类「好库」**，我上一版把它和「审核截图」混在一起谈了，是我的错。

### 好库对应哪类产品

调研里 **ShotDeck** 就是这类：电影截图 + 按光/构图/色调/情绪检索。
我们的好库要能：
- 存别人的好图（电影/大师/网上）
- 按「光 / 构图 / 色调 / 情绪 / 场景」检索
- 每张写一句「偷师点」

### 三个库的关系

```
好库（学） ──→ 写进脚本/分镜 ──→ 拍
                                  ↓
不好库（别再犯） ←── 复盘比对 ←── 我的库（自己的成片）
```

## 11.2 不自动抽帧，改成「按人的反馈定位」

**用户明确否掉**：「视频导入自动抽帧不要了吧，AI 审美还是不太行」。

**有硬证据支持他**：AADB 数据集 5 个标注者一致性 Kendall's W 只有 **0.5322**
——连人类对「构图好不好」都没共识，AI 更不该当裁判。

**用户提的替代方案（更好）**：
> 「有别人评论过那里好看这种的可以有，比如视频是大家看过的有评论的网上」

| 信号 | 怎么用 |
|---|---|
| **B 站弹幕密度** | 弹幕突然暴涨的时间点 = 大家都觉得「这一下好看」 |
| **评论区「第几分几秒绝了」** | 直接定位 |
| **高赞评论里的时间戳** | 定位 + **理由**（他们说了好在哪） |

**为什么这比 AI 好**：
1. 不用猜，是真实的人类集体判断
2. **评论里带理由**（「这个逆光绝了」）→ 这正好就是「偷师点」

→ 所以：不自动抽帧，改成「**按弹幕/评论热度提示这段值得看**」，用户手动截。

## 11.3 摄影方法论补强带来的字段修正

读了第 09 / 22 / 25 课后，三个字段要改：

### ① 「光」维度有现成词表了（摄影通行分类）

| 光位 | 判定特征（看照片能判） |
|---|---|
| 顺光 | 脸的光线很均匀，缺少立体感（人像里最容易「平」的一种） |
| 侧顺光 | 45° |
| 侧光 | 90°，一半亮一半暗（俗称阴阳脸） |
| 侧逆光 | 身后45°；轮廓光+鼻头光 |
| 逆光 | 「拥有最强层次感」 |
| 顶光 | 鼻下阴影 |
| 底光 | 下巴向上光 |

**光质另算**：「影子深、有边缘 = 硬光；无边缘、过渡均匀 = 柔光」

### ② 「情绪」不是单张标签，是「整组主题 + 曲线」

> 「从平静慢慢有些爆发，然后再到完全安静下来」
> 「几乎每一张图看着都有一点点病态」「最后放了一个窗户，好像看到希望」

→ 情绪字段应该挂在**系列/整组**上，不是一个主题词 + 一条情绪曲线；
单张图可以有「表情」标签，但不是「情绪」。

### ③ 加「可实现性」判断

**摄影常识**：把别人片子的色调搬到自己照片上，只有在**题材、风格、配色都相近**时才成立；
条件差太远时，同一套调色会「反噬」画面。

→ 参考库每条要有：**可实现 / 不可实现**（这也是之前调研里已经提过的标签）

**「参考图 ↔ 自己成片 并排对比」这个功能，现在就做，还是以后再说？**

# 十二、v5 修订：补完摄影方法论后新增的字段

> 这一版来自对摄影方法论的系统补强（构图/光线/灯光/磨皮/情绪/调色六个模块）。
> 只写通用摄影知识，不引用任何具体课程内容。

## 12.1 新增候选字段（8 个）

| 字段 | 取值 | 必要性 | 为什么 |
|---|---|---|---|
| **光影结构是否完整** | 完整 / 被磨平 | **高** | 人像修图最常见的失败是「把脸磨平了」，光在脸上的结构没了。这是「不好库」最有价值的判据之一 |
| **背景虚化** | 浅 / 中 / 深 | 中 | **比记录光圈值 f/1.4 更有意义**——用户关心的是视觉结果，不是参数 |
| **焦段感** | 广角（脸会变形）/ 标准 / 长焦（脸被压缩） | 中 | 焦段改变人脸透视，这是「风格」维度，不是「参数」维度 |
| **灯数** | 1 / 2 / 3+ | 中 | 只对「灯光人像」题材显示 |
| **主灯作用** | 控环境 / 做造型 | 中 | 同上 |
| **色片** | 有（什么颜色）/ 无 | 中 | 同上 |
| **色彩搭配** | 互补（橙蓝 / 红青）/ 类似（蓝白）/ 单色 | 中 | 灯光人像的核心检索词，而且是成套的名字 |
| **胶片** | 底片型号 + 冲扫方式 | 可选 | 「胶片感」是可追溯的具体配方，不是玄学 |

## 12.2 色温要记两项，不是一项

**摄影常识里的一个坑**：光源的色温值，和相机白平衡设置里的色温数值，**变化方向是相反的**
（数值变小反而画面变冷）。

→ 参考库如果记色温，必须同时记：
- **光源色温**（这个灯/这个时段的光是多少 K）
- **相机白平衡设置**（当时设了多少 K）

只记一个，以后无法复现。

## 12.3 「磨皮不能破坏光」应该做成一条审美检查项

人像修图里最难的一步不是调色，是**磨皮**——因为它要在「让皮肤变好」和「保持光在脸上的结构」之间平衡。

**失败的样子**：脸变得平整光滑，但光没了——鼻子没立体感、颧骨没阴影、轮廓糊了。

→ 做成一条可勾的检查项：**「光影结构还在吗？」**
→ 这条同时属于「不好库」（记录踩过的坑）和「参考 vs 实拍对比」（诊断差异）

## 12.4 对「参考 vs 实拍对比」的诊断项补充

之前的六项（光位/色温/构图/景别/情绪/背景）要补两项：

| 诊断项 | 怎么比 |
|---|---|
| **光影结构** | 参考有立体感 / 实拍被磨平或补光过度 |
| **色彩搭配** | 参考是橙蓝互补 / 实拍是单色 |

## 12.5 v5 状态

需求到这里，**字段设计已经完整**（v1 四件事 + v2 偷师点 + v3 标签体系 + v4 三类库 + v5 摄影字段）。

**原型已占位**：`docs/prototypes/photo-ref/index.html`
（三个库 + 偷师点 + 参考 vs 实拍对比 + 筛选 + 批量/截帧入口）

**下一步**：等用户验收原型，再决定先实现哪一块。

# 十三、v6 修订：「场景」维度定稿（外部调研后）

## 13.1 核心结论：场景必须拆成两个正交维度

> **场景类型**（受控词表，15 个叶子）+ **地点**（自由文本）
>
> **不要把场景做成一个不断加长的标签列表。**

### 为什么必须分开

**地点是容器，场景是容器里的环境类型。**

| 地点（容器） | 里面有哪些场景类型 |
|---|---|
| 亚龙湾 | 沙滩 / 雨林 / 草坪 / 礁石 / 花园 |
| 民政局 | 大厅 / 颁证台 / 门口 / 车内 / 附近咖啡店 |

合并的话会产生「地点 × 场景」的组合爆炸——这正是标签膨胀的来源。

而且**同一场景类型会跨地点复用**：「海边」可以在三亚、厦门、青岛；「咖啡店」在任何城市。

**产品佐证**：
- Google Photos 侧栏把 **Places** 单独分开
- Lightroom 把 **Where** 做成地点层级，另用 Who/What/When 描述其他维度
- 旅拍业务自己就把「心仪的城市」和「心仪的风格」分开问

**没有找到任何公开产品把「地点 + 场景类型」做成同一棵树。**

## 13.2 场景类型 v1：5 组、15 个叶子

| 大类 | 叶子 | 打标时看什么 |
|---|---|---|
| **室内棚拍** | 影棚 / 纯色背景 | 背景纸、柔光箱、影棚灯、无明显环境 |
| | 实景基地 / 主题棚 | 欧式柱、韩式布景、中式木构、仿真街景 |
| **室内生活** | 居家 / 室内 | 沙发、床、厨房、阳台、窗帘 |
| | 店铺 / 民宿 / 咖啡店 | 吧台、货架、菜单、民宿床品、书店 |
| **城市人文** | 城市街拍 / 建筑 | 街道、巷弄、斑马线、招牌、天桥、地标 |
| | 交通 / 车内 | 车内座椅、方向盘、车窗、车站、公路 |
| | 展馆 / 活动现场 | 展台、漫展场馆、舞台、灯光架 |
| **自然户外** | 公园 / 校园 / 绿地 | 树、草坪、长椅、跑道、教学楼 |
| | 海边 / 水边 | 沙滩、礁石、海浪、栈桥、湖边、泳池 |
| | 山林 / 草地 / 花海 | 树林、山路、草地、花田、芦苇、茶园 |
| | 古镇 / 园林 / 古建 | 白墙黛瓦、木构、亭台、石板路、城墙 |
| | 废墟 / 工业 / 天台 | 断墙、水泥、厂房、铁架、天台、车库 |
| **仪式政务** | 民政局 / 政务大厅 | 红底、登记窗口、颁证台、宣誓厅、喜字 |
| | 教堂 / 礼堂 / 宴会厅 | 彩窗、长椅、拱顶、酒店宴会厅 |
| **其他** | 无法判断 | 环境信息不足 |

**先不单列的**：「雪山 / 沙漠 / 盐湖」暂放「山林 / 草地 / 花海」；
「漫展」放「展馆 / 活动现场」。量大了再加二级。

**教堂和民政局不能合并**：领证和婚礼是两种业务，检索语义不同。

## 13.3 地点：独立维度，不做长受控列表

| 项 | 做法 |
|---|---|
| **城市** | 20–30 个常用做下拉 + 自由输入 |
| **具体地点** | 自由文本（「西湖区民政局」「亚龙湾公共沙滩」） |
| **未知** | 允许留空，**不强迫填** |
| **层级** | 最多 3 层（国家 → 省 → 城市）；具体地点不做层级 |

## 13.4 标签膨胀的控制数字（有出处）

| 原则 | 出处 |
|---|---|
| **2–3 层**，用 facet 组合替代深树 | Trimming an Untamed Taxonomy |
| **少于 4 层**，每子类至少 2 个条目，**3 次点击可达** | FotoWare |
| **3–4 层**；**400 个叶子是灾难**，用户用不到第 3 层 | Aetopia |
| 「把不同性质的词放同一层」是最大毛病；应建**平行维度**而非一棵树 | 中文 taxonomy 资料 |

### 我们的执行数字

| 项 | 目标 |
|---|---|
| 场景大类 | 4–6 个 |
| **场景叶子** | **12–16 个**（现在是 15） |
| 场景层级 | **2 层** |
| 每维度取值 | 5–12 个 |
| 每张图标签数 | **3–6 个** |
| **总受控值** | **60–80 个**（超 100 要警惕） |

## 13.5 维护规则（防膨胀）

1. **一个概念一个规范词**，同义词走「入口词」表（棚拍=影棚；海边=海景；民政局=婚姻登记处）
2. **新值只在「其他」超过 10% 且连续 2 个月时增加**；不要在一次批量上传中临时加
3. **3 个月使用率 < 5% 的叶子合并或停用**；停用不删除，保留历史映射
4. **一个叶子超过 20% 的图就考虑拆分**；拆前先看是不是「其他」在混淆
5. **每季度审查**：看「其他」占比、搜了但库中没有的词
6. **变更留记录**：旧值→新值映射 + 生效日期

## 13.7 批量打标签流程（100–500 张）

1. **先建词表，再上传**：批量过程中**不加新值**
2. **按拍摄批次打默认值**：一次拍摄通常同一题材、同一地点、1–2 个场景
3. **用「最近使用标签」**：适合大批量重复标注
4. **只强制 3 个字段**：题材、场景类型、人数；其他允许空
5. **「其他」集中放**：每周统一看一次，再决定加值还是归并
6. **保存常用筛选**：领证 / 情侣 / 老年 / coser 各存一个智能集合

## 13.8 六条「不要做」

- ❌ 不要把地点塞进场景词表（「民政局门口」是地点不是场景）
- ❌ 不要照搬影楼销售目录（影楼按套系卖，按视觉找是两回事；它能组合上千种场景）
- ❌ 不要一开始做 50+ 场景
- ❌ 不要让「其他」成为垃圾桶（>10% 说明词表缺类）
- ❌ 不要把风格/服装/色调塞进场景
- ❌ 不要给情绪做下拉（已定用合成）

## 13.9 一句话

> 场景维度的目标不是「穷尽所有拍摄地」，而是
> **让摄影师在 3 次点击内找到「我想要的那种环境」**。
> 15 个场景叶子 + 一个独立的地点字段，比 100 个场景标签更接近这个目标。

# 十四、v7 修订：对比不是唯一形态，参考图也可以临时给

> 用户指出：「作品可能有的是直接拍的，然后分析，没有对比，这种考虑过吗？
> 并且对比的应该是可以自己传的。」

**这暴露了我之前一个隐藏假设：默认「每张作品都有参考图」。** 不成立。

## 14.1 两种模式，不是一种

| 模式 | 前提 | 干什么 | 依据 |
|---|---|---|---|
| **参考对照** | 有参考图 | 比「像不像」 | Lightroom Reference View 的心智 |
| **分析作品** | **没有参考图** | 看「好在哪、差在哪」 | Adobe Project Indigo / PickEpic 的心智 |

**实际拍摄里很多是直接拍的**：客户没给参考、临时想到的画面、抓拍。
这些没有「参考」可比，但仍然需要复盘。

### 分析模式的关键设计

**不打分。** 分成三类输出：

| 类别 | 内容 | 标记 |
|---|---|---|
| **成立的地方** | 可观察的事实 | 绿标「可观察事实」 |
| **可疑的地方** | 需要创作者判断的点 | 黄标「要你判断」 |
| **看不到的地方** | EXIF 里没有的信息 | 灰标「参数里没有」 |

> 比如：「f/4 让背景还看得见轮廓，虚化比常见的弱。
> **是故意保留环境，还是当时光线不够？**」
> —— 这是提问，不是结论。

**「看不到的地方」这一类尤其重要**：你当时想表达什么、这张在整组里是开头还是结尾，
这些 EXIF 永远读不出来，只能由人说。

## 14.2 参考图必须支持「临时给」

**不能假设参考图一定在库里。**

真实场景：
- 客户刚在微信发来一张「我想要这种感觉」
- 刚在小红书刷到一张，还没入库
- 电脑里存着一张，从来没用过

### 三种来源

| 来源 | 交互 |
|---|---|
| **从审美库选** | 走库内检索 |
| **临时上传 / 拖入** | 直接把文件拖进面板 |
| **粘贴图片** | Ctrl+V |

**关键**：临时参考图**不用先入库**。对比完再决定要不要存进审美库。

> 这符合「采集摩擦要低」的原则——如果对比前必须先入库，
> 用户会放弃对比，直接凭感觉看。

## 14.3 两个模式共享同一个助手

对比助手和分析助手是同一个，只是切换上下文：

| 模式 | 助手第一句话 |
|---|---|
| 参考对照 | 「我看完两张图的参数了，硬数据上差在这几处…」 |
| 分析作品 | 「这张我只看得到参数和画面，**看不到你的意图**…我不打分。」 |

**都要做的事**：先报确定的（EXIF），再指出不确定的，最后提问。

# 十五、v8 修订：分析模式去掉三类卡片（用户明确要求）

> 用户原话：「不需要这三卡片，我自己分析。显示下拍摄参数和当时的脚本啥的，
> 可以折叠编辑。最多和智能体聊聊，让它总结，然后可以添加到反思。」

## 15.1 我上一版做错了什么

我做的是「**工具替你分析**」——输出三类卡片（成立/可疑/看不到）。
用户要的是「**工具替你摆材料，分析自己来**」。

> **这是个方向性错误：把「辅助」做成了「代替」。**

## 15.2 改成：三块折叠记录 + 一个能聊的助手

### 三块折叠区（默认收起，点开可编辑）

| 折叠区 | 内容 | 来源 |
|---|---|---|
| **拍摄参数** | 相机 / 镜头 / 焦距 / 光圈 / 快门 / ISO / 白平衡 / 时间 / 地点 | **EXIF 自动读** |
| | **补录**：当时的光、现场状况 | **人填**（EXIF 看不出） |
| **当时的脚本** | 项目 / 场景 / 分镜 / 要的画面 / 必带道具 | 关联摄影策划台 |
| | **偏离了** + **为什么** | **人填** |
| **客户/自己的评价** | 客户原话（别转述）+ 自己的判断 | **人填** |

**关键**：每一块都是「**自动的自动填，人工的人工补**」，来源标清楚（绿标 EXIF / 黄标人填）。

### 智能体的角色变了

| 之前（错） | 现在（对） |
|---|---|
| 替你分析、输出结论卡片 | **陪你聊，帮你把话理清楚** |
| 「成立/可疑/看不到」 | 「要不要我整理成一句可以存的反思？」 |
| 单方面给判断 | **等你先说自己感觉到什么** |

**交互示例**（原型里的）：
```
你：这张我感觉光对了，但脸有点太暖，说不上来哪不对
AI：看参数对上了：白平衡设的是 6100K，而当时的光是下午 5 点侧后方的太阳，
    这个时段的自然光本身偏暖，相机再往暖设就叠加了。
    再加上你补录的「风大、抓十几张」，说明是按快门优先在抢瞬间，
    颜色判断被牺牲了。
    下次可以试：白平衡往 5200K 压，或者拍之前先对白纸定一次。
    → 生成总结，存进反思
```

**AI 的作用**：**用你补录的信息 + EXIF，把你「说不上来」的感觉翻译成具体原因**。
它不做审美裁判，它做翻译。

### 存进反思是一步动作

AI 生成的总结 → 你确认 → **存进「反思」库**，带自动标签（白平衡/傍晚/逆光）。

这条链路把三个库串起来了：
```
作品（这张图） → 和 AI 聊 → 总结 → 存进 反思（下次别再犯）
```

# 十六、v9 修订：补两个维度（个性来源 / 表演方式）+ 一个漏掉的对象

## 16.1 新增两个维度：这张片子是「谁」的个性

人像作品里的「个性/性格」来自两处，需要分开记：

| 维度 | 取值 | 用途 |
|---|---|---|
| **个性来源** | 模特的 / 摄影师的 | 这组片子是记录她，还是表达我 |
| **表演方式** | **本色出演** / **角色扮演** | 让模特做自己 vs 让她演一个角色 |

**为什么重要**：
- 「角色扮演」是绝大多数商业/写真拍摄的实际形态（摆姿势、演情绪）
- 「本色出演」很难，前提是**你足够了解这个模特**
- 两者对脚本、对引导口令的要求完全不同

## 16.2 ⭐ 漏掉的一个对象：模特 / 客户

之前所有调研和需求里都没有这个对象。但真实工作流里它是核心：

**你要「本色出演」，就得了解这个人。**

建议加一个轻量对象：

| 字段 | 内容 |
|---|---|
| 称呼 | |
| 性格特点 | 她自己说的 + 你观察到的 |
| 拍过的片子 | 关联作品库 |
| 适合的方向 | 什么风格她最好看 |
| 她自己的偏好 | 她喜欢/不喜欢什么 |
| 注意事项 | 镜头恐惧、体态问题、沟通方式 |

**为什么值得单独建档**：
- 老客户/老模特复拍是常态
- 「了解」是慢慢积累的，散在作品里会丢
- 这也是「作品库」和「反思库」之外，第三个需要长期沉淀的东西

## 16.3 反思库可以有一条固定检查清单

人像后期有固定的处理顺序（修瑕疵和磨皮可以互换，其余不宜乱序）。
反思时按顺序过一遍，比自由写更容易发现遗漏：

```
曝光 / 白平衡 → 瑕疵 → 液化（形体）→ 磨皮（高光阴影结构）
→ 调色 → 肤色 → 锐化/输出
```

**注意**：这只是「检查顺序」，不是「我们替他做」——判断仍然是人做。

本版无原型改动（维度与对象是需求层的）。
原型最新是 v8：三块折叠记录 + 能聊的助手 + 存进反思。

| 字段 | 内容 |
|---|---|
| **一句话** | 那条经验（≤60 字，可编辑） |

| **来源** | 分析作品 / 参考对照 |
| **时间** | |

## 17.3 三个库的完整流向

```
审美（别人的好片子）
   ↓ 找参考对比
作品（自己拍的） ──→ 分析作品 / 参考对照
   ↓                        ↓
   └──────────────────────┤
                          ↓
                    反思（一条条可检索的经验）
                          ↓
                    下次拍摄前翻一翻
```

**注意「反思」不是附属于作品的**：它是独立的库，能脱离原图单独检索。
但它**挂着原图**，所以能随时点回去看「当时是什么情况」。
