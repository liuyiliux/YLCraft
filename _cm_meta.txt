refactor(platforms): 平台元数据收敛为**单一事实来源**（消除 4 处重复）

## 问题（用户问"符不符合公共的在公共、个性化的在自己文件夹"）

**目录分层是对的**，但**平台元数据散落 4 个文件**，共 58 项内联映射：

    api/v1/users.py            SUPPORTED（含 conn_platform/cookie_domain/no_login）
                               _CLIENT_ALIAS（5 项）
    api/v1/comments.py         COMMENTS_SUPPORTED
                               (连接名, cookie域名) 内联字典
                               逐个别名 if 转换（wb→weibo, dy→douyin…）
    services/platforms/
      health_routes.py         PROBE_SEARCH_TYPE
                               PROBE_KEYWORD_BY_PLATFORM
                               平台→连接名 内联字典（19 项）   ← 共 44 处平台名
                               no_login = p in ("youtube","telegram")  ← 硬编码
    api/v1/platform_stats.py   _ALIAS（7 项）

**真实后果**：新增一个平台要改 **4~5 个文件**，漏一个就**静默出错**：
  · 漏 comments.py 的映射 → 评论接口 KeyError
  · 漏 health_routes 的探测类型 → 体检拿不到结果
  · 别名忘了加 → create_client 找不到客户端

这正是"**公共代码成了平台知识的垃圾场**"。

## 改法：平台自己声明，公共层只聚合

### 新增 `platforms/meta.py`（注册表 + 查询 API）
    get_meta / resolve_name / all_metas / supports / supports_any
    no_login_platforms / probe_config

### 每个平台新增 `meta.py`（9 个）
声明 name / aliases / conn_platform / cookie_domain / no_login /
probe_search_type / probe_keyword / capabilities / user_dimension。

**所有易错点都写在平台自己的 meta 里**（附实测原因）：
  · bili 的 cookie_domain 是 `"bili"`（不是 bilibili）
  · weibo 是 `"weibo"`（不是 weibo.com —— 主站 cookie 在 m.weibo.cn 无效）
  · twitter 是 `"x.com"`（不是 twitter）
  · 微博**没有** replies 能力（楼中楼实测拿不到）
  · B站有 comments_paged（更完整的分页）但没有 replies
  · 快手**没有** user_profile（平台就没这个接口）
  · 番茄没有搜索探针（probe_search_type 为空 → 体检跳过）

### 4 个公共文件改为从 meta 生成
  · `users.py`      SUPPORTED / _CLIENT_ALIAS → 惰性表（按 user_dimension + 能力筛选）
  · `comments.py`   COMMENTS_SUPPORTED / 映射表 / 别名转换 → meta
  · `health_routes.py`  探针类型 / 连接名 / 免登录名单 → meta（**44 处平台名 → 0**）
  · `platform_stats.py` _ALIAS → meta

**用惰性表而不是模块级常量**：元数据是懒加载的（首次访问才扫目录），
模块导入时还没扫完。

## ⚠️ 顺带修一个有数据风险的细节

`platform_stats.normalize_platform("xhs")` 原来归到 `"xhs"`，
而 meta 的正式名是 `"xiaohongshu"` —— 直接切换会让**历史统计查不到**
（旧记录 provider 写的是 `xhs`），表现为"数据凭空变少"。

修法：查询用 `IN (...)` 覆盖**正式名 + 所有别名**（`aliases_for_query`）。

## 验证（端到端，行为完全不变）

    health:  bili/telegram/fanqie/youtube 全部 ready=True
             （探针词正确：telegram 用 "telegram"、fanqie 提示"没有内容搜索"）
    stats:   bili 与 bilibili 归并一致、x 与 twitter 归并一致
    users:   youtube/wb/x 各返回 20 个用户；番茄 **400 + 动态生成的支持列表**
    comments: 6 平台 200；小红书 501；微博/B站子回复 501 + 各自说明

## 测试（只跑相关文件）
新增 `tests/test_platform_meta_single_source.py`（15 条）：
  · 每个平台都必须声明 meta
  · **三个易错 cookie_domain** 的值
  · 能力声明与实现**一致**（声明 comments 就必须有实现）
  · 微博不得声称有 replies
  · **四个公共文件里不得再有平台映射表**（防回退）

⚠️ 写最后一条时踩了三次坑：注释/docstring 里会写
`PROBE_SEARCH_TYPE = {"bili": "video", ...}` 来说明"原来有什么"，
简单 grep、甚至按 AST 语句行号取，都会把**历史说明**误判成硬编码。
最后用 `tokenize` 按 token 类型过滤（丢 COMMENT 和独占行的 STRING）才对。
