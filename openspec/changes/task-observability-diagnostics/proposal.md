# Proposal: 任务诊断与事件时间线

## What

为异步任务补充可诊断状态与事件时间线，让用户和开发者不必只依赖后端控制台日志判断任务为什么卡住或失败。

优先覆盖新接入的 `image_generation` 异步生图任务，并保持设计可复用于下载、字幕、BGM、电子书等已有任务。

核心能力：

1. **任务诊断字段** - 在任务 payload/result/detail 中暴露外部任务 ID、远端状态、轮询次数、最后轮询时间、失败次数和最后错误。
2. **任务事件时间线** - 为任务追加结构化事件，如创建、提交远端、轮询中、完成、下载图片、入素材库、失败。
3. **任务详情可见** - 任务中心详情页展示诊断字段和事件时间线。
4. **图片异步生图优先接入** - ModelScope 等异步生图任务可以直接看到远端状态变化与失败原因。

## Why

- 当前日志主要在项目功能内部或后端控制台，用户在任务中心只能看到粗粒度状态。
- 异步生图的失败点较多：创建任务、轮询接口、远端排队、图片下载、素材入库、项目回写。没有诊断字段时排查成本高。
- 统一任务队列已经存在，适合先做轻量增强，而不是立刻建设完整日志中心。

## What changes

| 层 | 新增 | 修改 |
|---|---|---|
| Backend | 任务事件结构与 append helper | `app.core.task_queue` 增加事件存储/更新能力 |
| Backend | 任务诊断字段规范 | 图片异步生图轮询时更新 `payload/result` 中的诊断字段 |
| Backend | `/api/v1/tasks/{id}` 返回事件与诊断数据 | `api/v1/tasks.py` 详情响应展示事件 |
| Frontend | 任务详情事件时间线 | `pages/tasks/index.tsx` 增加诊断区和事件列表 |
| Frontend | 图片生图页任务入口 | 异步生成状态区提供“查看任务详情” |

## Non-goals

- 不在第一阶段建设持久化日志表或 ELK/OTel 等系统级观测平台。
- 不采集敏感请求体、API Key、完整图片 base64 或完整第三方响应。
- 不一次性迁移所有历史任务，先覆盖 `image_generation`，再逐步接入其他任务。
- 不替代后端 logger；任务事件用于产品内诊断，logger 仍用于服务运行排查。

## User flow

1. 用户在图片生成页提交 ModelScope 异步生图。
2. 后端创建内部任务，保存 `external_task_id/provider/model`，记录 `created/submitted_remote` 事件。
3. 前端轮询图片任务。
4. 每次轮询更新 `poll_count/last_remote_status/last_polled_at`，必要时追加事件。
5. 任务完成后记录下载与素材入库事件。
6. 用户可在任务中心打开详情，看到任务当前诊断字段和事件时间线。
