# Proposal: 创作项目闭环重构

## What

将 YLCraft 从“多个独立工具页面”重构为围绕 **创作项目、素材库、画布** 的闭环系统。

当前项目已经有很多从开源项目参考或移植出来的大体框架，但真正形成稳定闭环的能力主要是：

1. 下载与本地素材入库。
2. 小说下载、书架与阅读。
3. AI 图片生成与图片资产保存。

本次规划不要求保留所有历史页面的原交互。除上述稳定能力外，其他模块可以被合并、降级为实验能力，或者围绕新闭环重做。

目标闭环：

```text
小说/原创创意/本地素材
  -> 创作项目
    -> 故事大纲 JSON
    -> 章节/剧集规划 JSON
    -> 单章/单集细纲
    -> 正文/短剧脚本
    -> 漫画分镜/视频分镜
    -> 图片/视频/音频生成
  -> 素材库沉淀
  -> 画布编排
  -> 导出/发布准备
```

## Why

- 用户真正需要的是“从素材到成片/漫画/短剧脚本”的连续生产链路，而不是一堆互相孤立的功能入口。
- 素材库和画布天然是所有能力的中转站：下载、小说、图片生成、视频生成、剪辑、字幕、发布都应该围绕它们流动。
- 参考站 PlotCanvas 的价值不在 UI 外观，而在它把小说/漫画/短剧拆成了稳定的阶段机：故事大纲、章节规划、当前话细纲、正文、漫画分镜/图片。
- YLCraft 已有 `Story`、`Character`、`Asset`、`AssetHub`、下载、小说、AI 图片等基础能力，适合通过一次产品架构重整变成闭环工具。

## Goals

- 建立 `CreativeProject` 或升级现有 `Story` 为创作项目工作台。
- 将用户提供的故事大纲 JSON 和章节规划 JSON 变成第一版稳定数据协议。
- 将小说下载内容转换为可拆解的项目输入，支持从已有小说提炼角色、世界观、章节摘要和短剧脚本。
- 将角色、世界观、章节、分镜、提示词、图片、视频都作为素材节点沉淀到素材库。
- 建立项目画布，用节点方式编排角色、场景、分镜、素材和生成结果。
- 将现有稳定能力接入闭环：下载入库、小说阅读/章节、AI 图片生成。
- 对历史半成品模块做导航与状态治理，减少用户误以为都已完整可用。

## Non-goals

- 不在本阶段自建云端资源池、云端缓存或云端生成平台。
- 不复制参考站的代码、页面和账号体系，只吸收工作流设计。
- 不承诺一次性修完所有历史模块。
- 不把公众号文章作为核心生产入口，它只作为可选素材来源。
- 不优先做公开资源搜索、内容推荐或资源站聚合。

## What changes

| Layer | Change |
|---|---|
| Product | 将一级心智调整为“项目工作台 + 素材库 + 画布”，其他能力作为动作入口 |
| Backend | 新增或扩展创作项目数据模型，存储 outline、chapter_plan、episode_detail、script、storyboard |
| Backend | 增加严格 JSON 生成、校验、修复和版本保存能力 |
| Backend | 小说章节支持转换为项目输入，并生成拆解结果 |
| Backend | 素材库增加项目关联、来源链路和生成谱系 |
| Frontend | `/story` 从一次性 Story Maker 升级为项目工作台 |
| Frontend | `/assets` 成为所有生成物和下载物的统一检索入口 |
| Frontend | 增加画布视图或项目内画布 Tab，用节点组织创作链路 |
| Navigation | 标记实验功能，收拢半成品入口，避免用户被未完成模块打断 |

## MVP scope

第一阶段只做可以闭环的最小版本：

1. 创作项目列表与项目详情。
2. 从创意生成故事大纲 JSON。
3. 从故事大纲生成章节/剧集规划 JSON。
4. 从小说章节导入为项目输入。
5. 将角色写入角色库，将文本规划写入素材库或项目素材关联。
6. 在项目页面选择章节生成短剧脚本草稿或漫画分镜草稿。
7. 分镜提示词可一键跳转 AI 图片生成，并将结果回写项目素材。

## Success criteria

- 用户能从一个创意生成结构化大纲和章节规划。
- 用户能从已下载小说选择章节，生成短剧脚本或分镜草稿。
- 生成的角色、章节、分镜、图片都能在素材库中找到，并能追溯来源项目。
- 项目页面能展示当前阶段、已生成内容、下一步动作。
- 下载、小说、AI 图片三个稳定能力被串起来，而不是继续孤立存在。
