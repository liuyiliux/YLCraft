# 角色管理设计优化

## Why

YLCraft 当前角色管理页面（`frontend/src/pages/characters/index.tsx`，约 3800 行）功能已覆盖角色 CRUD、立绘生成/版本管理、九宫格切片、角色圣经分区（identity/motivation/speech/behavior/ability/arc）、世界使用链接和 AI 补全。但相比 `eternityspring/shuohao-skills` 的 `novel-characters` 报告（report.html + 角色设定图），存在明显的**信息密度与阅读体验**差距：

1. **卡片墙信息密度低**：角色列表是 6 列卡片，每张卡片只展示一张缩略图 + 名称 + 1 行描述 + 几个标签。角色之间缺少可比较的骨架，难以从列表层面预判哪个角色已完善、哪个还需要补充。
2. **详情抽屉太挤**：Drawer（860px）内叠放了身份板 + 4 个 QuickPanel + 详细面板 + 外观折叠面板 + 统计 + 操作按钮，垂直滚动很长。用户无法一眼抓住"这个角色到底长什么样、性格是什么、原文依据在哪里"。
3. **缺少"设定集"视角**：参考仓库把每个角色做成一张 **16:9 角色设定图**（左 34% 半身像 + 右三视图 + 右下细节条），并在报告里提供**关系图谱**。YLCraft 目前没有角色之间的关系建模，也没有角色设定图的统一视图。
4. **没有原文/事实溯源标记**：参考报告用铁锈红边栏 + `（推断）` 标记来区分"有原文依据"和"为可用性补的"信息。YLCraft 的角色字段全部平铺，用户无法知道某个描述是来自小说原文还是 AI 补全。
5. **Prompt 使用效率低**：参考报告的每个角色有 7 个复制按钮（出图提示词、设定图提示词、反向提示词、音色提示词、JSON），YLCraft 虽然在抽屉里有"预览立绘提示词"，但没有统一的"这个角色可以直接拿去用的完整资产包"视图。

## Product Goal

借鉴 `shuohao-skills/novel-characters` 的视觉设计语言，重构 YLCraft 的角色管理页面：

1. **列表升级为"角色册"视图**：保留搜索/筛选，但卡片从"缩略图 + 名字"升级为紧凑的设定预览——立绘 + 关键字段摘要 + 完善度指示器（哪些 Bible 字段已填）。
2. **详情从 Drawer 升级为双栏布局**：左栏角色设定图/立绘 + 关键信息，右栏 Bible 分区 + 原文溯源 + 生成提示词。借用参考报告的主区布局（`1fr / 500px` 双栏、断点 1240px）。
3. **新增"关系图谱"视图**：为角色建立简单的关系建模（`character_relationships` 表或复用餐数据字段），在角色管理页提供一个全景关系图谱。
4. **新增"角色设定图"生成预设**：在现有 portrait 预设基础上增加 `character_sheet_16_9`（参考参考仓库的三区布局），生成一张包含半身像 + 三视图 + 细节条的设定图。
5. **信息分级与溯源标记**：区分"原文/素材来源字段"与"AI 补全/推断字段"，在 UI 上用视觉标记（如参考报告的 `（推断）` 标签）区分。
6. **Prompt 资产包**：每个角色详情提供一个可折叠的"出图提示词 + 音色提示词 + JSON 导出"面板，全部可复制。

## Scope

- 前端 `frontend/src/pages/characters/index.tsx` 重构为双栏 + 设定集视图。
- 新增 `character_relationships` 表（`character_id`、`related_character_id`、`relation_type`、`relation_note`、`source`）+ Alembic 迁移。
- 新增 portrait 预设 `character_sheet_16_9` 的提示词模板。
- 新增 `POST /api/v1/characters/{id}/relationships` 等关系 CRUD 接口。
- 角色详情新增 "Prompt 资产包" 折叠面板（出图/音色/JSON 导出）。
- 角色字段增加 `source_evidence` 标记（区分原文来源 vs AI 推断）。
- 关系图谱前端组件（内联 SVG 或轻量 SVG，不引重型图库）。

## Non-Goals

- 不改变角色数据模型的主干字段（`Character` 表结构保持向后兼容，新增字段走迁移）。
- 不实现全自动小说角色拆分（那是 Skill 层的事，本变更聚焦 UI 与关系建模）。
- 不重构 Asset Hub 或立绘生成链路，只新增一个预设和关联 UI。
- 不实现多角色画风一致性批量出图（需要生图供应商支持参考图，另作议题）。
- 不新增独立的全屏路由（`/characters/fullscreen/:id`）：全屏在 AppLayout 内通过 Header 隐藏实现，保持路由结构单一。（修正：原定「不做全屏工作台」，产品确认后升级为工作区 + 全屏切换。）
- 不引入外部图库（如 d3）；关系图谱用内联 SVG 或项目已有依赖。

## Success Criteria

- 角色列表页一眼可判断角色的完善度（Bible 字段覆盖比例）。
- 详情视图在 1280px 宽度下不出现横向滚动，主区双栏阅读体验流畅。
- 关系图谱能展示角色间关系，悬停高亮、点击跳转到对应角色详情。
- `character_sheet_16_9` 预设能生成包含左半身像 + 右三视图 + 细节条的设定图。
- 角色详情能看到每个字段的来源标记（原文 / AI 推断 / 未设置）。
- Prompt 资产包面板覆盖：出图提示词、音色提示词、角色 JSON、设定图提示词，每个都有复制按钮。
