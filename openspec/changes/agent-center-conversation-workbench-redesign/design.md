# Design: Agent Center 对话工作台

## Product Constraints

1. **Low barrier**：默认界面只要求用户选择对话或直接输入目标，不要求理解 Run、Tool schema、Memory provenance 或上下文快照。
2. **Visual outcomes**：消息、执行过程、确认和最终产物在同一时间线上呈现；技术细节按需展开。
3. **Script-first token economy**：搜索、整理、下载、格式转换、持久化和批处理等确定性操作优先由工具或脚本执行，模型负责理解、判断和创作。

## Information Architecture

- 左栏：新对话、最近对话、当前智能体摘要。
- 主栏顶部：当前对话标题、上下文状态、智能体选择和少量工作台命令。
- 主栏正文：用户消息、内联执行轨迹、助手答复。
- 主栏底部：输入框、发送动作和必要状态。
- 抽屉：全部历史、工具与测试、Profile/模型/记忆设置。
- 完整轨迹：从消息流中的折叠摘要进入，不作为默认并列工作区。

## Failure Isolation

- 线程列表失败时仍允许开始新对话。
- 工具、记忆、模型连接器和运行树失败时只影响对应摘要或抽屉。
- 当前线程恢复失败时明确提示并允许重试，不自动制造第二个对话。
- 页面渲染异常由 Agent 专用 Error Boundary 接管，不让整个应用白屏。
- 流式请求失败保留已接收文本和当前输入，用户可以在同一线程重试。

## Visual Rules

- 使用安静的双栏工作台，不使用 Hero、指标墙、渐变光晕或多层卡片。
- 左栏 240-264px，主消息列最大阅读宽度约 920px。
- 用户消息可使用行动色，助手消息尽量无卡片化；轨迹使用低对比折叠块。
- 每个区域只有一个主要动作；图标按钮提供 Tooltip 和可见 focus 状态。
- 1180px 以下隐藏常驻左栏，以历史抽屉访问对话；移动端输入区保持可发送。

## Acceptance

- 首屏只出现对话导航、当前对话、消息和输入框，高级管理能力不抢占主层级。
- 刷新后恢复同一 thread 及完整多轮消息，不创建重复 thread。
- 任一辅助接口失败不会清空当前消息或阻止发送。
- 完成 Run 的过程默认折叠，等待确认和失败步骤保持可见。
- 1440px、1280px 和移动宽度无大片无意义空白、横向溢出或按钮遮挡。
