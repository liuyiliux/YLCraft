# 预演台 AI 场景编排与动作资产

## Why

3D 预演台已经能摆场景、出截图、合成视频，但它是"人手摆"的工具：创作者从空场景起手，逐个添加对象、拖手柄、调参数。而分镜格里其实已经写好了这一格需要的调度、景别、镜头角度和时长——这些文本目前只流向生图/生视频，在花钱生成之前没有任何空间层面的校验。本次变更把预演台从"人手摆的工具"升级为"可被 AI 编排、也可被人微调的场景层"，并补齐它唯一缺失的内容供给：动作。

### AS-IS（当前行为）

1. 预演场景只能手工搭建：添加模型、几何体、人形占位、全景、灯光，再逐个调整位置/旋转/缩放并打关键帧。复杂场景（多人、多物体）的搭建成本高到创作者会放弃预演。
2. 分镜面板已经写好的调度、景别、镜头角度、时长等文本，只作为生图/生视频的提示词使用；预演台不会读取它们，创作者仍在凭想象猜测角色站位、物品比例与机位关系。
3. 人形占位只有极少数固定姿势，且姿势是静态摆位、没有时间维度；除了个别自带骨骼动画的示范模型外，"让角色动起来"实际做不到。预演的可交付参考因此只有静态截图。
4. 通用人形占位的身体比例与真人相差明显（头部偏大、腿偏短），而"人物站位与物品比例预演"正是预演台的核心用途。
5. AI 侧已经可以读取场景摘要并提交受控的场景修改，但可写参数没有校验（错误参数会静默落库）、确认环节只给出数值差异（看不出摆得对不对），并且姿势与动作不是可引用的数据，AI 只能填写模型自带的动画名。

### TO-BE（目标行为）

1. **对应 AS-IS 1**——分镜格可一键生成预演初稿：把该格已写好的调度、人物数量、景别、镜头角度、时长翻译成空间参数（人形数量与相对站位、身高、机位与镜头光学）；也可用自然语言直接下达场景指令。两种入口走同一条通道：AI 提议 → 在 3D 画面中预览 → 人工确认 → 落库。创作者由"从零搭建"变为"微调初稿"。
2. **对应 AS-IS 2**——预演生成时读取该分镜格已保存的调度、景别、镜头角度与时长；创作者在花钱生成之前就能看到空间关系，不必再凭想象猜测站位、比例与机位。
3. **对应 AS-IS 3**——动作与姿势成为可独立复用、可被 AI 引用的业务资产（独立存放，不进入素材库）；静态姿势与随时间变化的动态动作同源，因此预演产出同时覆盖静态参考图与动态参考视频。
4. **对应 AS-IS 4**——通用人形占位按真人比例重建，身高可调且整体等比缩放；它既能承载静态姿势，也能承载动态动作。
5. **对应 AS-IS 5**——AI 提交的任何修改都要经过参数校验（非法参数拒绝并给出可读原因）；确认前的结果以可在 3D 画面中观察、可撤销的方式呈现，未确认不改变已保存场景；姿势与动作成为 AI 可查询、可引用的清单，AI 不再靠猜动作名。

## What Changes

- **分镜格一键生成预演初稿**：以分镜格已保存的调度、人物、景别、镜头角度、时长为输入，生成含人形对象、相对站位、机位与镜头参数的场景初稿；初稿可直接落库为可编辑场景，也可作为提议等待确认。
- **自然语言场景指令**：在预演台内或 Agent 对话中以自然语言描述场景（摆什么、放多大、什么姿势、什么机位），由 AI 翻译为受控的场景修改并提交；与一键生成初稿复用同一套提议/确认/落库通道。
- **动作与姿势资产（新增独立资产类型）**：同时容纳"只含一帧的静态姿势"和"随时间变化的动态动作"；条目记录适用骨架规格、时长、帧率、是否可循环、来源与许可。该资产不进素材库，不参与素材库的检索与血缘体系。
- **通用人形占位升级**：按真人比例重建（头身比、腿长占比、脚底贴合地面），身高可调；可绑定动作资产中的姿势或动作。
- **动作求值的确定性约束**：动作与姿势必须能被"按帧号取值"这一确定方式求值，禁止依赖实时播放状态；这是动态参考视频保持真帧率、同一帧永远对应同一姿态的前提。
- **AI 修改的参数校验**：对 AI 提交的节点类型、身高、姿势、动作引用、模型引用等参数做白名单与范围校验，非法参数一律拒绝并给出可读原因，不得静默落库。
- **确认前的可视化预览**：AI 提议的结果要能在 3D 画面中观察（半透明或线框形式），确认后才写入已保存场景；场景被他人改动过的提议整批作废并要求重新读取。
- **非人形对象的动作策略**：自带骨骼动画优先；无自带动画时使用通用变换动作（位移/旋转/缩放曲线）。**本变更不做骨骼重定向，也不为怪兽等非人形对象生成骨骼动画。**
- **非目标（明确排除）**：不做通用建模、不做网格编辑、不做 IK 与物理、不做绑骨、不替代专业 DCC 工具；不改造下游视频生成是否接受"参考视频"，该对接由后续变更负责。

## Capabilities

### New Capabilities

- `previs-motion-assets`: 动作与姿势资产——静态姿势与动态动作的统一表达、适用骨架规格、时长/帧率/循环、来源与许可，以及供人与 AI 引用该资产的只读清单。
- `previs-agent-composition`: AI 驱动的预演场景编排——从分镜格文本或自然语言生成场景初稿，参数校验、可视化预览、人工确认与受控落库的完整通道。
- `previs-human-proxy`: 通用人形占位——真人比例、身高可调、可绑定姿势与动作，作为预演台人形对象的默认载体。

### Modified Capabilities

- `3d-director-previs`: 场景节点与操作契约扩展——节点可承载姿势与动作引用；受控操作集合增加设置身高、设置姿势、分配动作等语义操作；AI 操作须经参数校验，且确认前须提供可视化预览。（注：该能力目前仅存在于 `3d-director-previs` 变更中，尚未归档到 `openspec/specs/`，本次以其为修改对象。）

## Impact

### 受影响系统与模块

| 系统/模块 | 影响说明 |
|----------|---------|
| 3D 预演台（前端） | 新增初稿生成入口、动作/姿势选择与预览、AI 提议的可视化预览与确认交互；人形占位比例重建 |
| 3D 预演台（后端） | 场景契约扩展（姿势/动作引用）、动作资产的管理与清单接口、初稿生成与参数校验 |
| Agent 导演助手与工具目录 | 新增场景编排相关工具（生成初稿、动作清单），扩展受控操作集合与参数校验，沿用既有确认、锁定、场景版本校验与授权机制 |
| 分镜面板 | 作为初稿生成的输入来源被只读引用；不回写分镜文本，不产生第二份分镜数据 |
| 素材库（Asset Hub） | 仅被只读引用（非人形对象、背景）；动作资产不进入素材库，不新增素材库检索维度 |
| 任务中心与导出链路 | 复用既有截图回流与视频导出；不新增导出能力 |

### 外围系统依赖

- **下游视频生成是否接受"参考视频"**：由后续变更负责，本变更只保证预演产出可用的参考视频，不据此阻塞验收。
- **专业 DCC 工具（Blender/Maya/Unreal）**：本变更不集成、不替代；需要影视级骨骼动画时仍由外部工具承担。
- **第三方动作数据来源的许可**：由动作资产条目的来源与许可字段如实记录，本变更不代用户判定授权边界。

### 数据与接口

- **复用既有业务标识**：项目标识 `project_id`、分镜内容标识 `storyboard_content_id`、分镜格号 `panel_number`、场景版本号 `revision`、素材标识 `asset_id`。
- **新增业务标识**：动作资产标识（用于场景节点引用与 AI 指定动作）。
- **新增只读清单**：面向 AI 的可用动作清单（含适用骨架规格与语义标签），使 AI 能够先查后引，而不是猜动作名。
- **关键约束**：场景仍以稳定标识引用对象；动作资产不复制到场景内，只存引用；沿用既有的截图回流与视频导出的来源标注。

## 待确认项 / 已确认项

| # | 待确认内容 / 原待确认内容 | 当前状态 / 确认结果 |
|---|-------------------------|-------------------|
| 1 | 预演台是否只做静态参考 | 已确认：静态与动态都要；动态是参考视频的来源 |
| 2 | 动作资产是否放入素材库 | 已确认：不放入，独立存储；使用顺序为先选对象再选动作 |
| 3 | 人形对象是否必须使用用户自己的模型 | 已确认：不必须；通用人形 + 动作即可，AI 生成不依赖原始模型外观；仅非人形与特殊造型才使用素材库模型 |
| 4 | 怪兽等非人形对象如何产生动作 | 已确认：模型自带动作优先，其次用不依赖骨骼的通用变换动作；不做骨骼重定向 |
| 5 | AI 编排的主入口 | 已确认：分镜格一键生成初稿为主入口，自然语言指令为辅 |
| 6 | 是否阻塞于下游支持参考视频 | 已确认：不阻塞，由后续变更对接 |
| 7 | 对 AI 产出质量的预期 | 已确认：AI 产出的是"可编辑初稿"，验收不要求一次到位 |
| 8 | 动作资产的首批动作/姿势清单与命名口径 | ❓ 待确认：在 specs 阶段与任务清单一起定义 |
| 9 | 分镜字段到空间参数的映射表（含字段缺失时的默认行为） | ❓ 待确认：需要在 specs/design 阶段逐字段定稿 |
| 10 | 尺寸锚点表的口径与条目（人形身高以外的常见参照物） | ❓ 待确认：条目范围需要收敛，避免维护成本 |
| 11 | 动作来源与许可是否必须为落库必填 | ❓ 待确认：涉及商用合规，倾向必填但需要确认执行方式 |
| 12 | 动态参考视频的默认时长与帧率口径 | ❓ 待确认：倾向沿用分镜格时长与既有固定帧率 |
| 13 | 自然语言指令的入口位置（预演台内 / Agent 对话） | ❓ 待确认：影响交互与实时性设计 |
| 14 | 造型化的示范模型（如机甲类角色模型）是否继续保留在人形占位选项中 | 已确认：移出人形占位选项（会给下游生成引入无关造型暗示），需要时按普通模型从素材库添加；文件已删除，已落地 |
| 15 | 人形占位的默认外观配色 | 已确认：改为中性中灰（彩色会被当作真实配色传给生成模型；纯白易被读成"白衣/白皮肤"且高光糊掉结构），已落地 |
| 16 | UE 白模是否继续作为人形占位载体 | 已确认：**下线**，人形占位只剩通用胶囊人。依据：白模自带 0 条动画（实测 `animations: []`、73 节点 / 1 蒙皮 / 67 关节），且参数型动作的通道是胶囊人的 16 个关节，选中它只能站着不动——"能选却动不了"比没有这个选项更像 bug；白模文件与许可记录保留，待 P2「参数型动作烘焙成 GLB」接回作为蒙皮验证载体，已落地 |

## 验收标准

1. 从任一已有分镜格可一键生成预演初稿；初稿至少包含与分镜格人物数量一致的人形对象、符合调度描述的相对站位、与景别/镜头角度对应的机位与镜头参数；生成过程不在素材库产生重复资产。
2. 预演初稿在写入已保存场景之前必须经过一次人工确认；确认界面能在 3D 画面中观察到提议结果（而非仅数值或文本差异）；未确认的提议不改变任何已保存数据。
3. AI 提交的非法参数（不存在的姿势、超出允许范围的身高、不可用的动作或模型引用、未知节点类型）被拒绝，拒绝原因可读，且场景中不出现由非法参数造成的坏数据。
4. 同一动作可分配给符合其骨架规格的多个对象；静态姿势与动态动作均可驱动通用人形；对同一场景重复导出同一帧区间，逐帧结果可复现（同一帧永远对应同一姿态）。
5. 通用人形在静态与动态下均符合真人比例（头身比、腿长占比、脚底贴合地面）；身高调整时整体等比缩放且不出现悬空或陷地。
6. 非人形对象可在不进行骨骼绑定的前提下，通过通用变换动作完成位移与姿态变化，并在导出视频中体现该运动。
7. 预演台可导出静态参考图与动态参考视频；两者均带场景标识与机位来源信息，并可回流到来源分镜格作为生成参考。
