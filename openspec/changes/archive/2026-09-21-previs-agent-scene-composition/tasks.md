- [x] 1.10 【由外部参考发现】运镜的**首尾静止**（已落地）：一条来自外部工作台的镜头经验（"升降起止各留 1s 静止"，让观众先看清再运动；见 `docs/reference/REF_PROJECTS.md` 2026-09-20 一节）。现状：`pages/previs/cameraMoves.ts` 的升降 / 摇臂 / 推拉都是**整段连续运动**，缺首尾停留。落地要点——① 停留只能"占用"区间首尾，因此**首帧必须仍精确等于传入机位**（既有断言不能破，加停留只会让前 N 帧同值）；② 停留时长要随总时长退化（镜头只有 1 秒时不该各留 1 秒），建议按"总时长的比例 + 上限"取；③ 属于**手艺口径**而非数学约束，需要一条断言守住"首尾同值且中段确实在动"，否则"加了停留"和"模板没生效"在测试里长得一样
- [ ] 1.11 【调研结论 · **另开 change**，本期不做】外部动作数据接入的可行路径（调研已完成，结论见 `docs/reference/REF_PROJECTS.md` 2026-09-20 第二节）：**文章里那条路（GVHMR + SMPL-X）许可不通**——SMPL-X 许可页明确禁止商用、商用只能向 Meshcapade 购买；GVHMR 自身是非商用学术许可且**必须联网拉取受门控的 SMPL/SMPL-X 体模**才能跑；产物还是**骨骼 FK 动画**，落在本期未排期的 `carrier=bone` 线上。**真正可行的路是绕开 SMPL 生态**：免许可障碍的 **BVH → 我们 23 通道的映射器**，产出自有 `params` 条目、胶囊人立刻能用、不需要 GPU 与 5GB 权重。最小切片四步（取一条 CMU 类 BVH → 写映射器 → 用既有不变量验收 → 落库成动作条目，来源与许可如实记录），最值钱的是第 2 步：映射器成立后**任何** BVH 都能一键入库。**本期不做的理由**：不解除任何当前阻塞，预演只需要"看得出在走"（手写 15 条已覆盖），且它属于骨骼型那条后续线

- **纯函数 + 事实注入**：`build_previs_draft(scene, panel, prop_assets=...)` 不碰数据库；分镜格由接口层从 `(storyboard_content_id, panel_number)` 读出（面板号只在各自分镜内唯一，所以必须带 content_id），"道具 → 素材"由接口层查好后传进来。因此翻译逻辑可完整单测（18 例）。

- **俯仰由几何决定高度**：档位给的是俯角，机位高度 = 眼高 + 距离 × tan(俯角)，并夹在 0.2–6m（鸟瞰在 12m 距离下会算出十几米，对预演没意义）。**构图偏移注视点而不是挪机位**：机位代表"从哪拍"、构图代表"主体落在画面哪里"；偏移量按真实光学换算（画面宽 = 成像面宽 ÷ 焦距 × 距离），所以"三分线"在任何焦距下都落在真正的三分线上。
- **不翻译就不生成**：文字形态的 `movement_path`、非静止的 `camera_motion`、`location`（全景只支持纯色、贴图未接入）**只写 `warnings[]` + `defaults[]`**，并指路到既有能力（机位面板的 26 类运镜模板）。**生成一个渲染不出来的节点比不生成更糟**。

- **顺带修掉一个真缺陷**：`apply_operations` 原来只在循环结束后才把新建节点/机位/关键帧写回场景，导致**同一批里后面的操作看不见前面刚建出来的对象**——初稿这种"先建人、再给这个人打位移关键帧"的批次会静默少做几步。现在每轮先同步本地集合；`validate_operations` 同步改为维护"进行中的场景副本"，于是"同批引用新建对象"在校验与落库两侧语义一致（此前是"落库能成功、校验先拒绝"）。
