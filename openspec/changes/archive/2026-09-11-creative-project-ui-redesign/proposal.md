# 创作项目工作台 UI 重构

## Why

当前 /story 把项目总览、项目设定、章节规划、单章细纲、正文、脚本、分镜、素材、日志和高级 JSON 编辑放在同一条长页面和同一层级中。用户无法判断自己是在看项目还是在写某一章，大量字段和按钮同时出现，认知负担高，滚动距离长。

## What Changes

将创作项目页重构为两个明确工作模式，复用现有数据和 API，不创建第二套项目事实来源：

1. **项目总览**：项目状态、故事蓝图、大纲、圣经/世界、章节规划、角色、资产、生产进度和问题清单。模块默认折叠，按需展开。
2. **单章工作室**：只围绕一个章节工作，展示章节细纲、正文、脚本、分镜、审核、上下文、素材和生成操作。章节列表是可收窄导航，不把全书正文铺在工作区。

模式切换不应要求用户每次判断流程：项目页打开时优先给出“继续上次工作”和一条按依赖、缺口、锁定状态计算的下一步建议；用户也可以显式进入项目总览或任一章节。

顶部只保留项目身份、模式、当前章节、保存状态、模型入口和一个主操作；批量生成、JSON、高级配置、导出和危险操作放入二级菜单或抽屉。

## Non-goals

- 不新增项目、章节、正文或素材的重复数据库模型。
- 不改变候选正文提升、章节锁定、Writer Room、Context Pack 和 Asset Hub 事实规则。
- 不在本计划内重做全局导航、画布或素材库。
- 不把所有内容强行改成等权重卡片。

## Impact

- Frontend: frontend/src/pages/story/index.tsx，必要时拆分同目录 UI 子组件。
- Documentation: docs/DESIGN.md、docs/architecture/YLCRAFT_SYSTEM_ARCHITECTURE.md。
- 若不改 API，不扩展 API surface；若产生新接口，必须同步 API 清单。
