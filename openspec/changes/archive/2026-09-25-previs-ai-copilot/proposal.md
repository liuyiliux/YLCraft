# 预演台 AI 对话入口与生成资产接入

## Why

预演台现在只能手动摆场景。Agent 侧的能力其实已经有了——"先查后摆"的只读工具（动作清单、可摆对象、按分镜格出初稿）与"预览 → 人工确认 → CAS 落库"的写入链路，都是上一个 change（`2026-09-21-previs-agent-scene-composition`）做完并归档的。

问题是**入口不在预演台**：用户必须离开画面、去 Agent 工作台用文字描述，再回到预演台看结果、点确认——**上下文断了**，而预演恰恰是"看着画面调"的活。用户明确要求：在预演台里直接跟 AI 对话摆场景。

同时用户提出把手边的生产能力接进来：用 Blender / 图生 3D 造模型放进来、背景不要只填纯色而是能生成与摆放。这两件事都已有基础设施（Blender 脚本集、`POST /model-3d/generate`、素材库），缺的是**从预演台里发起**以及全景贴图的渲染支持。

## What Changes

分两期，**先做第一期**：

1. **对话入口**：预演台内嵌一个可折叠的对话栏（右侧，与左侧图层面板对称），运行一个权限收窄到预演的助手角色。它复用既有工具：`get_previs_composition_options`（能摆什么 / 尺寸锚点 / 素材库模型）、`list_previs_motions`（动作清单）、`generate_previs_draft`（按分镜格出初稿）、`previs_preview_operations`（只读预览）、`previs_apply_operations`（写入，**必须人工确认**）。
   - 对话里产生的每个改动都**先渲染成幽灵预览**，由用户点确认才落库——这条边界不因"入口搬到预演台"而放宽。
2. **生成资产接进预演台**（另起一期）：**全景背景贴图支持**（先"从素材库选一张图当全景"，零额度；再"直接生成一张全景"，需生图额度）。~~Blender / 图生 3D 的发起入口~~ **已取消**：模型生成不归预演台（见非目标）。~~three.js 程序化模型~~ **已取消**（见非目标）。

## 非目标

- **不在预演台发起"生成模型"，也不做程序化组合体**（2026-09-22 决策，用户判断）：**模型生成只走图生 3D 工作台**，入库后从素材库选入场景（该路径已通）；**预演台的定位是"自动搭建布景"**——把已有的人形 / 几何体 / 素材 / 动作 / 机位按调度摆进场景，**不承担"造模型"**。关键理由是**入参不对**：**分镜参考图是"一整个杂乱场景"，不是单体**，拿它去图生 3D 得不到可用的独立模型；而"程序化组合体"做下去必然滑向简易建模器（理由见 tasks 的"已澄清"第 3 条）。
- **不做非人形对象的运动**：沿用 `2026-09-21-previs-agent-scene-composition` 的结论（变换型动作本期无求值路径）。给物件做运动用手打关键帧，AI 可代劳算坐标与帧号。
- **不做骨骼型动作、不做重定向**：人物动作用我们自己的参数型动作（胶囊人 + 23 通道），这是既有决定，不因本变更改变。
- **不做多轮自主编排**：每一步都要人确认，助手不自己落库。
- **不替代 Blender / Unreal / Maya 的编辑能力**：本变更只是"把生成能力接进来摆放"，不做建模器。

## 边界与风险

| 风险 | 说明 |
| --- | --- |
| **对话改到不该改的东西** | 助手权限只给预演相关工具，且写入必须人工确认（沿用既有授权边界与确认链路）；锁定对象只能读不能写是既有硬规则 |
| **助手编造能力** | 已知教训：工具说明写错，Agent 就会编出做不到的方案（如变换型动作）。因此每个工具说明都必须与实现一致，且"查不到一律返回空集并说明" |
| **生成资产的成本** | 图生 3D 与生图都花钱；全景贴图先做"从素材库选图"这一零额度档，生成档单独开关 |
| **Blender 依赖** | Blender 是外部进程（既有 `model3d` 链路已在用），预演台只是发起方，失败要给可读原因而不是静默 |

## 已确认项

| # | 问题 | 结论 |
| --- | --- | --- |
| 1 | 第一期做对话入口还是生成资产 | **先做对话入口**（价值最高、依赖最少：工具与确认链路都已就绪） |
| 2 | 对话栏放在哪 | **右侧可折叠**，与左侧图层面板对称 | 用户确认（2026-09-21） |
| 3 | 助手用什么身份 | **新建只做预演的助手角色** `previs-assistant`（权限比导演更窄） | 用户确认（2026-09-21）；已落地 |
| 4 | 全景背景先做哪种 | 先**从素材库选图**（零额度），再考虑直接生成（需额度） | 用户确认（2026-09-21） |
| 5 | 助手要不要持写工具 | **不持**。助手只提出并预览；落库由用户在界面点确认触发（前端走既有应用链路）。这样既不破坏已归档规格"写工具只给两个导演"的边界，也让助手没有"自己决定落库"的可能 | 本 design 决策（2026-09-21）；已落地并加测试 |
