# 内容包工作台与输出适配器

## 背景

当前内容生产方案已经能区分短剧、故事漫画、科普、平台图文、小说和单镜头，但非小说项目仍然复用 `/story` 的“大纲 → 圣经/世界 → 章节/细纲”界面。这样会把绘本、科普卡片、公众号文章和小红书图文误解成必须先建立完整故事世界的项目，用户需要多次往返填写中间表单才能得到最终产物。

仓库已有独立的多平台生图工作台（`/multi-platform-gen`、`MultiPlatformGen.tsx`、`/api/v1/images/generate-outline`、`/api/v1/images/generate-batch`、`PlatformTemplate`），但它与创作项目之间缺少统一的“内容包”数据契约。相同主题在公众号、绘本、小红书和科普卡片中被重复生成，平台适配也容易变成另一条生产线。

## 目标

1. 保留小说、长篇短剧和复杂连续叙事的完整流水线，不改变正文、章节、连续性和 Writer Room 的权威数据边界。
2. 为绘本/漫画、科普图文、公众号文章、小红书轮播、短视频脚本和单镜头建立一次生成内容包的轻量工作台。
3. 把现有多平台生图的主题大纲、平台模板、批量生图能力抽到共享服务，既支持独立页面，也支持内容包项目内调用。
4. 让一份内容包可以输出为多个平台适配结果，避免为每个平台重新生成核心内容。
5. 让用户在一次生成后直接看到可编辑的内容卡、图片提示词、图片任务和导出/发布选项；只在消耗型生成、发布或外部写入前确认。

## 非目标

- 不删除或重写现有完整创作项目流水线。
- 不把公众号、小红书、抖音等平台各自做成独立的内容事实源；平台只是输出适配器。
- 不在本阶段实现通用自动排版设计器、自动事实核验或全自动发布。
- 不要求所有内容包都拥有正文、项目圣经、角色卡或章节规划。
