## Context

当前 AI 模型配置界面 (`frontend/src/pages/settings/index.tsx`) 存在以下问题：
1. **过度设计**：无论选择什么类型（LLM/Image/Video），都会显示请求模板和响应配置字段
2. **缺少预设**：用户每次添加新模型都需要手动填写所有配置项
3. **界面混乱**：高级配置字段默认展开，造成视觉干扰

根据用户反馈，OpenAI、Gemini 等主流服务商使用标准 API 格式，不需要自定义模板。只有硅基流动等特定服务商需要参数映射配置。

## Goals / Non-Goals

**Goals:**
- 简化 LLM 类型的配置界面，不显示高级配置字段
- 为 Image/Video 类型添加预设配置，包括 request_template 和 response_config
- 添加服务商+类型组合的预设配置系统
- 实现自动填充逻辑，选择服务商和类型后自动填入推荐配置
- 添加"应用推荐配置"按钮，提供一键配置功能

**Non-Goals:**
- 不修改后端 API 或数据库结构
- 不改变现有配置的存储格式
- 不影响已有的配置数据

## Decisions

### 决策 1: 预设配置数据结构
采用嵌套对象结构 `PROVIDER_PRESETS[provider][type]`，支持按服务商和类型组合提供配置。

**理由**：不同服务商的不同类型（LLM/Image）需要不同的配置，嵌套结构能清晰表达这种关系。

**替代方案**：使用扁平结构 + 条件判断，不够直观且难以维护。

### 决策 2: 自动填充时机
在用户选择服务商和类型后立即自动填充配置。

**理由**：减少用户操作步骤，提升体验。用户仍可手动修改配置。

**替代方案**：仅在点击按钮时填充，需要额外操作步骤。

### 决策 3: 高级配置显示逻辑
- LLM 类型：不显示高级配置（request_template、response_config 等）
- Image/Video 类型：默认折叠隐藏高级配置

**理由**：LLM 服务（OpenAI、Gemini）使用标准格式，不需要自定义模板；Image 服务可能需要配置（如硅基流动需要参数映射）。

### 决策 4: 按钮样式
采用渐变紫色主题，与现有界面风格保持一致。

**理由**：主色调使用紫色渐变，符合项目设计规范。

## Risks / Trade-offs

| Risk | Mitigation |
|------|------------|
| 用户期望手动配置而不是自动填充 | 自动填充不会覆盖用户已输入的内容（编辑模式），用户可随时修改 |
| 预设配置可能过时 | 预设配置存储在前端代码中，需要定期更新；提供手动修改能力 |
| 某些服务商/类型组合没有预设 | 添加通用配置作为兜底；提示用户手动配置 |
| 按钮位置影响界面布局 | 将按钮放在服务商选择旁边，保持界面整洁 |
