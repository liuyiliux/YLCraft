fix: 清除假支持/假数据 + 异常语义正确化（审计发现项全修）

## 一、假支持：账号中心的 TikTok

用户能在账号中心看到 TikTok、粘贴 cookie、保存连接 —— 一切正常。
但**后端根本没有 TikTok 采集客户端**（`create_client('tiktok')`
报 Unsupported platform，搜索页下拉也没有）。

结果：建了连接**没有任何入口能用它**。铁律：**假选项比没有更糟**。

已从 `SUPPORTED_PLATFORMS`（后端）与 `PLATFORM_METAS`（前端）删除，
并写明"以后真要做需要补什么"。

⚠️ **注意区分**：`connectors/social/tiktok` 是**另一套**（OAuth 发布
连接器，16KB 真实存在），它保留是对的 —— 采集与发布是两回事。

## 二、假数据：「总播放量」是捏造的

「总播放量」和「总点赞数」**读的是同一个字段** `profile.likes`，
而后端 `/bilibili/up/profile` **根本没有播放量字段**
（只有 `fans`/`likes`/`following`）。

两张卡显示同一个数字，而且"总播放量"的值其实是**累计获赞** ——
量级完全不同，用户会据此做出错误的内容判断。

已改成四张卡各显示不同的**真实**指标：总获赞 / 总关注 / 总粉丝数 / 视频总数。

## 三、异常语义：该 401 的报 500

### X 和微博的登录异常继承错了基类

`twitter/client.py` 和 `twitter/search_http.py` 各定义了一个**同名**
`TwitterAuthError`：
  · `search_http.py` 的继承 `LoginExpiredError` ✅（2026-09-30 改的）
  · `client.py` 的只继承 `RuntimeError` ❌（**漏改**）

而 `client.py` 抛的正是后者（用户搜索/资料/作品路径）—— 于是 API 层的
`except LoginExpiredError` **全部落空**，登录态过期返回
**HTTP 500**「获取我的资料失败」。

500 语义是"服务端故障"，用户不会想到要去账号中心重新登录
—— 而这恰恰是用户自己能解决的问题。

已修（微博同理）。这又是"同一个东西两处定义、只改一处"的老坑。

### 小红书详情 461 谎报"笔记不存在"

461（风控）原本抛裸 `RuntimeError` → `crawler/service.py` 的
`except Exception: return {}` 吞成空 dict → 路由层变成
**404「笔记不存在或获取失败」**。

但 461 是**风控**，笔记**确实存在**（用户刚从搜索结果点进来）。
用户会以为笔记被删了。

三处一起修：
  1. `note.py` 4 处裸 `RuntimeError` → 分类异常
     （461/被拦截 → `RiskControlError`、缺 cookie → `LoginExpiredError`、
      `notFound` → `ContentNotFoundError`、超时 → `NetworkError`）
  2. `service.py` 穿透列表补 `RiskControlError`/`NetworkError`/`ContentNotFoundError`
  3. ⚠️ **`service.py` 根本没 import 这三个类型** —— 补上

第 3 点最隐蔽：穿透了却没 import = 运行到那行抛 `NameError`，
然后被 `except Exception: return {}` 吃掉 ——
**修复"看起来生效了"其实没有**。

## 四、静默失败：用户点了没反应也不知道为什么

### B站数据统计 / 视频信息

`catch { /* 忽略 */ }` → 面板空白 → 用户会把"空白"读成
"这个视频播放量是 0"，而真相可能是 401（cookie 过期）/ 429（风控）。

⚠️ **空面板和"全是 0"在视觉上几乎一样**，尤其危险。

已加 `statsError` / `videoInfoError` + Alert 提示，
并明确写"这是**请求失败**，不是「数据为 0」"。

### 番茄面板（审计称"最主动误导"的一处）

`.catch(() => {})` → 网络抖动被吞 → `connections` 保持 `[]` →
界面渲染「请先在账号中心添加番茄账号」→ 用户跑去账号中心发现
**账号明明在**，回来更困惑。

已用 `Result`（warning）区分"加载失败"和"确实没账号"。

## 五、Telegram「我的频道」：后端做了前端没接

`/telegram/channels`（列出已加入的频道/群组）早就实现了，
登录页却只能"去采集"搜关键词。

已在登录页加「我的频道」按钮 + 列表（按需加载，失败也如实提示）。
点某个频道可直接跳去采集页搜它。

## 六、断点续传：登记的 outtmpl 是假的

平台下载器路径（**B站/抖音/X 走这条**，不是 yt-dlp）登记的
`outtmpl` 是 `str(savedir / title)` —— 一个**普通路径**，
不是 yt-dlp 的 `%(title)s` 模板。

`_partial_size_for` 据此 glob 不到任何 `.part` → `bytes_done` 恒为 0
→ `/download/resumable` 把它当成"没有可续传数据"。

改成传**空串** = 如实表示"这条路径不按 .part 追踪"，
`list_resumable` 会因为找不到半成品而过滤掉它（**不谎报**）。

## 七、batches.json 无限增长

只追加、从不清理，而 `update_item` 每次都要全量
`_load()` + `_save()`。500 条的批次会调 1500 次 `update_item`，
复杂度 O(批次总数 × 总条目) × 1500。

已实现清理：创建批次时清理**已完成**的旧批次
（保留最近 20 个）。未完成的**永不自动删** ——
那是用户的断点续传依据。

## 八、样式：story 页面 3 处表格缺 scroll

`outline.tsx`（流水线表/角色表）、`tabs.tsx`（日志表/素材关联表）、
以及素材关联表的时间列缺 `nowrap`。
窄容器下会把定宽列压扁（表头变竖排单字）—— 与用户之前截图的问题同类。
