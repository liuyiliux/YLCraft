feat(crawler): 连接「停用/启用」+ 记住每平台账号 + 游客态选项

## 用户诉求

"加个禁用按钮 因为小红书风控被封了"
"1.平台选择账号记住 2.可以选择无账号的 这样是不是不会对账号有影响了"

## ⚠️ 先澄清一个技术事实（写进 UI 提示了）

**"无账号"≠"不被风控"**。多数平台不支持匿名搜索：
  · 小红书不带 cookie → **直接返回 `-100`**（搜都搜不了）
  · 抖音/快手匿名能搜但结果极少、更容易被判爬虫
风控主要看 **IP + 请求频率**，不看有没有账号。

所以"不影响账号"的**正确用法是「停用」**（停一阵）或换 IP ——
这条已写进游客态选项的提示里，避免用户误以为选"无账号"就安全。

## 一、连接停用/启用（后端）

  · `ConnectionStatus` 加 **`DISABLED`**（与 `expired/failed` **语义不同**：
    后者是系统判定凭证坏了，前者是**用户主动关**）
  · `POST /platforms/{id}/disable?reason=xxx` —— 凭证**保留**，随时能启用
  · `POST /platforms/{id}/enable` —— 恢复成 **`unknown`**（待验证），
    不直接断言 `active`（我们没验证过，那是体检的职责）

### ⚠️ 两个关键修复

**① 兜底路径也要跳过停用连接**

`resolve_connection` 在 conn_id 失效时会"回退到该平台最新连接" ——
如果那条被停用了，回退过去就等于**停用失效**（用户点了停用，
请求还在打那个账号）。已改为只找**未停用**的。

**② 枚举值要同步到 PostgreSQL**

`status` 在 PG 里是 **native enum**，Python 加值**不会自动同步** ——
写入时报 `invalid input value for enum connectionstatus`。
而且这个错**只在真去停用时才出现**（导入检查、单测全发现不了）。
已加幂等迁移脚本 `scripts/sync_enum_values.py`。

（实测 DB 里还有 `active`/`ACTIVE` 两套历史值，脚本两个都补。）

### 体检区分"停用"和"需登录"

两者都返回空 cookie，但**出路完全不同**：
  · 没有连接   → 去账号中心获取登录态
  · 被用户停用 → **去启用它**（凭证还在，不需要重新登录）
混成一句"请先获取登录态"会让用户白跑一趟账号中心。

另：**停用时不做搜索探针**（那正是用户想避免的）。

## 二、前端三件事

**① 记住每个平台的账号**（`connByPlatform`）

原来是一个全局 state，切平台立刻重置成第一个 ——
多账号用户每次切回来都要重选。现在按平台存一张表。

**② 「不使用账号（游客态）」选项 + 风险提示**

显式给这个选项，但配 Alert 说清"这不是避免风控的办法"。

**③ 停用/启用按钮 + 状态可视化**

⚠️ 顺带修了一个会让功能"不可逆"的 bug：
前端加载连接时**只留 `status === 'active'`** ——
用户停用后连接**从下拉消失，再也找不到启用按钮**
（停用变成了软删除，与设计意图完全相反）。
已改为保留 `active` + `disabled`，并给停用项加 ⏸ 标记。

默认选中的账号也会**跳过已停用的**（否则一进来就搜索失败）。

## 实测（端到端）

    禁用        → 200 "已停用 —— 搜索/体检会跳过该连接，凭证仍保留"
    禁用后体检  → credential_ok=False，提示"凭证仍然保留，
                  **不需要重新登录**"；search 提示"**不会发起搜索**"
    启用        → 200 "已启用 —— 建议跑一次体检确认登录态"
    启用后体检  → credential_ok=True（凭证还在，1757 字节）
