# 知识回流：content-package-workspaces（归档 2026-09-14，20/21）

本报告记录归档时从该 change 抽取的可复用知识，以及**归档前核对 delta spec 时发现的 5 处过度声明**。
归档状态：任务 20/21，唯一未勾项 `#16` 因"独立草稿路径不存在"而无实现对象（详见 tasks.md）。

## 一、新增领域知识

### 1. 两种生产族（`production_family`）

| 族 | 编排单位 | 阶段词表 | 产出 |
| --- | --- | --- | --- |
| `narrative` | **章节** | `outline` / `chapter_plan` / `chapter_outline` / `script` / `novel_body` / `storyboard` / `comic_pages` / `video` | 正文、脚本、分镜 |
| `content_package` | **条目**（页/卡/镜头/文章包） | `package_plan` / `item_text` / `item_prompt` / `media_batch` / `package_outputs`（可选 `item_review` / `layout`） | 条目化内容包 + 平台适配输出 |

两族**共用** `ProjectContent`、生产计划结构（`ProductionPlanSchema`）与确认规则；区别只在编排单位，因此各有自己的阶段词表。词表是**路由输入（指导）而非校验器**——计划节点的 `stage` 仍是自由字符串，未知值不被拒绝（既有计划里存在 `stage="image"` 这类自定值）。

### 2. 内容包契约

- 六种 `package_type`：`page_book` / `knowledge_cards` / `article_package` / `social_carousel` / `shot_list` / `single_media`。
- **`ui_enabled`** 是"本期只做 API、不建 UI"的开关标记：只有前两种为 true。
- item 七态：`draft` / `ready` / `generating` / `succeeded` / `failed` / `stale` / `archived`。
- **`index` 即页序**：保存时由表单数组顺序重算，适配器据此排布；已保存条目带着自己的 `id` 移动，所以换序不会让引用它的输出失效。

### 3. 适配器

- 五种 `adapter_type`：`wechat_official_account` / `xiaohongshu_carousel` / `short_video` / `pdf_ebook` / `asset_bundle`。
- **按产出形态命名而非按平台**：短视频平台导出结构同一套，差异属发布环节。
- 三条边界：不调外部平台、不写回源包、不保存第二份事实源。
- `planning_only`（`short_video` / `pdf_ebook`）：只出规划数据，需后续渲染，不得当作成品。
- 产出集合由方案声明的 `output_adapters` 决定（绘本→PDF+素材包；科普/平台图文→公众号+小红书+素材包；单镜头→素材包）。

### 4. 两档校验

硬错误仅限**结构性、无法安全落库**者（未知类型、items 非数组、`status` 越界、条数超上限）；内容质量类（条数偏低、缺推荐字段、整包无媒体提示词）只收 `warnings`。理由：生成是 LLM 驱动的，"先存标题、再补提示词"是内容包增量编辑的正常中间态，硬拒会让调用方存不了半成品版本。

## 二、新增业务规则

1. **schema 是条数的唯一权威**：生成数量按类型上限夹取（`single_media` 上限 1）。若放任按默认 12 条生成，保存时会被按类型拒绝——表现为"生成成功但保存失败"。
2. **过期按依赖判定**：只有 `source_item_ids` 命中变更条目的输出标 `stale`。当前五个适配器都产出整包级产物，故改任一条都会让全部输出过期——这是依赖判定的正确结论，不是无差别作废。
3. **单条重跑不重规划整包**：省 token，且不冲掉用户已手改的条目。
4. **`content_package` 目前只有项目内一条路径**：无独立草稿（`content_package_drafts` 全仓 0 命中）。

## 三、新增工程约束（本次踩到的坑）

| 坑 | 说明 |
| --- | --- |
| **`Form.List` 里的原生 `<button>` 默认 `type=submit`** | 放进 antd `<Form>` 后一点就**提交整个表单**（顺手保存并关闭弹窗）。风险只来自原生 `<button>`；antd `<Button>` 默认 `htmlType="button"` 无此问题。 |
| **`imageContextKey` 会补齐 `chapterNumber`** | 写入端用 `context.chapterNumber ?? activeChapterNumber`；读取端漏掉该字段就得到**另一个键**，表现为"生成成功却在界面上看不到"。 |
| **单条与批量生成的结果写入位置必须一致** | 批量写回条目表单；单条原先只写页面级 `inlineImages`。已统一为写回表单，且**只在新地址非空时才覆盖** `image_url`（否则异步分支只回 `assetId` 会抹掉已有图）。 |
| **表单字段值在 `input`/`textarea` 里** | 用 `inner_text` 断言表单界面会误判为"字段没渲染"，必须读控件 `value`。 |
| **异步渲染元素的计数会抖动** | `img[src*=...]` 在重渲染瞬间可能少一个，**不能据此判定数据丢失**——以数据库/接口为准。 |
| **`tsconfig` 关了 `noUnusedLocals`** | `tsc` 不报死导入，删代码后要另行扫描"标识符是否只出现在导入行"。 |
| **`frontend/` 没有 ESLint 配置** | `npm run lint` 脚本存在但跑不起来，**在未改动代码上同样失败**（既有工具链缺口）。 |

## 四、可复用操作知识

- **免费真实生图后端 Agnes**：连接器 `agnes-image-21-flash`（provider `agnes`，模型 `agnes-image-2.1-flash`，文生图+图生图），尺寸取值 `1K/2K/3K/4K`，约 10–15 秒/张。用于**不消耗额度**的真实链路验证。
- **同步 vs 异步供应商**：任务账本仅在生成返回 `pending` 任务时创建（`api/v1/images.py`）；同步供应商在请求内完成，**不留任务记录**——其留痕落在**事件日志 + Asset Hub**。

## 五、归档前核对发现的 5 处过度声明（已收窄）

主 spec 是后续 change 读取的"当前真相"，留一句没做的事，下一个读到它的人就会以为它存在。

| # | 原文声明 | 事实 | 处理 |
| --- | --- | --- | --- |
| 1 | "the planner can create a package using those sources as `source_context`" | `generate_content_package` 只接收 topic/brief，调用 `validate_profile_inputs` 时**未传** `source_assets`/`source_links` | 收窄为"输入校验接受、契约可携带"，并注明**生成尚未消费素材** |
| 2 | 文章包一次规划返回 "title candidates, summary, …, Markdown/HTML-ready content" | 提示词只要求返回 `title/topic/brief/items`；`title_candidates`/`lead`/`markdown`/`html` 仅声明未生成 | 收窄为 title + brief + 有序章节（各含文本与提示词），并注明包级字段**尚未生成** |
| 3 | 轮播包返回 "cards, caption, tags, dimensions, per-card prompts" | `caption`/`tags`/`dimensions` 不在 `ContentPackagePlanSchema` 输出里 | 收窄为有序卡片 + 每卡文本与提示词；尺寸与页序由适配器在产出时决定 |
| 4 | "allow the user to **select** multiple package items and confirm one batch action / the **selected** twelve items" | 没有逐条勾选：批量动作覆盖包内**所有带提示词的条目** | 收窄措辞并注明**没有逐条勾选** |
| 5 | "Every task MUST … enter the existing **task center**" | 任务账本只对**异步**供应商创建（返回 `pending`） | 收窄为"返回 pending 任务者额外进任务中心"，并注明同步供应商的留痕在事件日志 + Asset Hub |

另收窄一处范围夸大："multi-platform generation is a shared capability" 原文暗示项目会调用平台模板与批量生成服务；实际**已共享**的是 `ContentPackagePlanner`（大纲规划）与两个展示组件（`GeneratedMediaThumb` / `PackageOutputList`），**未共享**的是内容包规划本身（用服务层自己的 JSON 生成）。

## 六、可复用的验证手法

- **数据级确定性验证优于界面计数**：验证"只重跑那一条"时，改看 `POST .../assets` 产生的**素材关联**（带 `source_index`）——点击前后只有目标条目的关联增加，其余条目计数与资产集合完全不变。这比数页面元素可靠得多。
- **用免费后端把"未验证"变成"已验证"**：本项目多个 change 长期停在"已实现但未端到端验证（需额度）"；免费供应商存在时应当优先跑通，否则该缺口会一直挂着。
