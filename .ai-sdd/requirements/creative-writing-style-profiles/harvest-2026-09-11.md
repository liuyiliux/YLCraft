## 二、术语与业务对象（6 项，全部 ✅ 新增）

| 术语 | 定义 | 来源 | 去重 |
|---|---|---|---|
| **写作风格档案（WritingStyleProfile）** | 从测量与模型分析中提炼的、**可审核/可版本化/可审计**的抽象表达机制对象；只描述"怎么写"，**不承载"写了什么"** | design.md「Product model」、`writing_style.py` | ✅ 新增 |
| **风格三层模型** | ① `ProjectStyleMeasurement`：某正文版本的观测证据，**不可直接当提示词**；② `WritingStyleProfile`：可审核抽象（含规则、置信度、溯源、版权边界）；③ `ProjectWritingStyleLink`：运行时选择（项目+阶段+强度），**不是档案本身** | design.md L5-12 | ✅ 新增 |
| **来源快照与有界样本** | 从 `NovelSourceSnapshot` 取有界样本（≤12000 字 / 40 块）做**本地确定性测量聚合**（句长/段落/对话占比/标点密度/字词多样性，按字数加权），样本分析完即弃，档案只留 hash、测量指标与字符偏移 | tasks #6、架构文档写作风格段 | ✅ 新增 |
| **表达式契约（prompt_contract）** | 档案中有界的可注入集合：`rules`（每维一行 `维度名：值` + 反模板约束，上限 40 条）、`new_examples`（新造示例，非原文摘抄）、`prohibited_source_material` | `build_prompt_contract` | ✅ 新增 |
| **绑定强度（intensity）** | 绑定时的注入力度档位，**不是标签**：决定进入提示词的规则与示例条数 | design.md L93-95、本轮实现 | ✅ 新增 |
| **归档可逆** | 归档是"下线"而非删除：档案退出运行时选择，但**已有绑定关系保留**（自动失效）；取消归档回到草稿 | tasks #14、本轮实现 | ✅ 新增 |

## 三、业务规则与校验逻辑（8 项，全部 ✅ 新增）

| 规则 | 内容 | 来源 | 去重 |
|---|---|---|---|
| **生命周期** | `draft → reviewed → active → archived`；`restore` 使 `archived → draft`，**绝不直接跳到 reviewed/active**（材料闸门必须重跑） | design.md「Lifecycle」、`writing_styles.py:restore_style_profile` | ✅ 新增 |
| **归档 ≠ 删除** | 归档后 `runtime_profiles` 不再返回该档案，但 `ProjectWritingStyleLink` 记录保留；取消归档后也不自动生效，需重新 review + activate | `tests/test_writing_style_profiles.py` | ✅ 新增 |
| **提取恒为草稿** | 提取**绝不自动激活**；激活与绑定是分离步骤，且激活只接受 `reviewed` | tasks #6、Agent 工具说明 | ✅ 新增 |
| **材料闸门位置** | 泄漏/合规闸门放在 `review` 与 `activate`；**违规档案可以留在草稿里查看与修正，但进不了生效链路**；`update_draft` 编辑后闸门自动重算 | tasks #11 | ✅ 新增 |
| **泄漏判定阈值** | ① 来源专名/禁用词污染；② 与来源样本**连续 12 字重合**（复述原文）→ 判违规；③ 新造示例与样本 **8-gram 重合率 ≥ 0.12** → 仅告警 | tasks #11、`inspect_style_material` | ✅ 新增 |
| **导入不是免检通道** | Markdown Skill 导入同样产出 `draft` 并跑同一套材料检查，不会绕过闸门 | tasks #10 | ✅ 新增 |
| **强度决定注入量** | `subtle / balanced / strong` 分别注入最多 **8 / 16 / 24** 条规则与 **1 / 2 / 4** 个新造示例，并在注入块标题标注两字标签（参考 / 贴合 / 严格） | 本轮实现、`INTENSITY_POLICY` | ✅ 新增 |
| **风格审阅只报告** | `review_prose_deviation` 比对实测与基线，severity 阈值 warn 0.35 / off 0.75；反模板约束与禁止项只作人工核对提醒；**绝不改写正文或档案** | tasks #12 | ✅ 新增 |

## 七、工程约束与模式（5 项，全部 ✅ 新增）

1. **T6 层预算 1200 字符，且与项目 Skill 包共用**：强度标签只占两个字、**不额外占行**。把强度说明写长会把风格规则挤出预算，表现为"明明绑定了风格却没注入规则"——这是最容易被误判为 bug 的约束。
2. **注入块必须由纯函数生成**：`build_style_prompt_block`（纯函数，便于单测）负责拼装，端与服务不各写一份，避免强度/标签行为漂移。
3. **风格是 T6 唯一职责**：档案只能注入 T6 表达机制，**不得覆盖 T0-T5 正典、动态状态、章节契约与已批准正文**，也不得把风格内容复制进项目。
4. **人机边界必须一一对等**：真人 HTTP 与 Agent 工具共用 `WritingStyleService`。本轮踩坑：Agent 有 `archive` 却缺 `restore`，等于"能归档不能撤销"，实际把归档变成删除。**新增状态流转时，HTTP 与 Agent 工具要同时补。**
5. **`TOOLS` 是函数列表，不是"名字 → 工具"字典**：判断某工具是否注册，应比对 `tools/__init__.py` 的 `__all__` 或 `ToolRegistry.get_tool(name)`；写成 `'名字' in TOOLS` 恒为 `False`（本轮据此得出过"注册失败"的错误结论）。新增工具需在 `__init__.py` 三处同时登记：导入块 / `TOOLS` 列表 / `__all__`（`__all__` 是**带引号**的字符串写法）。

## 八、设计决策（4 项，全部 ✅ 新增）

| 决策 | 理由 | 被否决的方案 |
|---|---|---|
| **先内部集成（A），再经混合（C）开放外部 Agent** | 内部服务掌握来源访问、存储、校验、激活与运行时注入，一致性与可审计性最好 | **B：外部 Agent 直连** —— 会绕过溯源/确认/版权控制，并造成档案 schema 漂移 |
| **风格是软约束，只报告偏离** | 偏离多少由人决定，自动改写正文会破坏人工创作主导权 | 按偏差分数自动回改正文/档案 |
| **提取 / 激活 / 绑定三步分离且每步需确认** | 防止"提取即生效"，保证人始终在环 | 提取后自动激活并绑定 |
| **反模板审查证据驱动** | 机械禁用三段式、排比、短句会误伤正常文学手法；只有局部证据显示重复、以解释代行动、声音不符或场景受损才算缺陷 | 黑名单式的"三段式即 AI 味" |
