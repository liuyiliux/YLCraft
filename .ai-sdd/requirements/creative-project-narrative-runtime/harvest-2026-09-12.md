## 二、术语与业务对象（7 项 ✅ 新增）

| 术语 | 定义 | 证据 |
|---|---|---|
| **叙事运行时（narrative runtime）** | **项目级**子系统：把已批准的正文转为持久叙事状态，再为下一章装配有界上下文。**不替代** Writer Room / Asset Hub / Agent Runtime / Canvas | design.md「Product Boundary」 |
| **`ProjectNarrativeSnapshot`** | 每个已批准正文版本一份**当前**快照，历史快照保留；承载有界摘要、角色状态、时间线增量、未决问题、`context_fingerprint` | design.md「Data Model」 |
| **`ProjectStoryEvent`** | 归一化事件：类型/参与者/地点/时间线序/章节溯源/证据锚点，可被图谱与上下文包查询 | design.md「Data Model」 |
| **`ProjectForeshadowing`** | 伏笔台账：`kind` / `statement` / 埋设章 / 预期窗口 / 状态 / 证据锚点 | design.md「Data Model」 |
| **`ProjectStyleMeasurement`** | 风格测量：篇幅、对话占比、句法节奏、说明性估计、张力分、声线相似度与测量来源 | design.md「Data Model」 |
| **`ProjectNarrativeRun`** | 持久化的手动/批次/自动驾驶运行状态：目标章、步骤、来源快照、游标、重试次数、token/成本、状态与失败诊断；**沿用既有任务/trace 约定** | design.md「Data Model」 |
| **Context Pack V2 七层（T0–T6）** | T0 锁定正典 / T1 活跃叙事状态 / T2 活跃伏笔 / T3 章节契约 / T4 局部连贯 / T5 语义召回 / T6 风格与题材 | design.md「Context Pack V2」 |

## 三、业务规则与校验逻辑（7 项 ✅ 新增）

| 规则 | 内容 |
|---|---|
| **正典 vs 提案（canon / proposal）分界** | 只有 `novel_body`（人工 promote）与**锁定**的 `project_bible`/`world_asset` 可作**硬约束**进入生成；快照是有界状态（仅能由**源版本重放**改变）；事件/伏笔为软状态（仅显式动作或确定性重放可改状态）；**判定候选永不自动接受**；Writer Room 候选、Canvas/资产/Agent 线程数据默认**不进**上下文 |
| **派生状态必须可溯源** | 快照、事件、台账行**始终**携带 `project_id` / `source_content_id` / `source_version` / `chapter_number` / 源指纹 / 抽取与运行溯源 |
| **源版本替换用 supersede 而非销毁** | 新的已批准正文版本**取代**旧版本派生的状态（`superseded`），旧状态仍保留可查 |
| **Aftermath 管线幂等** | 幂等键 = `source_content_id + source_fingerprint + pipeline_version`；仅在 `novel_body` 创建或**显式重放**后调度 |
| **失败隔离** | 富化失败**不影响已批准正文的有效性**；运行标记 `partial` 并列出可重试的失败阶段 |
| **重放必须用同一源版本** | 绝不"因为有同号章节就顺手用最新章" |
| **待决候选与未批准记录不得泄漏** | 待决候选、未批准台账行、agent 记忆、游离 canvas 数据**永不进入 T0–T5**；当前候选内容可作为"重写来源"显式提供，但**必须标注为候选而非正典** |

## 六、枚举与字典（4 项 ✅ 新增）

- **`ProjectNarrativeSnapshot.status`**：`success` / `partial` / `failed` / `superseded`
- **`ProjectForeshadowing.kind`**：`clue` / `promise` / `object` / `relationship` / `rule`
- **`ProjectForeshadowing.status`**：`pending_review` / `active` / `advanced` / `resolved` / `overdue` / `ignored` / `superseded`
- **叙事运行模式**：`manual`（用户触发单动作）/ `batch`（选章选步，依赖与跳过可见）/ `guarded_autopilot`（**只**推进到候选生成、审阅与 aftermath，**在 promote、事实接受、台账激活与发布之前停下**）

---

## 七、工程约束与踩坑（3 项 ✅ 新增）

1. **T0 永不静默截断**：超出时**必须显式报 `context_overflow`**，而不是悄悄丢掉一部分锁定正典。T1–T6 走预算制，并**记录被纳入/排除的源 ID 与原因**。
2. **异步生图不能"让正文运行成功"**：图像生成是**外部生产任务**，只有在**任务真正完成且 Asset Hub 谱系回写已校验**之后，才算生产运行成功。（本轮实测补充：`generate-storyboard` 只产出文字分镜草稿，**不产生生图任务**，因此该闸门在实测中未被触发。）
3. **熔断器触发条件**：反复供应商失败、上下文溢出、结构化输出非法、预算超限、质量底线持续不达标。**恢复必须显式用户动作**，不自动重试。

## 八、设计决策（4 项 ✅ 新增）

| 决策 | 理由 | 被否决的方案 |
|---|---|---|
| **不新建第二个通用 agent runtime** | `ProjectNarrativeRun` 沿用既有任务/trace 约定，避免两套运行时 | 为叙事再起一套通用运行时 |
| **先只读诊断，再增量开放** | 迁移与上线顺序：先建表与只读诊断 → 提供显式 `rebuild narrative state`（按章顺序处理已批准 `novel_body`）→ 手动手动模式验证幂等与部分重试 → 再开 Context Pack V2 与制作台检视 → **自动驾驶默认关闭**（项目级开关） | 启动时激进回填、直接开自动驾驶 |
| **伏笔初版必须人工确认** | AI 抽取只产生 `pending_review`；确定性消费证据可**提议** `advanced`/`resolved`，但首发仍要求用户确认 | 让抽取结果直接进入生成输入 |
| **叙事图谱独立于项目谱系与 Canvas** | 图谱读已确认事实与台账，避免把提案与正典混在一张图里 | 复用项目谱系图 |
