## 二、术语与业务对象（7 项 ✅ 新增）

| 术语 | 定义 | 证据 |
|---|---|---|
| **创作项目（CreativeProject）** | **唯一的工作单元**：一级心智是「项目工作台 + 素材库 + 画布」，其他能力降级为项目内的动作入口 | proposal「Product」 |
| **项目内容项（ProjectContent）** | 每个阶段的产出**独立存储**（不塞进一个大 JSON blob），以便重新生成、版本化、关联、检索、复用 | design「Project content item」 |
| **阶段机** | `outline → chapter_plan → chapter_outline → body → comic_pages / script → storyboard`，每阶段只能消费**上游已保存**的产物 | design「Generation strategy」 |
| **项目资产关联（ProjectAssetLink）** | 项目 ↔ 素材库节点的带语义关联：`role` + `relation` | design「Project asset link」 |
| **素材库作为项目持久记忆** | 角色 → `Character` + 素材节点；世界观/章节摘要/脚本/分镜/提示词 → 文本素材；AI 图与视频 → 媒体素材 | design「Asset library」 |
| **画布作为项目编排面** | 不是独立玩具页，而是项目的组合面：节点（project/outline/chapter/character/scene/prompt/image/video/audio/note）+ 边（contains/uses/references/derived_from/variant_of） | design「Canvas」 |
| **稳定 vs 实验能力分级** | 稳定：下载、小说、AI 图片、素材库、创作项目。实验：视频生成、剪辑、字幕、BGM、发布、爬虫、Agent | design「Frontend information architecture」 |

## 三、业务规则与校验逻辑（7 项 ✅ 新增）

| 规则 | 内容 |
|---|---|
| **阶段感知生成（核心）** | ① 大纲只用创意或小说摘要；② 章节计划必须用**已保存**的大纲；③ 单话细纲用大纲 + 章节计划；④ 正文/脚本用细纲 + **锁定的**角色/世界观数据；⑤ 分镜用脚本场景 + 视觉风格 + 角色外观 |
| **JSON-first + 校验 + 一次修复** | 系统提示词定义角色/输出 schema/禁 Markdown；后端用 Pydantic 校验；失败则带校验错误**修复一次**；原始请求响应、模板元数据与归一化结果**都进生成日志** |
| **生成单元必须独立存储** | 阶段产出不可全藏在单个大 JSON 里——分开存才能重生成/版本化/关联/检索/复用 |
| **每个生成资产必须记录谱系** | 必须记录 project id、content id、prompt、model、provider 与来源关系 |
| **实验模块不得阻断主流程** | 历史半成品应标注并在主导航中收拢；不得让用户被未完成模块打断 |
| **资产双轨先用兼容层** | 普通素材表与资产中枢并行时，先做兼容层，再逐步统一存储（不一次性大迁移） |
| **画布状态先存项目 metadata** | 必要时再提升为独立表——避免过早引入新表 |

## 四、API 知识（1 项 ✅ 新增）

`/api/v1/creative-projects/**` 主干（多数已存在，此处只补**阶段端点命名**）：

```text
POST /creative-projects/{id}/generate-outline
POST /creative-projects/{id}/generate-chapter-plan
POST /creative-projects/{id}/chapters/{chapter}/generate-detail
POST /creative-projects/{id}/chapters/{chapter}/generate-script
POST /creative-projects/{id}/chapters/{chapter}/generate-storyboard
POST /creative-projects/from-novel
GET|POST /creative-projects/{id}/assets
GET|PUT  /creative-projects/{id}/canvas
```

**生图回写项目的关键**（2026-09-12 实测确认）：`POST /images/generate` 必须带 `project_id` + `content_id` + `source_type`，
且 `source_index` / `chapter_number` **须为字符串**；否则不产生项目 `derived_from` 谱系。

## 七、工程约束与踩坑（4 项 ✅ 新增）

1. **阶段模板体系要兼容历史模板**：扩展 `platform_templates` 增加 `template_scope` / `template_stage` / `description` / `system_template` / `variables`，使历史多平台图片模板继续可用，同时创作项目的系统/用户提示词可在模板管理 UI 编辑。**内置模板是兜底**，用户覆盖优先。
2. **`Select-String` 不递归子目录**：核对实现时必须递归搜索（本项目已因该坑误判过"没实现"）。
3. **`npm run smoke:pages` 不是浏览器验证**：它只做源码 marker 检查；真实 UI 验证须用 `patchright`（后端 venv 已装）+ Chromium。
4. **生图 lineage 字段类型**：`source_index` / `chapter_number` 传整数会 422，**必须是字符串**。

## 八、设计决策（4 项 ✅ 新增）

| 决策 | 理由 | 被否决的方案 |
|---|---|---|
| **新建表（Path A）而非扩展 `stories`** | `Story` 命名与字段对小说/漫画/短剧/画布过窄；新表更清晰且不破坏既有 Story Maker | 在 `stories` 上加 JSON 字段（Path B） |
| **先只做最小闭环** | 首版只覆盖大纲、章节计划、小说导入与生图交接 | 一次性交付全部阶段与画布 |
| **画布是项目组合面** | 画布承载"项目 → 产物 → 素材"的编排，而非独立玩具页 | 把画布做成独立功能页 |
| **LLM JSON 不稳定要靠工程兜底** | Pydantic 校验 + 一次修复 + 原始日志 + 版本化 | 仅靠提示词工程保证 JSON 正确 |

## 九、冲突项

无。两个 delta spec（`asset-canvas-loop` 6 需求、`creative-project-workflow` 8 需求）与 99/99 任务一致。

**2026-09-12 实测记录（#57 闸门，真实供应商）**：新建项目 → 大纲/章节计划/单话细纲/分镜全部 200（分镜 8 面板）→
`POST /images/generate` 带全 lineage 字段 → 真实 siliconflow 返回 PNG；项目资产关联 **0 → 1 条**，
`role=generated`、`relation=derived_from`、资产中枢 `source_type=ai_generated` 且已落盘。

**一处待观察**：资产 `file_path` 记为 `backend/backend/app/storage/images/...`（`backend/` 前缀重复），
资产可用但前缀疑有冗余。
