## 二、术语与业务对象（3 项 ✅ 新增）

| 术语 | 定义 | 证据 |
|---|---|---|
| **稳定 / 实验能力分级** | 稳定：下载、小说、AI 图片、素材库、创作项目。实验：视频生成、剪辑、字幕、BGM、发布、爬虫、Agent——**直到接入项目闭环** | design「Frontend IA」 |
| **画布作为项目编排面** | 不是独立玩具页：节点 `project/outline/chapter/character/scene/prompt/image/video/audio/note`，边 `contains/uses/references/derived_from/variant_of` | design「Canvas」 |
| **素材库作为项目持久记忆** | 角色→`Character`+素材节点；世界观/章节摘要/脚本/分镜/提示词→文本素材；AI 图与视频→媒体素材 | design「Asset library」 |

## 三、业务规则（4 项 ✅ 新增）

| 规则 | 内容 |
|---|---|
| **实验模块不得阻断主流程** | 历史半成品要标注并在主导航收拢，避免用户被未完成模块打断 |
| **画布状态先存项目 metadata** | 必要时再提升为独立表——不过早引入新表 |
| **资产双轨先用兼容层** | 普通素材表与资产中枢并行时先兼容，再逐步统一，不做一次性大迁移 |
| **生成日志要留全链路** | 原始请求/响应 + 选中模板元数据 + 归一化结果都要进生成日志 |

## 五、工程约束（3 项 ✅ 新增）

1. **阶段模板体系要兼容历史模板**：扩展 `platform_templates` 增加 `template_scope` / `template_stage` /
   `description` / `system_template` / `variables`，使历史多平台图片模板继续可用。**内置模板是兜底**，用户覆盖优先。
2. **LLM JSON 不稳定靠工程兜底**：Pydantic 校验 + 一次修复 + 原始日志 + 版本化，而不是只靠提示词工程。
3. **服务端内部消费的文件地址用 `to_storage_path` 存相对路径**（`backend/app/storage/...` 形态），
   由 `resolve_storage_path` 在各机器还原；**该项目根相对约定由 `asset_file_resolver` 统一**，
   且 `to_storage_path` 已改为**幂等**（相对路径按项目根解析），可安全重复调用。

## 六、设计决策（3 项 ✅ 新增）

| 决策 | 理由 | 被否决的方案 |
|---|---|---|
| **新建表（Path A）而非扩展 `stories`** | `Story` 命名与字段对小说/漫画/短剧/画布过窄 | 在 `stories` 上加 JSON 字段（Path B） |
| **首版只做最小闭环** | 只覆盖大纲、章节计划、小说导入与生图交接 | 一次性交付全部阶段与画布 |
| **画布是项目组合面** | 承载"项目 → 产物 → 素材"编排 | 做成独立功能页 |

## 七、冲突项

无。两个 delta spec 与 99/99 任务一致。

**归档前实测（2026-09-12，已完成并落证于任务 #57）**：新鲜项目 → 大纲/章节计划/单话细纲/分镜 →
`POST /images/generate` 带 lineage 字段（`project_id` + `content_id` + `source_type`，且
`source_index`/`chapter_number` **须为字符串**）→ 真实 siliconflow 返回 PNG；项目资产关联
**0 → 1 条**，`role=generated` / `relation=derived_from`，资产中枢 `source_type=ai_generated` 且已落盘。

**一条易错经验**：只调 `/images/generate` 而不带上述 lineage 字段**不会**产生项目谱系，
容易被误读为"后端不支持写谱系"——实际是调用方漏参。
