# 需求采集 · 区域几何重构（region-geometry-rework）

> 状态：已确认
> 采集日期：2026-09-04
> change：region-geometry-rework
> 来源：用户口述 + Azgaar Fantasy-Map-Generator 截图（政治地图，有机海岸线与势力疆界）

## 一、背景与痛点（用户原话要点）

- 起因：觉得现有世界地图"难看"，去搜开源小说地图项目，找到 Azgaar Fantasy-Map-Generator；
  喜欢它"地图像一个真实的地方"，而不是我们"一个个点"。
- **根因不是样式，是数据模型语义错了**：
  当前「区域」实现为**成员据点围成的凸包**——等于把"福贵的房子"当成了"村子的城墙角"。
  正确语义：**区域是有形状的地理范围（村子/城墙围出的地方），据点是区域内的一个位置（福贵的房子）**。

## 二、已确认决策（本轮采集成果）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 区域形状来源 | **双模式：生成 + 手绘**。默认一键生成有机轮廓，用户可再手动微调 |
| 2 | 据点 ↔ 区域归属 | **引用为准（`region_id`），位置仅提示**。据点落在形状外时画布给警告条，不强制移动、不自动改引用（符合"引用不复制"纪律，不产生隐式数据变更） |
| 3 | 程序化生成 | **可控生成**：参考 Azgaar 的算法思路，但**由我们的结构化数据确定性驱动**，不接它的随机世界生成管线。形状是据点派生的，不是凭空生成的 |
| 4 | 旧数据兼容 | **清理数据**（不做兼容迁移）——执行范围待最终确认，见第六节 |
| 5 | AI 输出粒度 | **语义参数 + seed → 确定性算法展开顶点**。AI 输出：中心、面积感、形态意象（狭长河村/圆形寨子/破碎山城等）、不规则度；几何交给算法。理由：LLM 不擅长精确几何，擅长语义；结果稳定可重放 |
| 6 | 生成触发环节 | **独立动作**：已有据点后，用户点「生成区域形状」或 Agent 调工具单独生成。可控、可预览、可重放，不动现有提取链路 |
| 7 | 单区域顶点上限 | **64**。超出由算法自动抽稀（性能与绘制质量平衡） |
| 8 | 嵌套层级视觉 | **默认父淡子艳**（父=疆域：填充淡、边界粗虚线；子=聚落：填充实、边界细实线）；**选中时颜色更艳**（可切换强调） |
| 9 | 清理数据范围 | **清掉所有地图数据**（`world_maps` + `world_map_revisions` 全部删除，从零开始）。执行前先备份，属破坏性操作，已明确确认 |
| 10 | 嵌套层数 | **不限层数**，由层级深度自动计算视觉权重（越深填充越实、边界越细） |
| 11 | 形态意象词表 | **三维度**：自然意象（8）× 聚落形态（6）× 人工构筑（3+），详见第八节 |
| 12 | 据点 kind 扩展 | **同步扩展到 20 种**，每种配内联 SVG 图标（与区域几何重构同批做），详见第八节 |
| 13 | 备份 | **不备份**，直接清库（现有地图均为测试数据） |

## 三、新术语与行业知识（通用上下文候选）

| 术语 | 含义 | 归属 |
|---|---|---|
| Voronoi / Delaunay | 平面剖分：把区域按"种子点"切成细胞（cell）；Azgaar 用 Delaunay 三角 + Voronoi 细胞构成陆地单元 | 通用上下文（新增） |
| 细胞（cell） | Voronoi 剖分出的最小地理单元，带高度/归属；有机边界来自细胞联合的边缘 | 通用上下文（新增） |
| 凸包（convex hull） | 包住一组点的最小凸多边形。**当前错误实现**：用它把据点连成区域 | 通用上下文（纠错：这是要被替换的旧做法） |
| jitter / 扰动 | 对顶点做随机偏移（受 seed 控制），让规整多边形变得有机 | 通用上下文（新增） |
| Catmull-Rom / 平滑 | 折线插值成曲线的算法；用于把折角顶点渲染成柔和岸线/城墙 | 通用上下文（新增） |
| 可控生成 | 由已知数据 + 参数 + seed 确定性地产出形状，可重放、可微调，区别于"随机世界生成" | 通用上下文（新增） |
| 点在多边形内（point-in-polygon） | 判断据点是否落在区域形状内的算法。本次**不用于自动归属**，仅用于"据点在形状外"的提示 | 通用上下文（新增） |

## 四、补充设计约束

1. **不接随机世界生成管线**：Azgaar 的高度图→生物群系→河流→国家链与"结构化数据是正典"纪律冲突。只借鉴其**有机轮廓的算法思路**（细胞联合/扰动/平滑的数学部分）。
2. **形状不产生事实**：区域形状是**视觉几何**，不代表新的世界事实；据点与实体的引用关系仍是唯一正典。
3. **确定性优先**：同一个（参数 + seed）必须产出同一个形状，才能进版本历史与对比。
4. **可重放**：保存 `seed + 参数`，点「重新生成」即重算；若顶点已被手绘修改，重新生成前必须提示确认会覆盖。
5. **顶点上限 64**：算法展开后抽稀到 ≤64，保证 SVG/Polygon 渲染与版本快照体积可控。
6. **后端/前端分工**：形状展开算法放**前端**（实时预览、参数可调、可重放）；AI 只产出语义参数。后端负责存储、版本 CAS 与（可选）Agent 工具触发。

## 五、补充需求澄清

1. 区域数据模型需新增：形状顶点序列、生成参数（中心/面积感/形态意象/不规则度）、`seed`、模式（`auto` 参数驱动 / `manual` 手绘固化）、父区域 `parent_id`（支持嵌套）。
2. 渲染需支持嵌套层级：按父子层级排序绘制（父在下、子在上），选中态提亮。
3. 导出与 `/render` SVG 需输出新几何（点位 JSON 增加 `shape` 字段）。
4. 版本历史（append-only）与回滚机制不变，形状变化随 revision 一起进快照。
5. Agent 工具需新增「生成/重新生成区域形状」能力（与真人同一 service 层，符合"Agent 工具与真人共用"的既有纪律）。

## 八、形态意象词表方案（待确认）

**调研结论：Azgaar 没有"形态词表"**——它的区域形状是 Voronoi 细胞剖分 + 地形派生的自然结果，
不存在"圆形寨子/狭长河村"这类语义模板。因此**语义形态是我们自己的设计维度，也是相对它的差异化**
（它只能"地形长什么样就什么样"，我们可以"用户说什么形态就给什么形态"）。

可从它借鉴的类型体系：
1. **Biomes（13 种）**：Marine / Hot desert / Cold desert / Savanna / Grassland /
   Tropical seasonal forest / Temperate deciduous forest / Tropical rainforest /
   Temperate rainforest / Taiga / Tundra / Glacier / Wetland —— 自然环境语义。
2. **Markers（地物图标类型）**：山峰/火山/湖泊/瀑布/沼泽/森林/城堡/塔楼/废墟/洞窟/矿场/
   桥梁/渡口/神殿/修道院/战场/锚地/灯塔/磨坊/农场/葡萄园/集市/港口等
   —— 是我们「据点 kind」的扩展来源（现仅 5 个：据点/城池/关隘/场景/其他，太粗）。
3. **States / Provinces**：层级嵌套参考（我们已定为不限层）。

**定稿：三维度词表**（AI 各维度选其一 + 连续参数 + seed）：

| 维度 | 取值（受控） | 对展开算法的影响 |
|---|---|---|
| 自然意象（8） | 平原 / 森林 / 山地 / 丘陵 / 湿地 / 荒漠 / 河谷 / 海岸 | 长宽比、边缘粗糙度、凹入强度 |
| 聚落形态（6） | 圆形寨子 / 带状街区 / 散点村落 / 环山聚落 / 方形城邑 / 沿河狭长 | 基础骨架形状与顶点分布 |
| 人工构筑（3+） | 城墙方形 / 要塞星形 / 港口半岛（可继续扩展：梯田环状、环形山寨） | 叠加规则几何特征（直角、星角、半岛凸出） |
| 连续参数 | 面积感（小/中/大）、不规则度（0~1） | 尺度与扰动幅度 |
| seed | 整数 | 保证同参数同结果（可重放） |

展开示例：`{自然: 河谷, 聚落: 沿河狭长, 人工: 港口半岛, 面积感: 中, 不规则度: 0.4, seed: 817}`
→ 沿河拉长的轮廓 + 一侧半岛凸出 + 中等扰动。

**据点 kind 扩展清单（20 种，每种配内联 SVG 图标）**

| 分组 | 类型 |
|---|---|
| 聚落（4） | 村落 / 城镇 / 都城 / 庄园 |
| 军事（3） | 城池 / 关隘 / 战场 |
| 交通（4） | 港口 / 渡口 / 桥梁 / 驿站 |
| 人文（5） | 集市 / 神殿 / 塔楼 / 废墟 / 陵墓 |
| 自然（4） | 山峰 / 森林 / 湖泊 / 矿场 |
| 兜底（1） | 其他 |

图标规范沿用 `docs/design/world-map-workbench-style.md` §7：Lucide 风格内联 SVG，
24×24 视口、`stroke-width:1.75`、`currentColor`、禁 emoji。
