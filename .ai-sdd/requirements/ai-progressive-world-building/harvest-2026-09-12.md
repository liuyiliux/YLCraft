## 二、术语与业务对象（6 项 ✅ 新增）

| 术语 | 定义 | 证据 |
|---|---|---|
| **梯子原则（I1/I2/I3）** | I1 平台持有梯子（结构）、I2 AI 只能踩梯子上加（填值）、I3 平台永远能解析（可列出/检索/导出/对比）。本域所有需求的顶层约束 | proposal |
| **域（domain）与域契约** | 世界设定的模块（如地点/宗教/语言/文化/生态）；每个域有属性契约（`attributes` schema），是"AI 能填哪些字段"的唯一依据 | `WorldDomainService.resolve_specs` |
| **层次策略（layers）** | 域内条目的层级组织方式（如 `世界 → 国家 → 城市 → 地点`），由模板 `layers_json` 定义 | `WorldBuildingTemplates.tsx` |
| **三档生成动作** | `draft_world`（想法→多域骨架）、`expand_domain`（按层次细化整个域）、`expand_entity`（按域 schema 补单个实体字段） | `world_generation.py` |
| **`CandidateOrigin`** | 候选的来源性质：`original`（真实原文）/ `outline`（项目大纲）/ `ai_draft`（AI 创作、无原文）/ `ai_inferred`（模型推断） | `models/novel_source.py` |
| **世界构建模板** | `layers_json`（层次策略）+ `prompts_json`（三档提示词，支持 `{layers}`/`{domain}`/`{hint}` 等占位）；`project_id` 为空即内置种子模板 | 迁移 039 |

## 三、业务规则与校验逻辑（6 项 ✅ 新增）

| 规则 | 内容 | 证据 |
|---|---|---|
| **结构变更必须过闸** | 模型输出分 `items`（内容）与 `suggested_fields` / `suggested_domains`（结构建议）；建议落 `world_domain_definitions` 且 `source=ai_suggested`、`is_enabled=False`，**不自动生效** | `_persist_suggested_domains` |
| **生成内容不得伪造证据** | `origin=ai_draft` 的候选 `evidence_json="[]"`，审阅页与导出均带来源标注 | D2 / R6 |
| **写入唯一通道是 `apply`** | 生成只产候选，正典写入只能经 `POST /world-extraction-runs/{id}/apply` | D5 |
| **内置域字段只可追加不可删除** | 保证历史 `attributes_json` 始终可解析 | `WorldDomainService.resolve_specs` |
| **契约外字段转建议而非丢弃** | 服务层只接受「已勾选且在属性契约内」的值，其余一律转为 `suggested_fields` | `expand_entity` 步骤 4 |
| **幂等去重** | 候选 `fingerprint = gen:{project_id}:{entity.id}`，重复补充同一实体不会产生第二条候选 | `world_generation.py` |

## 四、API 知识（5 项 ✅ 新增）

| 接口 | 关键约定 |
|---|---|
| `GET/PUT/DELETE /api/v1/projects/{project_id}/world-domains[/{domain_key}]` | 列出域契约 / 覆盖内置域或新增自定义域 / 重置内置默认或移除自定义域 |
| `POST /api/v1/projects/{project_id}/world-generation/expand-entity/preview` | **不调用模型**，只返回组装好的提示词；用于降低试错成本 |
| `POST /api/v1/projects/{project_id}/world-generation/expand-entity` | 按域 schema 补实体字段，产出 `ai_draft` 候选 |
| `POST /api/v1/projects/{project_id}/world-generation/expand-domain` | 按模板层次策略细化整个域 |
| Agent 工具 | `expand_world_entity_attributes`、`expand_world_domain`（异步，复用任务工具轮询）、`resolve_world_domain_suggestion` |

契约细节：失败一律抛 `ValueError` → API 转 400，且**运行落 `failed` + `diagnostics_json.error`，不产生脏候选**；前端弹窗内 `message.error` 展示。

## 七、工程约束与踩坑（5 项 ✅ 新增）

1. **复用既有管线的"审阅/写入"半段，只新增"生成"半段**：`WorldExtractionRun` 已有 `domains_json`/`checkpoint_json`/`trace_json`/`diagnostics_json`/`status` 与局部失败语义，`WorldFactCandidate` 已有 `payload_json`/`evidence_json`/`origin`/`status` 与审阅流。新建一套会复制这些机制并制造双份游标语义。
2. **来源性质放在候选级 `origin`，不要放证据上**：放证据上会导致"同一条候选混有多种来源"时无法表达；放 UI 上会导致导出、上下文打包、Agent 返回全部失真。
3. **把"AI 能改什么"的边界前移到响应 schema**：`WorldGenerationSchema` 同时声明 `items` 与 `suggested_*`，模型无法靠"多返回一个字段"偷偷改结构。
4. **同步而非异步的判据**：单实体、单次模型调用、`max_tokens=2000`，耗时与既有 `extract` 同量级；但 `expand_domain` 与未来多域生成需重新评估（OQ-A）。
5. **design.md 可能滞后于 tasks.md**：本次审计一度以为 `expand_domain` 未实现（design 的 API 表标"待实现"），实际代码已落地且任务有 `_Done:` 证据。**判断"做没做"以代码与 tasks 的 `_Done:` 为准，design 的表格可能未回填。**

## 八、设计决策（5 项 ✅ 新增）

| 决策 | 理由 | 被否决的方案 |
|---|---|---|
| D1 不新建 `WorldGenerationRun` / `WorldGenerationCandidate` 两张表 | 会产生第二套运行/游标/诊断语义，且 `reconcile_run`/`detect_contradictions` 无法复用 | 新建两套表 |
| D2 来源性质用独立枚举值（`outline` / `ai_draft`） | 候选级属性，天然带进审阅列表、导出、上下文打包 | 降级为 `ai_draft`（低估大纲可信度）/ 只改 UI（数据层永久丢语义） |
| D3 结构变更在响应契约层就与内容分离 | 把 schema 主权留在平台侧 | 模型自由输出、服务层事后过滤并顺手登记（等于交出 schema 主权） |
| D4 模板存新表 `world_building_templates` | 需按项目查询、内置种子、版本与启用状态 | 塞进 `creative_projects` 的一个 JSON 字段 |
| D5 `expand_entity` 只产候选不改已确认正典 | 写入点唯一是架构红线，直接改写会静默修改 `is_locked` 事实卡 | 确认后直接 UPDATE `attributes_json` |
