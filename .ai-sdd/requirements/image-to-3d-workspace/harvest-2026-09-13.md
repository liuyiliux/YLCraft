## 二、术语与业务对象（3 项 ✅ 新增）

| 术语 | 定义 | 证据 |
|---|---|---|
| **图转 3D 任务账本** | 与通用任务中心**独立**的 `model3d_generation_tasks` 表，承载 `kind`（`generation`/`rigging`）、provider、model、进度、诊断 | 任务 #2 |
| **TC3-HMAC-SHA256 连接器** | 腾讯云 Hunyuan 3D 预设：`api_format=tencent_tc3`，凭据形式 `SecretId:SecretKey`，适配器内置 TC3 签名与 **POST 轮询模板** | 任务 #9 |
| **生成方式（inputMode）** | `text`（文生 3D，只需描述）/ `image`（图生 3D，需参考图或素材 id）——**默认是 `image`** | 前端 L111 |

## 三、业务规则（4 项 ✅ 新增）

| 规则 | 内容 |
|---|---|
| **提交前必须满足输入守卫** | 默认 `image` 模式；未提供参考图/素材时点提交会被 `message.warning` **静默 return**，不发任何请求 |
| **结果必须入资产中枢并带来源谱系** | 完成的 3D 结果写入 Asset Hub，`source_type=image_to_3d` |
| **供应商任务 id 与本地账本 id 分离** | 供应商 id 可能是"不透明编码载荷"；本地账本用 `model3d_<hex>` 短 id，原始 id 另存供轮询 |
| **绑骨需要源模型公网可达** | 腾讯云绑骨只接受**公网可达**的 GLB/FBX；优先走 COS 上传并给 24h 签名 URL，否则回退 `BASE_URL + /model3d-files/public/` |

## 四、API（1 项 ✅ 新增）

```text
GET  /api/v1/model-3d/backends?capability=generation|rigging   # 连接器清单（含 motion_types、poll_interval）
POST /api/v1/model-3d/generate    { prompt, provider, model, source_asset_id, source_image, options }
GET  /api/v1/model-3d/tasks/{id}  # 轮询，返回 url/asset_id/diagnostics
GET  /api/v1/model-3d/history     # 台账历史
POST /api/v1/model-3d/rig         { provider, source_asset_id|source_url, motion_type?, file_type? }
```

- 静态目录：`/model3d-files`（挂载 `backend/storage/model3d`）。

## 五、枚举与字典（2 项 ✅ 新增）

- **`kind`**：`generation`（图/文生 3D）/ `rigging`（绑骨蒙皮）
- **绑骨模式**：`skeleton`（仅骨架）/ `motion`（骨架 + 一个预设动作，`motion_type` 1–48，动作为人形武术类：回旋踢/左勾拳/蓄力出拳/受击…）

## 六、工程约束与踩坑（5 项 ✅ 新增）

1. **`/model-3d/history` 会过滤掉 `pending` 任务**——用它轮询"新任务是否创建"会得出**错误结论**（显示 5 条、库里实际 6 条）。核对任务是否提交成功应查 `asset_representations`/任务表，或直接用 `GET /model-3d/tasks/{task_id}`。**本条曾导致误判"未提交"，进而在额度已消耗的情况下准备重复提交。**
2. **生成表单默认折叠**：须先点「创建模型」展开右侧面板，否则定位不到输入控件。
3. **提交按钮文案是「生成 3D 模型」**，不是「生成」。
4. **Ant Design 的 `message.warning` 约 3 秒自动消失**——自动化验证若等待过久，会完全看不到拦截提示，误以为"点了没反应"。
5. **真实生成会扣供应商额度**（Hunyuan 3D 回执 `ResultCreditConsumed`，本次 20 点）。**任何触发真实生成的验证都必须先向用户确认费用。**
