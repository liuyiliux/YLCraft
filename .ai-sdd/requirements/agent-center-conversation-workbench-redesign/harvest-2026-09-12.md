## 二、术语与业务对象（2 项 ✅ 新增）

| 术语 | 定义 | 证据 |
|---|---|---|
| **对话优先信息架构（conversation-first）** | `/agent` 主界面收敛为「对话列表 + 对话正文 + 输入框」；智能体选择降为**紧凑上下文控件**；工具/记忆/配置/完整轨迹**按需打开**；计划、工具调用、观察、委派、确认**按发生顺序内联**进消息流，完成后默认折叠 | proposal.md「What Changes」 |
| **执行证据内联** | 计划/工具调用/观察/委派不再集中在独立面板，而是**按发生顺序内联到消息流**——与 T6「结果可视」约束配套 | tasks #6 |

## 三、业务规则与校验逻辑（2 项 ✅ 新增）

| 规则 | 内容 |
|---|---|
| **主任务优先，管理信息不占主界面** | 收敛目标是"主任务不被管理信息淹没"；高级能力（工具测试、Profile 编辑、运行树）**不删除、只降低默认层级** | proposal「Non-goals」 |
| **辅助能力失败不阻塞聊天** | 线程、Profile、工具、记忆、模型、运行详情各自有**局部** loading / error / retry；**不因辅助接口失败而整页报错**；线程恢复失败必须**显式**且**不得创建重复会话**；请求失败保留**已流式产出的部分输出**与重试入口 | tasks #9–#11 |

## 四、工程约束（1 项 ✅ 新增）

1. **Agent 页面的 Markdown 是手写解析器，不是第三方库**：`parseInlineMarkdown` + `parseSimpleMarkdown`（`pages/agent/index.tsx:357-395`）自己产出 `MarkdownBlock`（paragraph / heading / list / quote / table）。排查 Agent 消息渲染问题时**不要去找 `react-markdown`**。

## 五、设计决策（3 项 ✅ 新增）

| 决策 | 理由 | 被否决的方案 |
|---|---|---|
| **三条产品约束写入架构约束**：① 低门槛（降低普通人操作门槛）；② 结果可视（直观呈现过程与产物）；③ **脚本优先**（确定性操作交给脚本与服务，减少模型调用与 Token 消耗） | YLCraft 的价值不是"堆更多配置"，而是降低门槛 + 可视 + 省 Token | 靠增加配置项与面板来提升"能力" |
| **不改后端契约** | 本次是**纯前端信息架构重构**：不改 Agent 运行时、工具协议、记忆模型、Supervisor/Worker 机制，`API surface 不变` | 顺带重构后端运行时 |
| **不做成仪表盘或营销首页** | 明确写入 Non-goals | 把 `/agent` 改造成数据看板 |
