# YLCraft 平台重构基调

## 一句话

> **我们的对手不是"功能更多的平台"，是"用户看不懂的平台"。**
> **门槛优先于能力，克制优先于丰富。**

完整依据：`docs/architecture/PLATFORM_REBUILD_BASELINE.md`

---

## 动手前：先判断你改的是哪一层

| 层 | 是什么 | 例子 |
| --- | --- | --- |
| **L1 基础功能** | 一个点，无复杂逻辑 | 裁剪、AI 生图、图生 3D |
| **L2 组合功能** | 一个页面拼了多个功能 | 创建项目、生图页、3D 工作台 |
| **L3 画布** | 用基础节点 + 复杂节点拼 | 剧本→分镜→生图→动图→出片 |

**导航用「工具 / 工作台 / 画布」三个词，不用「基础功能 / 组合功能」。**

## 产品基调

### P1 门槛优先于能力
加功能前先问：**外行能不能不看文档就会用？**

- [ ] 新用户第一次打开能找到吗
- [ ] 需要读文档吗
- [ ] 默认值合理吗（不配置就能出结果）

> 反面：LibTV 有完整文档 + 视频教程，用户仍说「完全不知道该怎么弄」。

### P2 默认一条路，进阶才分岔
- [ ] 首屏只有一条清晰的路
- [ ] 高级功能是**折叠**不是**藏死**
- [ ] 参数默认露出 ≤3 个

> 反面：我们导航 8 组 44 项摊平；LibTV 一来就是节点图。

### P3 同一能力，两个入口
**页面对话式**（慢慢做）+ **节点流程式**（自动跑），都调同一份后端能力。

- [ ] 有手工和自动两个入口吗
- [ ] 两个入口结果一致吗（参数能全量传）

### P4 加新用途 = 加配置
- [ ] 改了超过 3 个文件吗？→ 结构不对
- [ ] 能用配置表达吗（spec / 模板 / SKILL.md）

> 画布侧写 spec 描述页面能力，**页面不动**。

## 交互基调

### I1 说人话：讲「设计」，不讲「验证」

| ❌ 别这样 | ✅ 这样 |
| --- | --- |
| `[原图保留][脸没变形][光位一致]` | `磨皮：保留皮肤纹理，没磨成塑料感`<br>`背景：主光位跟着原图走`<br>`如需调整…告诉我` |

- [ ] 这段话用户能直接发给客户吗
- [ ] 说的是"为什么这么设计"还是"我检查过了"

> 依据：Lovart 2.0 报告 = 完成 → 3~5 条设计要点 → 尺寸用途 → 邀请调整。
> IUI '26 证明「我确认的」和「我没法确认的」是两类，不能并列。

### I2 检查必须是独立动作，且带证据
- [ ] 检查的是**一整套**（不是单张）
- [ ] 每个问题带**可验证数字**（相似度 0.62 / 光源 210° / 1024→1536）
- [ ] 问题**定位到具体位置**，能一键跳过去
- [ ] 分级：要修 / 建议

> 反面：生成后自动贴一句"已检查通过"，没有数字。

### I3 价格永远可见，且来自配置
- [ ] 点之前知道花多少
- [ ] 换模型价格跟着变（不是硬编码）
- [ ] 按价格分组（便宜→贵），不按功能分组

> 依据：ArtCraft 成本 chip / Lovart 右键标价。
> 我们 `ai_connector.py` 已有 `price_per_call`，缺 `price_per_unit` + `unit`。

### I4 状态分级，不用色块刺激
- [ ] 状态用小圆点，不用彩色 tag
- [ ] 区分「已保存」和「已测试」
- [ ] 失败态用"缺"表达（灰化 + 角标），不用大红块

### I5 空态必须有下一步
- [ ] 空态可点入口 ≥3 个
- [ ] 每个入口有明确产物
- [ ] 不是「暂无数据」

## 工程基调

### E1 🔴 页面与节点是兄弟

```
      后端能力（同一份 API）
            ▲          ▲
    ┌───────┴──┐  ┌────┴─────────┐
    │ 页面(UI) │  │ 画布节点      │
    └──────────┘  └───────────────┘
```

- [ ] 没有让页面抽 `run()` 去配合画布
- [ ] spec 放在画布侧，页面不知道它的存在
- [ ] 纯前端能力（裁剪/滤镜）抽成**共享纯函数**，页面只改 import

### E2 🔴 拖拽期间不重建被拖 DOM

```js
// ❌ pointerdown 里重建 → 正在拖的元素消失
gSel = id; renderGraph();

// ✅ 只改 class，拖完再重建
gSel = id;
list.forEach(x => x.classList.toggle('sel', x.dataset.id === id));
```

**这条已经踩过两次（自由画布 + 节点图）。**

### E3 未知就标未知
- [ ] 灰掉的功能说明**为什么**
- [ ] 未验证的写"未验证"
- [ ] 报告里有「没做什么」

## 提交前：违规清单

| 症状 | 违反 | 改法 |
| --- | --- | --- |
| 一屏 ≥4 个区块 | P2 | 折叠到 2~3 |
| 要看文档才会用 | P1 | 空态引导 + 默认值 |
| 加功能改 5 个文件 | P4 | 抽配置/spec |
| Agent 汇报贴一串 chip | I1 | 改成设计解说 |
| 说"检查通过"没数字 | I2 | 给证据 |
| 价格硬编码 | I3 | 从配置读 |
| 状态用大红大绿块 | I4 | 换小圆点 |
| 空页面只有"暂无数据" | I5 | 给 3 个入口 |
| 界面出现 `canvasNodeId` / `source_node_id` | I1+E1 | 引擎术语不外露 |
| 拖拽不跟手 | E2 | 查是否重建 DOM |
| 功能灰着不解释 | E3 | 写明原因 |

## 🔴 改任何东西前的第 0 步：先查调研台账

**`docs/research/RESEARCH_LEDGER.md`** 是全部调研对象的台账（40 份文档、十几个平台）。
每条标明「采纳了什么 / 还欠什么」。

- 加功能前：**先看台账，别重复调研**
- 问"某某平台怎么做的"：**先查台账**
- 台账里"欠"的项：要么转任务，要么明确砍掉，不能永久挂着

**教训（2026-10-19 用户指出）**：
我调研了 40 份文档但没建索引，导致每次都要用户提醒"你不是调研过吗"。
**调研不建索引 = 白调研。**
