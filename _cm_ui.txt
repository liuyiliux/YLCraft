feat(ui): 批量下载前端接线（进度面板 + 续跑 + 移除记录）

## 为什么必须做前端

⚠️ 本仓库**反复踩过的坑**：后端实现了但**前端没接**
（X、快手、YouTube/Telegram、微博、抖音/小红书体检都犯过）。
后端接口做好只是"能做"，没 UI 入口 = 没做。

实测确认：`createDownloadTask` 在**前端根本没被调用过** ——
批量下载功能此前**完全没有入口**。

## 加了什么

### 1. API 封装（`api/index.ts`）
    createDownloadBatch / listDownloadBatches / resumeDownloadBatch
    deleteDownloadBatch / listResumableDownloads / resumeDownload

### 2. 批量下载按钮（搜索结果工具栏）
勾选素材后出现「批量下载 (N)」。

⚠️ **排除微信文章** —— 它们有自己的按钮 + 格式选项
（混在一起会让用户以为能选格式，实际走通用路径）。

### 3. 进度面板（Modal）
  · 每批显示：标题 / 进度条 / `done/total` / **分状态计数**
    （待下载 / 下载中 / 已完成 / 失败）
  · **续跑**按钮（只跑没成功的）
  · **移除记录**按钮
  · ⚠️ 明确写"**只删任务记录，已下载的文件会保留**" ——
    不说的话用户会以为文件也没了，不敢点

### 4. 轮询进度（4 秒一次）
⚠️ **全部完成后自动停**（避免无意义的持续轮询）。

## 实测（完整前端链路）

    提交 3 项 → HTTP 200 "已创建批次并开始下载"
    轮询： 0% → 33.3% → 66.7% → **100%**（真实进度）
            counts 依次 {"running":1,"pending":2} → {"done":3}
    续跑： "该批次**没有待跑或失败的条目**（全部已完成）"
            ← 不假装"已开始"，如实说明
    删记录："已删除批次记录（文件保留）"
    文件：  确实还在（字幕/弹幕都下了）✅

## 测试（只跑相关文件）
`tests/test_download_resume.py` 扩到 **24 条**，新增 5 条守前端：
  · **前端真的调了**那三个接口（防"后端做了前端没接"）
  · 有进度 UI（batchPanelOpen / batchList / progress）
  · 有轮询 **且完成后会停**
  · handleBatchDownload **排除微信文章**
  · UI 说明"移除记录不删文件"

相关测试合计 **96 passed**。
