## 一、修两个「静默丢字段」的真 bug（后端）

实测发现 YouTube / Telegram 的详情**时长和播放量都是 0/缺失**，
而平台侧明明有值（YouTube duration=16012、views=4937万）：

| 字段 | 修前 | 修后 |
|------|------|------|
| Telegram duration | 0 | **6 秒** |
| Telegram views | 缺失 | **151万** |
| YouTube duration | 0 | **16012 秒（4:26:52）** |
| YouTube views | 缺失 | **4937万** |

两处都漏在**链路的中间层**，而且都是**静默**的：

1. **`crawler.service.get_note_detail` 的转换字典漏了 `duration`**
   —— 平台对象有值、模型有这个字段，中间那个大字典**没放进去**。
2. **`crawler.models.NoteDetail` 没有 `views` 字段**
   —— service 一直在传，但 pydantic 默认**忽略多余字段** → 前端永远拿不到。

⚠️ 与仓库里 `collect_count` 那个坑**同类**（"字段名不对，
pydantic 静默忽略"）。四层转换（平台对象 → dict → pydantic → 前端）
**每层都可能静默丢**，所以加了结构性测试：
`test_service_detail_dict_includes_all_model_fields` 断言转换字典
必须覆盖模型的所有字段。

## 二、前端：详情显示播放量 + 时长

通用详情原来**只显示 赞/收藏/评论/分享** —— 把「播放量」「时长」
漏了，而这两个恰是 YouTube/Telegram/B站 最核心的数字。
**症状**：YouTube 详情看不出视频多长、多少人看过
（列表里有，点进去反而没有）。

补了一行「播放/时长」，并修 `formatDuration` 的**小时**处理 ——
YouTube 长课程有 4 小时以上（16012 秒），只写 `m:ss` 会显示成
`26:52`，用户以为视频只有 26 分钟。

## 三、Telegram 富文本渲染（含 XSS 防线）

Telegram 消息正文里有 `<a>` 链接、`<br>`、加粗 —— 后端在
`raw_data.html` 里给了原始 HTML。原来按纯文本渲染，
**所有外链都变成不可点击的字符串**（用户得手动复制），
而 Telegram 消息大量依赖外链。

⚠️ **但绝不能直接 `dangerouslySetInnerHTML` 原始 HTML** ——
那是 XSS 入口（消息可以内含任意标签，比如转发别人发的
带 `<script>` 的内容）。所以加了 `sanitizeTelegramHtml`：

  · **白名单**：a / br / b / i / u / s / code / pre / tg-spoiler
  · 其它标签**只脱标签、留文字**
  · `<a>` 只留 href，且校验协议（挡 `javascript:` / `data:`）
  · 先整体干掉 script / style / iframe / object / embed
  · 不引 DOMPurify（输入面窄，正则白名单够用，**零新依赖**）

另渲染 Telegram 特有的**转发来源**与**正文外链列表**。
